# Theming

AUI supplies the look, React supplies the structure. Every component works without CSS; add `import '@airlib/aui'` for the full library, or `import '@airlib/aui/components/widgets/button.css'` for one component's own rules. The full library brings the theme tokens, base defaults, component families, and utilities that make a component look finished.

Selective imports never pull unrelated component families, and CSS never loads through JavaScript utilities — `import { configure } from '@airlib/react-aui'` and `import { SIZES } from '@airlib/aui/utils'` carry types and configuration only.

## Layers

Cascade order is declared once, in the library entry stylesheet:

```css
@layer theme, base, component, utility, reduced-motion;
```

`theme` holds every design token, `base` ships the element defaults and the keyboard focus ring, `component` owns each component's structure and token mappings (`.aui-control`, `.aui-button`), and `utility` ships the spacing, layout, text, size, and touch helpers plus `.aui-action`. Utilities come last so a helper can refine a component rule; HTML class order never decides precedence.

## Tokens

Primitive tokens live once in `theme`, components reference them through semantic tokens:

```css
.demo-themed {
  --color-primary: oklch(55% 0.18 250);
  --spacing: 0.25rem;
}
```

Override any `--color-*`, `--spacing`, radius, or component token such as `--aui-control-radius` from your own stylesheet or inline style. Spacing derives with `calc(var(--spacing) * 4)`, colors shift with `color-mix(in srgb, var(--color-primary) 90%, white)`. Light and dark ship together via `light-dark()` and `color-scheme: light dark`.

## Sizes, variants, colors

One vocabulary across every component:

```tsx
import { Button } from '@airlib/react-aui';

<Button size="sm" variant="tonal" color="success">Saved</Button>
```

Sizes `xs`–`xxl` default `md`, variants `filled`, `elevated`, `tonal`, `outlined`, `text` default `filled`, colors `primary`, `secondary`, `tertiary`, `error`, `success`, `warning`, `info` default `primary`. Explicit props win; otherwise the configured fallback applies:

```tsx
import { configure } from '@airlib/react-aui';

configure({ button: { size: 'sm' } });
```

## Palette

Every color token rendered live — each swatch pairs a background role with its `on-` role (`Aa` is set in the on-color), so a broken pairing is visible instead of theoretical. Outlines render as borders on `surface`; override `--seed-color` or any `--color-*` above and the whole grid follows the derivation chain.

## Spacing

One base unit, everything else derived — bar widths below are the tokens themselves, so overriding `--spacing` re-flows the whole scale (`xs`–`xxl` are `spacing * 1, 2, 4, 6, 8, 12`). Component sizes live separately as `--size-*` (`spacing * 6` through `spacing * 16`, starting at 24px).

:::interactive[Spacing scale]{standalone}

```tsx
const SIZES: Array<[string, string]> = [
  ['--spacing-xs', 'spacing * 1'],
  ['--spacing-sm', 'spacing * 2'],
  ['--spacing-md', 'spacing * 4'],
  ['--spacing-lg', 'spacing * 6'],
  ['--spacing-xl', 'spacing * 8'],
  ['--spacing-xxl', 'spacing * 12'],
];

const SpacingDemo = () => (
  <div>
    {SIZES.map(([token, formula]) => (
      <div key={token} className="demo-spacing-row">
        <span className="demo-spacing-label">{token}</span>
        <div className="demo-spacing-bar" style={{ width: `var(${token})` }} />
        <span className="demo-type-token">{formula}</span>
      </div>
    ))}
  </div>
);
```

## Utilities

Framework-agnostic helpers carry the same vocabulary without React or CSS side effects:

```tsx
import { SIZES, VARIANTS, COLORS } from '@airlib/aui/utils';
```

Use them for configuration and prop values. They never inject styles and never touch the DOM.

### Spacing utilities

`m` = margin, `p` = padding, then direction (`b` block, `i` inline, `bs`/`be` block-start/end, `is`/`ie` inline-start/end), then size (`0`, `xs`–`xxl`, plus `auto` for margin) — so `mi-xs` is `margin-inline: var(--spacing-xs)` and `mis-xs` is `margin-inline-start`. Gap is the full word: `gap-*`, `gap-row-*`, `gap-col-*`.

:::interactive[Spacing utilities]{standalone}

```tsx
const SpacingUtilitiesDemo = () => (
  <div>
    <div className="flex-row items-center gap-sm">
      <div className="demo-spacing-bar" style={{ width: 'var(--spacing-md)' }} />
      <span className="demo-type-token">flex-row items-center gap-sm</span>
    </div>
    <div className="mi-md p-sm" style={{ border: '1px dashed var(--color-outline)' }}>
      <span className="demo-type-token">mi-md p-sm — margin-inline + padding</span>
    </div>
    <div className="flex-row gap-xs">
      <div className="demo-spacing-bar" style={{ width: 'var(--spacing-sm)' }} />
      <div className="demo-spacing-bar" style={{ width: 'var(--spacing-sm)' }} />
      <span className="demo-type-token">gap-xs</span>
    </div>
  </div>
);
```

## Overrides

Your classes add next to the built-in ones by default. With `overrides` set once, a supplied `className` replaces them across every component:

```tsx
import { configure } from '@airlib/react-aui';

configure({ overrides: true });

// class="my-btn"
<Button className="my-btn">Save</Button>
```

Behavior, refs, events, and accessibility are unchanged.

## Global defaults

`@airlib/aui` includes the base layer, so the full-library import brings the element defaults along with the components. A single component stylesheet brings none of them — no tokens, no base defaults, no utilities — so pair it with what you load yourself, or use the full library.
