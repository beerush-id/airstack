# Theming

AUI supplies the look, React supplies the structure. Every component works without CSS; add `import '@airlib/aui'` for the full library, or `import '@airlib/aui/components/widgets/button.css'` for one component and the shared looks it builds on. The full library brings the theme tokens, base defaults, component families, and utilities that make a component look finished.

Selective imports never pull unrelated component families, and CSS never loads through JavaScript utilities — `import { configure } from '@airlib/react-aui'` and `import { SIZES } from '@airlib/aui/utils'` carry types and configuration only.

## Layers

Everything AUI ships lives under one `aui` layer, so your stylesheet places the whole library with a single name, and its own `theme` or `components` layers — yours, Tailwind's — never merge with AUI's:

```css
@layer reset, aui, app;

@import '@airlib/aui/base/reset.css' layer(reset);
@import '@airlib/aui';
```

Anything in a layer after `aui`, or in no layer at all, wins over AUI. Inside it, the order is fixed by the library:

```css
@layer aui.theme, aui.base, aui.component, aui.utility, aui.reduced-motion;
```

`aui.theme` holds every design token, `aui.base` the keyboard focus ring, `aui.component` each component's structure and token mappings (`.aui-control`, `.aui-button`), and `aui.utility` the spacing, layout, text, size, and touch helpers plus `.aui-action`. Utilities come last so a helper can refine a component rule; HTML class order never decides precedence.

The page reset — element margins, heading sizes, list styles, form fonts — is yours to opt into: import `base/reset.css` into a layer of your own, before anything that styles prose. Skip it when your app already has one, such as Tailwind's preflight.

Reduced motion is the one rule nothing overrides. When people ask their system for less motion, AUI turns transitions and animations off with `!important`, which beats every page style, so no app style can bring motion back against their setting. A spinner keeps a slow turn, since a still ring wouldn't say "working".

When you import a single component stylesheet instead of the whole library, wrap it yourself so it lands in the same place: `@import '@airlib/aui/components/widgets/dialog.css' layer(aui);`.

The desktop shell — windows, the dock, and the answers above it — isn't in the main stylesheet, so apps that never draw a desktop don't carry it. When you build one, add `@import '@airlib/aui/desktop.css';` beside the main import; it lands in the same `aui` layer. Its components come from `@airlib/react-aui/desktop`.

## Tokens

Primitive tokens live once in `theme`, components reference them through semantic tokens:

```css
.demo-themed {
  --color-primary: oklch(55% 0.18 250);
  --spacing: 0.25rem;
}
```

Override any `--color-*`, `--spacing`, radius, or component token such as `--aui-control-radius` from your own stylesheet or inline style. Spacing derives with `calc(var(--spacing) * 4)`, colors shift with `color-mix(in srgb, var(--color-primary) 90%, white)`. Light and dark ship together via `light-dark()` and `color-scheme: light dark`.

## Sizes, variants, colors

One vocabulary across every component:

```tsx
import { Button } from '@airlib/react-aui';

<Button size="sm" variant="tonal" color="success">Saved</Button>
```

Sizes `xs`–`xxl` default `md`, variants `filled`, `elevated`, `tonal`, `outlined`, `text`, `glass` default `filled`, colors `primary`, `secondary`, `tertiary`, `error`, `success`, `warning`, `info` default `primary`. Explicit props win; otherwise the configured fallback applies:

```tsx
import { configure } from '@airlib/react-aui';

configure({ button: { size: 'sm' } });
```

### Fields take three variants

Anything you type into — text inputs, the combobox field, steppers, code cells, date fields — takes `filled`, `tonal`, or `outlined`. A field needs a visible boundary, so the press-only `text` and `elevated` variants are not offered, and neither is `glass`, whose contrast depends on what's behind it. TypeScript says so:

```tsx
<TextInput variant="outlined" color="success" placeholder="Coupon code" />
```

A field stays neutral at rest and shows its color on hover, focus, the caret, and errors, so it never reads as a button.

## Style a composite once

When a component is made of parts — a select's trigger and options, a menu's button and items, a dialog's buttons — set `size`, `color`, and `variant` on the outer component and every part follows:

```tsx
<Select options={CITIES} size="sm" color="tertiary" />

<Menu size="lg" color="secondary">
  <MenuButton>Export</MenuButton>
  <MenuPanel>
    <MenuItem name="pdf">As PDF</MenuItem>
    <MenuItem name="csv" color="error">As CSV (beta)</MenuItem>
  </MenuPanel>
</Menu>
```

A part still decides for itself when you tell it to. The value a part uses is, first to last:

1. the part's own prop (`color="error"` on that one item);
2. the nearest outer component's prop (`color="secondary"` on the menu);
3. the part's configured default from `configure()`;
4. the built-in default.

A few secondary buttons keep their own quieter variant even under a filled parent — a dialog's close, a confirm's cancel, a toast's dismiss — so the main action stays the loudest thing on the sheet.

## Palette

Every color token rendered live — each swatch pairs a background role with its `on-` role (`Aa` is set in the on-color), so a broken pairing is visible instead of theoretical. Outlines render as borders on `surface`; override `--seed-color` or any `--color-*` above and the whole grid follows the derivation chain.

Backgrounds and the things on them take different families, so they never land on the same tone. **Surfaces** (`surface`, `surface-lowest` … `surface-highest`) are neutral: the page, and wrappers that only group content, like a card. **Containers** (`container`, `container-lowest` … `container-highest`) carry a faint hue of the seed: the things placed on a surface — a dialog, a menu, a field, a list. Both climb the same ladder; a container placed on a card, or on the page, always reads apart from it.

## Glass

Windows, the dock, the assistant's answers, and desktop widgets are all made of the same glass: a tint over what's behind, blurred, with light caught along the edge. When something of your own floats over the desktop — a player, a status card, a panel beside a window — give it the same glass with a class instead of copying the recipe, so it matches them and follows the theme:

- `aui-glass-frame` — the outer pane: tinted, blurred, edged, rounded, and lifted.
- `aui-glass-panel` — a frosted pane on a frame, like a window's sidebar.
- `aui-glass-surface` — a solid surface on a frame, for what people read and work on, like a window's content.

```tsx
<aside className="aui-glass-frame now-playing">
  <div className="aui-glass-surface now-playing-track">
    <p>Clair de Lune</p>
    <p>Claude Debussy</p>
  </div>
</aside>
```

Tune a piece of glass through its variables, never by restating the properties, so it stays the same glass as everything else:

```css
.now-playing {
  --aui-glass-tint: 75%;
  --aui-glass-radius: var(--radius-xl);
  --aui-glass-shadow: var(--elevation-3);
}
```

- `--aui-glass-tint` — how much surface color covers what's behind; `--aui-glass-bg` is that color.
- `--aui-glass-blur` — how strongly what's behind is blurred.
- `--aui-glass-edge` — the light caught along the edge.
- `--aui-glass-radius`, `--aui-glass-shadow` — the pane's corners and how it lifts.
- `--aui-glass-panel-tint`, `--aui-glass-surface-bg`, `--aui-glass-lift` — a panel's tint, a surface's color, and how either lifts off its frame.

A control on glass that is glass itself — a button with `variant="glass"` — keeps its tint but skips a second blur, which would only muddy it. When people ask for less transparency, glass turns solid. Popups — menus, popovers, a select's list — have a glass of their own and keep it.

## Utilities

Framework-agnostic helpers carry the same vocabulary without React or CSS side effects:

```tsx
import { SIZES, VARIANTS, COLORS } from '@airlib/aui/utils';
```

Use them for configuration and prop values. They never inject styles and never touch the DOM.

### Spacing utilities

`m` = margin, `p` = padding, then direction (`b` block, `i` inline, `bs`/`be` block-start/end, `is`/`ie` inline-start/end), then size (`0`, `xs`–`xxl`, plus `auto` for margin) — so `mi-xs` is `margin-inline: var(--spacing-xs)` and `mis-xs` is `margin-inline-start`. Gap is the full word: `gap-*`, `gap-row-*`, `gap-col-*`.

## Overrides

Your classes add next to the built-in ones by default. With `overrides` set once, a supplied `className` replaces them across every component:

```tsx
import { configure } from '@airlib/react-aui';

configure({ overrides: true });

// class="my-btn"
<Button className="my-btn">Save</Button>
```

Behavior, refs, events, and accessibility are unchanged.

## Global defaults

`@airlib/aui` includes the base layer, so the full-library import brings the element defaults along with the components. A single component stylesheet brings that component plus the shared looks it is built from — the control shape, the field surface, the floating panel, the list row — but no tokens, no base defaults, and no utilities, so pair it with what you load yourself, or use the full library. Importing several component stylesheets never duplicates the shared looks.
