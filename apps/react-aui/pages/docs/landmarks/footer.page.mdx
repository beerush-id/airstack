# AUI Footer

Closing links, legal text, and status sit at the end of every page, and a landmark is what lets a user jump straight to them. The footer compiles `contentinfo` onto a real `<footer>` and adds a name only when a document carries two.

Styling is optional. Without AUI CSS the Footer stays a correct, operable landmark; with it, the same markup gets the AUI treatment through the full library.

:::interactive[Footer demo]

```tsx
import { Footer, Toggle } from '@airlib/react-aui';
import { $bind, mutable, setup, Snippet } from '@airlib/react';
import { GlassStage } from '@/components/GlassStage.js';

const FooterDemo = setup(() => {
  const state = mutable({ named: true });

  return () => (
    <div className="demo-button">
      <Toggle pressed={$bind(state, 'named')}>
        {() => (state.named ? 'Named' : 'Unnamed')}
      </Toggle>
      <GlassStage>
        <div className="flex gap-md items-center justify-center">
          <Snippet>
            {() => (
              <Footer label={state.named ? 'Site' : undefined}>
                <span>© AirLib</span>
              </Footer>
            )}
          </Snippet>
        </div>
      </GlassStage>
    </div>
  );
}, 'FooterDemo');
```

## Usage

```tsx
import { Footer } from '@airlib/react-aui';
import '@airlib/aui/components/landmarks/footer.css';

export const SiteFooter = () => (
  <Footer label="Site">
    <span>© AirLib</span>
  </Footer>
);
```

For the full library — tokens, base defaults, every component, and the utilities — load `import '@airlib/aui';` instead. The landmark stylesheet carries no visuals; the native host supplies the semantics.

### Properties

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `label` | `string` | — | The name screen readers announce, compiled to `aria-label`. Omitted when absent. |
| `labelledby` | `string` | — | The ID of an element that provides the name, compiled to `aria-labelledby`. |
| `id` | `string` | — | Your hook for fragment links; the controller compiles no identifier. |
| `className` | `string` | — | Added alongside the built-in classes, or in place of them with `overrides` enabled. |
| `children` | `ReactNode` | — | Closing links, legal text, and status inside the footer. |
| `ref` | `Ref<HTMLElement>` | — | Access to the underlying footer element. |

Set, change, or clear `label` or `labelledby` and the projection follows. Both props compile to their `aria-*` counterparts only and never leak onto the host as plain attributes.

To make `className` replace the built-in classes, turn on `overrides` once in [Theming](/docs/theming#overrides).

Keyboard: none. The footer takes no focus and claims no keys; the links inside keep their own behavior.
