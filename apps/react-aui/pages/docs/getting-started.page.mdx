# Getting Started

From an empty file to a working, accessible component: install two packages, load one stylesheet, and hand a component your data. This page walks one component — a city picker — from its simplest form to fully custom, so you see every path the library offers before you need it.

## Install

```bash
npm install @airlib/react-aui @airlib/aui
```

Your app supplies `react`, `react-dom`, and `typescript`. The rest of AirLib — `@airlib/react` for state, `@airlib/aria` for behavior — comes along as dependencies.

## Load the styles

Load the whole look once, at your app's entry:

```tsx
import '@airlib/aui';
```

That brings the theme tokens, the element defaults, every component, and the layout and text utilities. If you only use a few components, load just theirs — each stylesheet brings the component and the shared looks it is built from:

```tsx
import '@airlib/aui/components/widgets/select.css';
```

Styles are optional. Without them every component is still a correct, keyboard- and screen-reader-ready control; the stylesheet is what makes it look finished.

## Your first component

Hand the component your data and bind its value to your state. It renders the trigger, the popup, the options, and the keyboard handling:

:::interactive[City picker]

```tsx
import { Select } from '@airlib/react-aui';
import { $bind, mutable, setup, Snippet } from '@airlib/react';

const CITIES = { ams: 'Amsterdam', ber: 'Berlin', lis: 'Lisbon', osl: 'Oslo' };

const CityPicker = setup(() => {
  const trip = mutable({ from: 'lis' });

  return () => (
    <div className="flex flex-col gap-sm">
      <Select label="Departure" options={CITIES} value={$bind(trip, 'from')} />
      <Snippet>{() => <span>Leaving from {CITIES[trip.from]}</span>}</Snippet>
    </div>
  );
}, 'CityPicker');
```

```html
<CityPicker />
```

<CityPicker />

:::

`$bind(trip, 'from')` is a two-way binding: picking an option writes `trip.from`, and writing `trip.from` from anywhere moves the select. There is no change handler to write and no open state to keep — the component owns both. Listen to `onchange` only when you want to react to the user's choice, for example to save it.

## Make it look the part

One vocabulary styles every component: `size` (`xs`–`xxl`), `color` (`primary`, `secondary`, `tertiary`, `error`, `success`, `warning`, `info`), and `variant`. Set them on the component and every part inside it — the trigger, the popup, the options — follows:

```tsx
<Select options={CITIES} value={$bind(trip, 'from')} size="lg" color="tertiary" variant="outlined" />
```

Set a default once instead of on every call:

```tsx
import { configure } from '@airlib/react-aui';

configure({ select: { size: 'sm' } });
```

## Change what a row shows

When the label alone is not enough — an airport code in front of the city, say — keep the component and supply the content through a slot. The behavior and the structure stay the library's; you only decide what renders inside:

```tsx
<Select options={CITIES} value={$bind(trip, 'from')}>
  <Select.Snippet for="option">
    {(entry) => (
      <span>
        <b>{entry.key.toUpperCase()}</b> {entry.label}
      </span>
    )}
  </Select.Snippet>
</Select>
```

Every component with a data prop offers slots for its trigger, rows, or panels; each component's page lists them.

## Build it from parts

When the layout is yours to invent — a footer row inside the popup, mixed rows, rows from several sources — compose the parts yourself. They still find each other: no ids to wire, no open state to pass down:

```tsx
import { Select, SelectOption, SelectPanel, SelectTrigger } from '@airlib/react-aui';

<Select value={$bind(trip, 'from')} size="lg">
  <SelectTrigger placeholder="Choose a departure" />
  <SelectPanel>
    <SelectOption value="ams">Amsterdam</SelectOption>
    <SelectOption value="ber">Berlin</SelectOption>
  </SelectPanel>
</Select>
```

`size="lg"` on the root still reaches the trigger and every option. A part's own prop wins when you set one.
