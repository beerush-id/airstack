# AUI Tabs

Settings pages, product details, dashboards: when several panels share one spot and people look at one at a time, you need tabs. Building them by hand means pairing every tab with its panel for screen readers, keeping the strip to a single stop in the tab order, moving between tabs with the arrow keys without swapping panels behind the reader's back, and making sure one tab is always open.

**AUI Tabs** does all of that. Give it the tab names and what each panel shows, bind the open tab to your state if you need it, and it renders the strip, the panels, and the selection that glides from tab to tab.

:::interactive[Tabs demo]

```tsx
import { Tabs, Toggle } from '@airlib/react-aui';
import { $bind, mutable, setup, Snippet } from '@airlib/react';
import { DemoControl } from '@/components/DemoControl.js';

const SECTIONS = { account: 'Account', security: 'Security', notifications: 'Notifications' };

const PANELS = {
  account: 'Personal details, email, and profile settings.',
  security: 'Two-factor authentication and security keys.',
  notifications: 'Which email and in-app alerts you receive.',
};

const TabsDemo = setup(() => {
  const state = mutable({
    current: 'account',
    size: 'md',
    color: 'primary',
    variant: 'filled',
    vertical: false,
    disabled: false,
  });

  return () => (
    <div className="demo-button">
      <DemoControl
        size={$bind(state, 'size')}
        color={$bind(state, 'color')}
        variant={$bind(state, 'variant')}
        disabled={$bind(state, 'disabled')}
      >
        <Toggle size="sm" pressed={$bind(state, 'vertical')}>
          {() => (state.vertical ? 'Vertical' : 'Horizontal')}
        </Toggle>
      </DemoControl>
      <div className="aui-card flex p-xl">
        <Snippet>
          {() => (
            <Tabs
              label="Account settings"
              items={SECTIONS}
              value={$bind(state, 'current')}
              orientation={state.vertical ? 'vertical' : 'horizontal'}
              size={state.size}
              color={state.color}
              variant={state.variant}
              disabled={state.disabled}
            >
              <Tabs.Snippet for="panel">{(entry) => PANELS[entry.name]}</Tabs.Snippet>
            </Tabs>
          )}
        </Snippet>
      </div>
      <Snippet>{() => <span>Open tab: {state.current}</span>}</Snippet>
    </div>
  );
}, 'TabsDemo');
```

## Usage

### From a list of tabs

When the tabs are known up front, pass them as `items` and fill each panel through the `panel` slot. Each entry's key is the tab's name; its value is the text on the tab:

```tsx
import { Tabs } from '@airlib/react-aui';
import '@airlib/aui/components/widgets/tabs.css';

const SECTIONS = { account: 'Account', security: 'Security', billing: 'Billing' };

export const SettingsTabs = () => (
  <Tabs label="Settings" items={SECTIONS}>
    <Tabs.Snippet for="panel">
      {(entry) => <SettingsSection section={entry.name} />}
    </Tabs.Snippet>
  </Tabs>
);
```

The first tab opens by default. Bind `value` when the rest of your screen needs to know which tab is open, or to open one from elsewhere — a deep link, a "Go to billing" button:

```tsx
<Tabs label="Settings" items={SECTIONS} value={$bind(page, 'section')}>
  …
</Tabs>
```

Pass full entries instead of a map when a tab needs to be disabled:

```tsx
const SECTIONS = [
  { name: 'account', label: 'Account' },
  { name: 'billing', label: 'Billing', disabled: true },
];
```

### Custom tab content

When a tab needs more than text — an icon, an unread count — supply it through the `tab` slot. The tab keeps its behavior and selection; you decide what renders inside it:

```tsx
<Tabs label="Inbox" items={FOLDERS}>
  <Tabs.Snippet for="tab">
    {(entry) => (
      <>
        {entry.label} <span className="count">{unread[entry.name]}</span>
      </>
    )}
  </Tabs.Snippet>
  <Tabs.Snippet for="panel">{(entry) => <MessageList folder={entry.name} />}</Tabs.Snippet>
</Tabs>
```

### Building from parts

When the strip and the panels are not next to each other — the strip in a toolbar, the panels in the page body — or each panel is long, hand-written markup, compose the parts. A tab and its panel find each other by a shared `name`:

```tsx
import { TabButton, TabList, TabPanel, Tabs } from '@airlib/react-aui';

<Tabs value={$bind(page, 'section')}>
  <TabList label="Account settings">
    <TabButton name="account">Account</TabButton>
    <TabButton name="security">Security</TabButton>
  </TabList>
  <TabPanel name="account">
    <ProfileForm />
  </TabPanel>
  <TabPanel name="security">
    <SecurityKeys />
  </TabPanel>
</Tabs>
```

### Style it once

`size`, `color`, and `variant` on `Tabs` reach the strip and every tab; a tab's own prop still wins. See [Theming](/docs/theming#style-a-composite-once).

The variant decides how the open tab stands out as the selection glides between tabs: `filled` fills it with the color, `tonal` tints it, `outlined` rings it, `elevated` lifts it off the strip, and `text` drops the strip for a sliding underline.

### Properties

`Tabs`:

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `items` | `Record<string, string>` or `Array<{ name, label?, disabled? }>` | — | The tabs to render. Leave it out to compose the parts yourself. |
| `label` | `string` | — | The strip's name for screen readers. Give one whenever the page has more than one tab strip. |
| `value` | `Bindable<string>` | first tab | The `name` of the open tab. Bind it to read or change the open tab from outside. |
| `orientation` | `'horizontal'`, `'vertical'` | `'horizontal'` | Whether the strip runs across or down, and which arrow keys travel it. |
| `disabled` | `boolean` | `false` | Locks switching across the whole group. |
| `size` | `xs`–`xxl` | `'md'` | Reaches the strip and every tab. |
| `color` | `primary`, `secondary`, `tertiary`, `error`, `success`, `warning`, `info` | `'primary'` | The color of the open tab. |
| `variant` | `filled`, `tonal`, `outlined`, `elevated`, `text` | `'filled'` | How the open tab stands out. |
| `onchange` | `(event: CustomEvent<string>) => void` | — | A different tab opened; `detail` is its `name`. Use it to save or track the choice. |
| `className` | `string` | — | Added alongside the built-in classes, or in place of them with `overrides` enabled. |

Slots, used with `items`:

| Slot | Receives | Renders |
| --- | --- | --- |
| `panel` | the entry (`name`, `label`) | The content of that tab's panel. |
| `tab` | the entry (`name`, `label`) | What the tab itself shows, in place of its label. |

Parts, used without `items`:

| Part | Props | Notes |
| --- | --- | --- |
| `TabList` | `label`, `labelledby` | The strip. Name it so screen readers can tell strips apart. |
| `TabButton` | `name` (required), `disabled`, `selected` | One tab. `selected` opens it first when `value` is not set. |
| `TabPanel` | `name` (required) | The content shown while the tab with the same `name` is open. |

Set app-wide defaults once with `configure({ tabButton: { variant: 'tonal' } })`.

Keyboard: `Tab` lands on the open tab and leaves the strip on the next press. The arrow keys move between tabs (`Left`/`Right` across, `Up`/`Down` down a vertical strip) without changing the open panel; `Home` and `End` jump to the first and last tab; `Enter` or `Space` opens the focused tab. Disabled tabs are skipped. One tab is always open: activating the open tab changes nothing and fires no event.
