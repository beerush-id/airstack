# AUI Confirm

A confirm is the question a page asks before something irreversible: delete this project, publish now, discard the draft. Getting it right means the panel is always modal, `Escape` never answers for the reader, focus starts on the safe choice, and the two outcomes are announced as decisions rather than as a closed dialog.

**AUI Confirm** does all of that for you, and leaves the markup and the styling entirely yours. One state drives the trigger, the panel, the title, the description, and the two buttons; the panel compiles the `alertdialog` role and names itself; the cancel button takes focus when the panel opens. `Escape` is suppressed at every point — the decision belongs to the two buttons.

Styling is optional. Without AUI CSS the Confirm stays a correct, operable decision; with it, the same markup gets the AUI treatment through the full library.

:::interactive[Confirm demo]

```tsx
import { Confirm, ConfirmAction, ConfirmCancel, ConfirmDescription, ConfirmPanel, ConfirmTitle, ConfirmTrigger, Toggle } from '@airlib/react-aui';
import { $bind, mutable, setup, Snippet } from '@airlib/react';

const ConfirmDemo = setup(() => {
  const state = mutable({ open: false, last: 'Nothing decided yet' });

  return () => (
    <div className="demo-button">
      <div className="flex gap-xs w-full flex-wrap">
        <Toggle size="sm" pressed={$bind(state, 'open')}>
          {() => (state.open ? 'Close decision' : 'Open decision')}
        </Toggle>
        <div className="flex-1"></div>
        <span>{state.last}</span>
      </div>
      <div className="aui-card flex flex-wrap gap-lg items-center justify-center p-xl">
        <Snippet>
          {() => (
            <Confirm
              open={$bind(state, 'open')}
              onconfirm={() => (state.last = 'Project deleted')}
              oncancel={() => (state.last = 'Deletion declined')}
            >
              <ConfirmTrigger>Delete project</ConfirmTrigger>
              <ConfirmPanel>
                <ConfirmTitle>Delete project?</ConfirmTitle>
                <ConfirmDescription>Every notebook in it is removed for good. This cannot be undone.</ConfirmDescription>
                <ConfirmCancel>Keep project</ConfirmCancel>
                <ConfirmAction>Delete</ConfirmAction>
              </ConfirmPanel>
            </Confirm>
          )}
        </Snippet>
        <Snippet>
          {() => (
            <Confirm onconfirm={() => (state.last = 'Changes published')} oncancel={() => (state.last = 'Publishing cancelled')}>
              <ConfirmTrigger>Publish changes</ConfirmTrigger>
              <ConfirmPanel>
                <ConfirmTitle>Publish to production?</ConfirmTitle>
                <ConfirmDescription>Readers see the new version immediately.</ConfirmDescription>
                <ConfirmCancel>Cancel</ConfirmCancel>
                <ConfirmAction>Publish</ConfirmAction>
              </ConfirmPanel>
            </Confirm>
          )}
        </Snippet>
      </div>
    </div>
  );
}, 'ConfirmDemo');
```

## Usage

Put one trigger, one panel, one title, one description, and the two buttons inside the unit. The order of the buttons is a decision of your own — focus starts on cancel either way:

```tsx
import { Confirm, ConfirmAction, ConfirmCancel, ConfirmDescription, ConfirmPanel, ConfirmTitle, ConfirmTrigger } from '@airlib/react-aui';
import '@airlib/aui/components/widgets/confirm.css';

export const DeleteProject = () => (
  <Confirm onconfirm={() => project.remove()}>
    <ConfirmTrigger>Delete project</ConfirmTrigger>
    <ConfirmPanel>
      <ConfirmTitle>Delete project?</ConfirmTitle>
      <ConfirmDescription>Every notebook in it is removed for good.</ConfirmDescription>
      <ConfirmCancel>Keep project</ConfirmCancel>
      <ConfirmAction>Delete</ConfirmAction>
    </ConfirmPanel>
  </Confirm>
);
```

For the full library — tokens, base defaults, every component, and the utilities — load `import '@airlib/aui';` instead. A lone component stylesheet carries only that component's rules.

Leave `open` out and the trigger drives the panel; set it and the panel follows yours. Bind it to open the decision from outside:

```tsx
import { $bind, mutable } from '@airlib/react';

const state = mutable({ open: false });

<Confirm open={$bind(state, 'open')}>
  <ConfirmTrigger>Delete project</ConfirmTrigger>
  <ConfirmPanel>
    <ConfirmTitle>Delete project?</ConfirmTitle>
    <ConfirmDescription>Every notebook in it is removed for good.</ConfirmDescription>
    <ConfirmCancel>Keep project</ConfirmCancel>
    <ConfirmAction>Delete</ConfirmAction>
  </ConfirmPanel>
</Confirm>
```

### Answering

The action commits and closes; the cancel button declines and closes. Each fires its own event, and either can be cancelled to keep the panel open — useful when the decision needs an async check before it lands:

```tsx
<Confirm
  onconfirm={(event) => {
    if (!repository.canDelete()) event.preventDefault();
  }}
  oncancel={() => audit.note('declined')}
>
  <ConfirmTrigger>Delete project</ConfirmTrigger>
  <ConfirmPanel>
    <ConfirmTitle>Delete project?</ConfirmTitle>
    <ConfirmDescription>Every notebook in it is removed for good.</ConfirmDescription>
    <ConfirmCancel>Keep project</ConfirmCancel>
    <ConfirmAction>Delete</ConfirmAction>
  </ConfirmPanel>
</Confirm>
```

`Escape` and outside presses never answer. `Tab` and `Shift+Tab` stay inside the panel, `Enter` and `Space` activate the focused button, and focus starts on the cancel button. Closing returns focus to the trigger.

### Parts

| Part | Host | Role | What it does |
| --- | --- | --- | --- |
| `Confirm` | `div` | — | Holds `open`, the identifier namespace, and the two decision events. |
| `ConfirmTrigger` | `button` | — | Opens the panel. |
| `ConfirmPanel` | `div` | `alertdialog` | The always-modal container. Carries `aria-modal="true"`, naming, and `hidden` while closed. |
| `ConfirmTitle` | `div` | — | Names the decision. |
| `ConfirmDescription` | `div` | — | Explains what the decision commits. |
| `ConfirmCancel` | `button` | — | Declines and closes. Receives focus when the panel opens. |
| `ConfirmAction` | `button` | — | Commits and closes. |

### Properties

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `id` | `string` | `confirm-<n>` | The prefix every part's identifier derives from. Generated when omitted. |
| `open` | `Bindable<boolean>` | `false` | Whether the panel is showing. Bind it to open the decision from code. |
| `onconfirm` | `(event: CustomEvent<void>) => void` | — | Called when the action commits. `preventDefault()` keeps the panel open. |
| `oncancel` | `(event: CustomEvent<void>) => void` | — | Called when the cancel button declines. `preventDefault()` keeps the panel open. |
| `onopen` / `onclose` | `(event: CustomEvent<void>) => void` | — | Called once per visibility change. |
| `className` | `string` | — | Added alongside the built-in classes, or in place of them with `overrides` enabled. |
| `children` | `ReactNode` | — | The trigger and the panel. |
| `ref` | `Ref<HTMLDivElement>` | — | Access to the confirm root element. |

The confirm is always modal and never dismissable — there is no prop to change either. `ConfirmTrigger`, `ConfirmCancel`, and `ConfirmAction` take `disabled` and `className`; the panel takes a `ref`.

Your own classes are added next to the built-in ones:

```tsx
// class="aui-confirm my-decision"
<Confirm className="my-decision">
  <ConfirmTrigger>Delete project</ConfirmTrigger>
  <ConfirmPanel className="my-panel">
    <ConfirmTitle>Delete project?</ConfirmTitle>
    <ConfirmAction>Delete</ConfirmAction>
  </ConfirmPanel>
</Confirm>
```

To make `className` replace the built-in classes, turn on `overrides` once in [Theming](/docs/theming#overrides).
