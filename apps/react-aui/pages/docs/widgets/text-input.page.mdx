# AUI Text Input

A text field looks like the simplest control until you bind it to state: re-render it on every keystroke and the caret jumps, autocomplete fights you, and "invalid" or "required" never quite reach assistive tech. Text Input keeps one live string in sync with your state in both directions while the caret stays exactly where the user put it, and it tells you when the text is committed.

:::interactive[Text input demo]

```tsx
import { Readout, SearchInput, TextInput, Toggle } from '@airlib/react-aui';
import { $bind, mutable, setup, Snippet } from '@airlib/react';
import { DemoControl } from '@/components/DemoControl.js';
import { GlassStage } from '@/components/GlassStage.js';

const TextDemo = setup(() => {
  const state = mutable({ name: 'Ada Lovelace', query: '', size: 'md', color: 'primary', disabled: false, invalid: false });

  return () => (
    <div className="demo-button">
      <DemoControl size={$bind(state, 'size')} color={$bind(state, 'color')} disabled={$bind(state, 'disabled')}>
        <Toggle size="sm" pressed={$bind(state, 'invalid')}>
          {() => (state.invalid ? 'Set Valid' : 'Set Invalid')}
        </Toggle>
      </DemoControl>
      <Snippet>
        {() => (
          <GlassStage style={{ maxInlineSize: '20rem' }}>
            <div className="flex flex-col gap-lg justify-center">
              <Snippet>
                {() => (
                  <TextInput
                    label="Display name"
                    placeholder="Ada"
                    value={$bind(state, 'name')}
                    size={state.size}
                    color={state.color}
                    disabled={state.disabled}
                    invalid={state.invalid}
                  />
                )}
              </Snippet>
              <SearchInput
                label="Search docs"
                placeholder="Search"
                value={$bind(state, 'query')}
                size={state.size}
                color={state.color}
                disabled={state.disabled}
              />
              <Snippet>{() => <Readout label="Name" value={state.name} empty="Empty" />}</Snippet>
            </div>
          </GlassStage>
        )}
      </Snippet>
    </div>
  );
}, 'TextDemo');
```

## Usage

### Bind a value

Bind the field to a property of your state. Typing writes it; writing it from anywhere else updates the field, and the caret is never moved by either:

```tsx
import { TextInput } from '@airlib/react-aui';
import { $bind, mutable, setup } from '@airlib/react';
import '@airlib/aui/components/widgets/text-input.css';

const Profile = setup(() => {
  const profile = mutable({ name: '' });

  return () => <TextInput label="Display name" placeholder="Ada" value={$bind(profile, 'name')} />;
}, 'Profile');
```

`label` names the field for screen readers. To show a visible label, help text, and an error message next to the field, wrap it in a [Field](/docs/widgets/field).

### React to a commit

The bound value follows every keystroke. When you want the finished text — to save it, validate it, or send a request — listen for `onchange`, which fires once the user leaves the field with a new value:

```tsx
<TextInput label="Display name" value={$bind(profile, 'name')} onchange={(event) => saveName(event.detail)} />
```

### Search

For a query box, `SearchInput` is the same field announced as a search box, with the browser's search behavior:

```tsx
import { SearchInput } from '@airlib/react-aui';

<SearchInput label="Search orders" placeholder="Order number or customer" value={$bind(filters, 'query')} />;
```

### Kinds and states

`kind` picks the keyboard and validation the browser offers — `text`, `password`, `search`, `email`, `tel`, or `url`. `required`, `invalid`, `readonly`, and `disabled` are announced to assistive tech as well as styled:

```tsx
<TextInput label="Email" kind="email" required />
<TextInput label="Coupon" invalid={!couponOk} />
<TextInput label="Account ID" value="ACC-2041" readonly />
```

A read-only field stays focusable so its value can be selected and copied; a disabled field leaves the tab order.

### Longer text

For a message, a note, or a delivery instruction, one line is too little. Add `multiline` and the field becomes a text area with the same surface, binding, and states; `rows` sets how many lines it shows before it scrolls:

```tsx
<TextInput label="Delivery notes" placeholder="Gate code, where to leave it…" multiline rows={4} value={$bind(order, 'notes')} />
```

People can drag it taller, never wider, so it keeps the form's width. `multiline` is read once, when the field is created.

### Variants and colors

Fields take three variants: `filled` (default), `tonal`, and `outlined`. A field stays neutral at rest and shows its `color` on hover, focus, and the caret; `invalid` switches it to the error color:

```tsx
<TextInput label="Name" variant="filled" />
<TextInput label="Name" variant="tonal" color="secondary" />
<TextInput label="Name" variant="outlined" size="lg" />
```

Set app-wide defaults once with `configure({ textInput: { variant: 'outlined' } })`; see [Theming](/docs/theming#sizes-variants-colors).

### Properties

`TextInput` and `SearchInput` take the same props:

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `value` | `Bindable<string>` | `''` | The text, kept in sync both ways. |
| `label` | `string` | — | Accessible name. Use [Field](/docs/widgets/field) for a visible label. |
| `placeholder` | `string` | — | Hint shown while empty. |
| `kind` | `'text'`, `'password'`, `'search'`, `'email'`, `'tel'`, `'url'` | `'text'` | The kind of text expected. |
| `multiline` | `boolean` | `false` | A text area for several lines. Read once. |
| `rows` | `number` | `3` | Lines a multiline field shows before it scrolls. |
| `required` | `boolean` | `false` | Announced as required. |
| `invalid` | `boolean`, `'grammar'`, `'spelling'` | `false` | Announced as invalid and drawn in the error color. |
| `readonly` | `boolean` | `false` | Focusable and copyable, but not editable. |
| `disabled` | `boolean` | `false` | Not focusable, not editable. |
| `size` | `xs`–`xxl` | `'md'` | |
| `variant` | `filled`, `tonal`, `outlined` | `'filled'` | |
| `color` | `primary`, `secondary`, `tertiary`, `error`, `success`, `warning`, `info` | `'primary'` | |
| `onchange` | `(event: CustomEvent<string>) => void` | — | The committed text, when the user leaves the field. |
| `className` | `string` | — | Added next to the built-in classes, or replaces them with [`overrides`](/docs/theming#overrides). |

Any other `input` attribute (`name`, `autocomplete`, `maxLength`, …) passes through to the element.

## Keyboard

Typing, selection, undo, and autocomplete are the browser's own. `Tab` moves in and out; a disabled field is skipped.
