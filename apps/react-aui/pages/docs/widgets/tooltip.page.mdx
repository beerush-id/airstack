# AUI Tooltip

A tooltip explains a control: what a save button writes, what an icon means, which shortcut fires. Getting it right means describing the trigger only while the panel is open, revealing on focus without the pointer delay, staying open while the pointer crosses into the panel, and dismissing on `Escape` without moving focus anywhere.

**AUI Tooltip** does all of that for you, and leaves the markup and the styling entirely yours. The panel compiles `role="tooltip"` and starts hidden; the trigger gains `aria-describedby` only while the panel shows, so a screen reader never meets stale advice. The panel is a stop of neither the tab order nor the focus ring — it is an advisory, not a control.

Styling is optional. Without AUI CSS the Tooltip stays a correct advisory; with it, the same markup gets the AUI treatment through the full library.

:::interactive[Tooltip demo]

```tsx
import { Button, Toggle, Tooltip } from '@airlib/react-aui';
import { $bind, mutable, setup, Snippet } from '@airlib/react';

const TooltipDemo = setup(() => {
  const state = mutable({ open: false, above: false, dismissable: true });

  return () => (
    <div className="demo-button">
      <div className="flex gap-xs w-full flex-wrap">
        <Toggle size="sm" pressed={$bind(state, 'open')}>
          {() => (state.open ? 'Hide tooltip' : 'Show tooltip')}
        </Toggle>
        <Toggle size="sm" pressed={$bind(state, 'above')}>
          {() => (state.above ? 'Placed above' : 'Placed below')}
        </Toggle>
        <Toggle size="sm" pressed={$bind(state, 'dismissable')}>
          {() => (state.dismissable ? 'Outside press closes' : 'Outside press ignored')}
        </Toggle>
      </div>
      <div className="aui-card flex flex-col gap-lg justify-center p-xl">
        <span>Focus or hover a control — the tooltip follows the live placement</span>
        <div className="flex flex-wrap gap-md">
          <Snippet>
            {() => (
              <Button>
                Save
                <Tooltip
                  open={$bind(state, 'open')}
                  dismissable={state.dismissable}
                  yDir={state.above ? 'above' : 'below'}
                >
                  Stored on this device
                </Tooltip>
              </Button>
            )}
          </Snippet>
          <Snippet>
            {() => (
              <Button>
                Share
                <Tooltip yDir={state.above ? 'above' : 'below'}>Anyone with the link can read</Tooltip>
              </Button>
            )}
          </Snippet>
          <Snippet>
            {() => (
              <Button disabled>
                Publish
                <Tooltip>Never shown while the trigger is locked</Tooltip>
              </Button>
            )}
          </Snippet>
        </div>
      </div>
    </div>
  );
}, 'TooltipDemo');
```

## Usage

Render the tooltip inside the control it explains. The enclosing actionable element becomes its trigger; only when there is none does it fall back to the panel's parent in the DOM:

```tsx
import { Button, Tooltip } from '@airlib/react-aui';
import '@airlib/aui/components/widgets/tooltip.css';

export const SaveAction = () => (
  <Button>
    Save
    <Tooltip>Stored on this device</Tooltip>
  </Button>
);
```

For the full library — tokens, base defaults, every component, and the utilities — load `import '@airlib/aui';` instead. A lone component stylesheet carries only that component's rules.

Pointer arrival schedules the open after `delay`; focusing the trigger opens it at once. Both paths lead to the same panel, and `mode` chooses which gestures reach it at all:

```tsx
<Button>
  Share
  <Tooltip delay={500} mode={['hover', 'focus']}>
    Anyone with the link can read
  </Tooltip>
</Button>
```

Turn `focus` off and keyboard users get nothing; turn `hover` off and only focus and click reveal it. The panel is hoverable, so moving the pointer from the trigger into the panel keeps it open. Focus never waits, whatever the delay says.

Leave `open` out and the gestures drive the panel; set it and the panel follows yours. Bind it to show advice from code:

```tsx
import { $bind, mutable } from '@airlib/react';

const state = mutable({ open: false });

<Button>
  Save
  <Tooltip open={$bind(state, 'open')}>Stored on this device</Tooltip>
</Button>
```

`Escape` closes an open panel and stops the key from reaching listeners above the trigger. An outside press closes it only while `dismissable` is true. The panel takes no focus at any point, so `Escape` leaves focus exactly where it was — on the trigger.

A disabled trigger shows no advisory at all: `show()`, `scheduleOpen()`, and `toggle()` refuse while the control is locked:

```tsx
<Button disabled>
  Publish
  <Tooltip>Never shown while the trigger is locked</Tooltip>
</Button>
```

Placement is a token pair, not a calculation. `xDir` and `yDir` become `data-tooltip-x` and `data-tooltip-y` on the panel:

```tsx
<Button>
  Share
  <Tooltip yDir="above" xDir="after">
    Anyone with the link can read
  </Tooltip>
</Button>
```

### Properties

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `id` | `string` | `tooltip-<n>` | The panel identifier, and the value the trigger's `aria-describedby` points at while it is open. |
| `open` | `Bindable<boolean>` | `false` | Whether the panel is showing. Bind it to reveal the advice from code. |
| `mode` | `('hover' \| 'focus' \| 'click')[]` | `['hover', 'focus']` | Which gestures reveal the panel. Fixed when the panel is created. |
| `delay` | `number` | `300` | Milliseconds the hover gesture waits. Focus never waits. |
| `dismissable` | `boolean` | `true` | Whether an outside press closes the panel. `Escape` closes it either way. |
| `xDir` | `'before' \| 'after' \| 'left' \| 'between' \| 'right'` | — | Horizontal placement token, emitted as `data-tooltip-x`. |
| `yDir` | `'top' \| 'bottom' \| 'above' \| 'below' \| 'between'` | — | Vertical placement token, emitted as `data-tooltip-y`. |
| `onchange` | `(event: CustomEvent<boolean>) => void` | — | Called each time visibility commits, with the new state in `detail`. |
| `className` | `string` | — | Added alongside the built-in classes, or in place of them with `overrides` enabled. |
| `children` | `ReactNode` | — | One line of advice. |
| `ref` | `Ref<HTMLDivElement>` | — | Access to the panel element. |

The panel claims no tab stop and never takes focus. `Tab` reaches the trigger, which reveals the panel as it takes focus; the panel itself is never a stop.

Your own classes are added next to the built-in ones:

```tsx
// class="aui-tooltip my-hint"
<Button>
  Save
  <Tooltip className="my-hint">Stored on this device</Tooltip>
</Button>
```

To make `className` replace the built-in classes, turn on `overrides` once in [Theming](/docs/theming#overrides).
