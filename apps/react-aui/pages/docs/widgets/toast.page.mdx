# AUI Toast

A toast reports something that already happened: a draft saved, a sync finished, an upload that failed and is retrying. It appears on its own, says its piece, and leaves. It is the visible counterpart of the [Announcer](/docs/widgets/announcer), which has no surface at all.

**AUI Toast** does all of that for you, and leaves the markup and the styling entirely yours. The toast is the live region: `status` and polite by default, `alert` and assertive when critical, always atomic `false` so a partial update still announces. It arms one lifetime at creation, pauses it while the pointer or focus rests inside, and commits removal exactly once — expiry and the close button are the same path.

Styling is optional. Without AUI CSS the Toast stays a correct, operable message; with it, the same markup gets the AUI treatment through the full library.

:::interactive[Toast demo]

```tsx
import { Button, Toast, ToastClose } from '@airlib/react-aui';
import { $bind, mutable, setup, Snippet } from '@airlib/react';

const LIFETIME = 6000;

const ToastDemo = setup(() => {
  const state = mutable({ toasts: [] as { id: number; text: string; critical?: boolean; sticky?: boolean }[] });

  let seed = 0;

  const add = (text: string, critical?: boolean, sticky?: boolean) => {
    state.toasts = [...state.toasts, { id: ++seed, text, critical, sticky }];
  };

  const remove = (id: number) => {
    state.toasts = state.toasts.filter((entry) => entry.id !== id);
  };

  return () => (
    <div className="demo-button">
      <div className="flex gap-xs w-full flex-wrap">
        <Button size="sm" onClick={() => add('Draft saved')}>
          Save draft
        </Button>
        <Button size="sm" onClick={() => add('Upload failed — retrying', true)}>
          Retry upload
        </Button>
        <Button size="sm" onClick={() => add('Pinned until dismissed', false, true)}>
          Pin a message
        </Button>
        <div className="flex-1"></div>
        <span>{`${state.toasts.length} showing`}</span>
      </div>
      <div className="aui-card flex flex-col gap-md p-xl" style={{ minHeight: '9rem' }}>
        <Snippet>
          {() => (
            <div className="flex flex-col gap-sm" role="region" aria-label="Notifications">
              {state.toasts.map((entry) => (
                <Toast
                  key={entry.id}
                  critical={entry.critical}
                  duration={entry.sticky ? undefined : LIFETIME}
                  ondismiss={() => remove(entry.id)}
                >
                  <span>{entry.text}</span>
                  <ToastClose aria-label="Dismiss">Dismiss</ToastClose>
                </Toast>
              ))}
            </div>
          )}
        </Snippet>
      </div>
    </div>
  );
}, 'ToastDemo');
```

## Usage

Render each message as its own toast and take it out of your list when it reports dismissal. Nothing detaches the element for you — animations, stores, and queues stay yours to own:

```tsx
import { Toast, ToastClose } from '@airlib/react-aui';
import '@airlib/aui/components/widgets/toast.css';

export const SavedToast = ({ onDone }: { onDone: () => void }) => (
  <Toast duration={6000} ondismiss={onDone}>
    <span>Draft saved</span>
    <ToastClose aria-label="Dismiss">Dismiss</ToastClose>
  </Toast>
);
```

For the full library — tokens, base defaults, every component, and the utilities — load `import '@airlib/aui';` instead. A lone component stylesheet carries only that component's rules.

### Lifetime

`duration` is the visible lifetime in milliseconds, counted from creation. Without it no timer is armed and the message lives until dismissed. Pausing is automatic: hovering the toast or focusing inside it holds the time that is left, and leaving resumes the remainder:

```tsx
<Toast duration={6000} ondismiss={() => remove(entry.id)}>
  <span>Draft saved</span>
</Toast>
```

### Urgency

`critical` chooses the announcement and the treatment. A normal toast is a `status` region with `aria-live="polite"`; a critical one interrupts as an `alert` with `aria-live="assertive"`:

```tsx
<Toast critical duration={8000} ondismiss={onRetry}>
  <span>Upload failed — retrying</span>
</Toast>
```

Either way the live semantics are created with the region, so the message is announced when the toast appears and not again on later renders.

### Dismissal

Expiry, a close button, and dismissal from code all commit the same removal exactly once. A dismissed toast never re-arms, and a locked close button commits nothing:

```tsx
<Toast duration={6000} ondismiss={remove}>
  <span>Draft saved</span>
  <ToastClose disabled>Dismiss</ToastClose>
</Toast>
```

### Properties

#### Toast

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `critical` | `boolean` | `false` | Polite `status` when false, assertive `alert` when true. |
| `duration` | `number` | — | Visible lifetime in milliseconds. Omitting it leaves the message until dismissed. |
| `ondismiss` | `(event: CustomEvent<void>) => void` | — | Runs after removal commits, for expiry, the close button, or a direct call. |
| `className` | `string` | — | Added alongside the built-in classes, or in place of them with `overrides` enabled. |
| `children` | `ReactNode` | — | The message, and usually a close button beside it. |
| `ref` | `Ref<HTMLDivElement>` | — | Access to the toast element. |

#### ToastClose

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `disabled` | `boolean` | `false` | Locks the button so it commits nothing. |
| `className` | `string` | — | Added alongside the built-in classes, or in place of them with `overrides` enabled. |
| `children` | `ReactNode` | — | The button's content — a label, an icon, or both. |
| `ref` | `Ref<HTMLButtonElement>` | — | Access to the button element. |

The close button finds its toast in scope rather than through a prop, so create it inside the toast. A toast has no identifier of its own: `event.target` on the dismiss event is the toast element.

Your own classes are added next to the built-in ones:

```tsx
// class="aui-toast my-toast"
<Toast className="my-toast" duration={6000}>
  <span>Draft saved</span>
  <ToastClose className="my-close">Dismiss</ToastClose>
</Toast>
```

To make `className` replace the built-in classes, turn on `overrides` once in [Theming](/docs/theming#overrides).
