# AUI Code Input

A code input splits a verification code or PIN across separate cells while still being one field. The hard part is never the cells — it is **keeping the whole strip at a single tab stop**, **advancing the caret as characters land**, **spreading a pasted code across the cells that follow**, **shifting what remains left when a character goes**, and **telling your code when the value is complete**.

**AUI Code Input** does all of that for you, and leaves the markup and the styling entirely yours. The group holds the one contiguous string and the tab stop; the cells find it in scope, so nothing is wired by hand.

Styling is optional. Without AUI CSS the Code Input stays a correct, operable group of textboxes; with it, the same markup gets the AUI treatment through the full library.

:::interactive[Code input demo]

```tsx
import { CodeInput, CodeInputCell, Toggle } from '@airlib/react-aui';
import { $bind, mutable, setup, Snippet } from '@airlib/react';

const digits = (count: number) => Array.from({ length: count }, (_, index) => <CodeInputCell key={index} index={index} />);

const CodeInputDemo = setup(() => {
  const state = mutable({
    code: '42',
    backup: 'A9',
    locked: false,
  });

  return () => (
    <div className="demo-button">
      <div className="flex gap-xs w-full flex-wrap">
        <Toggle size="sm" pressed={$bind(state, 'locked')}>
          {() => (state.locked ? 'Locked' : 'Unlocked')}
        </Toggle>
        <div className="flex-1"></div>
        <Snippet>{() => <span>{state.code.length === 6 ? `${state.code} — complete` : `${state.code.length} of 6 digits`}</span>}</Snippet>
      </div>

      <div className="aui-card flex flex-col gap-lg p-xl">
        <Snippet>
          {() => (
            <CodeInput
              label="Verification code"
              length={6}
              value={$bind(state, 'code')}
              disabled={state.locked}
              oncomplete={(event) => console.log('complete', event.detail)}
            >
              {digits(6)}
            </CodeInput>
          )}
        </Snippet>

        <Snippet>
          {() => (
            <CodeInput label="Backup code" length={4} kind="alphanumeric" value={$bind(state, 'backup')} readonly={state.locked}>
              {digits(4)}
            </CodeInput>
          )}
        </Snippet>
      </div>
    </div>
  );
}, 'CodeInputDemo');
```

## Usage

The group is the wiring: put the cells inside it and they share its value. Any number of cells works, as long as there are as many as `length` says:

```tsx
import { CodeInput, CodeInputCell } from '@airlib/react-aui';
import '@airlib/aui/components/widgets/code-input.css';

const CODE_LENGTH = 6;

export const VerifyCode = ({ onComplete }: { onComplete: (code: string) => void }) => (
  <CodeInput label="Verification code" length={CODE_LENGTH} oncomplete={(event) => onComplete(event.detail)}>
    {Array.from({ length: CODE_LENGTH }, (_, index) => (
      <CodeInputCell key={index} index={index} />
    ))}
  </CodeInput>
);
```

For the full library — tokens, base defaults, every component, and the utilities — load `import '@airlib/aui';` instead. A lone component stylesheet carries only that component's rules.

### The value

One code, never a sparse set of cells. Typing or pasting into an empty cell appends at the first unfilled position; removing a character in the middle shifts everything after it left:

```tsx
const state = mutable({ code: '42' });

<CodeInput label="Verification code" length={6} value={$bind(state, 'code')}>
  {/* cells */}
</CodeInput>;
```

Read back, the value is the contiguous valid prefix up to `length`, so overflow is dropped rather than stored. `kind` decides which characters may join it — `'numeric'` (the default) takes `0-9`, `'alphanumeric'` also takes `a-zA-Z`. A character outside the set is ignored where it stands and the rest of that same input still lands:

```tsx
<CodeInput label="Backup code" length={4} kind="alphanumeric" value={$bind(state, 'backup')}>
  {/* cells */}
</CodeInput>
```

### One tab stop

The whole strip is one stop in the tab order, not six. Before focus enters, the entry cell is the first unfilled position — or the last cell when the code is full — so tabbing through the page never visits six cells in a row. Focus moves inside on its own as characters land.

### Pasting and autofill

A pasted string spreads from the cell that received it: accepted characters replace what stood there onward, anything past `length` is discarded, and focus lands on the next unfilled cell or the last one when the code is full. The first cell also carries `autocomplete="one-time-code"`, so an SMS code or a password manager fills the group the same way:

```tsx
<CodeInput label="Verification code" length={6} value={$bind(state, 'code')}>
  {/* a pasted "123456" fills all six cells and fires complete */}
</CodeInput>
```

### Deleting

`Backspace` clears the focused cell and shifts the rest left in place. On an unfilled cell it removes the character before it and steps focus back there. `Delete` clears the focused cell and shifts left without moving focus, so a value can be corrected without leaving the slot.

### Knowing when it is complete

The group reports at three edges:

| Event | Fires when | Detail |
| --- | --- | --- |
| `oninput` | An edit commits a different code | The updated code |
| `onchange` | Focus leaves the group and the code differs from when focus entered | The committed code |
| `oncomplete` | An edit yields a different code whose length equals `length` | The full code |

`onchange` is deliberately not per keystroke — the code is a single value, so it is compared on the way out. That makes it the right hook for validation and form state, while `oncomplete` is the one to hand a verification request:

```tsx
<CodeInput label="Verification code" length={6} value={$bind(state, 'code')} oncomplete={(event) => verify(event.detail)}>
  {/* cells */}
</CodeInput>
```

### Locking

`disabled` closes the whole group — every cell leaves the tab order and refuses typing, pasting, and deletion. `readonly` keeps the cells focusable and the arrows working while refusing every edit, which suits a code that is shown for copying rather than changed:

```tsx
<CodeInput label="Verification code" length={6} value={$bind(state, 'code')} readonly>
  {/* cells */}
</CodeInput>
```

### The cells

`CodeInputCell` renders a native `input` per position and takes only `index`. Each cell derives its character from the group, so writing `value` from outside updates the cells rather than falling out of step. Cell `0` gets the one-time-code hint; every cell's virtual keyboard follows `kind`.

Give the group a `label` and each cell is named `"{label}, character {n} of {length}"`, so a screen reader announces where the caret is. Leave `label` out and no English text is invented — the group is simply unnamed:

```tsx
<CodeInput label="Verification code" length={6}>
  <CodeInputCell index={0} />
  <CodeInputCell index={1} />
  {/* … */}
</CodeInput>
```

### Properties

#### CodeInput

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `value` | `Bindable<string>` | `''` | The code, kept as a contiguous valid prefix up to `length`. |
| `length` | `number` | `6` | How many character positions the code has. |
| `kind` | `'numeric'`, `'alphanumeric'` | `'numeric'` | The allowed character set. |
| `label` | `string` | — | The group's name, and the base of every cell's positional name. |
| `disabled` | `boolean` | `false` | Locks the group and drops every cell from the tab order. |
| `readonly` | `boolean` | `false` | Keeps cells focusable and navigable; refuses every edit. |
| `oninput` | `(event: CustomEvent<string>) => void` | — | The code after an edit changes it. |
| `onchange` | `(event: CustomEvent<string>) => void` | — | The code on blur once it differs from focus entry. |
| `oncomplete` | `(event: CustomEvent<string>) => void` | — | The full code, right after it reaches `length`. |
| `className` | `string` | — | Added alongside the built-in classes, or in place of them with `overrides` enabled. |
| `children` | `ReactNode` | — | The cells. |
| `ref` | `Ref<HTMLDivElement>` | — | Access to the group element. |

#### CodeInputCell

Takes `index` plus the standard attributes for an `input` host and `className`/`ref`. The character, the tab stop, `inputmode`, `autocomplete`, and the `disabled`/`readonly` state all come from the group.

Your own classes are added next to the built-in ones:

```tsx
// class="aui-code-input my-code"
<CodeInput className="my-code" label="Verification code" length={6}>
  {/* cells */}
</CodeInput>
```

To make `className` replace the built-in classes, turn on `overrides` once in [Theming](/docs/theming#overrides).

Keyboard: `ArrowLeft` and `ArrowRight` travel between the cells that hold characters and the first unfilled one, without wrapping. `Home` goes to the first cell, `End` to the first unfilled cell or the last cell when full. `Backspace` and `Delete` edit as described above, and `Tab` moves on from the group's single stop.
