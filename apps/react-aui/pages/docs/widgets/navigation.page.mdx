# AUI Navigation

Almost every app repeats a list of links on each page — a sidebar, a settings menu, a section index. Done by hand, keyboard users tab through every link on every page, screen-reader users can't jump straight to it, and the current page looks like every other link.

**Navigation** turns a list of destinations into a named, jumpable landmark. Keyboard users reach it with one tab and move between links with the arrow keys, the current page stands out, and a disabled link stays visible but can't be followed.

:::interactive[Navigation demo]

```tsx
import { Navigation } from '@airlib/react-aui';
import { $bind, mutable, setup, Snippet } from '@airlib/react';
import { DemoControl } from '@/components/DemoControl.js';

const NavigationDemo = setup(() => {
  const state = mutable({ size: 'md', color: 'primary', disabled: false });

  return () => (
    <div className="demo-button">
      <DemoControl size={$bind(state, 'size')} color={$bind(state, 'color')} disabled={$bind(state, 'disabled')} />
      <div className="aui-card flex flex-col gap-lg justify-center p-xl">
        <Snippet>
          {() => (
            <Navigation
              label="Project sections"
              size={state.size}
              color={state.color}
              links={[
                { href: '#overview', label: 'Overview', current: true },
                { href: '#members', label: 'Members' },
                { href: '#billing', label: 'Billing', disabled: state.disabled },
              ]}
            />
          )}
        </Snippet>
      </div>
    </div>
  );
}, 'NavigationDemo');
```

## Usage

### From a list of links

When your destinations are data — a route table, a settings list — pass them as `links`. Each entry needs an `href` and a `label`; mark the page the reader is on with `current`, and switch a destination off with `disabled`:

```tsx
import { Navigation } from '@airlib/react-aui';
import '@airlib/aui/components/widgets/navigation.css';

const SECTIONS = [
  { href: '/project/overview', label: 'Overview', current: true },
  { href: '/project/members', label: 'Members' },
  { href: '/project/billing', label: 'Billing', disabled: true },
];

export const ProjectNav = () => <Navigation label="Project sections" links={SECTIONS} />;
```

Give every navigation on a page its own `label` — it is the name screen-reader users pick from when they jump between landmarks.

### Richer rows with a slot

When a row needs more than its text — an icon, a count badge — keep `links` and fill each row through the `link` slot. The slot receives the entry; the link, its current mark, and the keyboard behavior stay the same:

```tsx
const MAILBOXES = [
  { href: '/mail/inbox', label: 'Inbox', current: true },
  { href: '/mail/drafts', label: 'Drafts' },
  { href: '/mail/spam', label: 'Spam' },
];
const UNREAD: Record<string, number> = { '/mail/inbox': 12, '/mail/drafts': 2, '/mail/spam': 48 };

<Navigation label="Mailboxes" links={MAILBOXES}>
  <Navigation.Snippet for="link">
    {(entry) => (
      <>
        {entry.label}
        <span className="text-label-sm">{UNREAD[entry.href]}</span>
      </>
    )}
  </Navigation.Snippet>
</Navigation>
```

### Composing the links yourself

When links come from different places or need their own handlers, place [Link](/docs/widgets/link) elements inside. They behave exactly like the rows `links` renders:

```tsx
import { Link, Navigation } from '@airlib/react-aui';

<Navigation label="Project sections">
  <Link href="/project/overview" current>Overview</Link>
  <Link href="/project/members">Members</Link>
  <Link href="/project/billing" disabled>Billing</Link>
</Navigation>
```

If a heading on the page already names the section, point at it with `labelledby` instead of repeating the text in `label`.

### Style it once

`size` and `color` on the Navigation reach every link inside it. See [Style a composite once](/docs/theming#style-a-composite-once).

### Properties

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `links` | `LinkEntry[]` | — | `{ href, label, current?, disabled? }` per destination. Renders one link row each. |
| `label` | `string` | — | The landmark's name for screen readers. |
| `labelledby` | `string` | — | ID of an element that already names the landmark, used instead of `label`. |
| `size` | `xs`, `sm`, `md`, `lg`, `xl`, `xxl` | `'md'` | Row height and type size for every link. |
| `color` | `primary`, `secondary`, `tertiary`, `error`, `success`, `warning`, `info` | `'primary'` | The current page's highlight. |
| `className` | `string` | — | Added alongside the built-in classes, or in place of them with `overrides` enabled. |
| `children` | `ReactNode` | — | Your own `Link` elements, when you compose instead of passing `links`. |
| `ref` | `Ref<HTMLElement>` | — | Access to the landmark element. |

Slots: `link` — `(entry: LinkEntry) => ReactNode`, the content of each row.

## Keyboard

`Tab` reaches the navigation once and leaves it once. `ArrowDown` / `ArrowUp` move to the next / previous link, skipping disabled ones and wrapping at the ends. `Home` / `End` jump to the first and last link. `Enter` follows the focused link.
