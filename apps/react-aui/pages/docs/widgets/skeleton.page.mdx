# AUI Skeleton

When content takes a moment, a spinner tells people to wait but not what is coming, and the page jumps when it lands. A skeleton draws the content's shape in advance — the lines of text, the avatar, the button — so the layout holds still and the wait feels shorter.

**In AUI a skeleton is a state, not a component.** Mark the region that is loading with `aria-busy="true"` and keep rendering your real layout. While it is busy, text that has no data yet becomes a bar, avatars and images become discs and blocks, and controls keep their size but lose their content. When the data arrives, flip `aria-busy` off and the same elements fill in — there is no second layout to keep in sync and nothing to remount.

:::interactive[Skeleton demo]

```tsx
import { Avatar, Button, Toggle } from '@airlib/react-aui';
import { $bind, mutable, setup, Snippet } from '@airlib/react';
import { GlassStage } from '@/components/GlassStage.js';

const TRIP = {
  title: 'Lisbon offsite',
  owner: 'Maya Chen',
  summary: 'Three days by the river: workshops in the morning, the old town after lunch, and dinner together every night.',
};

const SkeletonDemo = setup(() => {
  const state = mutable({ loading: true });
  const trip = () => (state.loading ? undefined : TRIP);

  return () => (
    <div className="flex-col gap-md p-lg">
      <div className="flex-row">
        <Toggle size="sm" pressed={$bind(state, 'loading')}>
          Loading
        </Toggle>
      </div>
      <GlassStage>
        <Snippet>
          {() => (
            <div className="flex-col gap-md" role="group" aria-label="Trip" aria-busy={state.loading}>
              <div className="flex-row items-center gap-md">
                <Avatar alt={trip()?.owner ?? ''} />
                <div className="flex-col gap-xs" style={{ flex: 1 }}>
                  <div className="aui-skeleton text-title-sm">{trip()?.title}</div>
                  <div className="aui-skeleton text-label-sm">{trip()?.owner}</div>
                </div>
              </div>
              <div className="aui-skeleton-lines" style={{ '--aui-skeleton-lines': 2 }}>
                {trip()?.summary}
              </div>
              <Button>View trip</Button>
            </div>
          )}
        </Snippet>
      </GlassStage>
    </div>
  );
}, 'SkeletonDemo');
```

Turn **Loading** off: the same card fills in, and nothing moves. Nothing in it changed except the data and one attribute.

## Usage

### Mark the region busy

Render your layout from the data you have — empty while it loads — and tie `aria-busy` to the loading state:

```tsx
import '@airlib/aui/components/widgets/skeleton.css';

const trip = getTrip.with(() => [props.id]);

<Snippet>
  {() => (
    <Card aria-busy={trip.status === 'pending'} aria-label="Trip">
      <Avatar alt={trip.data?.owner ?? ''} />
      <h3>{trip.data?.title}</h3>
      <p className="aui-skeleton-lines">{trip.data?.summary}</p>
      <Button>View trip</Button>
    </Card>
  )}
</Snippet>
```

While busy, these become placeholders:

- **Text with nothing in it yet** — headings, paragraphs, list items, labels — becomes one bar, part of the width.
- **Avatars and images** become discs and blocks of their own size.
- **Controls** — buttons, fields, selects — keep their size and lose their content, and can't be pressed.
- **Anything you mark** with `aui-skeleton`, for an element of your own that should read as a placeholder.

`aria-busy` also tells screen readers to wait and to announce the region once it is done, so the visual placeholder and the accessible state come from the same attribute.

### A paragraph still to come

An empty paragraph is one bar. Give it `aui-skeleton-lines` to stand in for several lines, and set how many with `--aui-skeleton-lines` (3 by default). The class keeps that many lines reserved after loading too, so text that arrives shorter never pulls the layout up — set it to the lines the text usually takes:

```tsx
<p className="aui-skeleton-lines" style={{ '--aui-skeleton-lines': 5 }}>
  {post.data?.body}
</p>
```

### Lists of unknown length

Until the data arrives you don't know how many rows there will be. Render a few empty ones with the same row component inside the busy region; they become placeholders the same way, and they match the real rows because they are the real rows:

```tsx
<ul aria-busy={orders.status === 'pending'} aria-label="Recent orders">
  <For each={() => orders.data ?? [{}, {}, {}]}>
    {(order) => <OrderRow order={order} />}
  </For>
</ul>
```

### Style it once

| Token | Default | What it sets |
| --- | --- | --- |
| `--aui-skeleton-fill` | on-surface at 10% | The placeholder color; reads on any surface. |
| `--aui-skeleton-shine` | on-surface at 4% | The shimmer passing across it. |
| `--aui-skeleton-width` | `60%` | How wide an empty line of text stands in as. |
| `--aui-skeleton-lines` | `3` | How many lines `aui-skeleton-lines` draws. |

The shimmer is decoration: it stops when people ask for reduced motion.
