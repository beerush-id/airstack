# AUI Field

A field ties a label, a control, helper text, and a failure message into one unit. It derives every part address from a single namespace, holds the failure back until the field has been touched, and keeps helper text and the failure on separate channels — falling back to the control's own rule when you pass none.

Styling is optional. Without AUI CSS the Field stays a correct, wired namespace; with it, the same markup gets the AUI treatment.

:::interactive[Field demo]

```tsx
import { Field, FieldControl, FieldDescription, FieldError, FieldLabel, Toggle } from '@airlib/react-aui';
import { $bind, mutable, setup, Snippet } from '@airlib/react';

const FieldDemo = setup(() => {
  const state = mutable({ value: '', touched: false, invalid: true });

  return () => (
    <div className="demo-button">
      <div className="flex gap-xs w-full">
        <div className="flex-1"></div>
        <Toggle size="sm" pressed={$bind(state, 'touched')}>
          {() => (state.touched ? 'Touched' : 'Untouched')}
        </Toggle>
        <Toggle size="sm" pressed={$bind(state, 'invalid')}>
          {() => (state.invalid ? 'Invalid' : 'Valid')}
        </Toggle>
      </div>
      <div className="aui-card flex flex-col gap-lg justify-center p-xl">
        <Snippet>
          {() => (
            <Field
              placeholder="you@example.com"
              required
              value={$bind(state, 'value')}
              touched={$bind(state, 'touched')}
              invalid={$bind(state, 'invalid')}
            >
              <FieldLabel>Work email</FieldLabel>
              <FieldControl />
              <FieldDescription>We send a sign-in link to this address.</FieldDescription>
              <FieldError>Enter a valid email address to continue.</FieldError>
            </Field>
          )}
        </Snippet>
        <span>Value: {state.value || '—'}</span>
      </div>
    </div>
  );
}, 'FieldDemo');
```

## Usage

Put the value and rules on `Field`; the parts wire by namespace. The control reads its id, disabled, required, and invalid state from the enclosing field:

```tsx
import { Field, FieldControl, FieldDescription, FieldError, FieldLabel } from '@airlib/react-aui';
import '@airlib/aui/components/widgets/field.css';

export const Email = () => (
  <Field placeholder="you@example.com" required>
    <FieldLabel>Work email</FieldLabel>
    <FieldControl />
    <FieldDescription>We send a sign-in link to this address.</FieldDescription>
    <FieldError>Enter a valid email address to continue.</FieldError>
  </Field>
);
```

Bind the live value and drive validation from your own rule. The failure shows once the field is both touched and invalid; before that, only the description announces:

```tsx
import { $bind, mutable, setup } from '@airlib/react';
import { Field, FieldControl, FieldError, FieldLabel } from '@airlib/react-aui';

const Email = setup(() => {
  const state = mutable({ value: '', touched: false });

  return () => (
    <Field
      value={$bind(state, 'value')}
      touched={$bind(state, 'touched')}
      invalid={state.value.indexOf('@') < 0}
    >
      <FieldLabel>Work email</FieldLabel>
      <FieldControl />
      <FieldError>Enter a valid email address.</FieldError>
    </Field>
  );
}, 'Email');
```

### Properties

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `id` | `string` | auto | Field namespace. Every part address derives from it. |
| `type` | `string` | `'text'` | Control type the field reports to its parts. |
| `value` | `Bindable<string \| number>` | — | Live field value. The controller writes it back on input. |
| `placeholder` | `string` | — | Hint forwarded to the control. |
| `required` | `boolean` | `false` | Requirement flag inherited by the control. |
| `disabled` | `boolean` | `false` | Locks the whole field; inherited by the control. |
| `invalid` | `Bindable<boolean>` | `false` | Failure flag. The controller writes it back from validation. |
| `touched` | `Bindable<boolean>` | `false` | Interaction flag gating the failure channel. |
| `invalidMessages` | `Bindable<string \| string[]>` | — | Failure text backing the error part. |
| `className` | `string` | — | Added alongside the built-in classes, or in place of them with `overrides` enabled. |
| `ref` | `Ref<HTMLDivElement>` | — | Access to the underlying namespace element. |

Parts: `FieldLabel` (wired by `for`), `FieldControl` (id, disabled, required, invalid from the namespace), `FieldDescription` (helper channel), `FieldError` (failure channel, shown once touched and invalid).

Your own classes are added next to the built-in ones:

```tsx
// class="aui-field my-field"
<Field placeholder="Email" className="my-field">
  <FieldLabel>Email</FieldLabel>
  <FieldControl />
</Field>
```

To make `className` replace the built-in classes, turn on `overrides` once in [Theming](/docs/theming#overrides).
