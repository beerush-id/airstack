# AUI Avatar

Every app that has people shows their faces somewhere: the comment author, the account menu, the members of a project. The picture is the easy part. The rest is what to show when it fails or never existed, how to name it for screen readers, and how to stack five of them without the edges turning to mush.

**AUI Avatar** gives you a round picture that falls back to the person's initials, named by the same `alt` you would give an image. **AvatarGroup** overlaps a row of them and collapses the rest into a count.

:::interactive[Avatar demo]

```tsx
import { Avatar, AvatarGroup, Badge } from '@airlib/react-aui';
import { $bind, mutable, setup, Snippet } from '@airlib/react';
import { DemoControl } from '@/components/DemoControl.js';
import { GlassStage } from '@/components/GlassStage.js';
import maya from '@/assets/avatar-1.jpg?asset&sizes=128';
import leo from '@/assets/avatar-2.jpg?asset&sizes=128';
import sara from '@/assets/avatar-3.jpg?asset&sizes=128';
import noah from '@/assets/avatar-4.jpg?asset&sizes=128';

const MEMBERS = [
  { alt: 'Maya Chen', src: maya.src },
  { alt: 'Leo Park', src: leo.src },
  { alt: 'Ivy Brooks' },
  { alt: 'Sara Ortiz', src: sara.src },
  { alt: 'Noah Reyes', src: noah.src },
  { alt: 'Omar Haddad' },
];

const AvatarDemo = setup(() => {
  const state = mutable({ size: 'md', color: 'primary', disabled: false });

  return () => (
    <div className="demo-button">
      <DemoControl size={$bind(state, 'size')} color={$bind(state, 'color')} />
      <Snippet>
        {() => (
          <GlassStage>
            <div className="flex flex-wrap gap-xl items-center justify-center">
              <Avatar alt="Ivy Brooks" size={state.size} color={state.color} />
              <Avatar src={noah.src} alt="Noah Reyes" size={state.size} color={state.color}>
                <Badge dot label="Online" color="success" position="bottom-end" />
              </Avatar>
              <AvatarGroup
                label="Project members"
                items={MEMBERS}
                max={4}
                moreLabel={(n) => `${n} more members`}
                size={state.size}
                color={state.color}
              />
            </div>
          </GlassStage>
        )}
      </Snippet>
    </div>
  );
}, 'AvatarDemo');
```

## Usage

### One avatar

Give it the picture and the person's name. While the picture loads, if it fails, or if there is no `src` at all, the initials of `alt` show instead:

```tsx
import { Avatar } from '@airlib/react-aui';
import '@airlib/aui/components/widgets/avatar.css';

<Avatar src={user.photo} alt={user.name} />
```

`alt` works the way it does on an image: it is what screen readers announce. An empty `alt` marks the avatar decorative — use that when the name is already written right next to it. Avatars ship no wording of their own: the name, the group's `label`, and the "+N" sentence all come from you.

### Show presence or a count

Put a [Badge](/docs/widgets/badge) inside the avatar. It pins itself to the corner and grows and shrinks with the avatar:

```tsx
<Avatar src={user.photo} alt={user.name}>
  <Badge dot label="Online" color="success" position="bottom-end" />
</Avatar>
```

Whatever you put inside sits on the avatar; the picture and the initials stay.

### A group of people

Hand `AvatarGroup` the people and how many to show; the rest collapse into a "+N" avatar. Give that count a sentence in your app's language with `moreLabel`, or screen readers hear just "+N":

```tsx
import { AvatarGroup } from '@airlib/react-aui';

<AvatarGroup
  label="Project members"
  items={members}
  max={4}
  moreLabel={(n) => `${n} more members`}
  size="sm"
/>
```

Each entry is `{ alt, src? }`. When one avatar needs more — a badge, its own color — compose them yourself; the group still overlaps them and passes its size and color down:

```tsx
<AvatarGroup label="Reviewers" size="sm">
  <Avatar src={ada.photo} alt="Ada Lovelace" />
  <Avatar src={alan.photo} alt="Alan Turing">
    <Badge dot label="Requested changes" color="error" />
  </Avatar>
</AvatarGroup>
```

### An app you can open

Launchers, docks, and app switchers show apps the way an avatar shows people: a picture, or a glyph or initials when there is none. `AppIcon` is that tile as a button. Give it the app's name as `alt` and wire `onClick` like any button:

```tsx
import { AppIcon } from '@airlib/react-aui';
import { CalendarIcon } from '@airlib/react-aui/icons';

<AppIcon alt="Calendar" icon={<CalendarIcon />} onClick={() => calendar.open()} />
```

Put the name inside and it becomes a caption under the tile, the way a launcher lists apps. The caption then names the button, so screen readers hear the name once:

```tsx
<AppIcon alt="Invoices" src={invoices.logo} onClick={() => invoices.open()}>
  Invoices
</AppIcon>
```

It is a plain button, so `aria-pressed`, `disabled`, and every other button attribute work as usual. Set `--aui-app-icon-size` to draw the tile larger than a control.

When the button is already something else — a dialog trigger, a menu button — put `AppIconTile` (it takes `alt`, `src`, `icon`, `color`) inside that button and give the button the `aui-app-icon` class. It then looks, hovers, presses, and shows focus like every other app icon. The dock's launcher button is built this way.

### Style it once

`size` and `color` set on a group reach every avatar in it; an avatar's own prop wins. An avatar is as tall as a control at the same size, so an `sm` avatar lines up with an `sm` button. The color tints the initials background. See [Theming](/docs/theming#style-a-composite-once).

### Properties

`Avatar`:

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `alt` | `string` | — | Required. The person's or entity's name; seeds the initials. Empty marks it decorative. |
| `src` | `string` | — | Picture to show; it paints as it arrives. Initials show if it fails or without it. |
| `size` | `xs`–`xxl` | `'md'` | Same height as a control at that size. |
| `color` | `primary`, `secondary`, `tertiary`, `error`, `success`, `warning`, `info` | `'primary'` | Tints the initials background. |
| `children` | `ReactNode` | — | What sits on the avatar, such as a `Badge`. The picture and initials stay. |

`AvatarGroup`:

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `label` | `string` | — | Names the group, e.g. "Project members". |
| `items` | `Array<{ alt: string; src?: string }>` | — | Renders one avatar per entry. |
| `max` | `number` | — | How many to show before collapsing the rest into "+N". |
| `moreLabel` | `(count: number) => string` | — | What the "+N" count means for screen readers, in your app's language. |
| `size`, `color` | as above | — | Reach every avatar in the group. |
| `children` | `ReactNode` | — | Your own avatars, when you compose instead of passing `items`. |

`AppIcon` takes every button attribute, plus:

| Prop | Type | Default | Notes |
| --- | --- | --- | --- |
| `alt` | `string` | — | Required. The app's name; names the button and seeds the initials. |
| `src` | `string` | — | Picture of the app. The glyph or initials show while it loads, if it fails, or without it. |
| `icon` | `ReactNode` | — | A glyph shown in place of the initials. |
| `size`, `color` | as above | `'md'`, `'primary'` | The tile is as tall as a control at that size; the color tints it. |
| `children` | `ReactNode` | — | A caption under the tile. It names the button instead of `alt`. |
