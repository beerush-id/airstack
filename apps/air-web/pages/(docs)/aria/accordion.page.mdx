# Headless Accordion

An accordion stacks sections that open and close behind their headers. Getting it right means **pairing every header with its panel**, **announcing which sections are open**, **letting the arrow keys travel the headers**, and **telling your code when the expansion changes**.

**Headless Accordion** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const accordion = aria('accordion', props);

<div ref={accordion.ref} {...accordion.restProps(['children'])} />
```

:::tip
**The `name` is the pairing.** Give a header and a panel the same `name` and both sides of `aria-controls` and `aria-labelledby` are derived from it — no identifiers to keep in step, and no mount order to respect.

## Accordion

**The group as a whole.** It holds which sections are open, and the headers and the panels all follow it.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'accordion',
  props?: AccordionProps
): AccordionAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type AccordionProps = ComponentProps<'div'> & {
  id?: string;
  value?: string;
  required?: boolean;
  disabled?: boolean;
  orientation?: 'horizontal' | 'vertical';
  manual?: boolean;
  onchange?: (event: CustomEvent<string | null>) => void;
};

const Accordion = setup<AccordionProps>((props) => {
  const accordion = aria('accordion', props);

  return () => (
    <div ref={accordion.ref} {...accordion.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type AccordionProps = ComponentProps<'div'> & {
  id?: string;
  value?: string;
  required?: boolean;
  disabled?: boolean;
  orientation?: 'horizontal' | 'vertical';
  manual?: boolean;
  onchange?: (event: CustomEvent<string | null>) => void;
};

const Accordion = setup<AccordionProps>((props) => {
  const accordion = aria('accordion', props);

  return (
    <div ref={accordion.ref} {...accordion.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

For several sections open at once, declare the array archetype: `{ multiple: true, value: ['payment'] }`. `multiple` and `value` narrow together, so `onchange` is typed to `string[]` instead of `string | null`.

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **id** _string, optional_: The prefix both sides of the pairing are built from. Generated as `accordion-<n>` when you leave it out, so headers end up as `{id}-accordion-{name}` and panels as `{id}-region-{name}`.
- **value** _string, optional_: The `name` of the open section, or `undefined` when everything is closed. Leave it out and the group keeps its own expansion; set it and the group follows your state.
- **value** _string[], optional, with `multiple: true`_: The names of the open sections. `[]` means none.
- **multiple** _boolean, optional, default `false`_: Declares the array archetype, where `value` is a list of names and each section toggles on its own.
- **required** _boolean, optional, default `false`, single expansion only_: Keeps one section open. Activating the open header changes nothing, and with no `value` of your own the first header to mount takes it.
- **disabled** _boolean, optional_: Locks activation and the arrow keys across the **whole group**.
- **orientation** _'horizontal' | 'vertical', optional, default `'vertical'`_: Which arrow keys travel the headers. The root compiles no `role` and no `aria-orientation`, so this reaches the keys and nothing else.
- **manual** _boolean, optional, default `true`_: Whether moving focus leaves the sections alone. Pass `false` and each header opens as focus reaches it.
- **onchange** _(event: CustomEvent&lt;string | null&gt;) =&gt; void, optional_: Called after each commit with the whole value in `detail`. With `multiple: true` it is `(event: CustomEvent<string[]>) => void`.

### Properties

_What you read or write on the instance afterwards._

- **id** _string_: The prefix in use, generated when you left it out.

### Methods

_What you call on the instance._

- **`button(props?, options?)`** → `AccordionButtonAria`: Creates a header belonging to this group.
- **`panel(props?)`** → `AccordionPanelAria`: Creates a panel belonging to this group.

### How it behaves

- **The root is a plain container.** It compiles no `role` of its own, so your layout stays yours and the panels don't have to live inside it.
- **The pairing is derived, not tracked.** Matching `name` values produce both sides of `aria-controls` and `aria-labelledby`, so a panel may mount before its header and the two still meet.
- **Single expansion collapses freely.** Activating the open section closes it and the value reads `undefined`; `required` refuses that collapse instead.
- **Multiple expansion toggles each name on its own.** Opening one section leaves the others as they are.
- **Activation is cancellable.** Calling `preventDefault` on the click stops both the commit and the event.
- **One flag disables everything.** `disabled` on the group leaves every header visible but inert — no activation, no arrow travel.

### Events

_What it tells you._

- **`change`** — fires once per commit, with the whole value in `detail`: `string | null` in single expansion, `null` when everything is closed, `string[]` in multiple. Switching from one section to another is a single commit, not a collapse plus an expand. A vetoed activation fires nothing.

```tsx
const accordion = aria('accordion', {
  value: 'shipping',
  onchange: (event) => submit(event.detail),
});
```

### Navigation

_What the keys do._

- **`ArrowDown` / `ArrowUp`** — focus the **next / previous** enabled header, wrapping at the ends.
- **`ArrowRight` / `ArrowLeft`** — the same travel with `orientation: 'horizontal'`.
- **`Home` / `End`** — focus the **first / last** enabled header.
- **`Tab`** — walks every enabled header in turn, then into the content of the open panel. The accordion is not a single tab stop.
- With `manual: false`, each of these keys also activates the header focus lands on.

## Accordion Button

**One header.** Give it the same `name` as a panel and the two are linked.

### Usage

```ts
aria<E extends BaseElement = HTMLButtonElement>(
  role: 'accordion-button',
  props?: AccordionButtonProps,
  options?: AccordionButtonOptions
): AccordionButtonAria<E>
```

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **name** _string, optional_: The identity this header shares with its panel. Both derived identifiers are built from it, so a header without one has nothing to pair on.
- **id** _string, optional_: Replaces this header's generated identifier in the DOM. The panel still names the derived `{id}-accordion-{name}`, so an `id` here is not what the panel points at.
- **selected** _boolean, optional_: Takes the expansion when the group has no `value` of its own. With `required` on the group and no `value`, the first header to mount takes it instead.
- **disabled** _boolean, optional_: This header alone refuses activation and is skipped by the arrow keys. A group disabled at the top applies on top of it.

### Options

_What you fix when you create it. Read once, never reactive._

- **native** _boolean, optional, default `true`_: Pass `false` when the host isn't a `<button>` and you get `role="button"`, `Enter` and `Space` activation, and an explicit place in the tab order.

### Properties

_What you read or write on the instance afterwards._

- **expanded** _boolean, read and write_: Whether this section is open. Writing `true` opens it and `false` closes it — unless the header is disabled or the group is `required`.
- **value** _string_: This header's `name`.
- **disabled** _boolean_: Whether this header is locked, **including by the group**.
- **id** _string_: This header's identifier in the DOM.

### Methods

_What you call on the instance._

- **`select()`**: Opens this section. _Does nothing while disabled._
- **`deselect()`**: Closes it. _Does nothing while disabled, or while the group is `required`._
- **`toggle()`**: Opens or closes it, whichever applies.

### How it behaves

- **Announced as a header that opens something.** `aria-expanded` plus `aria-controls` pointing at the paired panel. A native `<button>` keeps its own role; a custom host is given `role="button"`.
- **Every enabled header stays in the tab order.** No roving tabindex — `Tab` reaches each one in turn.
- **It works with no accordion above it.** A standalone header toggles its own section and its own panel.
- **Disabled means inert.** It stays visible and announced as disabled, and refuses clicks and keys on either host.

### Events

_What it tells you._

- **`change`** — on a header with no accordion above it, fires when it toggles with `true` or `false` in `detail`. Inside a group the accordion is the surface that promises the event.

### Navigation

_What the keys do._

- **`Enter` / `Space`** — toggles the focused section. A native `<button>` does this itself; a custom host gets the activation synthesized.
- **`Click`** — toggles the clicked section.

## Accordion Panel

**The content under one header.** On screen only while its `name` is open.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'accordion-panel',
  props?: AccordionPanelProps
): AccordionPanelAria<E>
```

:::

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **name** _string, optional_: The identity this panel shares with its header. Falls back to `id`, then to its own generated one.
- **id** _string, optional_: Replaces this panel's generated identifier in the DOM. The header still points at the derived `{id}-region-{name}`.

### Properties

_What you read or write on the instance afterwards._

- **expanded** _boolean_: Whether this panel is **on screen**.
- **key** _string_: What this panel pairs on — its `name`, or its `id` when it has no name.
- **id** _string_: This panel's identifier in the DOM.

### How it behaves

- **Hidden until its section opens.** A closed panel carries `hidden`, so it is off screen and out of reach for screen readers.
- **Named by its header.** Announced as a region labelled by the header that opens it.
- **Mount it only when you need it.** `panel.expanded` lets you keep heavy content out of the tree until its section opens.

### Navigation

_What the keys do._

- **`Tab`** — continues from the header into the content of the open panel.

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### Accordion

```ts
type AccordionProps = SingleAccordionProps | MultipleAccordionProps;

interface SingleAccordionProps {
  id?: string;
  multiple?: false;
  value?: string;
  required?: boolean;
  disabled?: boolean;
  orientation?: 'horizontal' | 'vertical';
  manual?: boolean;
  onchange?: (event: CustomEvent<string | null>) => void;
}

interface MultipleAccordionProps {
  id?: string;
  multiple: true;
  value?: string[];
  disabled?: boolean;
  orientation?: 'horizontal' | 'vertical';
  manual?: boolean;

interface AccordionAttributes {
  id: string;
  onkeydown?: (event: KeyboardEvent) => void;
}

declare class AccordionAria {
  id: string;

  button(props?: AccordionButtonProps, options?: Partial<AccordionButtonOptions>): AccordionButtonAria;

```

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`attributes`** is the dictionary you spread; **`ref`** is what you bind the element with; **`props`** is the full props dictionary for spreading onto the host; **`restProps(omit)`** hands back your props with the keys you name left out.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
