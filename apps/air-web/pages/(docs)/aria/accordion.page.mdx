# AirLib Headless Accordion

Stacked disclosure sections look simple until every header needs its own `aria-expanded`, every panel needs a reciprocal `aria-controls` / `aria-labelledby` pair that survives renames, arrow keys need to travel the headers without expanding them, and each commit needs to announce itself. **AirLib Headless Accordion** (`aria('accordion')`) is a role-less root coordinating header triggers and region panels: deterministic pair IDs derived from matching `name` values, single or multi-expansion, vetoable activation, and committed values announced on the root — without dictating markup or styles.

```tsx
const accordion = aria('accordion', props);

<div ref={accordion.ref} {...accordion.restProps(['children'])} />
```

## Accordion

Role-less root orchestrator holding the expanded value and publishing ambient context for the triggers and panels.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'accordion',
  props?: AccordionProps
): AccordionAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type AccordionProps = ComponentProps<'div'> & {
  id?: string;
  value?: string | string[] | null;
  multiple?: boolean;
  required?: boolean;
  disabled?: boolean;
  onchange?: (event: CustomEvent<string | null | string[]>) => void;
};

const Accordion = setup<AccordionProps>((props) => {
  const accordion = aria('accordion', props);

  return () => (
    <div ref={accordion.ref} {...accordion.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type AccordionProps = ComponentProps<'div'> & {
  id?: string;
  value?: string | string[] | null;
  multiple?: boolean;
  required?: boolean;
  disabled?: boolean;
  onchange?: (event: CustomEvent<string | null | string[]>) => void;
};

const Accordion = setup<AccordionProps>((props) => {
  const accordion = aria('accordion', props);

  return (
    <div ref={accordion.ref} {...accordion.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

For multiple expansion declare the array archetype: `{ multiple: true, value: ['shipping'] }`. `multiple` and `value` narrow together, so `onchange` receives `string[]` instead of `string | null`.

### Parameters

- `props.id` *(string, optional)*: Namespace the pair IDs derive from. Generated as `accordion-<n>` when omitted; triggers derive `{id}-accordion-{name}`, panels `{id}-region-{name}`.
- `props.value` *(string | string[] | null, optional)*: Expanded item key in single mode (`undefined` is the collapsed token in code); an array of keys in multiple mode (`[]` when none).
- `props.multiple` *(boolean, optional, default `false`)*: Declares the multi-expansion archetype, where `value` is an array of keys.
- `props.required` *(boolean, optional, default `false`)*: When `true`, single mode keeps one section expanded — activating the open section refuses to collapse it.
- `props.disabled` *(boolean, optional)*: Locks out activation and roving across the whole accordion.
- `props.onchange` *(handler, optional)*: Called with the `change` event after each commit; `detail` is the new value without a cast.

### How it behaves

- Compiles no `role` — the root is a non-semantic container.
- Single mode is free by default: activating the open section collapses everything (`undefined` in code, `null` on the DOM event wire). `required: true` refuses the collapse instead.
- Multiple mode toggles keys in the array independently; `[]` means none expanded.
- A consumer that cancels the activation (`preventDefault`, captured) stops both the commit and the event.
- An uncontrolled group starts fully collapsed and claims nothing; a trigger with a `selected` hint claims the initial value instead.

## Accordion Button

Interactive header trigger compiling `aria-expanded` and pairing with its panel through a matching `name`.

```ts
aria<E extends BaseElement = HTMLButtonElement>(
  role: 'accordion-button',
  props?: AccordionButtonProps,
  options?: AccordionButtonOptions
): AccordionButtonAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type AccordionButtonProps = ComponentProps<'button'> & {
  name?: string;
  id?: string;
  expanded?: boolean;
  disabled?: boolean;
};

const AccordionButton = setup<AccordionButtonProps>((props) => {
  const button = aria('accordion-button', props);

  return () => (
    <button ref={button.ref} {...button.restProps(['children'])}>
      {props.children}
    </button>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type AccordionButtonProps = ComponentProps<'button'> & {
  name?: string;
  id?: string;
  expanded?: boolean;
  disabled?: boolean;
};

const AccordionButton = setup<AccordionButtonProps>((props) => {
  const button = aria('accordion-button', props);

  return (
    <button ref={button.ref} {...button.restProps(['children'])}>
      {props.children}
    </button>
  );
});
```

:::

### Parameters

- `props.name` *(string, optional)*: Semantic identity matching the paired panel.
- `props.id` *(string, optional)*: Explicit DOM identifier overriding automatic pair derivation.
- `props.expanded` *(boolean, optional)*: Initial expansion hint when the root is uncontrolled.
- `props.disabled` *(boolean, optional)*: Prevents interaction with this trigger. Group-level disablement applies too.
- `options.native` *(boolean, optional, default `true`)*: Pass `false` on non-button hosts to attach `Space` / `Enter` synthesis and an explicit `tabindex`.

### How it behaves

- Compiles `aria-expanded="true" | "false"` and `aria-controls` pointing at the paired panel ID. Native hosts omit the redundant `role`; custom hosts publish `role="button"`.
- Every enabled trigger stays in the tab order — the accordion is not a single tab stop. Disabled triggers are skipped by arrow travel and refuse activation on both hosts.
- Standalone triggers (no root above them) toggle their own local state.

## Accordion Panel

Content section compiling `role="region"`, visible only while its `name` is expanded.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'accordion-panel',
  props?: AccordionPanelProps
): AccordionPanelAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type AccordionPanelProps = ComponentProps<'div'> & {
  name?: string;
  id?: string;
};

const AccordionPanel = setup<AccordionPanelProps>((props) => {
  const panel = aria('accordion-panel', props);

  return () => (
    <div ref={panel.ref} {...panel.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type AccordionPanelProps = ComponentProps<'div'> & {
  name?: string;
  id?: string;
};

const AccordionPanel = setup<AccordionPanelProps>((props) => {
  const panel = aria('accordion-panel', props);

  return (
    <div ref={panel.ref} {...panel.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

- `props.name` *(string, optional)*: Semantic identity matching the paired trigger.
- `props.id` *(string, optional)*: Explicit DOM identifier overriding automatic pair derivation.

### How it behaves

- Compiles `role="region"` with `aria-labelledby` pointing at the paired trigger ID.
- Collapsed panels receive `hidden` from the engine; `panel.expanded` mirrors the root value for conditional rendering.

## Events

| Event | Authored by | Trigger | `detail` |
| :--- | :--- | :--- | :--- |
| `change` | The accordion root | Activation committed the expansion | The whole updated value (`string \| null` single, `string[]` multiple) |

```tsx
const accordion = aria('accordion', {
  value: 'shipping',
  onchange: (event) => submit(event.detail),
});
```

A vetoed activation dispatches nothing. In code the single-mode empty token is `undefined`; on the DOM event wire it reads `null` (platform `CustomEvent` coercion).

## Keyboard Navigation

| Key | Behavior |
| :--- | :--- |
| `ArrowDown` / `ArrowUp` | Moves focus across headers, wrapping at the ends, skipping disabled ones. |
| `Home` / `End` | Moves focus to the first / last enabled header. |
| `Enter` / `Space` on a header | Toggles its section. |
| `Click` on a header | Toggles its section. |
| `Tab` | Moves through every enabled header, then into the expanded panel content. |

## What you get

- **Pairing without bookkeeping.** Matching `name` values derive both sides of `aria-controls` / `aria-labelledby`, order-independent — panels may mount before their triggers.
- **Expansion that never surprises.** Free collapse by default, `required` pinning when one section must stay open, independent array toggling in multiple mode.
- **Commits you can hear.** Every activation dispatches one bubbled `change` and calls `onchange` with the whole value — vetoable, typed to the archetype without a cast.
- **Lockout that composes.** Member and group `disabled` combine; disabled headers are skipped in travel and refuse activation on both hosts.
- **Zero markup lock-in.** Native `<button>` headers or custom hosts, panels wherever the layout needs them.
