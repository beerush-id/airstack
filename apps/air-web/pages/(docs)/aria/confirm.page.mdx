# AirLib Headless Confirm

Destructive workflows such as deleting data or revoking credentials demand deliberate confirmation. Unlike general-purpose dialogs, a confirmation unit is a specialized alertdialog: it interrupts workflow execution, communicates `role="alertdialog"`, traps keyboard focus within its container, suppresses outside pointer and `Escape` dismissals, and places initial focus safely on the Cancel action. **AirLib Headless Confirm** (`aria('confirm')`) manages these interactions and state coordination across both native `<dialog>` and custom DOM trees.

```tsx
const root = aria('confirm', { open: false });
const trigger = root.trigger();
const panel = root.panel();
const title = root.title();
const description = root.description();
const action = root.action();
const cancel = root.cancel();

<>
  <button ref={trigger.ref} {...trigger.props}>Delete Project</button>
  <div ref={panel.ref} {...panel.props}>
    <h3 ref={title.ref} {...title.props}>Delete Project</h3>
    <p ref={description.ref} {...description.props}>This action cannot be undone.</p>
    <button ref={cancel.ref} {...cancel.props}>Cancel</button>
    <button ref={action.ref} {...action.props}>Delete</button>
  </div>
</>
```

:::interactive[Confirmation Alertdialog]
```tsx
import { aria, type CancelEvent, type ConfirmEvent } from '@airlib/aria';
import { setup, teleport } from '@airlib/react';
import type { ComponentProps, PropsWithChildren } from 'react';

type ConfirmProps = PropsWithChildren<{
  open?: boolean;
  id?: string;
  onConfirm?: (e: ConfirmEvent) => void;
  onCancel?: (e: CancelEvent) => void;
}>;

const ConfirmRoot = setup<ConfirmProps>((props) => {
  aria('confirm', props);
  return () => props.children;
});

const ConfirmTrigger = setup<ComponentProps<'button'>>((props) => {
  const trigger = aria('confirm-trigger', props);
  return () => (
    <button ref={trigger.ref} {...trigger.props}>
      {props.children}
    </button>
  );
});

const ConfirmPanel = setup<ComponentProps<'div'>>((props) => {
  const panel = aria('confirm-panel', props);

  return () => {
    if (!panel.confirm?.open) return null;

    return teleport(
      <div ref={panel.ref} {...panel.props}>
        {props.children}
      </div>
    );
  };
});

const ConfirmTitle = setup<ComponentProps<'h3'>>((props) => {
  const title = aria('confirm-title', props);
  return () => (
    <h3 ref={title.ref} {...title.props}>
      {props.children}
    </h3>
  );
});

const ConfirmDescription = setup<ComponentProps<'p'>>((props) => {
  const description = aria('confirm-description', props);
  return () => (
    <p ref={description.ref} {...description.props}>
      {props.children}
    </p>
  );
});

const ConfirmCancel = setup<ComponentProps<'button'>>((props) => {
  const cancel = aria('confirm-cancel', props);
  return () => (
    <button ref={cancel.ref} {...cancel.props}>
      {props.children}
    </button>
  );
});

const ConfirmAction = setup<ComponentProps<'button'>>((props) => {
  const action = aria('confirm-action', props);
  return () => (
    <button ref={action.ref} {...action.props}>
      {props.children}
    </button>
  );
});

const Confirm = Object.assign(ConfirmRoot, {
  Trigger: ConfirmTrigger,
  Panel: ConfirmPanel,
  Title: ConfirmTitle,
  Description: ConfirmDescription,
  Action: ConfirmAction,
  Cancel: ConfirmCancel,
});

const ConfirmDemo = () => (
  <Confirm onConfirm={() => console.log('Confirmed.')} onCancel={() => console.log('Canceled.')}>
    <Confirm.Trigger className="confirm-trigger">
      Delete Repository
    </Confirm.Trigger>
    <Confirm.Panel className="confirm-panel">
      <div className="confirm-header">
        <Confirm.Title className="confirm-title">
          Delete Repository
        </Confirm.Title>
      </div>
      <Confirm.Description className="confirm-description">
        Are you sure you want to delete this repository? All branches, commits, and releases will be permanently removed.
      </Confirm.Description>
      <div className="confirm-actions">
        <Confirm.Cancel className="confirm-cancel">
          Cancel
        </Confirm.Cancel>
        <Confirm.Action className="confirm-action">
          Confirm Delete
        </Confirm.Action>
      </div>
    </Confirm.Panel>
  </Confirm>
);
```

## Anatomy & Entities

A confirmation alertdialog is composed of seven cooperating entities. You can instantiate them directly from the `confirm` coordinator or via standalone role lookups:

```ts
// Coordinator
const root = aria('confirm', props?: ConfirmProps);

// Sub-Entities (factory methods or standalone role strings)
const trigger     = root.trigger();      // or aria('confirm-trigger')
const panel       = root.panel();        // or aria('confirm-panel')
const title       = root.title();        // or aria('confirm-title')
const description = root.description();  // or aria('confirm-description')
const cancel      = root.cancel();       // or aria('confirm-cancel')
const action      = root.action();       // or aria('confirm-action')
```

## Entity Specifications

### Confirm Coordinator

The root coordinator managing open state, unique ID namespacing, and ambient context propagation across confirm parts.

- **Role / Type**: Composite Coordinator
- **Factory**: `aria('confirm', props?)` or `confirm(props?)`
- **Parameters (`ConfirmProps`)**:
  - `open` *(boolean, optional, default `false`)*: Controls visibility of the confirmation alertdialog.
  - `id` *(string, optional)*: Explicit base identifier used to coordinate child element IDs (`aria-controls`, `aria-labelledby`, `aria-describedby`).
- **Controller Properties & Methods**:
  - `open` *(boolean)*: Reactive open state getter and setter.
  - `modality`: Strictly `'modal'`.
  - `dismissable`: Strictly `false`.
  - `show()`: Opens the confirmation alertdialog.
  - `close()`: Closes the confirmation alertdialog.
  - `toggle()`: Toggles the open state.
  - Sub-entity factories: `root.panel()`, `root.trigger()`, `root.action()`, `root.cancel()`, `root.title()`, `root.description()`.

### Confirm Panel

The modal window container carrying WAI-ARIA alertdialog semantics and focus trapping.

- **Role / Type**: `role="alertdialog"`
- **Factory**: `root.panel(props?, options?)` or `aria('confirm-panel', props?, options?)`
- **Compiled Attributes (`panel.props`)**:
  - `role`: `'alertdialog'`
  - `id`: Linked to `${confirmId}-panel`.
  - `aria-modal`: `'true'`
  - `aria-labelledby`: Linked to `${confirmId}-title`.
  - `aria-describedby`: Linked to `${confirmId}-description`.
  - `hidden`: Applied when closed on custom hosts.
- **Behaviors**:
  - **Focus trapping**: Traps `Tab` and `Shift+Tab` cycles strictly inside the panel element.
  - **Non-dismissable**: Suppresses outside pointer clicks and `Escape` key events to require an explicit choice.
  - **Close event**: Dispatches a standard `close` event when the confirmation dialog closes.

### Confirm Trigger

The control button that opens the confirmation dialog.

- **Role / Type**: Interactive Trigger Button
- **Factory**: `root.trigger(props?, options?)` or `aria('confirm-trigger', props?, options?)`
- **Compiled Attributes (`trigger.props`)**:
  - `type`: `'button'` on native hosts.
  - `aria-haspopup`: `'dialog'`
  - `aria-expanded`: `'true'` when open, `'false'` when closed.
  - `aria-controls`: ID referencing the linked confirmation panel.
- **Behaviors**:
  - Clicking toggles the confirmation dialog open state.
  - Automatically captures the opening trigger and restores focus upon closure.

### Confirm Cancel

The safe dismissal button. Initial focus automatically lands here when the confirmation dialog opens.

- **Role / Type**: Safe Dismiss Button
- **Factory**: `root.cancel(props?, options?)` or `aria('confirm-cancel', props?, options?)`
- **Compiled Attributes (`cancel.props`)**:
  - `type`: `'button'` on native hosts; `role="button"` and `tabindex="0"` on custom hosts.
  - `autofocus`: Automatically applied so focus lands safely on Cancel rather than a destructive action.
- **Behaviors**:
  - Activating dispatches a bubbling `cancel` event (`CustomEvent('cancel', { bubbles: true, cancelable: true })`), closes the confirmation dialog, and restores focus to the trigger without executing the action.

### Confirm Action

The confirmation button that confirms the prompt.

- **Role / Type**: Confirmation Button
- **Factory**: `root.action(props?, options?)` or `aria('confirm-action', props?, options?)`
- **Compiled Attributes (`action.props`)**:
  - `type`: `'button'` on native hosts; `role="button"` and `tabindex="0"` on custom hosts.
- **Behaviors**:
  - Activating dispatches a bubbling `confirm` event (`CustomEvent('confirm', { bubbles: true, cancelable: true })`), closes the confirmation dialog, and restores focus to the trigger.

### Confirm Title

The heading element that accessible labels the confirmation dialog.

- **Role / Type**: Accessible Label
- **Factory**: `root.title(props?, options?)` or `aria('confirm-title', props?, options?)`
- **Compiled Attributes (`title.props`)**:
  - `id`: Unique identifier referenced by the panel's `aria-labelledby`.

### Confirm Description

The explanation text that accessible describes the confirmation prompt.

- **Role / Type**: Accessible Description
- **Factory**: `root.description(props?, options?)` or `aria('confirm-description', props?, options?)`
- **Compiled Attributes (`description.props`)**:
  - `id`: Unique identifier referenced by the panel's `aria-describedby`.

## Keyboard Navigation

- **Tab**: Cycles forward through focusable elements inside the confirmation alertdialog. Trapped circularly within the panel.
- **Shift + Tab**: Cycles backward through focusable elements inside the confirmation alertdialog.
- **Escape**: Suppressed. Outside dismissal and Escape keys are ignored to prevent accidental cancellation without reading.
- **Space / Enter**: Activates the focused button (`ConfirmCancel` or `ConfirmAction`).

## What you get

- **Alertdialog semantics.** Emits `role="alertdialog"` with `aria-modal="true"` to prompt immediate attention from assistive technology.
- **Safe initial focus.** Automatically places initial focus on `ConfirmCancel` instead of a destructive action button, preventing unintended confirmation via hasty keystrokes.
- **Non-dismissable modality.** Suppresses outside clicks and `Escape` dismissal so that critical decisions require an explicit button choice.
- **Automatic focus restoration.** Remembers the opening trigger element and restores focus smoothly when the prompt completes.
- **Deterministic part linkages.** Coordinates `aria-controls`, `aria-labelledby`, and `aria-describedby` across parts without manual wiring.
