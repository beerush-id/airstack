# Headless Confirm

A confirm stops a destructive action until the user chooses. Getting it right means **interrupting as an alertdialog**, **landing the first focus on the safe choice**, **refusing dismissal without a decision**, and **returning focus where the user started**.

**Headless Confirm** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const confirm = aria('confirm', props);
const trigger = confirm.trigger();

<button ref={trigger.ref} {...trigger.restProps(['children'])} />
```

## Confirm

**The decision as a whole.** It holds the open state and names the parts; the trigger, the panel, and the four elements inside it all follow it.

### Usage

```ts
aria<E extends HTMLElement = HTMLElement>(
  role: 'confirm',
  props?: ConfirmProps,
  options?: ConfirmOptions
): ConfirmAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type ConfirmProps = ComponentProps<'div'> & {
  id?: string;
  open?: boolean;
  onconfirm?: (event: CustomEvent<void>) => void;
  oncancel?: (event: CustomEvent<void>) => void;
};

const Confirm = setup<ConfirmProps>((props) => {
  const confirm = aria('confirm', props);

  return () => (
    <div ref={confirm.ref} {...confirm.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps, JSX } from 'solid-js';

type ConfirmProps = ComponentProps<'div'> & {
  id?: string;
  open?: boolean;
  onconfirm?: (event: CustomEvent<void>) => void;
  oncancel?: (event: CustomEvent<void>) => void;
};

const Confirm = setup<ConfirmProps>((props) => {
  const confirm = aria('confirm', props);

  return (
    <div ref={confirm.ref} {...confirm.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **open** _boolean, optional, default `false`_: Whether the panel is showing. Read and write it through `confirm.open`.
- **id** _string, optional_: The prefix every part's identifier is built from, generated as `confirm-<n>` when you leave it out.
- **onconfirm** _(event: CustomEvent&lt;void&gt;) =&gt; void, optional_: Called when the action button commits the decision.
- **oncancel** _(event: CustomEvent&lt;void&gt;) =&gt; void, optional_: Called when the cancel button declines it.
- **onopen** / **onclose** _(event: CustomEvent&lt;void&gt;) =&gt; void, optional_: The panel's visibility edges, once per transition, whichever path caused it.

### Properties

_What you read or write on the instance afterwards._

- **open** _boolean, read and write_: Whether the panel is showing.
- **modality** _'modal'_: Always modal — the trap and the background lock are not optional here.
- **dismissable** _boolean_: Always `false` — `Escape` and outside clicks never answer for the user.
- **id** _string_: The prefix in use, generated when you left it out.

### Methods

_What you call on the instance._

- **`show()`**: Opens the panel.
- **`close()`**: Closes it and returns focus to the trigger.
- **`toggle()`**: Opens or closes, whichever applies.
- **`trigger(props?, options?)`** → `ConfirmTriggerAria`: Creates the button that opens it.
- **`panel(props?, options?)`** → `ConfirmPanelAria`: Creates the alertdialog container.
- **`title(props?, options?)`** → `ConfirmTitleAria`: Creates the element that names it.
- **`description(props?, options?)`** → `ConfirmDescriptionAria`: Creates the element that explains it.
- **`action(props?, options?)`** → `ConfirmActionAria`: Creates the destructive button.
- **`cancel(props?, options?)`** → `ConfirmCancelAria`: Creates the safe button.

### Events

_What it tells you._

- **`confirm`** — the action button was activated and the decision committed.
- **`cancel`** — the cancel button was activated and the decision declined.
- **`open` / `close`** — the panel's visibility edges.

```tsx
const confirm = aria('confirm', {
  onconfirm: () => repository.delete(),
  oncancel: () => audit.note('declined'),
});
```

Calling `preventDefault` on `confirm` or `cancel` stops the close, so an async check can answer first.

### Navigation

_What the keys do._

- **`Tab` / `Shift+Tab`** — cycle through the panel's focusable elements, trapped inside it.
- **`Escape`** — suppressed. The decision belongs to the two buttons.
- **`Enter` / `Space`** — activate the focused button, which starts out as Cancel.

### Properties

### How it behaves

- **Announced as opening something.** `aria-haspopup="dialog"` with `aria-expanded` tracking the panel and `aria-controls` pointing at it.
- **Clicking toggles.** A disabled trigger refuses, on either host.
- **It gets the focus back.** When the panel closes, focus returns here.

### Properties

_What you read or write on the instance afterwards._

- **open** _boolean_: Whether the panel is showing.

### How it behaves

- **Announced as an interruption.** `role="alertdialog"` with `aria-modal="true"`, labelled by the title and described by the description through derived identifiers.
- **Focus stays inside.** `Tab` and `Shift+Tab` cycle within the panel; the background is locked while it is open.
- **No accidental answers.** Outside clicks and `Escape` are suppressed — only the two buttons close it.
- **Hidden when closed on a custom host.** A native `<dialog>` host carries its own visibility; any other element gets `hidden`.

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`props`** / **`restProps(omit)`** is what you spread onto the host — your props minus the keys the controller writes and any you name, with the compiled attributes merged in; **`ref`** is what you bind the element with; **`attributes`** is that compiled dictionary on its own, when you need the low-level view.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
