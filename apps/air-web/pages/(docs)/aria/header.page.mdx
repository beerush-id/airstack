# Header

Every page repeats the same header: identity, global navigation, maybe an account menu. Assistive technologies need that repetition identified once so it can be skipped, and a page with no `banner` landmark forces users to listen through it to find out where the content starts.

`@airlib/aria` compiles the header landmark onto the element you already render. Bound to a native `<header>` it emits no redundant role, because a body-level header already implies `banner`; bound to a `<div>` it supplies `role="banner"`, and it compiles the accessible name whenever more than one header needs telling apart.

You compose a header using this piece:

- **Header**: The prime header landmark that compiles `role="banner"` only when the host does not already imply it.

## What you get

- **Native-first projection.** A `<header>` keeps its implicit role; a custom host gets an explicit `role="banner"`.
- **Optional naming.** `label` and `labelledby` compile to `aria-label` and `aria-labelledby` for the rare page with more than one header.
- **Structure only.** No focus, no keyboard handling, and no state — nothing to keep in sync.

## Header

In Aria, Header is the page header landmark created with `aria('header')` that projects banner semantics onto a native or custom host.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'header',
  props?: HeaderProps,
  options?: HeaderOptions
): HeaderAria<E>
```

### Parameters

- `props.label` *(string, optional)*: Accessible label compiled to `aria-label`.
- `props.labelledby` *(string, optional)*: Element ID providing the accessible name, compiled to `aria-labelledby`.
- `options.native` *(boolean, optional, default `true`)*: Pass `false` when binding to a custom `<div>` host that implies nothing.

### How it behaves

With `native: true` the controller compiles only the accessible name, leaving the role to the host element. With `native: false` it adds `role="banner"`. The name is compiled whenever `label` or `labelledby` is present and omitted otherwise, so an unnamed page header carries no redundant `aria-label`.

:::tip[Only the page header is a banner]
A `<header>` nested inside `<main>`, `<article>`, `<aside>`, or `<section>` is not a banner landmark — it is the header of that section. The header entity belongs to the body-level header, and a page should hold at most one.
:::

### Usage

To use Header, create the landmark with `aria('header', props)`, then pass `header.ref` and spread `header.attributes` onto your header element:

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type HeaderProps = ComponentProps<'header'> & {
  label?: string;
  labelledby?: string;
};

const Header = setup<HeaderProps>((props) => {
  const header = aria('header', props);
  const restProps = props.$omit([...header.ownKeys, 'label', 'labelledby', 'children', 'className']);

  return () => (
    <header ref={header.ref} {...restProps} {...header.attributes} className={props.className}>
      {props.children}
    </header>
  );
}, 'Header');
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type HeaderProps = ComponentProps<'header'> & {
  label?: string;
  labelledby?: string;
};

const Header = setup<HeaderProps>((props) => {
  const header = aria('header', props);
  const restProps = props.$omit([...header.ownKeys, 'label', 'labelledby', 'children', 'className']);

  return (
    <header ref={header.ref} {...restProps} {...header.attributes} className={props.className}>
      {props.children}
    </header>
  );
});
```

:::

## Putting It Together

Once your component is wired with `aria('header')`, place it at the top of the document body:

```tsx
<Header>
  <strong>AirLib</strong>
  <nav>Docs · Blog · Sign in</nav>
</Header>
```

## Keyboard Navigation

- **None.** A landmark takes no tab stop and claims no keys. Assistive technologies reach it through their own landmark commands, and the controls inside it keep their own keyboard behavior.
