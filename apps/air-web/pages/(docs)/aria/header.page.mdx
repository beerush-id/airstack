# Headless Header

Identity, global navigation, and the account controls repeat at the top of every page, and a landmark is what lets a user skip them or jump straight back to them.

Getting it right means **compiling `banner` onto a generic host**, **naming it only when a document carries two**, **leaving a real `<header>` its own implicit role**, and **taking no focus and claiming no keys**.

**Headless Header** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const header = aria('header', props);

<div ref={header.ref} {...header.restProps(['children'])} />
```

:::interactive[Storefront Header]

type DemoHeaderProps = ComponentProps<'div'> & {

  const header = aria('header', props);

  label?: string;
  children: ReactNode;

const DemoPageHeader = setup<DemoPageHeaderProps>((props) => {
  const header = aria('header', props, { native: true });

  return () => (
    <header ref={header.ref} {...header.restProps(['children'])} className="demo-header">
      {props.children}
    </header>
  );

:::tip
**Only the body-level header is a banner.** A `<header>` inside `<main>`, `<article>`, `<aside>`, or `<section>` heads that section instead and exposes no landmark role at all, so keep the landmark on the body-level header and hold to one per page.

## Header

**The header landmark.** It compiles `banner` onto a generic host and carries the accessible name that tells two headers apart.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'header',
  props?: HeaderProps,
  options?: HeaderOptions
): HeaderAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type HeaderProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
  children: ReactNode;
};

const Header = setup<HeaderProps>((props) => {
  const header = aria('header', props);

  return () => (
    <div ref={header.ref} {...header.restProps(['children'])}>
      {props.children}
    </div>
  );
}, 'Header');
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps, JSX } from 'solid-js';

type HeaderProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
  children: JSX.Element;
};

const Header = setup<HeaderProps>((props) => {
  const header = aria('header', props);

  return (
    <div ref={header.ref} {...header.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **label** _string, optional_: The name screen readers announce for this header, compiled to `aria-label`. Omitted when absent, so an unnamed page header carries no redundant attribute.
- **labelledby** _string, optional_: The ID of an element already on the page that provides that name, compiled to `aria-labelledby`.

### Options

_What you fix when you create it. Read once, never reactive._

- **native** _boolean, optional, default `false`_: Pass `true` when the host is a real `<header>`, which already implies `banner`. The redundant role is dropped and only the name is compiled.

### Properties

_What you read or write on the instance afterwards._

- **label** _string | undefined_: The label in force.
- **labelledby** _string | undefined_: The ID reference in force.
- **named** _boolean_: Whether the landmark carries an accessible name.

### How it behaves

- **Compiles `role="banner"` on a generic host.** A `<div>` host is announced as the document header, whatever the surrounding markup looks like.
- **The role follows `native`, never the host tag or its position.** Pass `native: true` and the element supplies the role itself; a custom host keeps its compiled role wherever you place it, including inside a section.
- **Naming is reactive.** Set, change, or clear `label` or `labelledby` and the projection follows on the next write.
- **Both names can be set at once.** The controller writes whichever you pass, and the name resolution order is the platform's — `aria-labelledby` before `aria-label` — so name the header once, in the way your markup can keep true.
- **Structure only.** No `tabindex`, no `aria-live`, no key handling, and no state of its own; the links and controls you place inside it keep their own keyboard behavior, and nothing they do is intercepted.
- **Two headers on one page are yours to manage.** The controller never counts headers and never suppresses a second one, so the name is what keeps them apart in a landmark list.
- **Both name props stay off the DOM as plain attributes.** `label` and `labelledby` compile to `aria-label` and `aria-labelledby` only, so `restProps(['children'])` is the whole omission list.

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### Header

```ts
interface HeaderProps {
  label?: string;
  labelledby?: string;
}

interface HeaderOptions {
  native?: boolean;
}

interface HeaderAttributes {
  role?: 'banner';
  'aria-label'?: string;
  'aria-labelledby'?: string;
}

declare class HeaderAria {
  get label(): string | undefined;
  get labelledby(): string | undefined;
  get named(): boolean;
}
```

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`attributes`** is the dictionary you spread; **`ref`** is what you bind the element with; **`props`** is the full props dictionary for spreading onto the host; **`restProps(omit)`** hands back your props with the keys you name left out.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
