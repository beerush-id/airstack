# AirLib Headless Header

Every page repeats the same header: identity, global navigation, maybe an account menu. Assistive technology needs that repetition named once so it can be skipped, and a page with no `banner` landmark makes a screen reader user listen through the whole header to find out where the content starts. **AirLib Headless Header** (`aria('header')`) compiles `role="banner"` onto the generic host you already render, adds an accessible name when a page carries more than one header, and stays purely structural — no focus, no keys, no state to keep in sync.

```tsx
const header = aria('header', props);

<div ref={header.ref} {...header.restProps(['children'])} />
```

## Header

The prime header landmark. It projects banner semantics onto a generic host and compiles the accessible name that tells two headers apart.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'header',
  props?: HeaderProps,
  options?: HeaderOptions
): HeaderAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type HeaderProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
  children: ReactNode;
};

const Header = setup<HeaderProps>((props) => {
  const header = aria('header', props);

  return () => (
    <div ref={header.ref} {...header.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type HeaderProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
};

const Header = setup<HeaderProps>((props) => {
  const header = aria('header', props);

  return (
    <div ref={header.ref} {...header.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

- `props.label` *(string, optional)*: Accessible label compiled to `aria-label`. Omitted when absent, so an unnamed page header carries no redundant attribute.
- `props.labelledby` *(string, optional)*: Element ID providing the accessible name, compiled to `aria-labelledby`.
- `options.native` *(boolean, optional, default `false`)*: Pass `true` when the host is a real `<header>`, which already implies `banner` — the redundant role is dropped and only the name is compiled.

### How it behaves

- Compiles `role="banner"` on a generic host. With `native: true` the role is left to the `<header>` element and only the accessible name is emitted.
- The role comes from `native` alone — never from the host tag and never from where the element sits in the tree — so a custom host keeps its compiled role wherever you place it.
- `label` compiles to `aria-label` and `labelledby` to `aria-labelledby`, both reactively: set, change, or clear either one and the projection follows.
- Both may be present at once; neither takes precedence, and assistive technology resolves the name from what the host exposes.
- Structure only: no `tabindex`, no `aria-live`, no key handling, and no state. Nothing on either host is prevented or swallowed.
- Keeping one `banner` per page is yours to manage — the controller never counts headers and never suppresses a second one.
- `label` and `labelledby` are consumed by the controller and carried in `ownKeys`, so `restProps(['children'])` is the whole omission list — neither leaks to the DOM as a stray attribute.

:::tip[Only the page header is a banner]
A `<header>` nested inside `<main>`, `<article>`, `<aside>`, or `<section>` is not a banner landmark — it is the header of that section, and HTML exposes no role for it at all. The header entity belongs to the body-level header, and a page should hold at most one. A custom host compiles `role="banner"` wherever it is placed, so nesting one inside a section publishes a second banner: keep the entity at document scope.
:::

## Keyboard Navigation

- **None.** A landmark takes no tab stop and claims no keys. Assistive technologies reach it through their own landmark commands, and the controls inside it keep their own keyboard behavior.

## What you get

- **Banner on a generic host.** A `<div>` becomes a navigable landmark with no markup lock-in.
- **No redundant role.** `native: true` on a real `<header>` leaves the implicit role alone.
- **Optional naming.** `label` and `labelledby` cover the rare page with more than one header.
- **Placement-stable output.** The compiled attributes are identical in SSR and after hydration, because nothing is read from the DOM.
- **Structure only.** No focus, no keys, no state — nothing to keep in sync.
