# Headless Date Range Picker

A date range is two picks that only count together. Getting it right means **holding `change` silent until both ends are picked**, **ordering the pair no matter which end was picked first**, **landing on the day you left when the calendar reopens**, and **travelling months without saving anything**.

**Headless Date Range Picker** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const picker = aria('date-range-picker', props);

<div ref={picker.ref} {...picker.restProps(['children'])} />
```

## Date Range Picker

**The group as a whole.** It holds the saved range, the unfinished draft, and the shown month, and the fields, the button, and the calendar all follow it.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'date-range-picker',
  props?: DateRangePickerProps
): DateRangePickerAria<E>
```

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **id** _string, optional_: The prefix the fields, the button, and the calendar are linked through. Generated as `date-range-picker-<n>` when you leave it out.
- **value** _[string, string], optional_: The saved pair as ordered dates. After the first pick that end is set and the other is still empty.
- **month** _number, optional_: The shown month as `1`–`12`. Defaults to the saved start's month, otherwise the current month.
- **year** _number, optional_: The shown year as `YYYY`. Defaults to the saved start's year, otherwise the current year.
- **min** _string, optional_: The earliest date that can be chosen. Earlier days read disabled.
- **max** _string, optional_: The latest date that can be chosen. Later days read disabled.
- **label** _string, optional_: The calendar's name for screen readers. Leave it out and the dialog is unnamed.
- **locales** _string[], optional_: The locale stack every label is formatted with. Defaults to the runtime locale.
- **disabled** _boolean, optional_: Locks editing, opening, and choosing across the **whole composite**.
- **required** _boolean, optional_: Marks range entry as required.
- **open** _boolean, optional_: Whether the calendar shows.
- **oninput** _(event: CustomEvent&lt;string&gt;) =&gt; void, optional_: The raw text as the start or the end is typed.
- **onchange** _(event: CustomEvent&lt;[string, string] | undefined&gt;) =&gt; void, optional_: The pair as it stands whenever a pick or a field edit changes it.
- **onopen** / **onclose** _(event: CustomEvent&lt;true&gt; | CustomEvent&lt;false&gt;) =&gt; void, optional_: The popup's edges, through every path.

### Properties

_What you read or write on the instance afterwards._

- **value** _[string, string] | undefined_: The pair. A waiting start has no end yet; a finished pair has both.
- **draft** _(string | undefined)[]_: The day picked so far while the pair is unfinished.
- **month** _number_: The month the grid shows, `1`–`12`. Writing it moves the grid.
- **year** _number_: The year the grid shows. Writing it moves the grid.
- **open** _boolean_: Whether the calendar shows.
- **disabled** _boolean_: Whether the composite refuses interaction.
- **range** _ParsedDate_: The shown month as a date — `monthStr` is the label the header shows.
- **today** / **start** / **end** _ParsedDate_: Today, the saved start, and the saved end as dates, ready to compare.
- **limit** _object_: The earliest and latest dates you allow, ready to compare, as `min` and `max`.
- **id** / **panelId** / **triggerId** _string_: The identifiers the parts link through.

### Methods

_What you call on the instance._

- **`select(start, end?)`**: Picks a day. The first pick waits for a partner; the second saves the ordered pair, fires `change`, and closes. Pass both ends to save at once.
- **`deselect(index?)`**: Clears one end, or the whole pair when no index is given, and fires `change`.
- **`navigateMonth(direction)`**: Moves the grid a month back (`-1`) or forward (`1`), across the year boundary. Chooses nothing.
- **`navigateYear(direction)`**: Moves the grid a year back (`-1`) or forward (`1`). Chooses nothing.

### How it behaves

- **The first pick waits.** One day marks a starting point and `change` stays silent until you pick the other end.
- **Order fixes itself.** Picking the end before the start still saves start → end, and equal picks save a valid single day.
- **A half pick replaces the pair.** The first pick sets that end and clears the other; the calendar reopens on the day you left.
- **Travel saves nothing.** Flipping months moves the grid, through `PageUp` / `PageDown` or the nav buttons; the pair stays put.
- **One tab stop for the whole grid.** The active day carries it; the rest stay out of the tab order.
- **The dialog is named by `label`.** Leave it out and the calendar carries no accessible name.

### Events

_What it tells you._

- **`input`** — a field edit as the start or the end is typed; the text arrives through `oninput`.
- **`change`** — the pair in `detail`, whenever a pick or a field edit changes it.

```tsx
const picker = aria('date-range-picker', {
  onchange: (event) => save(event.detail),
});
```

### Navigation

_The group handles no keys itself._ Text goes to the **start and end fields**, grid travel to the **calendar**, picking to the **days**.

## Shared with Date Picker

The start and end fields, the calendar button, the popup, and the day cells are the parts the single-date picker already documents — read [Date Picker](/docs/aria/date-picker) for their usage, parameters, and dictionaries. A range composes them with three differences:

- **Each field carries its slot.** The same `date-picker-input` takes `slot="start"` or `slot="end"`, so typing edits that end of the pair rather than a standalone date.
- **The calendar opens on the draft.** Opening lands focus on the draft start, otherwise the saved start, otherwise today, otherwise the first enabled day.
- **A pick is a step, not an answer.** `Enter` or `Space` on a day starts a draft or completes the pair, and the popup stays open through the first pick.

The saved start and end read `aria-selected="true"`, the stretch from the start up to the day before the end carries `data-in-range="true"`, and anything outside `min` / `max` reads `aria-disabled="true"`.

### Shared parts

The `date-picker-input`, `date-picker-trigger`, `date-picker-calendar`, `date-picker-day`, and `date-picker-nav` roles carry the dictionaries documented on [Date Picker](/docs/aria/date-picker#api-reference). Only the root changes shape:

```ts
type DateRangePickerValue = [string, string] | undefined;
```

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`props`** / **`restProps(omit)`** is what you spread onto the host — your props minus the keys the controller writes and any you name, with the compiled attributes merged in; **`ref`** is what you bind the element with; **`attributes`** is that compiled dictionary on its own, when you need the low-level view.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
