# Headless Date Range Picker

A date range is two picks that only count together. Getting it right means **keeping the half-picked start out of the saved range**, **ordering the pair no matter which end was picked first**, **throwing the draft away when the popup is abandoned**, and **travelling months without saving anything**.

**Headless Date Range Picker** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const picker = aria('date-range-picker', props);

<div ref={picker.ref} {...picker.restProps(['children'])} />
```

:::interactive[Pick a Range]
```tsx
import { aria } from '@airlib/aria';
import { setup, derived, For, Snippet, shadowPortal } from '@airlib/react';
import type { ComponentProps } from 'react';

type DemoRangeProps = ComponentProps<'div'> & {
  value?: [string, string] | null;
  min?: string;
  max?: string;
  disabled?: boolean;
};

const DemoRange = setup<DemoRangeProps>((props) => {
  const picker = aria('date-range-picker', props);

  return () => (
    <div ref={picker.ref} {...picker.restProps(['children'])} className="demo-date-picker">
      <div className="demo-date-picker-row">
        <DemoPickerInput slot="start" />
        <DemoPickerInput slot="end" />
        <DemoPickerTrigger />
      </div>
      <DemoPickerCalendar>
        <div className="demo-date-picker-nav">
          <DemoPrevMonth />
          <Snippet>
            {() => <span className="demo-date-picker-month">{picker.range.monthStr}</span>}
          </Snippet>
          <DemoYearInput />
          <DemoNextMonth />
        </div>
      </DemoPickerCalendar>
    </div>
  );
}, 'DemoRange');

type DemoPickerInputProps = ComponentProps<'input'> & {
  id?: string;
  disabled?: boolean;
};

const DemoPickerInput = setup<DemoPickerInputProps>((props) => {
  const input = aria<HTMLInputElement>('date-picker-input', props);

  return () => (
    <input ref={input.ref} {...input.props} placeholder="YYYY-MM-DD" className="demo-date-picker-input" />
  );
}, 'DemoPickerInput');

type DemoPickerTriggerProps = ComponentProps<'button'>;

const DemoPickerTrigger = setup<DemoPickerTriggerProps>((props) => {
  const trigger = aria<HTMLButtonElement>('date-picker-trigger', props);

  return () => (
    <button ref={trigger.ref} {...trigger.restProps(['children'])} className="demo-date-picker-trigger">
      📅
    </button>
  );
}, 'DemoPickerTrigger');

type DemoMonthNavProps = ComponentProps<'button'>;

const DemoPrevMonth = setup<DemoMonthNavProps>((props) => {
  const nav = aria<HTMLButtonElement>('date-picker-nav', { type: 'month', direction: -1 });

  return () => (
    <button ref={nav.ref} {...nav.restProps(['children'])} className="demo-date-picker-navbtn" aria-label="Previous month">
      ‹
    </button>
  );
}, 'DemoPrevMonth');

const DemoNextMonth = setup<DemoMonthNavProps>((props) => {
  const nav = aria<HTMLButtonElement>('date-picker-nav', { type: 'month', direction: 1 });

  return () => (
    <button ref={nav.ref} {...nav.restProps(['children'])} className="demo-date-picker-navbtn" aria-label="Next month">
      ›
    </button>
  );
}, 'DemoNextMonth');

const DemoYearInput = setup((props) => {
  const input = aria<HTMLInputElement>('date-picker-year-input', props);

  return () => (
    <input ref={input.ref} {...input.props} className="demo-date-picker-year" />
  );
}, 'DemoYearInput');

type DemoPickerCalendarProps = ComponentProps<'div'>;

const DemoPickerCalendar = setup<DemoPickerCalendarProps>((props) => {
  const calendar = aria<HTMLElement>('date-picker-calendar', props);
  const shadow = shadowPortal(() => calendar.open);

  return () => shadow(
    <div ref={calendar.ref} {...calendar.restProps(['children'])} className="demo-date-picker-calendar">
      {props.children}
      <div className="demo-date-picker-grid">
        <For each={() => calendar.grid.weeks}>
          {(day) => <div className="demo-date-picker-day demo-date-picker-head">{day}</div>}
        </For>
        <For each={() => calendar.grid.dates}>
          {(date) => <DemoDay date={date} />}

type DemoDayProps = ComponentProps<'div'> & {
  date: string;

const DemoDay = setup<DemoDayProps>((props) => {
  const day = aria<HTMLElement>('date-picker-day', props);

  return () => (
    <div ref={day.ref} {...day.restProps(['children'])} className="demo-date-picker-day">
      {day.date.date}
    </div>
  );
}, 'DemoDay');
```

## Date Range Picker

**The group as a whole.** It holds the saved range, the unfinished draft, and the shown month, and the fields, the button, and the calendar all follow it.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'date-range-picker',
  props?: DateRangePickerProps
): DateRangePickerAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type RangeProps = ComponentProps<'div'> & {
  id?: string;
  value?: [string, string] | null;
  draft?: [string, string];
  month?: string;
  open?: boolean;
  min?: string;
  max?: string;
  disabled?: boolean;
  required?: boolean;
  activeDate?: string;
  oninput?: (event: CustomEvent<[string, string]>) => void;
  onchange?: (event: CustomEvent<[string, string] | null>) => void;
  onopen?: (event: CustomEvent<true>) => void;
  onclose?: (event: CustomEvent<false>) => void;
  children: ReactNode;
};

const Range = setup<RangeProps>((props) => {
  const picker = aria('date-range-picker', props);

  return () => (
    <div ref={picker.ref} {...picker.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **id** _string, optional_: The prefix the fields, the button, and the calendar are linked through. Generated when you leave it out.
- **value** _[string, string] | null, optional_: The saved range as ordered `YYYY-MM-DD` endpoints. `null` means nothing saved; repeating one day twice saves a single-day range.
- **draft** _[string, string], optional_: The unfinished pick. A started draft reads `[day, ""]` — the empty end marks it incomplete.
- **month** _string, optional_: The shown month as `YYYY-MM`. Starts as the draft start's month, otherwise the saved start's, otherwise today's; travel updates it without touching the draft or the saved range.
- **open** _boolean, optional_: Whether the calendar shows. Flip it to open or close from code.
- **min** _string, optional_: The earliest date that can be chosen. Earlier days show disabled and refuse interaction.
- **max** _string, optional_: The latest date that can be chosen. Later days show disabled and refuse interaction.
- **disabled** _boolean, optional_: Locks editing, toggling, and choosing across the **whole group**.
- **required** _boolean, optional_: Marks range entry as required.
- **activeDate** _string, optional_: The day holding the tab stop. Starts as the draft start, otherwise the saved start, otherwise today.
- **oninput** _(event: CustomEvent&lt;[string, string]&gt;) =&gt; void, optional_: Called whenever an endpoint is edited or a day starts or completes a draft, with the current draft in `detail`.
- **onchange** _(event: CustomEvent&lt;[string, string] | null&gt;) =&gt; void, optional_: Called whenever a complete range saves, with the saved pair in `detail`.
- **onopen** _(event: CustomEvent&lt;true&gt;) =&gt; void, optional_: Called after the calendar opens, however it was opened.
- **onclose** _(event: CustomEvent&lt;false&gt;) =&gt; void, optional_: Called after the calendar closes, through every dismissal path.

### Options

_The date range picker doesn't take any options._

### Properties

_What you read or write on the instance afterwards._

- **value** _[string, string] | null | undefined_: The saved range. Writing sets it directly.
- **draft** _[string, string] | undefined_: The unfinished pick.
- **month** _string | undefined_: The shown month id.
- **activeDate** _string_: The day holding the tab stop, `""` when cleared.
- **calendarLabel** _string_: The popup name, `"Choose date range"`.

### Methods

_What you call on the instance._

- **`isSelected(date)`**: Whether `date` is one of the saved endpoints.
- **`isDisabledDate(date)`**: Whether `date` refuses interaction — the group locked, or outside `min` / `max`.
- **`activate(date)`**: Runs one pick step — starts a draft, or completes, orders, saves, and closes.
- **`navigateMonth(direction)`**: Steps the shown `month` back (`-1`) or forward (`1`) without saving anything. Invalid months hold still.
- **`editEndpoint(endpoint, text)`**: Writes one draft endpoint from a text field and announces it. _Does nothing while disabled._
- **`resetDraft()`**: Throws the draft away and brings back the saved range — or empties both fields when nothing is saved.
- **`emitInput(detail)`**: Announces a draft as if an endpoint was edited.
- **`emitChange(detail)`**: Announces a saved range as if a pair was completed.

### How it behaves

- **Drafts are not answers.** A half-pick lives only in `draft` — `value` changes solely when a complete, ordered pair saves.
- **Order fixes itself.** Picking the end before the start still saves start → end, and equal picks save a valid single day.
- **Abandoning restores.** `Escape`, dismissal, closing, or focus leaving without a finished pick discards the draft and brings back `value`.
- **Travel saves nothing.** Flipping months updates `month` alone — through `PageUp` / `PageDown`, or the shared `date-picker-prev-month` / `date-picker-next-month` buttons.
- **One tab stop for the whole grid.** The active day carries it; the rest stay out of the tab order.
- **The popup never traps.** Focus is free to leave — and leaving discards the draft.
- **Screen readers get two fields, a button, and a dialog.** Each field is named for its endpoint, and the calendar announces itself as `"Choose date range"`.

### Events

_What it tells you._

- **`input`** — fires when an endpoint is edited or a day starts or completes a draft, with the current draft in `detail`.
- **`change`** — fires when a complete range saves, with the saved pair (or `null`) in `detail`.

```tsx
const picker = aria('date-range-picker', {
  onchange: (event) => save(event.detail),
});
```

### Navigation

_The group handles no keys itself._ Text goes to the **endpoint fields**, grid travel to the **calendar**, picking to the **days**.

## Date Range Picker Input

**One endpoint field.** Render one for the start and one for the end.

### Usage

```ts
  props: DateRangePickerInputProps,
  options?: AriaOptions

```

```tsx [React]
  label?: string;

const Endpoint = setup<EndpointProps>((props) => {
  const input = aria<HTMLInputElement>('date-range-picker-input', props);

  return () => (
    <input ref={input.ref} {...input.restProps()} placeholder="YYYY-MM-DD" />
  );
});
```

```tsx [SolidJS]

import { setup } from '@airlib/solid';

  const input = aria<HTMLInputElement>('date-range-picker-input', props);

  );

```

:::

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **endpoint** _'start' | 'end', **required**_: Which end of the draft this field edits.
- **label** _string, optional_: The name screen readers give the field. Defaults to `"Start date"` / `"End date"` by endpoint.

### Options

_What you fix when you create it. Read once, never reactive._

- **native** _boolean, optional, default `true`_: Pass `false` when the host isn't an `<input>` and you get the `textbox` face instead of native field behavior.

### Properties

_What you read or write on the instance afterwards._

- **disabled** _boolean_: Whether the field refuses typing, **including by the group**.

### Methods

_The field exposes no methods of its own._

### How it behaves

- **Typing edits the draft.** Each keystroke rewrites that endpoint and announces it — `value` stays put.
- **Shows the draft, else the saved.** Each field carries its endpoint's draft text while a draft is open, otherwise the saved endpoint. Picking the pair rewrites both fields.
- **Locked means locked.** While the group is disabled, edits go nowhere.

### Events

_The field dispatches no events of its own._ Editing arrives as `input` on the **group**.

### Navigation

_What the keys do._

- **Printable keys** — edit the text like any field.

### Options

_The calendar doesn't take any options._

### How it behaves

- **Hidden until open.** A closed calendar is off screen and out of reach.
- **Days need no key wiring.** The popup handles every grid key from the focused day, so cells stay plain.
- **Screen readers get a named dialog.** Announced as `"Choose date range"`.

### Events

_The calendar dispatches no events of its own._ Picking arrives as `input` and `change` on the **group**.

### Navigation

_What the keys do — identical to the single-date calendar, except choosing runs a pick step._

- **`ArrowLeft` / `ArrowRight`** — focus the **previous / next** day.
- **`ArrowUp` / `ArrowDown`** — focus the day a **week back / forward**.
- **`Home` / `End`** — focus the **first / last** day of the week.
- **`PageUp` / `PageDown`** — flip the shown month back / forward, saving nothing.
- **`Enter` / `Space`** — draft the focused day, or complete and save the pair.
- **`Escape`** — discard the draft and close.
- **`Tab`** — leave the grid from the current day.

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`attributes`** is the dictionary you spread; **`ref`** is what you bind the element with; **`props`** is the full props dictionary for spreading onto the host; **`restProps(omit)`** hands back your props with the keys you name left out.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
