# Section

Long documents are hard to navigate by listening. A `region` landmark turns a significant, self-contained section into a destination in the assistive technology's landmark list — a table of contents for the page. The catch is that a section only becomes a landmark when it is named; an unnamed `<section>` is a generic container that appears in no list at all.

`@airlib/aria` compiles the section landmark onto the element you already render and enforces the naming rule: with `label` or `labelledby` it compiles `role="region"` plus the name, and without either it compiles no role, so an unnamed section is never announced as a landmark it does not qualify as.

You compose a section using this piece:

- **Section**: The named generic landmark that compiles `role="region"` only when it carries an accessible name.

## What you get

- **Naming enforced by compilation.** No accessible name means no `role="region"`, keeping the landmark list free of anonymous entries.
- **A `named` projection.** `section.named` tells your wrapper whether the section was actually exposed.
- **Native and custom hosts.** `<section>` and `<div>` both work, with the role compiled explicitly in either case when named.

## Section

In Aria, Section is the named section landmark created with `aria('section')` that compiles the role only when the section carries an accessible name.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'section',
  props?: SectionProps,
  options?: SectionOptions
): SectionAria<E>
```

### Parameters

- `props.label` *(string, optional)*: Accessible label compiled to `aria-label`. Required for the landmark to be exposed.
- `props.labelledby` *(string, optional)*: Element ID providing the accessible name, compiled to `aria-labelledby`. Point it at the section's own heading rather than duplicating the text.
- `options.native` *(boolean, optional, default `true`)*: Pass `false` when binding to a custom `<div>` host.

### How it behaves

When `label` or `labelledby` is present the controller compiles `role="region"` with the accessible name — explicitly, on native and custom hosts alike, because the HTML mapping only exposes a named `<section>` as a landmark. When neither is present no role is compiled and the element stays a generic container.

:::tip[Prefer labelledby over label]
A section almost always has a visible heading. Point `labelledby` at that heading's `id` instead of repeating its text in `label`: the name stays in sync when the heading changes, and the visible text and the announced name cannot drift apart.
:::

### Usage

To use Section, create the landmark with `aria('section', props)`, then pass `section.ref` and spread `section.attributes` onto your section element:

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type SectionProps = ComponentProps<'section'> & {
  label?: string;
  labelledby?: string;
};

const Section = setup<SectionProps>((props) => {
  const section = aria('section', props);
  const restProps = props.$omit([...section.ownKeys, 'label', 'labelledby', 'children', 'className']);

  return () => (
    <section ref={section.ref} {...restProps} {...section.attributes} className={props.className}>
      {props.children}
    </section>
  );
}, 'Section');
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

  label?: string;

};

  return (
    <section ref={section.ref} {...restProps} {...section.attributes} className={props.className}>
      {props.children}
    </section>
  );
});
```

:::

## Putting It Together

Once your component is wired with `aria('section')`, name the sections worth jumping to and leave the rest unnamed:

```tsx
<Section labelledby="pricing-heading">
  <h2 id="pricing-heading">Pricing</h2>
  <p>Plans and billing.</p>
</Section>
<section>
  <p>An ordinary section, deliberately not a landmark.</p>
</section>
```

## Keyboard Navigation

- **None.** The landmark takes no tab stop and claims no keys; the content inside it keeps its own keyboard behavior.
