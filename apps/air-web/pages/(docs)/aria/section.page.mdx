# Headless Section

A long page is reached through the landmark list, and a section joins that list only when it carries a name.

Getting it right means **compiling `region` only while the section is named**, **withdrawing the role when the name is cleared**, **taking no tab stop and claiming no keys**, and **keeping the name props off the host as stray attributes**.

**Headless Section** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const section = aria('section', props);

<div ref={section.ref} {...section.restProps(['children'])} />
```

:::interactive[Document Sections]
```tsx
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type DemoSectionProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
  children: ReactNode;
};

const DemoSection = setup<DemoSectionProps>((props) => {
  const section = aria('section', props);

  return () => (
    <div ref={section.ref} {...section.restProps(['children'])}>
      {props.children}
    </div>
  );
}, 'DemoSection');
```

## Section

**The named region.** It compiles `region` while the section carries an accessible name, and nothing at all while it does not.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'section',
  props?: SectionProps,
  options?: SectionOptions
): SectionAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type SectionProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
  children: ReactNode;
};

const Section = setup<SectionProps>((props) => {
  const section = aria('section', props);

  return () => (
    <div ref={section.ref} {...section.restProps(['children'])}>
      {props.children}
    </div>
  );
}, 'Section');
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps, JSX } from 'solid-js';

type SectionProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
  children: JSX.Element;
};

const Section = setup<SectionProps>((props) => {
  const section = aria('section', props);

  return (
    <div ref={section.ref} {...section.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **label** _string, optional_: The name the landmark list announces, compiled to `aria-label`. Either name prop publishes the section.
- **labelledby** _string, optional_: The ID of an element already on the page that carries that name, compiled to `aria-labelledby`.

### Properties

_What you read or write on the instance afterwards._

- **label** _string | undefined_: The label in force.
- **labelledby** _string | undefined_: The ID reference in force.
- **named** _boolean_: Whether the section carries a name, and therefore a role.

### How it behaves

- **The name is the gate.** With `label` or `labelledby` the host compiles `role="region"` next to the name; with neither it compiles no role and stays a generic container.
- **Clearing the name withdraws the role.** The projection is reactive, so dropping `label` or `labelledby` removes `role` on the next write.
- **`native` decides nothing here.** The role follows the name on both hosts, so a `<section>` and a `<div>` are treated the same.
- **Structure only.** No `tabindex`, no key handling, no state; the content inside keeps its own controllers and its own semantics.
- **Both name props stay off the host as plain attributes.** `label` and `labelledby` compile to `aria-label` and `aria-labelledby` only, so `restProps(['children'])` is the whole omission list.

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### Section

```ts
interface SectionProps {
  label?: string;
  labelledby?: string;
}

interface SectionOptions {
  native?: boolean;
}

interface SectionAttributes {
  role?: 'region';
  'aria-label'?: string;
  'aria-labelledby'?: string;
}

declare class SectionAria {
  get label(): string | undefined;
  get labelledby(): string | undefined;
  get named(): boolean;
}
```

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`props`** / **`restProps(omit)`** is what you spread onto the host — your props minus the keys the controller writes and any you name, with the compiled attributes merged in; **`ref`** is what you bind the element with; **`attributes`** is that compiled dictionary on its own, when you need the low-level view.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
