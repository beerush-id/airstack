# AirLib Headless Section

Long documents are hard to navigate by listening. A `region` landmark turns a significant, self-contained section into a destination in the assistive technology's landmark list — a table of contents for the page. The catch is that a section only becomes a landmark when it is named; an unnamed `<section>` is a generic container that appears in no list at all. **AirLib Headless Section** (`aria('section')`) enforces that rule by compilation: with `label` or `labelledby` it emits `role="region"` plus the name, and without either it emits no role, so an anonymous section never pollutes the landmark list.

```tsx
const section = aria('section', props);

<section ref={section.ref} {...section.restProps(['children'])} />
```

## Section

The named generic landmark. It compiles the role only when the section carries an accessible name, and exposes `section.named` so a wrapper can tell whether the landmark was actually published.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'section',
  props?: SectionProps,
  options?: SectionOptions
): SectionAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type SectionProps = ComponentProps<'section'> & {
  label?: string;
  labelledby?: string;
  children: ReactNode;
};

const Section = setup<SectionProps>((props) => {
  const section = aria('section', props);

  return () => (
    <section ref={section.ref} {...section.restProps(['children'])}>
      {props.children}
    </section>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type SectionProps = ComponentProps<'section'> & {
  label?: string;
  labelledby?: string;
};

const Section = setup<SectionProps>((props) => {
  const section = aria('section', props);

  return (
    <section ref={section.ref} {...section.restProps(['children'])}>
      {props.children}
    </section>
  );
});
```

:::

### Parameters

- `props.label` *(string, optional)*: Accessible label compiled to `aria-label`. Required for the landmark to be exposed.
- `props.labelledby` *(string, optional)*: Element ID providing the accessible name, compiled to `aria-labelledby`. Point it at the section's own heading rather than duplicating the text.
- `options.native` *(boolean, optional, default `false`)*: Inert for this role. The `region` role is compiled from the accessible name rather than from the host, so a named section gets `role="region"` either way.

### How it behaves

- With `label` or `labelledby` present, compiles `role="region"` together with the accessible name — explicitly, on native and custom hosts alike, because the HTML mapping only exposes a named `<section>` as a landmark.
- With neither present, compiles no role at all and the element stays a generic container. Clearing the name withdraws the role again, reactively.
- `section.named` reports whether the landmark is currently exposed, so a wrapper can branch on it.
- The role never depends on `native` or on the host tag: naming is the only gate.
- Structure only: no `tabindex`, no key handling, and no state. The content inside keeps its own semantics and controllers.
- `label` and `labelledby` are consumed by the controller and carried in `ownKeys`, so `restProps(['children'])` is the whole omission list — neither leaks to the DOM as a stray attribute.

:::tip[Prefer labelledby over label]
A section almost always has a visible heading. Point `labelledby` at that heading's `id` instead of repeating its text in `label`: the name stays in sync when the heading changes, and the visible text and the announced name cannot drift apart.
:::

## Keyboard Navigation

- **None.** The landmark takes no tab stop and claims no keys; the content inside it keeps its own keyboard behavior.

## What you get

- **Naming enforced by compilation.** No accessible name means no `role="region"`, keeping the landmark list free of anonymous entries.
- **A `named` projection.** `section.named` tells your wrapper whether the section was actually exposed.
- **Reactive promotion and demotion.** Adding or clearing the name adds or withdraws the role.
- **Native and custom hosts.** `<section>` and `<div>` both work, with the role compiled explicitly in either case when named.
- **Placement-stable output.** The compiled attributes are identical in SSR and after hydration, because nothing is read from the DOM.
