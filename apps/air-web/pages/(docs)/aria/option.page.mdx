# Headless Option

An option is one choice in a list somebody else drives. Getting it right means **deriving selected from the group instead of holding a private copy**, **staying out of the keyboard because the popup owns the arrows and the typeahead**, **moving the single tab stop to whichever option is on**, and **announcing the value sitting under the cursor**.

**Headless Option** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const option = aria('option', props);

<li ref={option.ref} {...option.restProps(['children'])} />
```

:::interactive[Currency Options]
```tsx
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type DemoListboxProps = ComponentProps<'ul'> & {
  label?: string;
  value?: string | string[];
  multiple?: boolean;
  disabled?: boolean;
};

const DemoListbox = setup<DemoListboxProps>((props) => {
  const box = aria('listbox', props);

  return () => (
    <ul ref={box.ref} {...box.restProps(['label', 'value', 'multiple', 'disabled', 'children'])} className="demo-option-list">
      {props.children}
    </ul>
  );
}, 'DemoListbox');

type DemoOptionProps = ComponentProps<'li'> & {
  value: string;
  selected?: boolean;
  disabled?: boolean;
  hint?: string;
};

const DemoOption = setup<DemoOptionProps>((props) => {
  const option = aria('option', props);

  return () => (
    <li ref={option.ref} {...option.restProps(['children', 'hint'])} className="demo-option">
      <span>{props.children}</span>
      <span className="demo-option-hint">{props.hint}</span>
    </li>
  );
}, 'DemoOption');
```

An option is a **member**, not a widget you drop on a page. Put them inside a [listbox](/docs/aria/listbox), a [select](/docs/aria/select), or a [combobox](/docs/aria/combobox): the container is what owns the arrows, the typeahead, and the one value every option is measured against.

## Option

**One row in the list.** It marks itself by matching the group's value against its own token.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'option',
  props: OptionProps,
  options?: OptionOptions
): OptionAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type OptionProps = ComponentProps<'li'> & {
  value: string;
  selected?: boolean;
  disabled?: boolean;
};

const Option = setup<OptionProps>((props) => {
  const option = aria('option', props);

  return () => (
    <li ref={option.ref} {...option.restProps(['children'])}>
      {props.children}
    </li>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';

  return (
    <li ref={option.ref} {...option.restProps(['children'])}>

  );
});
```

### Parameters

_What you pass in. The props object stays live — change a value on it and the option follows._

- **value** _Primitive, **required**_: The token this option stands for. **The group measures itself against it** — a single-select compares equality, a multi-select looks for it in the array.
- **selected** _boolean, optional_: A hint that this option is the one. Standalone it is the state; inside a group it only decides who claims a still-empty selection.
- **disabled** _boolean, optional_: Locks this option. The container's own `disabled` reaches every option the same way.
- **onchange** _(event: CustomEvent&lt;boolean&gt;) =&gt; void, optional_: Called when the selection changes. _Inside a group, `detail` carries the group's whole value instead._

### Options

_What you fix when you create it. Read once, never reactive._

- **native** _boolean, optional, default `false`_: Set `true` on a real `<option>` inside a `<select>`, where the `selected` property is synced and no `role`, `tabindex`, or `aria-selected` is added.
- **toggle** _boolean, optional, default `false`_: Lets a click on a **standalone** option invert its selection. Grouped options ignore it — the group's rules decide whether the slot can be emptied.

### Properties

_What you read or write on the instance afterwards._

- **selected** _boolean_: Whether this option is the one. **Read and write** — writing runs through the group's rules, so a required group can refuse the write.
- **value** _Primitive_: The token this option stands for.
- **disabled** _boolean_: Whether this option is locked, **including by the container**.
- **id** _string_: The option's own identifier — `option-<n>`, which is also the DOM id unless a group namespaces it.

### Methods

_What you call on the instance._

- **`select()`**: Takes the selection — the group's value becomes this token, or the array gains it. _Does nothing while disabled._
- **`deselect()`**: Gives the selection up. _Does nothing while disabled, or while the group requires a non-empty selection._
- **`toggle()`**: Selects or deselects. _A standalone option that isn't opted into `toggle` stays selected; a grouped option always follows the group._

### How it behaves

- **Selection is derived, not stored.** A single-select group marks this option when its value equals the token, a multi-select marks it when the array contains the token, and standalone it is `props.selected`. **One write to the group's value re-derives every option at once.**
- **The member owns no keystroke.** Nothing an option binds for itself reacts to `Space`, `Enter`, the arrows, `Home`/`End`, or typeahead — the popup is what reads the keyboard, and then activates the option under the cursor.
- **Re-activating the option on gives the slot back.** In an optional single-select group, activating the option that already holds it **empties the group**; a `required` group refuses and stays put. A multi-select group drops that token from the array and leaves the others alone. Standalone, activation only selects unless you opt into `toggle`.
- **The tab stop follows the choice.** `aria-selected="true"` comes with `tabindex="0"` and every other option gets `-1`, so focus comes back to the option that is on. A disabled option leaves the order entirely.
- **The cursor is announced.** Taking focus dispatches a `input` carrying this option's own token, which is how a popup echoes the highlighted value before anything is committed.
- **Disabled means inert.** A click is refused and the event itself is cancelled and stopped from bubbling — so nothing above the option reacts to a click on a locked row either.
- **A native `<option>` stays native.** `selected` is synced as a DOM property, `role`, `tabindex`, and `aria-selected` are left off, and the browser's own events are never replayed.
- **Linkage is shielded.** `id`, `aria-selected`, and `aria-disabled` can't be overwritten by a refiner of your own, and `value` is consumed, so it never lands on the element.

### Events

_What it tells you._

- **`change`** — fires when a commit by this option really moves the selection, with the group's whole value in `detail` when it is a member. A disabled option, a canceled click, and a write that changes nothing stay silent — emptying an optional slot counts as a real move, and fires.
- **`input`** — fires when this option **takes focus**, with its own token in `detail`.

```tsx
const option = aria('option', {
  value: 'eur',
  onchange: (event) => echoSelection(event.detail),
});
```

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### Option

```ts
interface OptionProps {
  value: Primitive;
  selected?: boolean;
  disabled?: boolean;
  onchange?: (event: CustomEvent<boolean>) => void;
}

interface OptionOptions {
  native?: boolean;
  toggle?: boolean;
}

interface OptionAttributes {
  id?: string;
  role?: 'option';
  selected?: boolean;
  disabled?: boolean;
  tabindex?: number;
  'aria-selected'?: 'true' | 'false';
  'aria-disabled'?: 'true' | 'false';
}

declare class OptionAria {
  id: string;
  get selected(): boolean;
  set selected(value: boolean);
  get disabled(): boolean;
  get value(): Primitive;

  select(): void;
  deselect(): void;
  toggle(): void;
}
```

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`attributes`** is the dictionary you spread; **`ref`** is what you bind the element with; **`props`** is the full props dictionary for spreading onto the host; **`restProps(omit)`** hands back your props with the keys you name left out.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
