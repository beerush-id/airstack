# Option

Native `<select>` elements cannot be easily styled across browsers, leading developers to construct custom dropdown menus, autocomplete pickers, and select lists using non-form elements such as `<li>` or `<div>`. Without accessible markup, assistive technologies cannot determine which item is selected, where focus is, or when an item is disabled.

`@airlib/aria` provides headless behavioral control for options. It compiles `role="option"`, projects `aria-selected` automatically from parent selection groups, handles standalone selection state, and coordinates focus without imposing markup or CSS.

You compose selectable items using this piece:

- **Option**: The selectable choice member that compiles `role="option"` and synchronizes its `aria-selected` state with an enclosing selection group or explicit selection prop.

## What you get

- **Automatic selection projection.** Automatically projects `aria-selected` based on whether its `value` matches the enclosing selection container.
- **Standalone and group support.** Works seamlessly inside an enclosing container or as a standalone controlled option via `selected`.
- **Disabled state coordination.** Reflects `aria-disabled` both from local disabled props and inherited container lockout.
- **Headless markup.** Compatible with `<li>`, `<div>`, or native `<option>` elements without layout constraints.

## Option

In Aria, Option is the selectable choice member created with `aria('option', props)` that manages selection projection and accessibility attributes for list and dropdown items.

```ts
aria<E extends BaseElement = HTMLElement, T extends Primitive = Primitive>(
  role: 'option',
  props: OptionProps<T>,
  options?: OptionOptions
): OptionAria<E>
```

### Parameters

- `props.value` *(Primitive, required)*: Choice candidate value matching the active selection of the enclosing group.
- `props.selected` *(boolean, optional)*: Explicit selection state when used standalone or uncontrolled outside a group.
- `props.disabled` *(boolean, optional)*: Disables the option, preventing selection and user interaction.
- `options.native` *(boolean, optional, default `false`)*: Set to `true` when binding to native `<option>` elements inside `<select>`.

### How it behaves

When bound to a custom element (`<li>` or `<div>`), Option compiles `role="option"` and dynamically manages `aria-selected`:
- **Inside Single-Selection Group**: Evaluates `group.value === props.value`.
- **Inside Multi-Selection Group**: Evaluates whether `props.value` is included in the group's selection array.
- **Standalone**: Evaluates `Boolean(props.selected)`.

Clicking the option activates it: in single-selection containers, it assigns the group value (or deselects if the group is optional); in multiple-selection containers, it toggles its value in the array. Disabled options ignore clicks and suppress selection changes.

:::tip[Enclosing Container]
Option is most powerful when placed inside an enclosing [Select](/docs/aria/select) composite, which provides roving focus, circular arrow navigation, and centralized selection state across all options.
:::

### Usage

To use Option, create the option instance with `aria('option', props)`, then pass `option.ref` and spread `option.attributes` onto your option element:

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type OptionProps = ComponentProps<'li'> & {
  value: string;
  selected?: boolean;
  disabled?: boolean;
};

const Option = setup<OptionProps>((props) => {
  const option = aria('option', props);
  const restProps = props.$omit([
    ...option.ownKeys,
    'value',
    'selected',
    'disabled',
    'children',
    'className',
  ]);

  return () => (
    <li ref={option.ref} {...restProps} {...option.attributes} className={props.className}>
      {props.children}
    </li>
  );
}, 'Option');
```

## Putting It Together

Once your component is wired with `aria('option', props)`, compose it inside a list or selection container:

```tsx
<ul>
  <Option value="us" selected={true}>
    <span>United States</span>
    <span>USD</span>
  </Option>
  <Option value="de">
    <span>Germany</span>
    <span>EUR</span>
  </Option>
  <Option value="jp" disabled={true}>
    <span>Japan</span>
    <span>Unavailable</span>
  </Option>
</ul>
```

## Keyboard Navigation

- **Tab**: Focuses into the option or moves to the next focusable page element when used standalone.
- **Space / Enter**: Selects the option when focused.
- **Arrow Keys**: When placed inside an enclosing composite like [Select](/docs/aria/select), arrow keys navigate through options under a single tab stop with circular roving focus.
