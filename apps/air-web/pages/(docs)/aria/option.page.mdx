# AirLib Headless Option

An option looks simple until you build a custom one: a native `<select>` resists cross-browser styling of its list, while custom `<li>` elements need hand-rolled `role`, roving tab stops, `aria-selected`, optional deselect, group membership sync, and — critically — no keyboard of their own, since traversal belongs to the popup. **AirLib Headless Option** (`aria('option')`) turns any element into an option that behaves — native `selected` sync on real options, full ARIA polyfills on custom hosts, single/multi derivation included, without dictating markup or styles.

```tsx
const option = aria('option', props);

<li ref={option.ref} {...option.props} />
```

type DemoOptionProps = ComponentProps<'li'> & {

## Option

Selectable choice member with native sync and group membership.

```ts
aria<E extends BaseElement = HTMLElement, T extends Primitive = Primitive>(
  role: 'option',
  props: OptionProps<T>,
  options?: OptionOptions
): OptionAria<E, OptionProps<T>>
```

### Usage

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type OptionProps = ComponentProps<'li'> & {
  value: string;
  selected?: boolean;
  disabled?: boolean;
};

const Option = setup<OptionProps>((props) => {
  const option = aria('option', props);

  return () => (
    <li ref={option.ref} {...option.restProps(['children'])}>
      {props.children}
    </li>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type OptionProps = ComponentProps<'li'> & {
  value: string;
  selected?: boolean;
  disabled?: boolean;
};

const Option = setup<OptionProps>((props) => {
  const option = aria('option', props);

  return (
    <li ref={option.ref} {...option.restProps(['children'])}>
      {props.children}
    </li>
  );
});
```

:::

The selected row comes from CSS keyed on `aria-selected` (see the style block above), never from controller state in JSX — the controller owns semantics, the stylesheet owns the highlight.

### Parameters

- `props.value` *(Primitive, required)*: Choice candidate value matching the active selection of the enclosing group.
- `props.selected` *(boolean, optional)*: Local selected hint in standalone mode; grouped options always derive from the ambient group value. A hint claims an empty registry.
- `props.disabled` *(boolean, optional)*: Blocks activation and state commits.
- `props.onchange` *(function, optional)*: Called with the selected state when the selection changes.
- `options.native` *(boolean, optional, default `false`)*: Pass `true` when binding native `<option>` elements inside a `<select>`.
- `options.toggle` *(boolean, optional, default `false`)*: Opt in to inverting a standalone selection on activation; without it standalone activation is select-only.

### How it behaves

- Single-selection derives `group.value === props.value`; multi-selection derives array membership; standalone derives `Boolean(props.selected)`. A `selected` hint claims an empty registry, and a `required` registry is claimed by the first member that mounts — idempotency alone never claims.
- Re-activating the holder of an optional single registry deselects (the slot clears); a `required` registry refuses. Multi registries toggle the token without duplicates. Standalone activation selects unless `toggle` opts into inversion.
- The member owns no keystroke: `Enter`, arrows, `Home`/`End`, letters, and full `Space` presses are all inert — traversal and typeahead belong to the enclosing popup.
- Native `<option>` hosts omit `role`, `tabindex`, and `aria-selected` and sync the `selected` IDL property instead; browser events are never re-dispatched. Custom hosts compile `role="option"`, `aria-selected`, roving `tabindex` (`0` active, `-1` otherwise), and always-explicit `aria-disabled`.
- `id`, `aria-selected`, and `aria-disabled` are shielded from consumer refiners, so container linkage addresses stay stable across activation. `value` joins `ownKeys` and never leaks to the DOM.
- Every real commit on a custom host fires a bubbling `change` event; canceled triggers, disabled hosts, and no-op mutations stay silent.
- The compiled dictionary carries no form attributes — selection state, not submission, is the contract.

:::tip[Popup Owns the Keyboard]
Options never bind arrow keys or typeahead themselves. Place them inside a [Select](/docs/aria/select) composite, which provides roving focus, circular arrow navigation, and centralized selection state across all options.
:::

## Putting It Together

Once your components are wired with `aria(...)`, compose them to build option lists with honest state:

```tsx
<DemoSelect value="us">
  <DemoOption value="us">United States</DemoOption>
  <DemoOption value="de">Germany</DemoOption>
  <DemoOption value="jp" disabled={true}>Japan</DemoOption>
</DemoSelect>
```

:::interactive[Option Interactive Demo]
```tsx
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type DemoSelectProps = ComponentProps<'ul'> & {
  value?: string;
  disabled?: boolean;
};

const DemoSelect = setup<DemoSelectProps>((props) => {
  const select = aria('select', props);

  return () => (
    <ul ref={select.ref} {...select.restProps(['value', 'disabled', 'children'])}>
      {props.children}
    </ul>
  );
}, 'DemoSelect');
```

## Keyboard Navigation

- **Tab**: Enters the list at the single tab stop (the active member). Members carry no tab stops of their own beyond the roving one.
- **Arrows / Home / End / typeahead**: Belong to the enclosing popup — members are inert to every keystroke by design.
- **Pointer**: Clicking a member selects (or deselects the holder of an optional registry, or toggles the token in multi registries).

## What you get

- **Native sync.** The `selected` property follows the registry on real options with no ARIA mirror and no re-dispatched events.
- **Custom element polyfills.** Role, roving tab stop, `aria-selected`, and pointer selection.
- **Honest registries.** Optional deselect, required refusal, duplicate-free multi-toggle, hint and required claiming.
- **Keyless members.** Zero keyboard ownership conflicts with popup traversal and typeahead.
- **Stable linkage.** Shielded addresses and announcements across activation and refiners.
