# Headless Menu

A menu is a command list behind a button, open only while it is being used.

Getting it right means **pairing the trigger, the panel, and the items through one root**, **carrying the popup contract on the trigger**, **roving the panel with the arrows and a typed prefix**, and **closing on `Escape` with focus back on the trigger**.

**Headless Menu** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const menu = aria('menu', props);

<div ref={menu.ref} {...menu.restProps(['children'])} />
```

:::interactive[Document Editor]
```tsx
import { aria } from '@airlib/aria';
import { setup, shadowPortal } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type DemoMenuProps = ComponentProps<'div'> & {
  open?: boolean;
  disabled?: boolean;
  label?: string;
};

const DemoMenu = setup<DemoMenuProps>((props) => {
  const menu = aria('menu', props);

  return () => (
    <div ref={menu.ref} {...menu.restProps(['children', 'label'])} className="demo-menu">
      {props.children}
    </div>
  );
}, 'DemoMenu');

type DemoMenuButtonProps = ComponentProps<'button'>;

const DemoMenuButton = setup<DemoMenuButtonProps>((props) => {
  const button = aria('menu-button', props);

  return () => (
    <button ref={button.ref} {...button.restProps(['children'])} className="demo-menu-button">
      {props.children}
      <span className="demo-menu-caret" />
    </button>
  );
}, 'DemoMenuButton');

type DemoMenuPanelProps = ComponentProps<'div'> & {
  label?: string;
  children: ReactNode;
};

const DemoMenuPanel = setup<DemoMenuPanelProps>((props) => {
  const panel = aria('menu-panel', props);
  const shadow = shadowPortal(() => panel.open);

  return () => shadow(
    <div ref={panel.ref} {...panel.restProps(['children'])} className="demo-menu-panel">
      {props.children}
    </div>
  );
}, 'DemoMenuPanel');

  name: string;
  disabled?: boolean;
  children: ReactNode;
};

const DemoMenuItem = setup<DemoMenuItemProps>((props) => {
  const item = aria('menu-item', props);

  return () => (
    <button ref={item.ref} {...item.restProps(['children'])} className="demo-menu-item">
      {props.children}
    </button>
  );
}, 'DemoMenuItem');

type DemoMenuItemCheckboxProps = ComponentProps<'button'> & {
  name: string;
  checked?: boolean | 'mixed';
  children: ReactNode;
};

const DemoMenuItemCheckbox = setup<DemoMenuItemCheckboxProps>((props) => {

      {props.children}
    </button>
  );

  label: string;
  value?: string;
  children: ReactNode;
};

const DemoMenuGroup = setup<DemoMenuGroupProps>((props) => {
  const group = aria('menu-item-group', props);

  return () => (
    <div ref={group.ref} {...group.restProps(['children'])} className="demo-menu-group">
      <span className="demo-menu-group-label">{props.label}</span>
      {props.children}
    </div>
  );
}, 'DemoMenuGroup');

type DemoMenuItemRadioProps = ComponentProps<'button'> & {
  value: string;
  children: ReactNode;
};

const DemoMenuItemRadio = setup<DemoMenuItemRadioProps>((props) => {
  const radio = aria('menu-item-radio', props);

    </button>
  );
}, 'DemoMenuItemRadio');
```

:::tip
**Traversal never runs a command.** Move through the items with the arrows or a typed prefix, then press `Enter`, `Space`, or click once to invoke the focused item — and `Escape` closes without invoking anything.

## Menu

**The root.** It owns the popup's visibility and pairs the trigger, the panel, and the items through ambient context.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'menu',
  props?: MenuProps
): MenuAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type MenuProps = ComponentProps<'div'> & {
  id?: string;
  open?: boolean;
  disabled?: boolean;
  onopen?: (event: CustomEvent<true>) => void;
  onclose?: (event: CustomEvent<false>) => void;
  oncommand?: (event: CustomEvent<string>) => void;
};

const Menu = setup<MenuProps>((props) => {
  const menu = aria('menu', props);

  return () => (
    <div ref={menu.ref} {...menu.restProps(['children'])}>
      {props.children}
    </div>
  );
}, 'Menu');
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type MenuProps = ComponentProps<'div'> & {
  id?: string;
  open?: boolean;
  disabled?: boolean;
  onopen?: (event: CustomEvent<true>) => void;
  onclose?: (event: CustomEvent<false>) => void;
  oncommand?: (event: CustomEvent<string>) => void;
};

const Menu = setup<MenuProps>((props) => {
  const menu = aria('menu', props);

  return (
    <div ref={menu.ref} {...menu.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **id** _string, optional_: The identifier the pair is scoped to, generated as `menu-<n>` when you leave it out. The panel derives its own from it.
- **label** _string, optional_: The menu's accessible name. **Pass it on the root**: the root and its panel share one props object, so the panel compiles it as `aria-label`. It is absent from `MenuProps`, so `restProps` will not strip it — omit it there if you don't want it on the host.
- **open** _boolean, optional_: Popup visibility. **Writing it through `menu.open` is the only way to open or close from your code.**
- **disabled** _boolean, optional_: Locks the whole tree — the trigger refuses to open and every item refuses to invoke.
- **onopen** _(event: CustomEvent&lt;true&gt;) =&gt; void, optional_: Called after the panel opens.
- **onclose** _(event: CustomEvent&lt;false&gt;) =&gt; void, optional_: Called after it closes, through every dismissal path.
- **oncommand** _(event: CustomEvent&lt;string&gt;) =&gt; void, optional_: Receives every item command that bubbles up, with the item's `name` in `detail`.

### Properties

_What you read or write on the instance afterwards._

- **id** _string_: The identifier in force, generated when you left it out.
- **open** _boolean_: The popup's visibility. **Writing it flips the panel and dispatches no event.**
- **panelId** _string_: The panel's derived identifier, the value the trigger points `aria-controls` at.
- **triggerId** _string_: The trigger's derived identifier.
- **disabled** _boolean_: Whether the whole tree is locked.

### Methods

_What you call on the instance._

- **`button(props?, options?)`** → `MenuButtonAria`: Creates a trigger belonging to this root.
- **`panel(props?)`** → `MenuPanelAria`: Creates a panel belonging to this root.
- **`isSubmenu()`** → `boolean`: Whether this root sits inside another menu.

### How it behaves

- **One root, three parts.** The trigger, the panel, and the items find the root through ambient context, so none of them takes a cross-reference prop.
- **Visibility has one owner.** The trigger writes `open` and nothing else, so the click, `Escape`, an outside press, and an item command all land on the same value.
- **A command closes the menu.** An item's `command` reaches `oncommand` and the root closes the panel on the same activation.
- **Disabling cascades.** `disabled` on the root refuses the trigger and every item, and the lock lifts cleanly when you clear it.
- **It compiles no role.** The root is an ordinary container; the semantics live on the panel and the items.
- **A nested root is a submenu.** A menu created inside another menu's panel recognizes the enclosing root, reports `isSubmenu()`, and nests its identifiers.

### Events

_What it tells you._

- **`open`** _CustomEvent&lt;true&gt;_: Fires after the panel opens.
- **`close`** _CustomEvent&lt;false&gt;_: Fires after it closes, through every dismissal path.
- **`command`** _CustomEvent&lt;string&gt;_: Fires when an item invokes, with that item's `name` in `detail`.

```tsx
const menu = aria('menu', {
  oncommand: (event) => run(event.detail),
  onclose: () => hint.show(),
});
```

## Menu Button

**The trigger.** It carries the popup contract and opens the panel.

### Usage

```ts

  options?: MenuButtonOptions

```

```tsx [React]
  disabled?: boolean;

    </button>
```

:::

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **disabled** _boolean, optional_: Refuses this trigger. The root's `disabled` applies on top of it.

### Options

_What you fix when you create it. Read once, never reactive._

- **native** _boolean, optional, default `true`_: Declares the host. A native `<button>` gets `type="button"` and the browser's own `Enter` and `Space`; a custom host compiles a tab stop and `aria-disabled` instead.

### Properties

_What you read or write on the instance afterwards._

- **disabled** _boolean_: Whether the trigger refuses to open, including the root's lock.

### How it behaves

- **It carries the popup contract.** `aria-haspopup="menu"`, `aria-expanded` following the panel, `aria-controls` pointing at the panel, and a derived identifier.
- **A native `<button>` gets `type="button"`**, so opening the menu never submits the form around it.
- **No menu role is compiled.** The role lives on the panel, so the trigger stays a button.
- **A click opens it, and so does `ArrowDown`.** On a native `<button>` the browser turns `Enter` and `Space` into that click; a custom host compiles a tab stop and leaves the activation to you.
- **Disabled closes the way in.** The root's lock or the trigger's own refuses every opening gesture on either host.

## Menu Panel

**The popup.** It carries the menu role, roves across the items, and dismisses itself.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'menu-panel',
  props?: MenuPanelProps
): MenuPanelAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';

import type { ComponentProps, ReactNode } from 'react';

type MenuPanelProps = ComponentProps<'div'> & {
  children: ReactNode;
};

  const panel = aria('menu-panel', props);
  const shadow = shadowPortal(() => panel.open);

  return () => shadow(
    <div ref={panel.ref} {...panel.restProps(['children'])}>
      {props.children}
    </div>
  );
}, 'MenuPanel');
```

```tsx [SolidJS]

import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type MenuPanelProps = ComponentProps<'div'>;

  const panel = aria('menu-panel', props);

  return (
    <div ref={panel.ref} {...panel.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Properties

_What you read or write on the instance afterwards._

- **id** _string | undefined_: The identifier in force, derived from the root.
- **open** _boolean_: The root's visibility, read through the panel.
- **popup** _PopoverAria_: The overlay that dismisses the panel and places focus.

### How it behaves

- **It roves like the listbox it is built on.** The arrows, `Home`/`End`, a typed prefix, and `Enter`/`Space` activation work over all three item roles.
- **The panel is a stop of its own.** Command items sit at `-1`, while a checkbox item and the checked radio item compile their own `0` — so `Tab` reaches the panel and then those items.
- **Its name comes from the root.** The panel takes the root's props through context, so a `label` passed to the panel itself is not read.
- **It dismisses itself.** `Escape` and a press outside close it, and focus returns to the trigger.
- **Visibility belongs to the root.** The panel reads and writes the root's `open` and holds no state of its own.
- **It is always vertical.** `aria-orientation="vertical"` is compiled whatever the layout looks like.
- **Mounting and positioning stay with you.** The panel reports visibility; where it is portaled and how it is placed are yours.

### Navigation

_What the keys do._

- **`ArrowDown` / `ArrowUp`** — the next / previous enabled item, wrapping at both ends.
- **`Home` / `End`** — the first / last enabled item.
- **Printable character** — the next enabled item whose text begins with the typed prefix.
- **`Enter` / `Space`** — activates the focused item.
- **`Escape`** — closes the panel and returns focus to the trigger.
- **`Tab`** — leaves the panel, stopping on each checkbox item and on the checked radio item first.

## Menu Item

**The command.** It invokes its `name` and closes the menu.

### Usage

```ts

  role: 'menu-item',
  props?: MenuItemProps,
  options?: MenuItemOptions
```

```tsx [SolidJS]
  const item = aria('menu-item', props);

  return (
    <button ref={item.ref} {...item.restProps(['children'])}>
      {props.children}
    </button>
  );

```

:::

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **name** _string, optional_: The identifier the command carries, and the only identity the item has.
- **disabled** _boolean, optional_: Refuses this item. The root's `disabled` applies on top of it.
- **oncommand** _(event: CustomEvent&lt;string&gt;) =&gt; void, optional_: Called on this item's own activation, with its `name` in `detail`.

### Options

_What you fix when you create it. Read once, never reactive._

- **native** _boolean, optional, default `true`_: Declares the host. A native `<button>` answers a click alone; a custom host gets `Space` and `Enter`.

### How it behaves

- **Activation invokes and closes.** A click, `Enter`, or `Space` dispatches `command` with the item's `name` and closes the panel.
- **Both hosts activate.** A native `<button>` answers a click; a custom host adds `Space` and `Enter`.
- **It compiles `role="menuitem"` and stays out of the tab order.** Every item sits at `-1`; the panel holds the stop.
- **Focus announces the item.** Landing on it dispatches `input` with its `name`, so a consumer can follow the cursor without committing.
- **Disabled refuses without hiding.** The item stays in the list, skipped by traversal and inert to activation.

### Events

_What it tells you._

- **`input`** _CustomEvent&lt;string&gt;_: Fires when focus lands on the item — an arrow, `Home`/`End`, or a typed prefix — with its `name` in `detail`.
- **`command`** _CustomEvent&lt;string&gt;_: Fires when the item activates, with its `name` in `detail`. **Bubbles to the root `oncommand`.**

:::

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **checked** _boolean, optional, default `false`_: The toggle state.
- **indeterminate** _boolean, optional_: The mixed state, compiled as `aria-checked="mixed"`.
- **disabled** _boolean, optional_: Refuses this item. The root's `disabled` applies on top of it.
- **name** _string, optional_: Identity carried for form-style consumers.
- **oninput** _(event: CustomEvent&lt;boolean&gt;) =&gt; void, optional_: Called with the new state as the activation lands. A native host leaves `input` to the browser.
- **onchange** _(event: CustomEvent&lt;boolean&gt;) =&gt; void, optional_: Called with the committed state after each activation.

### Options

_What you fix when you create it. Read once, never reactive._

- **native** _boolean, optional, default `false`_: Declares the host as a custom one, so `Space` and `Enter` are polyfilled on it and the item dispatches its own `input`.

### Properties

_What you read or write on the instance afterwards._

- **checked** _boolean_: The toggle state. Writing it moves the item.
- **indeterminate** _boolean_: The mixed state. **Activation from mixed commits `true` rather than inverting.**

### How it behaves

- **It compiles `role="menuitemcheckbox"`** with `aria-checked` carrying `true`, `false`, or `mixed` on either host.
- **No `type` is compiled.** Pass `type="button"` on a native host inside a form, so activating the item never submits it.
- **Activation toggles in place.** The panel stays open, so a run of toggles is one visit to the menu.
- **Mixed resolves to checked.** The first activation from `indeterminate` commits `true`.
- **It never coordinates with siblings.** The state lives on its own props.
- **Disabled refuses without hiding.**

### Events

_What it tells you._

- **`change`** _CustomEvent&lt;boolean&gt;_: Fires after activation with the committed state in `detail`. The menu stays open.

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **value** _string, optional_: The candidate this item stands for, compared with the enclosing group's value. An item without one never matches, so pass it.
- **disabled** _boolean, optional_: Refuses this item. The root's `disabled` applies on top of it.

### Options

_What you fix when you create it. Read once, never reactive._

- **native** _boolean, optional, default `false`_: Declares the host as a custom one, so `Space` and `Enter` are polyfilled on it.

### How it behaves

- **The group owns the value.** Inside a menu group the item is checked when the group's value equals its own, and selecting it writes that value.
- **Select-only.** Activating the item that already holds the value changes nothing and fires no event.
- **It compiles `role="menuitemradio"`** with `aria-checked` `true` on the match and `false` otherwise, and no `type` — pass `type="button"` on a native host inside a form.
- **The menu stays open.** A selection is a setting, not a command.
- **Without an enclosing group it holds its own `checked`.**

### Events

_What it tells you._

- **`change`** _CustomEvent&lt;boolean&gt;_: Fires when the selection changes.

```tsx [React]
    <div ref={group.ref} {...group.restProps(['children'])}>
      {props.children}
    </div>
  );
}, 'MenuItemGroup');
```

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **label** _string, optional_: The name screen readers announce for the section.
- **labelledby** _string, optional_: The ID of an element already on the page that provides that name.
- **value** _string, optional_: The checked value the radios inside are measured against.

### How it behaves

- **It scopes the radios inside it.** A radio is checked when this value matches, and selecting one writes this value.
- **Sibling groups stay independent.** Selecting inside one group leaves the others untouched.
- **It compiles `role="group"`** with its accessible name.
- **It is structural.** Traversal stays with the panel and the items stay at `-1`.

## Menu Bar

**The bar.** It holds several menus at one tab stop and moves across them with the left and right arrows.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'menu-bar',
  props?: MenubarProps
): MenubarAria<E>
```

:::code-group

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **label** _string, optional_: The name screen readers announce for the bar.
- **labelledby** _string, optional_: The ID of an element already on the page that provides that name.
- **disabled** _boolean, optional_: Refuses the bar's own roving keys. It does not reach the triggers inside it.

### How it behaves

- **It compiles `role="menubar"`** with `aria-orientation="horizontal"` and its accessible name.
- **One tab stop for the whole bar.** The arrows move between the triggers inside it.
- **The arrows never open a menu.** They move focus; opening stays with each trigger's own gesture.
- **Its disablement is its own.** `disabled` refuses the bar's roving keys while the controls inside keep their own state.

### Navigation

_What the keys do._

- **`ArrowRight` / `ArrowLeft`** — the next / previous control in the bar, wrapping at both ends.
- **`Home` / `End`** — the first / last control in the bar.

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`attributes`** is the dictionary you spread; **`ref`** is what you bind the element with; **`props`** is the full props dictionary for spreading onto the host; **`restProps(omit)`** hands back your props with the keys you name left out.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
