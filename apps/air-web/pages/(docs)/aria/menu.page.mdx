# AirLib Headless Menu

An application menu is a command list behind a button: closed it shows nothing, open it offers every action. Hand-rolled markup gets you half there — a trigger that never announces its popup, arrow keys that scroll the document instead of moving across items, focus lost to the void on dismiss, and checkable rows no assistive technology hears about. **AirLib Headless Menu** (`aria('menu')`) is a role-less root orchestrating a trigger button, a popup menu panel, and action, checkbox, and radio members: toggling plus `Enter`/`Space` activation on the trigger, delegated dismissal and focus restoration, single-tab-stop roving with typeahead in the panel, standalone toggles and group-scoped radios, and item commands bubbling to the root — without dictating markup or styles.

```tsx
const menu = aria('menu', props);

<div ref={menu.ref} {...menu.restProps(['children'])} />
```

## Menu

Role-less root orchestrator owning the popup visibility, publishing ambient context for the trigger, the panel, and the items.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'menu',
  props?: MenuProps
): MenuAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type MenuProps = ComponentProps<'div'> & {
  open?: boolean;
  disabled?: boolean;
  delay?: number;
  oncommand?: (event: MenuCommandEvent) => void;
  onopen?: () => void;
  onclose?: () => void;
};

const Menu = setup<MenuProps>((props) => {
  const menu = aria('menu', props);

  return () => (
    <div ref={menu.ref} {...menu.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type MenuProps = ComponentProps<'div'> & {
  open?: boolean;
  disabled?: boolean;
  delay?: number;
  oncommand?: (event: MenuCommandEvent) => void;
  onopen?: () => void;
  onclose?: () => void;
};

const Menu = setup<MenuProps>((props) => {
  const menu = aria('menu', props);

  return (
    <div ref={menu.ref} {...menu.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

- `props.id` *(string, optional)*: Scopes the identifier namespace for the pair (auto-generated as `menu-<n>` when omitted); the panel derives `{id}-menu`.
- `props.open` *(boolean, optional)*: Popup visibility flag, readable and writable through `menu.open`.
- `props.disabled` *(boolean, optional)*: Locks the whole tree — the trigger refuses activation and every item refuses invocation and leaves keyboard roving.
- `props.delay` *(number, optional, default `150`)*: Pointer-hover transition delay in ms, forwarded to the panel's internal popover.
- `props.oncommand` *(handler, optional)*: Receives every item `command` as it bubbles to the root, carrying the acting item's `name` as detail.
- `props.onopen` / `props.onclose` *(handlers, optional)*: Called when the popup opens or closes.

### How it behaves

- Compiles no `role` — the root is a non-semantic container.
- The pair scopes one trigger and one panel under a shared ID namespace. Activating the trigger toggles `open`, projecting `aria-expanded` and linking `aria-controls` to the panel.
- A programmatic write (`menu.open = true` or `props.open = true`) flips visibility but dispatches nothing on its own: visibility events come from the popup lifecycle.

:::tip[Multiple Paths]
You can coordinate the trigger and the panel through ambient context inside a menu wrapper, or instantiate them directly from the controller instance:
```ts
const menu = aria('menu', { id: 'file-menu' });
const trigger = menu.button();
const panel = menu.panel({ label: 'File actions' });
```
:::

## Submenus

A `menu` created inside another menu is a submenu — no separate parts exist. It keeps its own `open` state and panel namespace while keyboard roving defers to the parent container.

```tsx
const submenu = aria('menu', {});

submenu.isSubmenu(); // true inside an enclosing menu, false at the top level
```

## Menu Button

Popup trigger compiling the menu face and toggling the panel. Claims itself as the popover anchor.

```ts
aria<E extends BaseElement = HTMLButtonElement>(
  role: 'menu-button',
  props?: MenuTriggerProps,
  options?: MenuTriggerOptions
): MenuButtonAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type MenuButtonProps = ComponentProps<'button'> & {
  disabled?: boolean;
};

const MenuButton = setup<MenuButtonProps>((props) => {
  const button = aria('menu-button', props);

  return () => (
    <button ref={button.ref} {...button.restProps(['children'])}>
      {props.children}
    </button>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type MenuButtonProps = ComponentProps<'button'> & {
  disabled?: boolean;
};

const MenuButton = setup<MenuButtonProps>((props) => {
  const button = aria('menu-button', props);

  return (
    <button ref={button.ref} {...button.restProps(['children'])}>
      {props.children}
    </button>
  );
});
```

:::

### Parameters

- `props.id` *(string, optional)*: DOM element identifier.
- `props.disabled` *(boolean, optional)*: Disables this trigger. Menu-level disablement applies too.
- `options.native` *(boolean, optional, default `true`)*: Set to `false` on non-button elements to attach `Space` and `Enter` key handlers.

### How it behaves

- Projects `aria-haspopup="menu"`, `aria-expanded` tracking the popup, and `aria-controls` pointing at the panel id. No `role` is emitted — the menu role lives on the panel.
- Click, `Enter`, and `Space` toggle the popup.
- Without a root the button stays closed and inert.
- A disabled trigger refuses toggling on a native `<button>` (real `disabled`) and on custom hosts.

## Menu Panel

Popup menu container inheriting listbox mechanics, always vertical, with dismissal and focus return delegated to an internal popover.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'menu-panel',
  props?: MenuPanelProps
): MenuPanelAria<E>
```

The panel adopts the menu's ambient context and proxies `open`, `onopen`, and `onclose` to and from the internal popover. The popover owns light dismissal and focus return; it never mounts, hides, or positions DOM.

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup, shadowPortal } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type MenuPanelProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
  children: ReactNode;
};

const MenuPanel = setup<MenuPanelProps>((props) => {
  const panel = aria('menu-panel', props);
  const shadow = shadowPortal(() => panel.open);

  return () => shadow(
    <div ref={panel.ref} {...panel.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type MenuPanelProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
};

const MenuPanel = setup<MenuPanelProps>((props) => {
  const panel = aria('menu-panel', props);

  return (
    <div ref={panel.ref} {...panel.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

- `props.id` *(string, optional)*: Explicit element identifier (overrides the derived `{root-id}-menu` pair id).
- `props.label` *(string, optional)*: Accessible name announced for the menu.
- `props.labelledby` *(string, optional)*: Element ID providing the accessible name.

### How it behaves

- Compiles `role="menu"` with `aria-orientation="vertical"` and holds the panel id the trigger's `aria-controls` points at.
- Holds a single tab stop in sequential navigation, managing roving focus across enabled items.
- Traversal moves focus and commits nothing; activation commits through the item's own rules.
- Outside click and `Escape` dismiss through the internal popover and return focus to the button. Mounting, hiding, and positioning the panel stay with the consumer.

:::note[DOM Visibility]
`@airlib/aria` manages accessibility attributes and keyboard focus, not DOM visibility. Control panel visibility (`{menu.open && <MenuPanel />}` or CSS popover styles) in your application layer.
:::

## Menu Item

Command action item invoking its `name` on activation.

```ts
aria<E extends BaseElement = HTMLButtonElement>(
  role: 'menu-item',
  props?: MenuItemProps,
  options?: MenuItemOptions
): MenuItemAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type MenuItemProps = ComponentProps<'button'> & {
  name: string;
  disabled?: boolean;
  oncommand?: (event: MenuCommandEvent) => void;
  children: ReactNode;
};

const MenuItem = setup<MenuItemProps>((props) => {
  const item = aria('menu-item', props);

  return () => (
    <button ref={item.ref} {...item.restProps(['children'])}>
      {props.children}
    </button>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type MenuItemProps = ComponentProps<'button'> & {
  name: string;
  disabled?: boolean;
  oncommand?: (event: MenuCommandEvent) => void;
};

const MenuItem = setup<MenuItemProps>((props) => {
  const item = aria('menu-item', props);

  return (
    <button ref={item.ref} {...item.restProps(['children'])}>
      {props.children}
    </button>
  );
});
```

:::

### Parameters

- `props.name` *(string, optional)*: Semantic identifier carried as the `command` event detail.
- `props.disabled` *(boolean, optional)*: Disables this item. Menu-level disablement applies too.
- `props.oncommand` *(handler, optional)*: Item-level command listener invoked with the item's `name`.
- `options.native` *(boolean, optional, default `true`)*: Set to `false` on non-button elements to attach `Space` and `Enter` key handlers.

### How it behaves

- Compiles `role="menuitem"` and participates in the panel's roving tabindex. Inherits action activation from the button controller.
- Invoking dispatches `command` carrying its `name`, which bubbles to the root `oncommand`, and closes the menu.
- An effectively disabled item is locked out of activation and skipped by roving.

- `props.onchange` *(handler, optional)*: Called with the committed boolean — never the item name.
- `options.native` *(boolean, optional, default `false`)*: Set to `true` only for native checkbox hosts.

### How it behaves

- Compiles `role="menuitemcheckbox"` with `aria-checked` (`"true"` | `"false"` | `"mixed"`) on both native and custom hosts.
- Toggling dispatches `change` carrying the committed boolean and keeps the menu open.

## Menu Group

Labelled section scoping mutually exclusive radio selection strictly to its own members.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'menu-item-group',
  props?: MenuItemGroupProps
): MenuGroupAria<E>
```

Only the group publishes its own `selectionGroup` context — the menu root publishes none since it owns no `value`.

```tsx [React]
  );

```

```tsx [SolidJS]

    <div ref={group.ref} {...group.restProps(['children'])}>
```

:::

### Parameters

- `props.label` *(string, optional)*: Accessible name announced for the section.
- `props.labelledby` *(string, optional)*: Element ID providing the accessible name.
- `props.value` *(Primitive, optional)*: Scoped radio value — child radios are active when `group.value === props.value`.

### How it behaves

- Compiles `role="group"` with the accessible name.
- Sibling groups stay independent: selecting in one never disturbs another.

## Menubar

Top-level horizontal bar coordinating roving focus across menus. Inherits single-tab-stop roving from the toolbar controller and always navigates horizontally.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'menu-bar',
  props?: MenubarProps
): MenubarAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type MenubarProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
  children: ReactNode;
};
```

### Parameters

- `props.label` *(string, optional)*: Accessible name announced for the bar.
- `props.labelledby` *(string, optional)*: Element ID providing the accessible name.

### How it behaves

- Compiles `role="menubar"` with `aria-orientation="horizontal"` — orientation is locked, never configurable.
- `ArrowRight` / `ArrowLeft` move across top-level menus, wrapping at the ends; `Home` / `End` jump to the boundaries. Arrows move focus only and never activate.

## Events

| Event | Authored by | Trigger | `detail` |
| :--- | :--- | :--- | :--- |
| `input` | The item taking the cursor | Focus landed on it — arrows, `Home`/`End`, typeahead | That item's `name` |
| `command` | The menu item | Activation invoked it | The item's `name`; bubbles to the root `oncommand` and closes the menu |
| `change` | The checkbox item | Toggle committed | The committed boolean — the menu stays open |
| `change` | The radio item | Selection committed | The committed group value |
| `open` / `onopen` | The popup | The panel opened | The open state |
| `close` / `onclose` | The popup | The panel closed | The open state |

```tsx
const menu = aria('menu', {
  oncommand: (event) => save(event.detail),
  onopen: () => hideHint(),
  onclose: () => restoreHint(),
});
```

A programmatic write (`menu.open = true` or `props.open = true`) flips visibility but dispatches nothing: an external write is neither an opening gesture nor a commit, because nobody acted. A checkable or selectable item never reports a name in place of the state it inherits.

## Keyboard Navigation

| Key | Behavior |
| :--- | :--- |
| `Click` / `Enter` / `Space` on the button | Toggles the popup. |
| `ArrowDown` / `ArrowUp` in the panel | Roves across enabled items without activating. |
| `Home` / `End` in the panel | Jumps to the first / last enabled item. |
| Printable characters in the panel | Typeahead — moves focus to the item matching the rendered text. |
| `Enter` / `Space` on an item | Invokes the focused item. |
| `ArrowRight` / `ArrowLeft` in a menubar | Moves across top-level menus without activating. |
| `Escape` | Closes without invoking and restores focus to the button. |
| `Tab` | Exits the menu completely — the whole menu is one tab stop. |

## What you get

- **One tab stop.** The entire menu acts as one stop in the page flow; arrow keys move focus across items without trapping `Tab`.
- **Focus separated from activation.** Moving focus never executes an action and forwards `input` with the cursor name; only activation commits.
- **Commands bubble to one listener.** Items dispatch `command` with their `name`; the root `oncommand` hears every one, so consumers listen on the item, the menu, or both.
- **Independent toggles, scoped radios.** Checkbox items keep state on their own props (`'mixed'` survives until their own activation); radio items synchronize exclusively within their group.
- **Submenus without submenu parts.** A nested `menu` root reports `isSubmenu()` and keeps its own `open` state.
- **Zero markup lock-in.** Native `<button>` or custom hosts, any panel element, rich item rows.
