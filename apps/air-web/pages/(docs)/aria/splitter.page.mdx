# Headless Splitter

A pane boundary looks like a thin handle until the platform gets involved.

Getting it right means **stepping the position with four arrow keys while leaving every other key to the page**, **tracking a pointer drag outside the handle until release**, **clamping every write inside the declared bounds**, **announcing the position against real minimums and maximums**, and **keeping the allocation while leaving the tab order when locked**.

**Headless Splitter** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const partition = aria('splitter', props);

<div ref={partition.ref} {...partition.restProps(['children'])} />
```

:::interactive[Preview Layout]
```tsx
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type DemoSplitterProps = ComponentProps<'div'> & {
  label?: string;
  value?: number;
  min?: number;
  max?: number;
  step?: number;
  orientation?: 'horizontal' | 'vertical';
  disabled?: boolean;
};

const DemoSplitter = setup<DemoSplitterProps>((props) => {
  const partition = aria('splitter', props);

  return () => (
    <div className="demo-splitter" style={{ '--aria-splitter-offset': `${partition.offset}%` } as never}>
      <div className="demo-splitter-pane demo-splitter-pane-first">
        <span>Canvas</span>
      </div>
      <div
        ref={partition.ref}
        {...partition.restProps(['children', 'label'])}
        className="demo-splitter-grip"
      />
      <div className="demo-splitter-pane demo-splitter-pane-second">
        <span>Inspector</span>
      </div>
    </div>
  );
}, 'DemoSplitter');
```

## Splitter

**The movable partition.** It holds the position against real bounds, follows a pointer drag, and steps with the arrows.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'splitter',
  props?: SplitterProps,
  options?: SplitterOptions
): SplitterAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type SplitterProps = ComponentProps<'div'> & {

  value?: number;
  min?: number;
  max?: number;
  step?: number;
  orientation?: 'horizontal' | 'vertical';
  disabled?: boolean;
```

### Parameters

_What you pass in. The props object stays live — change a bound and every later move is measured against it._

- **value** _number, optional_: The partition position in percentage points, committed clamped to `min` and `max`. Missing, it falls back to `min`.
- **min** _number, optional, default `0`_: The lower bound, both for the position and for the announced minimum.
- **max** _number, optional, default `100`_: The upper bound, both for the position and for the announced maximum.
- **step** _number, optional, default `1`_: How far one arrow keystroke travels.
- **orientation** _'horizontal' | 'vertical', optional, default `'horizontal'`_: The axis the separator announces **and the axis a drag is measured along**. Column layouts need `'vertical'`, or a sideways drag moves nothing.
- **disabled** _boolean, optional_: Refuses keys and drags, parks the handle at `tabindex="-1"`, and leaves the allocation where it is.
- **label** _string, optional_: The name the handle is announced by, compiled to `aria-label`.
- **oninput** _(event: CustomEvent&lt;number&gt;) =&gt; void, optional_: Called with the committed position after every key step and every drag move.
- **onchange** _(event: CustomEvent&lt;number&gt;) =&gt; void, optional_: Called with the committed position when the interaction ends.

### Properties

_What you read or write on the instance afterwards._

- **value** _number_: The position with the bounds applied. Writing it clamps instead of rejecting.
- **min** _number_: The lower bound in use.
- **max** _number_: The upper bound in use.
- **step** _number_: The arrow increment in use.
- **disabled** _boolean_: Whether resizing is blocked.
- **offset** _number_: The position as a percentage of the declared span, published as `--aria-splitter-offset`. A range with no span reads `0`.
- **orientation** _'horizontal' | 'vertical'_: The axis the separator announces.

### How it behaves

- **The handle is a separator.** It compiles `role="separator"`, `tabindex="0"` (or `-1` while disabled), the announced value, minimum, maximum, and the orientation, plus `aria-disabled` on both states.
- **A pointer drag follows the parent area.** Tracking starts on the handle and continues outside it until release or cancellation, reading against the parent's box on the announced axis. Drags are continuous, never snapped to `step`.
- **Every write lands inside the bounds.** Keys hold at `min` and `max` instead of overshooting, and a write through `value` is clamped the same way.
- **`input` for every commit, `change` when the gesture moved.** A drag dispatches `input` per move and `change` on release only if the position moved from the drag start; a press that commits nothing stays silent.
- **Disabled keeps the allocation.** Keys and drags are refused, a mid-drag lock ends tracking at the last committed position, and the handle leaves the tab order.

### Events

_What it tells you._

- **`input`** — the committed position, after each key step and each drag move, in `detail`.
- **`change`** — the committed position once the interaction ends, in `detail`. A press that commits nothing is silent.

```tsx
const partition = aria('splitter', {
  value: 50,
  oninput: (event) => track(event.detail),
  onchange: (event) => save(event.detail),
});
```

### Navigation

_What the keys do._

- **`ArrowRight` / `ArrowDown`** — advance the partition by `step`, holding at `max`.
- **`ArrowLeft` / `ArrowUp`** — retreat by `step`, holding at `min`.
- **`Tab`** — focus the handle, or step over it while disabled.
- **Every other key** — left to the browser, including `PageUp` / `PageDown` and `Home` / `End`.

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### Splitter

```ts
interface SplitterProps {
  value?: number;
  min?: number;
  max?: number;
  step?: number;
  disabled?: boolean;
  label?: string;
  oninput?: (event: CustomEvent<number>) => void;
  onchange?: (event: CustomEvent<number>) => void;
}

interface SplitterOptions {
  native?: boolean;
}

interface SplitterAttributes {
  role?: 'separator';
  tabindex?: number;
  'aria-orientation'?: 'horizontal' | 'vertical';
  'aria-valuenow'?: number;
  'aria-valuemin'?: number;
  'aria-valuemax'?: number;
  'aria-label'?: string;
  'aria-disabled'?: 'true' | 'false';
  style?: { '--aria-splitter-offset': string };
}

declare class SplitterAria {
  get value(): number;
  set value(next: number);
  get min(): number;
  get max(): number;
  get step(): number;
  get disabled(): boolean;
  get offset(): number;
  get orientation(): 'horizontal' | 'vertical';
}
```

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`attributes`** is the dictionary you spread; **`ref`** is what you bind the element with; **`props`** is the full props dictionary for spreading onto the host; **`restProps(omit)`** hands back your props with the keys you name left out.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
