# AirLib Headless Splitter

A pane boundary looks like a thin handle until the platform gets involved: arrow keys must step it without stealing the rest, pointer drags must track outside the handle until release, every write must clamp without drifting past a bound, the position must announce against real bounds, and a disabled splitter must keep its allocation while leaving the tab order. **AirLib Headless Splitter** (`aria('splitter')`) owns that contract — a focusable separator with keyboard stepping and pointer drag, without dictating markup or styles.

```tsx
const partition = aria('splitter', props);

<div ref={partition.ref} {...partition.props}>
  <span className="demo-splitterfill" />
</div>
```

## Splitter

Movable pane partition compiling separator range semantics with drag and keys.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'splitter',
  props?: SplitterProps,
  options?: SplitterOptions
): SplitterAria<E>
```

### Usage

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type SplitterProps = ComponentProps<'div'> & {
  value?: number;
  min?: number;
  max?: number;
  step?: number;
  disabled?: boolean;
  label?: string;
};

const Splitter = setup<SplitterProps>((props) => {
  const partition = aria('splitter', props);

  return () => (
    <div ref={partition.ref} {...partition.restProps(['children'])} className={props.className}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
    </div>
  );
});
```

:::

Pane sizes read the published variable — no math in the component:

```css
.pane-first {
  flex-basis: var(--aria-splitter-offset);
}
```

### Parameters

- `props.value` *(number, optional)*: Partition position in percentage points, committed clamped to `[min, max]`. Falls back to `min`.
- `props.min` *(number, optional, default `0`)*: Lower partition bound.
- `props.max` *(number, optional, default `100`)*: Upper partition bound.
- `props.step` *(number, optional, default `1`)*: Increment applied per arrow keystroke.
- `props.disabled` *(boolean, optional)*: Blocks pointer and keyboard resizing, parks the handle at `tabindex="-1"`, and announces `aria-disabled="true"` without changing the allocation.
- `props.label` *(string, optional)*: Accessible handle name compiled to `aria-label`.
- `props.orientation` *('horizontal' | 'vertical', optional, default `'horizontal'`)*: Divider axis, announced as `aria-orientation` only when vertical.

### How it behaves

- Arrow keys travel the partition on either axis — `Right`/`Down` advance by `step`, `Left`/`Up` retreat — holding at the bounds instead of overshooting. Every other key stays with the browser, including `PageUp`/`PageDown` and `Home`/`End`.
- Primary-pointer drags track along the parent area even outside the handle until release or cancellation; drags are continuous, never snapped to `step`. A zero-size area produces no update.
- Every keyboard commit dispatches `input` and `change` carrying the partition; drags dispatch `input` per commit and `change` on release only when the value moved from the drag start.
- A disabled handle refuses keys and drags, and a mid-drag disable ends tracking at the last committed size.
- Panes size themselves from `--aria-splitter-offset`, published on the handle in compiled `style`. Script consumers read the same percentage from `splitter.offset` (`0`–`100`, `0` when the range has no span) — the numeric content of the variable, with no conversion.

## Putting It Together

Once your components are wired with `aria(...)`, compose partitions with honest bounds:

```tsx
<div className="flex gap-4 max-w-sm">
  <Splitter label="Preview width" value={40} min={10} max={90} />
</div>
```

## Keyboard Navigation

- **Tab**: Focuses the handle (`tabindex="0"`, resolving to `tabindex="-1"` while disabled).
- **ArrowRight / ArrowDown**: Advance the partition by `step`, holding at `max`.
- **ArrowLeft / ArrowUp**: Retreat the partition by `step`, holding at `min`.
- **Every other key**: Left unclaimed for the browser, including `PageUp`/`PageDown` and `Home`/`End`.

## What you get

- **Drag plus keys.** Pointer tracking along the parent area and four arrow keys drive the same clamped partition.
- **Committed writes.** Every commit lands inside the declared range and stays put.
- **Honest events.** `input` per commit and `change` when the interaction actually moved the value.
- **CSS-ready position.** `--aria-splitter-offset` sizes panes with no JS math.
