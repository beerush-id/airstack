# Headless Image

An image that loads slowly leaves a hole in your layout, and a `<div>` standing in for one has no semantics at all until you give it a role, a label, and load tracking by hand.

**Headless Image** coordinates the whole lifecycle — idle, loading, loaded, error — across a content element and a fallback element, so exactly one representation is on screen and assistive technology always hears the right label.

```tsx
const image = aria('image', props);
const content = aria('image-content');
const fallback = aria('image-fallback');

<div ref={image.ref} {...image.restProps(['children'])}>
  <img ref={content.ref} {...content.props} />
  <div ref={fallback.ref} {...fallback.props}>…</div>
</div>
```

:::interactive[Avatars]
```tsx
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type DemoAvatarProps = ComponentProps<'div'> & {
  src?: string;
  alt: string;
};

const DemoAvatar = setup<DemoAvatarProps>((props) => {
  const image = aria('image', props);
  const content = aria('image-content');
  const fallback = aria('image-fallback');

  return () => (
    <div
      ref={image.ref}
      {...image.restProps(['children'])}
      className="demo-image-frame"
      data-status={image.status}
    >
      <div ref={fallback.ref} {...fallback.props} className="demo-image-fallback">
        {props.alt.slice(0, 1)}
      </div>
      <img ref={content.ref} {...content.props} className="demo-image-content" />
    </div>
  );
}, 'DemoAvatar');
```

## Image

**The coordinator.** It owns the lifecycle and tells the two representations which of them is on screen.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'image',
  props: ImageProps
): ImageAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type AvatarProps = ComponentProps<'div'> & {
  src?: string;
  alt: string;
};

const Avatar = setup<AvatarProps>((props) => {
  const image = aria('image', props);
  const content = aria('image-content');
  const fallback = aria('image-fallback');

  return () => (
    <div ref={image.ref} {...image.restProps(['children'])}>
      <img ref={content.ref} {...content.props} />
      <div ref={fallback.ref} {...fallback.props}>
        {props.children}
      </div>
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type AvatarProps = ComponentProps<'div'> & {
  src?: string;
  alt: string;
};

const Avatar = setup<AvatarProps>((props) => {
  const image = aria('image', props);
  const content = aria('image-content');
  const fallback = aria('image-fallback');

  return (
    <div ref={image.ref} {...image.restProps(['children'])}>
      <img ref={content.ref} {...content.props} />
      <div ref={fallback.ref} {...fallback.props}>
        {props.children}
      </div>
    </div>
  );
});
```

:::

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **src** _string, optional_: The source URL. **Absent means idle**; setting one starts a load before any result exists.
- **alt** _string, **required**_: The alternative text, shared by content and fallback. **An empty string marks the image decorative.**
- **onchange** _(event: CustomEvent&lt;ImageStatus&gt;) =&gt; void, optional_: Called after every lifecycle transition, with the new status in `detail`.

### Properties

_What you read or write on the instance afterwards._

- **status** _'idle' | 'loading' | 'loaded' | 'error'_: Where the lifecycle stands. **Read it; assigning it never drives a load.**

### How it behaves

- **Four states, owned by the unit.** No `src` is idle; a `src` is loading until the loader settles into loaded or error.
- **A new source orphans the old load.** Late results from a superseded URL never commit, even for the same address.
- **Exactly one representation.** The fallback shows until the content settles, then steps aside.
- **Decorative means silent.** `alt=""` takes both parts out of the accessibility tree.
- **Nothing to focus, nothing to click.** Hiding is done with `aria-hidden` alone, so a load is never interrupted by representation swaps.

### Events

_What it tells you._

- **`change`** — fires after every lifecycle transition, with the new status in `detail`.

## Image Content

**The loaded representation.** A native `<img>` or any element standing in for one.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'image-content',
  props?: AriaProps
): ImageContentAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';

const content = aria('image-content');

<img ref={content.ref} {...content.props} />;
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';

const content = aria('image-content');

<img ref={content.ref} {...content.props} />;
```

:::

### How it behaves

- **Native stays native.** On an `<img>` the source and label are projected with no redundant role.
- **Custom hosts become images.** Once loaded and non-decorative, a non-`<img>` host carries the image role and the label.
- **It reports its own settling.** Load and error reach the coordinator from the element, and an image already in cache settles on mount.
- **Hidden but still loading.** While it isn't the active representation it stays out of the accessibility tree without stopping the load.

## Image Fallback

**The placeholder representation.** Initials, a skeleton, an icon — whatever stands in while the source settles.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'image-fallback',
  props?: AriaProps
): ImageFallbackAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';

const fallback = aria('image-fallback');

<div ref={fallback.ref} {...fallback.props}>…</div>;
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';

const fallback = aria('image-fallback');

<div ref={fallback.ref} {...fallback.props}>…</div>;
```

:::

### How it behaves

- **It is the image while it shows.** During idle, loading, and error it carries the image role and the shared label.
- **It steps aside once content settles.** After a successful load it withdraws from the accessibility tree.
- **Decorative images skip it too.** `alt=""` withdraws the fallback along with the content.

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### Image

```ts
type ImageStatus = 'idle' | 'loading' | 'loaded' | 'error';

interface ImageProps {
  src?: string;
  alt: string;
  onchange?: (event: CustomEvent<ImageStatus>) => void;
}

declare class ImageAria {
  get status(): ImageStatus;

  registerContent(element: Element): void;
  unregisterContent(element: Element): void;
  reportElement(element: Element, outcome: 'loaded' | 'error'): void;
}
```

The container itself carries no attributes of its own — it coordinates, and the two parts carry the semantics. The three methods above are the wiring the content part uses to report; you never call them.

### Image Content

```ts
interface ImageContentAttributes {
  role?: 'img';
  src?: string;
  alt?: string;
  'aria-label'?: string;
  'aria-hidden'?: 'true';
}

declare class ImageContentAria {}
```

### Image Fallback

```ts
interface ImageFallbackAttributes {
  role?: 'img';
  'aria-label'?: string;
  'aria-hidden'?: 'true';
}

declare class ImageFallbackAria {}
```

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`attributes`** is the dictionary you spread; **`ref`** is what you bind the element with; **`props`** is the full props dictionary for spreading onto the host; **`restProps(omit)`** hands back your props with the keys you name left out.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
