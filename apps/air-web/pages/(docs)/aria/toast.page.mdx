# Headless Toast

A toast is the feedback that must not steal your place: saved, uploaded, sent — announced once, visible for a few seconds, then gone.

Getting it right means **announcing once on mount instead of on every render**, **ending the lifetime on a timer that cleanup can cancel**, **pausing while the pointer rests on the toast or focus sits inside it**, and **committing exactly one removal**.

**Headless Toast** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const toast = aria('toast', props);

<div ref={toast.ref} {...toast.restProps(['children'])} />
```

:::interactive[Save Feedback]
```tsx
import { aria, type ToastAria, type ToastCloseAria } from '@airlib/aria';
import { mutable, setup } from '@airlib/react';

const LIFETIME = 6000;

interface HubToast {
  id: number;
  text: string;
  critical?: boolean;
}

const DemoToastItem = setup<{
  entry: HubToast;
  duration: number;
  critical?: boolean;
  ondismiss: () => void;
}>((props) => {
  const toast: ToastAria = aria('toast', props.$pick(['duration', 'critical', 'ondismiss']));
  const close: ToastCloseAria = aria('toast-close');

  return () => (
    <div
      ref={toast.ref}
      {...(toast.attributes as never)}
      style={{ '--demo-toast-life': `${props.duration}ms` } as never}
      className="demo-toast"
    >
      <span>{props.entry.text}</span>
      <button ref={close.ref} {...(close.attributes as never)} className="demo-toast-close">
        Dismiss
      </button>
    </div>
  );
}, 'DemoToastItem');

const DemoToastHub = setup(() => {
  const state = mutable({ toasts: [] as HubToast[] });

  let seed = 0;

  const add = (text: string, critical?: boolean) => {
    state.toasts = [...state.toasts, { id: ++seed, text, critical }];
  };

  const remove = (id: number) => {
    state.toasts = state.toasts.filter((item) => item.id !== id);
  };

  return () => (
    <div className="demo-toast-hub">
      <div className="demo-toast-actions">
        <button type="button" className="demo-toast-show" onClick={() => add('Draft saved')}>
          Save draft
        </button>
        <button
          type="button"
          className="demo-toast-show demo-toast-show--quiet"
          onClick={() => add('Upload failed — retrying', true)}
        >
          Retry upload
        </button>
      </div>

      {state.toasts.map((entry) => (
        <DemoToastItem
          key={entry.id}
          entry={entry}
          duration={LIFETIME}
          critical={entry.critical}
          ondismiss={() => remove(entry.id)}
        />
      ))}
    </div>
  );
}, 'DemoToastHub');
```

## Toast

**The region itself.** One message, one lifetime, one removal.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'toast',
  props?: ToastProps
): ToastAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type ToastProps = ComponentProps<'div'> & {
  critical?: boolean;
  duration?: number;
  children: ReactNode;
};

const Toast = setup<ToastProps>((props) => {
  const toast = aria('toast', props);

  return () => (
    <div ref={toast.ref} {...toast.restProps(['children'])}>
      {props.children}
    </div>
  );
}, 'Toast');
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps, JSX } from 'solid-js';

type ToastProps = ComponentProps<'div'> & {
  critical?: boolean;
  duration?: number;
  children: JSX.Element;
};

const Toast = setup<ToastProps>((props) => {
  const toast = aria('toast', props);

  return () => (
    <div ref={toast.ref} {...toast.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **critical** _boolean, optional, default `false`_: The urgency. `false` waits its turn as a `status` region, `true` interrupts as an `alert`.
- **duration** _number, optional_: The visible lifetime in milliseconds, counted from creation. Without it no timer arms and the toast lives until dismissed.
- **ondismiss** _(event: CustomEvent&lt;void&gt;) =&gt; void, optional_: Runs after the removal commits, with the `dismiss` event.

### Properties

_What you read on the instance afterwards._

- **duration** _number | undefined_: The lifetime in force, or nothing when no timer is armed.
- **remaining** _number | undefined_: The time left before expiry.
- **startedAt** _number | undefined_: The timestamp the lifetime was armed at.
- **dismissed** _boolean_: Whether removal has committed — read-only lifecycle state, not an input. A dismissed toast never re-arms.

### Methods

_What you call on the instance._

- **`dismiss()`**: Commits the removal exactly once — cancels the timer, flags the state, dispatches `dismiss`, then calls `ondismiss`.

### How it behaves

- **The toast is the region.** It compiles `role="status"` with `aria-live="polite"`, or `role="alert"` with `aria-live="assertive"` when `critical`, and always `aria-atomic="false"` so a partial update still announces.
- **One announcement, on mount.** The live semantics are created with the region, so the message is announced when the toast appears and not again on later renders.
- **A toast is always born alive.** It arms its lifetime at construction; the pending timer is cancelled on cleanup, so a toast that leaves early never expires something else.
- **Pause follows the pointer and focus.** Hovering the toast or focusing inside it holds the time that is left; moving focus within keeps the pause, and leaving resumes the remainder.
- **Removal commits once.** Expiry, a close button, and `dismiss()` all run the same path, so none of them can double-commit and a dismissed toast never re-arms.
- **The node stays until you remove it.** Nothing detaches the element; `event.target` identifies the dismissed toast, which is why the toast needs no id of its own.

### Events

_What it tells you._

- **`dismiss`** — fires once when the lifetime expires, when a close button is activated, or when `dismiss()` is called. It bubbles and carries no `detail`: `event.target` is the toast element itself.

```tsx
hub.addEventListener('dismiss', (event) => remove(event.target as HTMLElement));
```

## Toast Close

**The removal button.** It commits the same dismissal its toast owns.

### Usage

```ts
aria<E extends BaseElement = HTMLButtonElement>(
  role: 'toast-close',
  props?: AriaProps,
  options?: AriaOptions
): ToastCloseAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

const ToastClose = setup<ComponentProps<'button'>>((props) => {
  const close = aria('toast-close', props);

  return () => (
    <button ref={close.ref} {...close.restProps(['children'])}>
      {props.children}
    </button>
  );
}, 'ToastClose');
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

const ToastClose = setup<ComponentProps<'button'>>((props) => {
  const close = aria('toast-close', props);

  return (
    <button ref={close.ref} {...close.restProps(['children'])}>
      {props.children}
    </button>
  );
});
```

:::

### Parameters

- **disabled** _boolean, optional_: Locks the button so it commits nothing.

### Options

_What you fix when you create it. Read once, never reactive._

- **native** _boolean, optional, default `true`_: A real `<button>` keeps its own activation, and the controller compiles `type="button"` plus `disabled`. Pass `false` on a custom host for `role="button"`, a tab stop, and the `aria-disabled` mirror instead.

### Properties

_What you read on the instance afterwards._

- **disabled** _boolean_: Whether the close button is locked, which also parks a custom host at `tabindex="-1"`.

### How it behaves

- **It commits the toast's removal**, not a state of its own: an activation runs the same exactly-once dismissal the lifetime runs.
- **The toast is taken from ambient scope at construction**, never passed as a prop. Create the close with its toast — or after it; a close created before any toast has nothing to dismiss.
- **A locked button dismisses nothing.** The click is refused before it reaches the toast, so the message stays.
- **A canceled click is not a dismissal.** If something earlier in the tree already called `preventDefault()`, the close stands down.

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### Toast

```ts
interface ToastProps {
  critical?: boolean;
  duration?: number;
  ondismiss?: (event: CustomEvent<void>) => void;
}

interface ToastAttributes {
  role?: 'status' | 'alert';
  'aria-live'?: 'polite' | 'assertive';
  'aria-atomic'?: 'false';
}

declare class ToastAria {
  get duration(): number | undefined;
  get remaining(): number | undefined;
  get startedAt(): number | undefined;
  get dismissed(): boolean;

  dismiss(): void;
}
```

### Toast Close

```ts
interface ToastCloseProps {
  disabled?: boolean;
}

interface ToastCloseOptions {
  native?: boolean;
}

interface ToastCloseAttributes {
  role?: 'button';
  type?: 'button';
  disabled?: boolean;
  tabindex?: number;
  'aria-disabled'?: 'true' | 'false';
}

declare class ToastCloseAria {
  get disabled(): boolean;
}
```

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`props`** / **`restProps(omit)`** is what you spread onto the host — your props minus the keys the controller writes and any you name, with the compiled attributes merged in; **`ref`** is what you bind the element with; **`attributes`** is that compiled dictionary on its own, when you need the low-level view.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
