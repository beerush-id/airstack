# AirLib Headless Field

Every form repeats the same wiring by hand: a `<label>` needs `for` matching the input's `id`, helper text needs an `id` referenced by `aria-describedby`, and a failure needs `aria-invalid` plus `aria-errormessage` pointing at a polite live region — but only once the developer has actually left the field, or the form screams before anyone types. Miss one link and the field silently degrades for assistive technology. **AirLib Headless Field** (`aria('field')`) hosts an ambient field namespace that wires labels, slotted controls, descriptions, and error messages automatically — on native inputs or custom controls, without dictating markup or styles.

```tsx
const field = aria('field', props);

<div ref={field.ref} {...field.props} />
```

```tsx
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type DemoFieldProps = ComponentProps<'div'> & {
  id?: string;
  invalid?: boolean;
  touched?: boolean;
  required?: boolean;
  disabled?: boolean;
};

const DemoField = setup<DemoFieldProps>((props) => {
  const field = aria('field', props);

  return () => (
    <div ref={field.ref} {...field.restProps(['children'])} className="demo-field">
      {props.children}
    </div>
  );
}, 'DemoField');

type DemoFieldLabelProps = ComponentProps<'label'>;

const DemoFieldLabel = setup<DemoFieldLabelProps>((props) => {
  const label = aria('field-label');

  return () => (
    <label ref={label.ref} {...label.props} className="demo-field-label">
      {props.children}
    </label>
  );
}, 'DemoFieldLabel');

type DemoFieldControlProps = ComponentProps<'input'>;

const DemoFieldControl = setup<DemoFieldControlProps>((props) => {
  const control = aria('field-control');

  return () => (
    <input ref={control.ref} {...control.props} className="demo-field-input"
    />
  );
}, 'DemoFieldControl');

type DemoFieldDescriptionProps = ComponentProps<'p'>;

const DemoFieldDescription = setup<DemoFieldDescriptionProps>((props) => {
  const description = aria('field-description');

  return () => (
    <p ref={description.ref} {...description.props} className="demo-field-desc">
      {props.children}
    </p>
  );
}, 'DemoFieldDescription');

type DemoFieldErrorProps = ComponentProps<'p'>;

const DemoFieldError = setup<DemoFieldErrorProps>((props) => {
  const error = aria('field-error');

  return () => (
    <p ref={error.ref} {...error.props} className="demo-field-error">
      {props.children}
    </p>
  );
}, 'DemoFieldError');

const Demo = (props) => (
  <DemoField id={props.id} type="email" value={props.value ?? 'de@do'} required={props.required} invalid={props.invalid} touched={props.touched} placeholder="you@example.com" oninput={(e) => console.log('New value:', e.target.value)}>
    <DemoFieldLabel>Email address</DemoFieldLabel>
    <DemoFieldControl />
    <DemoFieldDescription>We will send a sign-in link to this address.</DemoFieldDescription>
    <DemoFieldError>Enter a valid email address to continue.</DemoFieldError>
  </DemoField>
);

Compare the two fields: the touched invalid one carries `aria-invalid="true"` and `aria-errormessage` pointing at the error id, and its error part drops `hidden` so the polite live region announces. `aria-describedby` keeps referencing only the helper text in both states. The untouched field stays clean no matter what `invalid` says — the same restraint a native input shows before you tab out of it. Type into either one: `d` fails the built-in email rule, `de@do` passes it.

## Field container

Ambient coordinator hosting the field namespace, the value, and the validation state. Parts created inside its setup scope discover it automatically — no prop drilling.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'field',
  props?: FieldProps,
  options?: AriaOptions
): FieldAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';

const EmailField = setup<{ invalid?: boolean }>((props) => {
  const field = aria('field', { id: 'email', required: true, invalid: props.invalid });

  return () => (
    <div ref={field.ref} {...field.props}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';

const EmailField = setup<{ invalid?: boolean }>((props) => {
  const field = aria('field', { id: 'email', required: true, invalid: props.invalid });

  return (
    <div ref={field.ref} {...field.props}>
      {props.children}
    </div>
  );
});
:::

### Parameters

- `props.id` *(string, optional)*: Explicit field namespace. Generated as `field-*` when omitted; every part derives its address from it.
- `props.value` *(string | number, optional)*: Current value. Rendered onto a native control and written back as the developer types.
- `props.type` *(string, optional)*: Input type rendered onto a native control, defaulting to `text`. Drives the built-in validation rule.
- `props.placeholder` *(string, optional)*: Placeholder rendered onto a native control.
- `props.invalid` *(boolean, optional)*: Validation failure flag. Reaches the control only while `touched` is true.
- `props.invalidMessages` *(string | string[], optional)*: Failure text. Written by validation, or set by you for failures the field cannot compute.
- `props.touched` *(boolean, optional)*: Set by the control's `blur`. Until it is true the field announces nothing.
- `props.required` *(boolean, optional)*: Requirement flag reflected onto the control.
- `props.disabled` *(boolean, optional)*: Disabled flag inherited by the control.
- `props.oninput` *(handler, optional)*: Fires on every keystroke with the control's input event.
- `options.validate` *(function, optional)*: `(value) => string | string[] | void`. Replaces the built-in rule; a non-empty return marks the field invalid and fills `invalidMessages`.
- `options.labelled` *(boolean, optional, default `true`)*: Pass `false` to keep `aria-labelledby` off the control and name it yourself.
- `options.described` *(boolean, optional, default `true`)*: Pass `false` to keep `aria-describedby` off the control and describe it yourself.
- `options.native` *(boolean, optional)*: Declare `{ native: true }` when binding a native `<fieldset>`.

### How it behaves

- Derives every part address from one namespace: `{id}-control`, `{id}-label`, `{id}-desc`, `{id}-error`.
- The container compiles `id` and nothing else — no role. A `<fieldset>` keeps its own native grouping semantics, and grouping several controls is your markup's job.
- Typing writes the control's value into `value`, then validates: your `validate` rule when you pass one, otherwise the control's native `checkValidity()`.
- Holds every failure back until `touched`, so a required field never opens red.
- Exposes the state directly: `id`, `type`, `value`, `placeholder`, `required`, `disabled`, `invalid`, `touched`, `invalidMessages`, `canValidate`, and `validate(value)`. `value`, `invalid`, `touched`, and `invalidMessages` are writable.
- Destroying the field detaches every part — controls freeze their last state instead of following a dead coordinator.

## Field Label

Accessible-name member binding to the control through `for` on a native label, or through an ID reference on a custom element. Finds its field through ambient context — create it in the same setup scope as the field.

```ts
aria<E extends BaseElement = HTMLLabelElement>(
  role: 'field-label',
  props?: AriaProps,
  options?: AriaOptions
): FieldLabelAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type FieldLabelProps = ComponentProps<'label'>;

const FieldLabel = setup<FieldLabelProps>((props) => {
  const label = aria('field-label');

  return () => (
    <label ref={label.ref} {...label.props}>
      {props.children}
    </label>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type FieldLabelProps = ComponentProps<'label'>;

const FieldLabel = setup<FieldLabelProps>((props) => {
  const label = aria('field-label');

  return (
    <label ref={label.ref} {...label.props}>
      {props.children}
    </label>
  );
});
```

:::

### Parameters

- `options.native` *(boolean, optional, default `true`)*: Native `<label>` hosts compile `for`. Pass `false` on custom elements, which receive the `{id}-label` address instead.

### How it behaves

- A `<label>` compiles `for` pointing at the control, and the control still carries `aria-labelledby="{id}-label"` unless the field is created with `labelled: false`.
- A custom element receives the `{id}-label` address, which the control points at via `aria-labelledby`.
- With no live field above it, a label compiles nothing rather than pointing at a missing control.

## Field Control

Slotted proxy reflecting ambient field state onto the bound element. Finds its field through ambient context — create it in the same setup scope as the field.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'field-control',
  props?: AriaProps,
  options?: AriaOptions
): FieldControlAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type FieldControlProps = ComponentProps<'input'>;

const FieldControl = setup<FieldControlProps>((props) => {
  const control = aria('field-control');

  return () => (
    <input ref={control.ref} type={props.type} {...control.props} />
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type FieldControlProps = ComponentProps<'input'>;

const FieldControl = setup<FieldControlProps>((props) => {
  const control = aria('field-control');

  return (
    <input ref={control.ref} type={props.type} {...control.props} />
  );
});
```

:::

### Parameters

- `options.native` *(boolean, optional, default `true`)*: Native inputs receive real `disabled` and `required`. Pass `false` on custom controls, which receive `aria-disabled` and `aria-required` instead.

### How it behaves

- Native inputs (`<input>`, `<select>`, `<textarea>`) reflect `type`, `value`, `placeholder`, `disabled`, and `required` as properties.
- Custom controls project `aria-disabled` and `aria-required` instead — explicit `"false"` until set, then explicit `"true"`.
- `aria-describedby` references the description and nothing else, for the life of the field.
- While the field is both touched and invalid the control gains `aria-invalid="true"` and `aria-errormessage="{id}-error"`; both withdraw the moment the value validates.
- Listens for `input` to write the value and run validation, and for `blur` to mark the field touched.
- Proxies the field state as `type`, `value`, `invalid`, `disabled`, and `required`.
- Destroying the field freezes the control at its last state instead of following dead props.

## Field Description

Helper-text container referenced through the control's `aria-describedby` for the life of the field. Finds its field through ambient context — create it in the same setup scope as the field.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'field-description',
  props?: AriaProps
): FieldDescriptionAria<E>
```

### Usage

:::code-group

```tsx [React]

import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type FieldDescriptionProps = ComponentProps<'p'>;

const FieldDescription = setup<FieldDescriptionProps>((props) => {
  const description = aria('field-description');

  return () => (
    <p ref={description.ref} {...description.props}>
      {props.children}
    </p>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type FieldDescriptionProps = ComponentProps<'p'>;

const FieldDescription = setup<FieldDescriptionProps>((props) => {
  const description = aria('field-description');

  return (
    <p ref={description.ref} {...description.props}>
      {props.children}
    </p>
  );
});
```

:::

### Parameters

- Takes no role-specific props or options — `<p>` is the only host, so there is nothing to declare.

### How it behaves

- Carries the `{id}-desc` address and stays referenced for the life of the field.
- Carries no live region — helper text is reference content, not an announcement.

## Field Error

Failure-message container with a polite live region, referenced only while the field is invalid. Finds its field through ambient context — create it in the same setup scope as the field.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'field-error',
  props?: AriaProps
): FieldErrorAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type FieldErrorProps = ComponentProps<'p'>;

const FieldError = setup<FieldErrorProps>((props) => {
  const error = aria('field-error');

  return () => (
    <p ref={error.ref} {...error.props}>
      {props.children}
    </p>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type FieldErrorProps = ComponentProps<'p'>;

const FieldError = setup<FieldErrorProps>((props) => {
  const error = aria('field-error');

  return (
    <p ref={error.ref} {...error.props}>
      {props.children}
    </p>
  );
});
```

:::

### Parameters

- Takes no role-specific props or options — `<p>` is the only host, so there is nothing to declare.

### How it behaves

- Carries the `{id}-error` address with `aria-live="polite"`.
- Stays `hidden` until the field is both touched and invalid, then reveals itself so the polite region announces.
- Reached through the control's `aria-errormessage`, never through `aria-describedby`.
- Publishes `visible` and `message` so you render the text yourself — the field authors no copy.

## Native and custom hosts

Each part defaults to the host you almost always bind: `field-label` assumes `<label>`, `field-control` assumes a native input. Only custom hosts declare themselves with `{ native: false }`, and only the container takes `{ native: true }` (for `<fieldset>`). Descriptions and errors take no host option at all — `<p>` is the only host there is. The same field logic drives a native checkout form and a fully custom design-system control.

## Keyboard Navigation

- **Tab**: Moves into the field's control and out to the next focusable element; the field adds no tab stops of its own.
- **Shift + Tab**: Returns to the previous focusable element in reverse order.
- **Enter / Space**: Owned entirely by the bound control; the field claims no keystrokes.

## What you get

- **Zero ID ceremony.** One namespace fans out to every part — no hand-matched `for`, `id`, or `describedby` strings.
- **Error wiring that waits for you.** Nothing is announced until the field is touched, then `aria-invalid`, `aria-errormessage`, and the polite live region all follow the value.
- **Validation with a native floor.** Pass `validate` for your own rule; pass nothing and the control's native `checkValidity()` decides, driven by `type`.
- **Native parity on demand.** Native hosts get real `disabled`/`required`/`for`; custom hosts get the equivalent ARIA states from the same code.
- **Clean teardown.** Destroying the field freezes parts instead of leaking listeners or projecting from dead state.
