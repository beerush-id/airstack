# Headless Field

A field ties a label, a control, helper text, and a failure message into one unit. Getting it right means **deriving every address from a single namespace**, **holding a failure back until the field is touched**, **keeping helper text and the failure on separate channels**, and **falling back to the control's own rule when you pass none**.

**Headless Field** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const field = aria('field', props);

<div ref={field.ref} {...field.restProps(['children'])} />
```

:::interactive[Sign-in Form]
```tsx
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type DemoFieldProps = ComponentProps<'div'> & {
  id?: string;
  value?: string;
  invalid?: boolean;
  touched?: boolean;
  required?: boolean;
  children: ReactNode;
};

const DemoField = setup<DemoFieldProps>((props) => {
  const field = aria('field', props);

  return () => (
    <div ref={field.ref} {...field.restProps(['children'])} className="demo-field-card demo-field-form">
      {props.children}
    </div>
  );
}, 'DemoField');

type DemoFieldLabelProps = ComponentProps<'label'>;

const DemoFieldLabel = setup<DemoFieldLabelProps>((props) => {
  const label = aria('field-label');

  return () => (
    <label ref={label.ref} {...label.props} className="demo-field-label">
      {props.children}
    </label>
  );
}, 'DemoFieldLabel');

type DemoFieldControlProps = ComponentProps<'input'>;

const DemoFieldControl = setup<DemoFieldControlProps>((props) => {
  const control = aria('field-control');

  return () => <input ref={control.ref} {...control.props} className="demo-field-input" />;
}, 'DemoFieldControl');

type DemoFieldDescriptionProps = ComponentProps<'span'>;

const DemoFieldDescription = setup<DemoFieldDescriptionProps>((props) => {
  const description = aria('field-description');

  return () => (
    <span ref={description.ref} {...description.props} className="demo-field-hint">
      {props.children}
    </span>
  );
}, 'DemoFieldDescription');

type DemoFieldErrorProps = ComponentProps<'span'>;

const DemoFieldError = setup<DemoFieldErrorProps>((props) => {
  const error = aria('field-error');

  return () => (
    <span ref={error.ref} {...error.props} className="demo-field-error">
      {props.children}
    </span>
  );
}, 'DemoFieldError');

const Demo = (props) => (
  <DemoField id={props.id} type="email" value={props.value} placeholder="you@example.com" required={props.required} invalid={props.invalid} touched={props.touched}>
    <DemoFieldLabel>Email address</DemoFieldLabel>
    <DemoFieldControl />
    <DemoFieldDescription>We will send a sign-in link to this address.</DemoFieldDescription>
    <DemoFieldError>Enter a valid email address to continue.</DemoFieldError>
  </DemoField>
);
```

## Field

**The unit as a whole.** It holds the namespace, the value, and the validation state; the label, the control, the description, and the error all follow it.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'field',
  props?: FieldProps,
  options?: AriaOptions
): FieldAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type FieldProps = ComponentProps<'div'> & {
  invalid?: boolean;
  required?: boolean;
};

const Field = setup<FieldProps>((props) => {
  const field = aria('field', props);

  return () => (
    <div ref={field.ref} {...field.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type FieldProps = ComponentProps<'div'> & {
  invalid?: boolean;
  required?: boolean;
};

const Field = setup<FieldProps>((props) => {
  const field = aria('field', props);

  return (
    <div ref={field.ref} {...field.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **id** _string, optional_: The namespace every part address is derived from, generated as `field-<n>` when you leave it out.
- **value** _string | number, optional_: The current value, rendered onto a native control and written back as the developer types.
- **type** _string, optional, default `'text'`_: The input type rendered onto a native control, and the rule the fallback validation applies.
- **placeholder** _string, optional_: The placeholder rendered onto a native control.
- **invalid** _boolean, optional_: Whether the field currently fails. It reaches the control only while `touched` is true.
- **invalidMessages** _string | string[], optional_: The failure text. Written by validation, or set by you for failures the field cannot compute.
- **touched** _boolean, optional_: Set when the control blurs. Until it is true the field announces nothing.
- **required** _boolean, optional_: Reflected onto the control.
- **disabled** _boolean, optional_: Inherited by the control.
- **oninput** _(event: InputEvent, target: HTMLInputElement) =&gt; void, optional_: Called on every keystroke, after the value is written and validation has run.

### Options

_What you fix when you create it. Read once, never reactive._

- **validate** _(value?: string | number) =&gt; string | string[] | void, optional_: Replaces the built-in rule; any return marks the field invalid and fills `invalidMessages`.
- **labelled** _boolean, optional, default `true`_: Pass `false` to keep `aria-labelledby` off the control and name it yourself.
- **described** _boolean, optional, default `true`_: Pass `false` to keep `aria-describedby` off the control and describe it yourself.
- **native** _boolean, optional, default `false`_: Declare it when the container is a native `<fieldset>`, which keeps its own grouping semantics.

### Properties

_What you read or write on the instance afterwards._

- **id** _string_: The namespace in use, generated when you left it out.
- **type** _string_: The input type in force.
- **value** _string | number | undefined, read and write_: The current value.
- **placeholder** _string_: The placeholder in force, empty when you set none.
- **invalid** _boolean, read and write_: Whether the field fails validation.
- **touched** _boolean, read and write_: Whether the field has been left once.
- **invalidMessages** _string | string[] | undefined, read and write_: The failure text the error part reads.
- **canValidate** _boolean_: Whether a `validate` option is in force.
- **disabled** _boolean_: Whether the whole field is locked.
- **required** _boolean_: Whether the field is required.

### Methods

_What you call on the instance._

- **`validate(value?)`**: Runs your rule for the value and returns its message, if any. Nothing is written until you assign the result.

### How it behaves

- **One namespace, every address.** The label, the control, the description, and the error derive their identifiers from the container's `id` — no address you maintained by hand.
- **The container carries no role.** It compiles `id` and nothing else; grouping several controls is your markup's job.
- **Typing validates.** Every keystroke writes the value, then runs your rule when you passed one, otherwise the control's own `checkValidity()`.
- **Failures wait for `touched`.** A required field never opens red, however early the value fails.
- **One field, one namespace.** Parts created in the same scope as the field discover it through ambient context; a second field on the page is a second namespace.
- **Teardown freezes the parts.** Destroying the field leaves each part at its last state instead of following a dead coordinator.

## Field Label

**The name of the control.** It binds through `for` on a native label, or through an ID reference on a custom element.

### Usage

```ts
aria<E extends BaseElement = HTMLLabelElement>(
  role: 'field-label',
  props?: AriaProps,
  options?: AriaOptions
): FieldLabelAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type FieldLabelProps = ComponentProps<'label'>;

const FieldLabel = setup<FieldLabelProps>((props) => {
  const label = aria('field-label');

  return () => (
    <label ref={label.ref} {...label.props}>
      {props.children}
    </label>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps, JSX } from 'solid-js';

type FieldLabelProps = ComponentProps<'label'>;

const FieldLabel = setup<FieldLabelProps>((props) => {
  const label = aria('field-label');

  return (
    <label ref={label.ref} {...label.props}>
      {props.children}
    </label>
  );
});
```

:::

### Options

_What you fix when you create it. Read once, never reactive._

- **native** _boolean, optional, default `true`_: A native `<label>` compiles `for`. Pass `false` on a custom element, which receives the `{id}-label` address instead.

### How it behaves

- **It points at the control, both ways.** A `<label>` compiles `for` at the control, and the control carries `aria-labelledby` back at `{id}-label`.
- **A custom element gets the address instead.** The label compiles its own identifier, which the control points at the same way.
- **With no field above it, it compiles nothing,** rather than pointing at a control that does not exist.

## Field Control

**The element the user works in.** It reflects the field's state onto whatever host you bind.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'field-control',
  props?: AriaProps,
  options?: AriaOptions
): FieldControlAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

const FieldControl = setup<ComponentProps<'input'>>((props) => {
  const control = aria('field-control');

  return () => <input ref={control.ref} {...control.props} />;
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

const FieldControl = setup<ComponentProps<'input'>>((props) => {
  const control = aria('field-control');

  return <input ref={control.ref} {...control.props} />;
});
```

:::

### Options

_What you fix when you create it. Read once, never reactive._

- **native** _boolean, optional, default `true`_: Native inputs receive real `disabled` and `required`. Pass `false` on a custom control, which receives `aria-disabled` and `aria-required` instead.

### Properties

_What you read or write on the instance afterwards._

- **type** _string_: The input type the field projects.
- **value** _string | number_: The value the field holds.
- **invalid** _boolean_: Whether the field fails validation.
- **disabled** _boolean_: Whether the field is locked.
- **required** _boolean_: Whether the field is required.

### How it behaves

- **Native hosts get the real properties.** `type`, `value`, `placeholder`, `disabled`, and `required` are written onto the element.
- **Custom hosts get the ARIA states.** `aria-disabled` and `aria-required` carry an explicit `"false"` until they are set, then `"true"`.
- **Helper text is the only thing `aria-describedby` points at**, for the life of the field.
- **A failure adds two attributes.** While the field is touched and invalid the control gains `aria-invalid="true"` and `aria-errormessage`, and both withdraw the moment the value validates.
- **Keystrokes and blur drive it.** `input` writes the value and validates; `blur` marks the field touched.
- **Teardown freezes it.** A destroyed field leaves the control at its last state instead of feeding it dead props.

## Field Description

**Helper text.** Referenced by the control through `aria-describedby` for the life of the field.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'field-description',
  props?: AriaProps
): FieldDescriptionAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

const FieldDescription = setup<ComponentProps<'p'>>((props) => {
  const description = aria('field-description');

  return () => (
    <p ref={description.ref} {...description.props}>
      {props.children}
    </p>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps, JSX } from 'solid-js';

const FieldDescription = setup<ComponentProps<'p'> & { children: JSX.Element }>((props) => {
  const description = aria('field-description');

  return (
    <p ref={description.ref} {...description.props}>
      {props.children}
    </p>
  );
});
```

:::

### How it behaves

- **One address, held for the life of the field.** It carries `{id}-desc`, the address the control's `aria-describedby` points at.
- **It is not an announcement.** Helper text is reference content, so it carries no live region.

## Field Error

**The failure message.** A polite live region, referenced only while the field is invalid.

### Usage


### Properties

_What you read or write on the instance afterwards._

- **visible** _boolean_: Whether the field is touched and invalid — the same state that drops `hidden`.
- **message** _string | string[] | undefined_: The text to render. The field authors no copy of its own.

### How it behaves

- **A polite live region.** It carries `{id}-error` and `aria-live="polite"`.
- **Hidden until it matters.** It drops `hidden` only while the field is both touched and invalid, so the announcement follows a real failure.
- **Reached through `aria-errormessage`, never through `aria-describedby`.**
- **You write the copy.** See `visible` and `message` in your own render.

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`attributes`** is the dictionary you spread; **`ref`** is what you bind the element with; **`props`** is the full props dictionary for spreading onto the host; **`restProps(omit)`** hands back your props with the keys you name left out.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
