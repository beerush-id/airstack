# Live Regions Overview

Save confirmations, validation errors, chat messages, and countdowns all happen away from focus. A screen reader user never hears them unless the container was declared live before the content arrived. The opposite failure is just as real: declaring everything live turns a ticking countdown or a stock ticker into an uninterrupted stream of announcements nobody can work over.

`@airlib/aria` compiles the announcement contract for each live region role — `aria-live`, `aria-atomic`, `aria-busy`, and `aria-relevant` — starting from the politeness and atomicity the role implies, and letting the author override either without restating the rest.

## What you get

- **Per-role defaults.** `alert` announces assertively and atomically, `status` politely and atomically, `log` politely entry by entry, `timer` and `marquee` not at all.
- **Overrides that take effect.** Setting `atomic: false` on an alert writes `aria-atomic="false"` explicitly, because the role would otherwise keep implying `true`.
- **Quiet markup when nothing is overridden.** A `log` emits no `aria-atomic="false"` and a `timer` no `aria-busy="false"`; defaults the platform already knows are left unwritten.
- **Busy suppression.** `busy` compiles to `aria-busy="true"` while a region is loading, so partial content is never announced.
- **Native status.** `status` binds to `<output>` by default and omits the redundant role.

## Politeness & Atomicity Defaults

| Role | Default politeness | Default atomic | Announces |
| :--- | :--- | :--- | :--- |
| `alert` | `assertive` | `true` | Time-sensitive messages, interrupting the current utterance. |
| `status` | `polite` | `true` | Advisory results such as "Draft saved" or "5 items found". |
| `log` | `polite` | `false` | Each appended entry, without re-reading the whole history. |
| `timer` | `off` | — | Nothing per tick; milestones are pushed deliberately. |
| `marquee` | `off` | — | Nothing by default; a rapidly changing ticker is not narration. |

## The Pre-Existing Container Rule

A live region must already be in the DOM before its content changes. Assistive technologies register the live observer when the container appears, so a region mounted together with its message is often never announced at all. Render the container empty, keep it mounted, and write the message into it.

## Shared Contract

Every live region takes the same tuning props:

```ts
props.politeness?: 'polite' | 'assertive' | 'off';  // compiled to aria-live
props.atomic?: boolean;                             // compiled to aria-atomic
props.busy?: boolean;                               // compiled to aria-busy when true
props.relevant?: string;                            // compiled to aria-relevant
```

`timer` adds `value` and `marquee` adds `paused` as reactive state projections. Neither compiles to an attribute — no ARIA attribute exists for them — so rendering the count and suspending the ticker stay with the consumer.

## Available Live Regions

- **[Alert](./alert)** — Urgent, time-sensitive messages that interrupt.
- **[Status](./status)** — Advisory results, bound to a native `<output>` by default.
- **[Log](./log)** — Append-only streams such as chat history and audit feeds.
- **[Timer](./timer)** — Elapsed and remaining time, silent per tick.
- **[Marquee](./marquee)** — Rapidly changing tickers with a pause state.
