# Log

Chat histories, audit trails, build output, and game feeds all grow one entry at a time. Announcing the whole list on every append forces the user to listen through the history again; announcing nothing means the conversation moves on without them. A log has to announce the new entry and only the new entry.

`@airlib/aria` compiles the log live region onto the element you already render. It emits `role="log"` with polite announcements and a non-atomic subtree by default, so an appended entry is read on its own, and `relevant` narrows the monitoring to additions when the stream only ever grows.

You compose a log using this piece:

- **Log**: The append-only live region that compiles `role="log"` with polite, per-entry announcements.

## What you get

- **Per-entry announcements.** `aria-atomic` defaults to false, so appending an entry announces that entry rather than the whole history.
- **Polite by default.** `aria-live="polite"` waits for the user to finish before announcing.
- **Addition-only monitoring.** `relevant="additions"` tells assistive technologies to ignore removals and text edits in the stream.
- **Busy suppression.** `busy` compiles to `aria-busy="true"` while a batch of entries is still loading.

## Log

In Aria, Log is the append-only live region created with `aria('log')` that compiles sequential announcement semantics onto a container.

```ts
aria<E extends BaseElement = HTMLElement>(role: 'log', props?: LogProps): LogAria<E>
```

### Parameters

- `props.politeness` *('polite' | 'assertive' | 'off', optional, default `'polite'`)*: Announcement priority, compiled to `aria-live`.
- `props.atomic` *(boolean, optional, default `false`)*: Whether the whole stream is announced as one unit, compiled to `aria-atomic` when set or true.
- `props.busy` *(boolean, optional)*: Suppresses announcements while entries are being fetched, compiled to `aria-busy` when true.
- `props.relevant` *(string, optional)*: Change kinds to monitor, compiled to `aria-relevant`.

The controller compiles no accessible name of its own. Bind `aria-label` on the element so the stream is announced by purpose, such as "Chat messages".

### How it behaves

The container is compiled with `role="log"` and `aria-live` resolved from `politeness`. `aria-atomic` is left unwritten unless the author sets it, because false is already the platform default and re-reading the whole stream is exactly what a log must not do. `aria-busy` and `aria-relevant` are emitted only when provided. The log takes no options: no native host implies the role, and announcement tuning is author-set props.

:::tip[Newest last]
A log is announced in source order, so append new entries at the end and keep older ones above. Prepending puts each new message after the last announcement in reading order, which reads as a stream running backwards.
:::

### Usage

To use Log, create the region with `aria('log', props)`, then pass `log.ref` and spread `log.attributes` onto your stream container:

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type LogProps = ComponentProps<'ul'> & {
  politeness?: 'polite' | 'assertive' | 'off';
  atomic?: boolean;
  busy?: boolean;
  relevant?: string;
  label?: string;
};

const Log = setup<LogProps>((props) => {
  const log = aria('log', props);
  const restProps = props.$omit([
    ...log.ownKeys,
    'politeness',
    'atomic',
    'busy',
    'relevant',
    'label',
    'children',
    'className',
  ]);

  return () => (
    <ul ref={log.ref} aria-label={props.label} {...restProps} {...log.attributes} className={props.className}>
      {props.children}
    </ul>
  );
}, 'Log');
```

```tsx [SolidJS]

import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type LogProps = ComponentProps<'ul'> & {

      {props.children}
    </ul>
  );
});
```

:::

The host is a `<ul>` here because a log is a list, but the controller binds to any container — the role is compiled explicitly, so a `<div>` host works identically.

## Putting It Together

Once your component is wired with `aria('log')`, append entries and monitor additions only:

```tsx
<Log label="Build output" relevant="additions">
  {entries.map((entry) => (
    <li key={entry.id}>{entry.text}</li>
  ))}
</Log>
```

## Announcement Behavior

- **On append**: the new entry alone is announced once the user's current utterance finishes.
- **On removal or edit**: nothing is announced while `relevant="additions"` is set.
- **While `busy`**: announcements are suppressed, so a partially loaded batch is never read out.
