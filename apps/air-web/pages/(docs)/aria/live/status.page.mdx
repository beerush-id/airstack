# Status

"Draft saved", "5 results found", "Copied to clipboard" — these results matter, but interrupting the user for them is worse than saying nothing. A status message has to wait its turn, be announced once as a whole, and never take focus away from the field the user is still typing in.

`@airlib/aria` compiles the status live region onto the element you already render. Bound to a native `<output>` it emits no redundant role, because `<output>` already implies `status`; bound to a `<div>` it supplies `role="status"`. Politeness and atomicity default to what the role implies and stay overridable.

You compose a status using this piece:

- **Status**: The advisory live region that compiles `role="status"` with polite, atomic announcements by default.

## What you get

- **Polite by default.** `aria-live="polite"` waits for the user to finish before announcing, so nothing is interrupted.
- **Whole-message announcements.** `aria-atomic="true"` is compiled so a replaced message is read in full rather than as a diff.
- **Native `<output>` support.** The default host is `<output>`, so the role is implied and no redundant attribute is emitted.
- **Busy suppression.** `busy` compiles to `aria-busy="true"` while a result is still being fetched.

## Status

In Aria, Status is the advisory live region created with `aria('status')` that compiles polite announcement semantics onto a native or custom host.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'status',
  props?: StatusProps,
  options?: StatusOptions
): StatusAria<E>
```

### Parameters

- `props.politeness` *('polite' | 'assertive' | 'off', optional, default `'polite'`)*: Announcement priority, compiled to `aria-live`.
- `props.atomic` *(boolean, optional, default `true`)*: Whether the whole region is announced as one unit, compiled to `aria-atomic`.
- `props.busy` *(boolean, optional)*: Suppresses announcements while the result is loading, compiled to `aria-busy` when true.
- `props.relevant` *(string, optional)*: Change kinds to monitor, compiled to `aria-relevant`.
- `options.native` *(boolean, optional, default `true`)*: Pass `false` when binding to a `<div>` host instead of `<output>`.

The controller compiles no accessible name of its own. Bind `aria-label` on the element when the result needs a name beyond its text.

### How it behaves

With `native: true` the role is left to the `<output>` element and only the announcement tuning is compiled. With `native: false` the controller adds `role="status"` for a custom host. `aria-live` always carries the resolved politeness, `aria-atomic` is written when it is true or explicitly set, and `aria-busy` and `aria-relevant` are emitted only when provided.

:::tip[Status is not a validation error]
A field error the user must act on belongs in an `alert`, or better, in `aria-invalid` plus `aria-describedby` on the field itself. `status` is for results that are useful to hear and safe to miss — reserve the interrupting channel for things that are not.
:::

### Usage

To use Status, create the region with `aria('status', props)`, then pass `status.ref` and spread `status.attributes` onto your output element:

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type StatusProps = ComponentProps<'output'> & {
  politeness?: 'polite' | 'assertive' | 'off';
  atomic?: boolean;
  busy?: boolean;
  relevant?: string;
  label?: string;
};

const Status = setup<StatusProps>((props) => {
  const status = aria('status', props);
  const restProps = props.$omit([
    ...status.ownKeys,
    'politeness',
    'atomic',
    'busy',
    'relevant',
    'label',
    'children',
    'className',
  ]);

  return () => (
    <output
      ref={status.ref}
      aria-label={props.label}
      {...restProps}
      {...status.attributes}
      className={props.className}
    >
      {props.children}
    </output>
  );
}, 'Status');
```

## Putting It Together

Once your component is wired with `aria('status')`, keep it mounted next to the control that produces the result:

```tsx
<button onClick={save}>Save draft</button>
<Status label="Save result">{saved ? 'Draft saved' : ''}</Status>
```

## Announcement Behavior

- **On content change**: the whole message is announced as soon as the user's current utterance finishes.
- **Focus**: never moves. The user keeps typing or reading where they were.
- **While `busy`**: announcements are suppressed, so a half-fetched result is never read out.
