# Alert

A deployment failure, an expired session, or a validation error has to reach the user immediately — but moving focus to the message destroys whatever the user was doing, and a message rendered without a live region is often never announced at all, because the container appeared at the same moment as its content.

`@airlib/aria` compiles the alert live region onto the element you already render. It emits `role="alert"` with the assertive, atomic announcement the role implies, lets the author override either, and leaves focus exactly where it was.

You compose an alert using this piece:

- **Alert**: The urgent live region that compiles `role="alert"` with assertive, atomic announcements by default.

## What you get

- **Interruption by default.** `aria-live="assertive"` and `aria-atomic="true"` are compiled so the message is announced whole, immediately.
- **Overrides that take effect.** `atomic: false` is written explicitly, because the role would otherwise keep implying `true`.
- **Focus preserved.** Nothing is focused, nothing is trapped — the announcement arrives where the user already is.
- **Busy suppression.** `busy` compiles to `aria-busy="true"` while the message is still loading.

## Alert

In Aria, Alert is the urgent live region created with `aria('alert')` that compiles assertive announcement semantics onto a container.

```ts
aria<E extends BaseElement = HTMLElement>(role: 'alert', props?: AlertProps): AlertAria<E>
```

### Parameters

- `props.politeness` *('polite' | 'assertive' | 'off', optional, default `'assertive'`)*: Announcement priority, compiled to `aria-live`.
- `props.atomic` *(boolean, optional, default `true`)*: Whether the whole region is announced as one unit, compiled to `aria-atomic`.
- `props.busy` *(boolean, optional)*: Suppresses announcements while the region is updating, compiled to `aria-busy` when true.
- `props.relevant` *(string, optional)*: Change kinds to monitor, compiled to `aria-relevant`.

The controller compiles no accessible name of its own. Bind `aria-label` on the element when the message needs one beyond its text.

### How it behaves

The container is compiled with `role="alert"`, `aria-live` resolved from `politeness`, and `aria-atomic` written whenever it is true or explicitly set. `aria-busy` and `aria-relevant` are emitted only when provided, so an idle alert carries no redundant state. The alert takes no options: there is no native host that implies the role, and announcement tuning is author-set props rather than engine configuration.

:::tip[Mount the container before the message]
Assistive technologies register the live observer when the container appears. An alert rendered together with its text — `{error && <Alert>{error}</Alert>}` — is frequently never announced. Keep the container mounted and write the message into it, clearing it back to empty rather than unmounting.
:::

### Usage

To use Alert, create the region with `aria('alert', props)`, then pass `alertRegion.ref` and spread `alertRegion.attributes` onto your message container:

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type AlertProps = ComponentProps<'div'> & {
  politeness?: 'polite' | 'assertive' | 'off';
  atomic?: boolean;
  busy?: boolean;
  relevant?: string;
  label?: string;
};

const Alert = setup<AlertProps>((props) => {
  const alertRegion = aria('alert', props);
  const restProps = props.$omit([
    ...alertRegion.ownKeys,
    'politeness',
    'atomic',
    'busy',
    'relevant',
    'label',
    'children',
    'className',
  ]);

  return () => (
    <div
      ref={alertRegion.ref}
      aria-label={props.label}
      {...restProps}
      {...alertRegion.attributes}
      className={props.className}
    >
      {props.children}
    </div>
  );
}, 'Alert');
```

:::

The tuning props are controller inputs, not HTML attributes, so they are omitted from the forwarded rest props alongside `label` and `className`.

## Putting It Together

Once your component is wired with `aria('alert')`, keep it mounted and write messages into it:

```tsx
<Alert label="Deployment status">
  {deployment.error ? `Deployment failed: ${deployment.error}` : ''}
</Alert>
```

## Announcement Behavior

- **On content change**: the whole message is announced immediately, interrupting whatever is currently being read.
- **Focus**: never moves. An alert is not a dialog and takes no focus, no tab stop, and no `Escape`.
- **While `busy`**: announcements are suppressed until the region reports it is finished updating.
