# AirLib Headless Select

A select is the option list collapsed behind a button: closed it shows one value, open it offers every choice. Hand-rolled markup gets you half there — a button that never announces its popup, arrow keys that scroll the document instead of opening the list, focus lost to the void on dismiss, and a selection no assistive technology hears about. **AirLib Headless Select** (`aria('select')`) is a role-less root orchestrating a combobox trigger, a popup listbox panel, and option members: toggling plus arrow-open on the trigger, delegated dismissal and focus restoration, roving with typeahead in the panel, single or multiple selection, and committed values announced on the root — without dictating markup or styles.

```tsx
const select = aria('select', props);

<div ref={select.ref} {...select.props} />
```

```tsx
import { aria } from '@airlib/aria';
import { setup, shadowPortal } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type DemoSelectProps = ComponentProps<'div'> & {
  value?: string | null;
  open?: boolean;
};

const DemoSelect = setup<DemoSelectProps>((props) => {
  const select = aria('select', props);

  return () => (
    <div ref={select.ref} {...select.restProps(['children'])} className="demo-select">
      {props.children}
    </div>
  );
}, 'DemoSelect');

type DemoSelectTriggerProps = ComponentProps<'button'>;

const DemoSelectTrigger = setup<DemoSelectTriggerProps>((props) => {
  const trigger = aria('select-trigger', props);

  return () => (
    <button ref={trigger.ref} {...trigger.restProps(['children'])} className="demo-select-trigger">
      {trigger.text || 'Select'}
    </button>
  );
}, 'DemoSelectTrigger');

type DemoSelectPanelProps = ComponentProps<'div'> & {
  children: ReactNode;
};

const DemoSelectPanel = setup<DemoSelectPanelProps>((props) => {
  const panel = aria('select-panel', props);
  const shadow = shadowPortal(() => panel.open);

  return () => shadow(
    <div ref={panel.ref} {...panel.restProps(['children'])} className="demo-select-panel">
      {props.children}
    </div>
  );
}, 'DemoSelectPanel');

type DemoOptionProps = ComponentProps<'div'> & {
  value: string;
  disabled?: boolean;
  children: ReactNode;
};

const DemoOption = setup<DemoOptionProps>((props) => {
  const option = aria('option', props);

  return () => (
    <div ref={option.ref} {...option.restProps(['children'])} className="demo-select-option">
      {props.children}
    </div>
  );
}, 'DemoOption');

const options = {
  ams: "Amsterdam",
  ber: "Berlin",
  cop: "Copenhagen",
  dub: "Dublin",
  vil: "Vilnius"
};

const Demo = (props) => (
  <DemoSelect {...props}>
    <DemoSelectTrigger />
    <DemoSelectPanel>
      {Object.entries(options).map(([value, label]) => (
        <DemoOption key={value} value={value}>{label}</DemoOption>
      ))}
    </DemoSelectPanel>
  </DemoSelect>
);
```

## Select

Role-less root orchestrator hosting the selection and the popup visibility, publishing ambient context for the trigger, the panel, and the options.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'select',
  props?: SelectProps
): SelectAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type SelectProps = ComponentProps<'div'> & {
  value?: string | string[] | null;
  open?: boolean;
  multiple?: boolean;
  query?: string;
  disabled?: boolean;
  required?: boolean;
  onopen?: () => void;
  onclose?: () => void;
};

const Select = setup<SelectProps>((props) => {
  const select = aria('select', props);

  return () => (
    <div ref={select.ref} {...select.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type SelectProps = ComponentProps<'div'> & {
  value?: string | string[] | null;
  open?: boolean;
  multiple?: boolean;
  query?: string;
  disabled?: boolean;
  required?: boolean;
  onopen?: () => void;
  onclose?: () => void;
};

const Select = setup<SelectProps>((props) => {
  const select = aria('select', props);

  return (
    <div ref={select.ref} {...select.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

For multiple selection declare the array archetype: `{ multiple: true, value: ['ams', 'ber'] }`. `multiple` and `value` narrow together.

### Parameters

- `props.value` *(string | null | string[], optional)*: Selected option value in the single archetype (`null` is the unselected token); an array of tokens in the multiple archetype.
- `props.open` *(boolean, optional)*: Popup visibility flag, readable and writable through `select.open`.
- `props.multiple` *(boolean, optional, default `false`)*: Declares the multi-select archetype, where `value` is an array of tokens.
- `props.query` *(string, optional)*: Filter query.
- `props.disabled` *(boolean, optional)*: Locks out toggling and committing across the whole select.
- `props.required` *(boolean, optional)*: A required select with nothing selected is claimed by the first enabled option.
- `props.id` *(string, optional)*: Explicit DOM identifier. Generated as `select-<n>` when omitted; the panel derives `{id}-panel`.
- `props.onopen` / `props.onclose` *(handlers, optional)*: Called when the popup opens or closes.

### How it behaves

- Compiles no `role` — the root is a non-semantic container.
- A programmatic write (`select.open = true` or `props.open = true`) flips visibility and flows through to the trigger's `aria-expanded`, but dispatches nothing on its own: visibility events come from the popup lifecycle.
- A commit in single mode closes the popup; a commit in multiple mode leaves it open.

## Select Trigger

Popup anchor compiling the combobox face and toggling the panel.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'select-trigger',
  props?: SelectTriggerProps
): SelectTriggerAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type SelectTriggerProps = ComponentProps<'button'> & {
  id?: string;
  disabled?: boolean;
};

const SelectTrigger = setup<SelectTriggerProps>((props) => {
  const trigger = aria('select-trigger', props);

  return () => (
    <button ref={trigger.ref} {...trigger.restProps(['children'])}>
      {props.children}
    </button>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type SelectTriggerProps = ComponentProps<'button'> & {
  id?: string;
  disabled?: boolean;
};

const SelectTrigger = setup<SelectTriggerProps>((props) => {
  const trigger = aria('select-trigger', props);

  return (
    <button ref={trigger.ref} {...trigger.restProps(['children'])}>
      {props.children}
    </button>
  );
});
```

:::

### Parameters

- `props.id` *(string, optional)*: DOM element identifier.
- `props.disabled` *(boolean, optional)*: Disables this trigger. Select-level disablement applies too.

### How it behaves

- Compiles `role="combobox"`, `aria-haspopup="listbox"`, `aria-expanded` tracking the popup, and `aria-controls` pointing at the panel id.
- Click, `Enter`, and `Space` toggle the popup; `ArrowDown` and `ArrowUp` on a closed trigger open it.
- `Escape` closes without committing and restores focus to the trigger.
- A disabled trigger refuses toggling and opening, on a native `<button>` (real `disabled`) and on custom hosts (`tabindex="-1"` plus `aria-disabled="true"`).

## Select Panel

Popup listbox inheriting the listbox's traversal, typeahead, and option coordination, with dismissal and focus delegated to an internal popover.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'select-panel',
  props?: SelectPanelProps
): SelectPanelAria<E>
```

`SelectPanelProps` is the listbox props. The panel adopts the select's ambient context and proxies `open`, `onopen`, and `onclose` to and from the internal popover.

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type SelectPanelProps = ComponentProps<'div'>;

const SelectPanel = setup<SelectPanelProps>((props) => {
  const panel = aria('select-panel', props);

  return () => (
    <div ref={panel.ref} {...panel.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type SelectPanelProps = ComponentProps<'div'>;

const SelectPanel = setup<SelectPanelProps>((props) => {
  const panel = aria('select-panel', props);

  return (
    <div ref={panel.ref} {...panel.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### How it behaves

- Compiles `role="listbox"` and holds the panel id the trigger's `aria-controls` points at.
- Traversal moves focus and commits nothing; activation commits through the option's own rules.
- Outside click and `Escape` dismiss through the internal popover; opening focuses the selected option first, else the first focusable.

## Options

Individual choices are the standard `option` role controller (`aria('option')`) — ambiently coordinated, selected rather than checked, and inert to keys of their own. See the [Option](/docs/aria/option) documentation for its value, label, and disablement contract.

## Events

| Event | Authored by | Trigger | `detail` |
| :--- | :--- | :--- | :--- |
| `input` | The option | Focus landed on it — arrows, `Home`/`End`, typeahead, or a click | That option's value |
| `change` | The select root | Activation committed the selection | The whole updated value |
| `open` / `onopen` | The popup | The panel opened | The open state |
| `close` / `onclose` | The popup | The panel closed | The open state |

```tsx
const select = aria('select', {
  value: 'ams',
  onopen: () => hideHint(),
  onclose: () => restoreHint(),
});
```

A programmatic write (`select.open = true` or `props.open = true`) flips visibility but dispatches nothing: an external write is neither an opening gesture nor a commit, because nobody acted.

## Keyboard Navigation

| Key | Behavior |
| :--- | :--- |
| `Click` / `Enter` / `Space` on the trigger | Toggles the popup. |
| `ArrowDown` / `ArrowUp` on a closed trigger | Opens the popup. |
| `ArrowDown` / `ArrowUp` / `Home` / `End` in the panel | Roves across options without committing. |
| `Space` / `Enter` on an option | Commits the selection. |
| `Escape` | Closes without committing and restores focus to the trigger. |
| `Tab` | Exits the select completely. |

## What you get

- **A popup without popup plumbing.** Dismissal, positioning, and focus restoration are delegated to the internal popover, so the select never reimplements them.
- **Traversal that never selects.** Roving forwards `input` with the cursor value; only activation dispatches `change` with the committed value.
- **Single closes, multiple stays.** The commit rule follows the archetype, so multi-select pickers never slam shut mid-choice.
- **Claimed when required.** A `required` select with nothing selected is announced through the first enabled option instead of silence.
- **Zero markup lock-in.** Native `<button>` or a custom trigger host, `<div>` or `<ul>` panel, rich option rows.
