# Headless Checkbox Group

A checkbox group holds one set of checked values across many boxes. Getting it right means **holding one committed set**, **letting each box toggle on its own**, **locking the whole set with one flag**, and **naming the grouping**.

**Headless Checkbox Group** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const group = aria('checkbox-group', props);

<div ref={group.ref} {...group.restProps(['children'])} />
```

## Checkbox Group

**The set as a whole.** It holds which values are checked and names the grouping; the boxes themselves are ordinary checkboxes.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'checkbox-group',
  props?: CheckboxGroupProps
): CheckboxGroupAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type CheckboxGroupProps = ComponentProps<'div'> & {
  id?: string;
  value?: string[];
  label?: string;
  disabled?: boolean;
};

const CheckboxGroup = setup<CheckboxGroupProps>((props) => {
  const group = aria('checkbox-group', props);

  return () => (
    <div ref={group.ref} {...group.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

The members are ordinary [`checkbox`](/docs/aria/checkbox) controllers — `checked`, `indeterminate`, and `disabled` keep working exactly as themselves inside the set.

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **value** _string[], optional, default `[]`_: The values currently checked. Leave it out and the group keeps its own set; set it and the group follows your state.
- **disabled** _boolean, optional_: Locks every member at once. Each box stays visible and announced as disabled.
- **label** _string, optional_: The name of the grouping, compiled to `aria-label`.
- **id** _string, optional_: The group's identifier in the DOM, generated as `checkbox-group-<n>` when you leave it out.

### Properties

_What you read or write on the instance afterwards._

- **value** _string[], read and write_: The checked values. Writing replaces the whole set.
- **disabled** _boolean_: Whether the group is locked.

### Methods

_What you call on the instance._

- **`checkbox(props?, options?)`** → `CheckboxAria`: Creates a member belonging to this group.

### How it behaves

- **Members toggle on their own.** Checking one adds its value to the set and unchecking removes it; siblings are untouched.
- **One flag locks the set.** `disabled` on the group cascades to every member — each refuses activation on either host.
- **Every box is its own tab stop.** No roving focus and no claimed arrow keys: `Tab` walks the enabled boxes in order and the page scrolls as usual.
- **A fieldset needs no role.** On a native `<fieldset>` host the compiled `role="group"` is left off; any other host gets it.
- **Each toggle tells you the whole set.** Every member fires `change`, and inside the group the event carries the committed array and bubbles to the container.

### Navigation

_What the keys do._

- **`Tab` / `Shift+Tab`** — the next / previous enabled box in the set.
- **`Space`** — toggles the focused box, as any checkbox does.

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### Checkbox Group

```ts
interface CheckboxGroupProps {
  value?: string[];
  disabled?: boolean;
  label?: string;
  id?: string;
}

interface CheckboxGroupAttributes {
  role?: 'group';
  'aria-label'?: string;
  'aria-disabled'?: 'true' | 'false';
}

declare class CheckboxGroupAria {
  get value(): string[];
  set value(val: string[]);
  get disabled(): boolean;

  checkbox(props?: Partial<CheckboxProps>, options?: Partial<CheckboxOptions>): CheckboxAria;
}
```

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`props`** / **`restProps(omit)`** is what you spread onto the host — your props minus the keys the controller writes and any you name, with the compiled attributes merged in; **`ref`** is what you bind the element with; **`attributes`** is that compiled dictionary on its own, when you need the low-level view.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
