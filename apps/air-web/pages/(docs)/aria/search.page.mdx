# AirLib Headless Search

Searching is one of the few tasks users want to jump to directly, and it is usually buried inside the header next to the navigation. Identifying the search facility as its own landmark is what lets assistive technologies offer it as a destination instead of making users tab through the header to find the field. **AirLib Headless Search** (`aria('search')`) compiles `role="search"` onto the generic or legacy `<form>` host you already render, names it when a page holds more than one search facility, and stays out of the query mechanics entirely.

```tsx
const search = aria('search', props);

<div ref={search.ref} {...search.restProps(['children'])} />
```

## Search

The search facility landmark. It projects search semantics onto a host that does not already imply them, which is the common case: a `<div>` wrapper or the legacy `<form role="search">` pattern.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'search',
  props?: SearchLandmarkProps,
  options?: SearchLandmarkOptions
): SearchAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type SearchProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
  children: ReactNode;
};

const Search = setup<SearchProps>((props) => {
  const search = aria('search', props);

  return () => (
    <div ref={search.ref} {...search.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type SearchProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
};

const Search = setup<SearchProps>((props) => {
  const search = aria('search', props);

  return (
    <div ref={search.ref} {...search.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

- `props.label` *(string, optional)*: Accessible label compiled to `aria-label`.
- `props.labelledby` *(string, optional)*: Element ID providing the accessible name, compiled to `aria-labelledby`.
- `options.native` *(boolean, optional, default `false`)*: Pass `true` only when the host is a real `<search>` element, which already implies the role. Leave the default for a `<div>` or `<form>` host.

### How it behaves

- Compiles `role="search"` on a generic host. With `native: true` the role is left to the `<search>` element and only the accessible name is emitted.
- The role comes from `native` alone — never from the host tag and never from where the element sits in the tree.
- `label` compiles to `aria-label` and `labelledby` to `aria-labelledby`, both reactively, and both are omitted when absent.
- It stays out of the query mechanics: no `action`, no `method`, no `tabindex`, and nothing borrowed from the field or the submit control inside it. Typing and submitting remain entirely yours.
- `label` and `labelledby` are consumed by the controller and carried in `ownKeys`, so `restProps(['children'])` is the whole omission list — neither leaks to the DOM as a stray attribute.

:::tip[The host decides the native flag]
A `<form>` implies a form landmark, not a search one, so the legacy `<form role="search">` pattern needs the compiled role — leave `native` at its default. Only a real `<search>` element already implies `search`, and that is the one case for `native: true`. Getting this backwards announces a search facility as a form.
:::

## Keyboard Navigation

- **None.** The landmark takes no tab stop of its own. Keyboard users interact with the field and submit control inside it.

## What you get

- **Search on a generic host.** A `<div>` or `<form>` becomes a jump destination.
- **Legacy host support.** A `<form>` host compiles the role explicitly, because a form implies `form`, not `search`.
- **Optional naming.** `label` and `labelledby` cover a page holding both a site search and a filtered-table search.
- **Out of the query.** No form attributes, no field state, no submission handling.
- **Placement-stable output.** The compiled attributes are identical in SSR and after hydration, because nothing is read from the DOM.
