# Headless Search

A search landmark marks the facility users jump to first, wherever it sits in the page. Getting it right means **compiling the search role on a host that does not imply it**, **naming the facility when a page holds more than one**, **leaving the query and the submit to you**, and **taking no focus of its own**.

**Headless Search** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const search = aria('search', props);

<div ref={search.ref} {...search.restProps(['children'])} />
```

:::interactive[Documentation Search]
```tsx
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type DemoSearchProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
};

const DemoSearch = setup<DemoSearchProps>((props) => {
  const search = aria('search', props);

  return () => (
    <div ref={search.ref} {...search.restProps(['children'])} className="demo-search">
      {props.children}
    </div>
  );
}, 'DemoSearch');
```
```html
<DemoSearch label="Documentation">
  <input type="search" aria-label="Search documentation" placeholder="Search documentation" className="demo-search-input" />
  <button type="button" className="demo-search-submit">Search</button>
</DemoSearch>
```

## Search

**The landmark.** It marks the search facility as its own destination and carries the name the page needs when several facilities exist.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'search',
  props?: SearchLandmarkProps,
  options?: SearchLandmarkOptions
): SearchAria<E>
```

:::code-group

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **label** _string, optional_: The facility's name, compiled to `aria-label`.
- **labelledby** _string, optional_: An element id to take the name from, compiled to `aria-labelledby`.

### Options

_What you fix when you create it. Read once, never reactive._

- **native** _boolean, optional, default `false`_: Set `true` only when the host is a real `<search>` element, which already implies the role. Leave it alone for a `<div>` or a legacy `<form>`.

### Properties

_What you read or write on the instance afterwards._

- **label** _string | undefined_: The name in use, when one was passed.
- **labelledby** _string | undefined_: The id the name comes from, when one was passed.
- **named** _boolean_: Whether the landmark carries a name at all.

### How it behaves

- **A custom host gets the role; a native one does not.** On anything but `<search>` the container compiles `role="search"`; with `native: true` the role is left to the element and only the name is written.
- **The role never follows the tag or the tree.** A `<form>` in the header compiles nothing on its own — the flag is the only switch, which is what the legacy `<form role="search">` pattern needs.
- **Naming is optional and reactive.** `label` and `labelledby` are written as they change and dropped when they are absent; a page with one facility needs neither.
- **The query is not its business.** No `action`, no `method`, no value, no submission: typing and sending stay with the field and the button inside.
- **No focus of its own.** The container compiles no `tabindex` and claims no keys, so the field remains the way in.
- **The name never leaks as an attribute.** `label` and `labelledby` belong to the controller's own keys, so `restProps(['children'])` is the whole omission list.

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### Search

```ts
interface SearchLandmarkProps {
  label?: string;
  labelledby?: string;
}

interface SearchLandmarkOptions {
  native?: boolean;
}

interface LandmarkAttributes {
  role?: 'search';
  'aria-label'?: string;
  'aria-labelledby'?: string;
}

declare class SearchAria {
  get label(): string | undefined;
  get labelledby(): string | undefined;
  get named(): boolean;
}
```

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`attributes`** is the dictionary you spread; **`ref`** is what you bind the element with; **`props`** is the full props dictionary for spreading onto the host; **`restProps(omit)`** hands back your props with the keys you name left out.
