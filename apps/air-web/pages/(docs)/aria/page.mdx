# Headless Kits

Building accessible web applications is difficult. Developers often face a frustrating trade-off: adopt heavyweight component libraries that dictate your markup, styles, and bundle size, or manually wire dozens of WAI-ARIA attributes, manage focus states, and polyfill keyboard interactions by hand. Reach for a headless library instead and it is typically tied to one framework, with verbose wiring mechanics of its own.

  ams: 'Amsterdam',
  ber: 'Berlin',
  cop: 'Copenhagen',
  dnb: 'Dublin',
  vil: 'Vilnius',
};
const cities = Object.entries(cityMap);

type DemoCityProps = ComponentProps<'div'> & {
  value?: string | string[] | null;
  query?: string;
  open?: boolean;
  multiple?: boolean;
  disabled?: boolean;
  required?: boolean;
};

const DemoCity = setup<DemoCityProps>((props) => {
  const combobox = aria('combobox', props, cityMap);

  const matches = derived(() => {
    const query = combobox.query.trim().toLowerCase();

    <div ref={combobox.ref} {...combobox.restProps(['children'])} className="demo-combobox">
      <DemoCityInput label="City" />
      <DemoCityPanel>
        <For each={() => matches.value}>
          {([key, city]) => <DemoCityOption value={key}>{city}</DemoCityOption>}
        </For>
        {matches.value.length === 0 ? <div className="demo-combobox-empty">No city matches that.</div> : null}

  );

**Headless Kits** (`@airlib/aria`) eliminates this trade-off. It provides headless behavioral state machines that manage accessibility semantics, keyboard navigation, and composite coordination — written once and usable from React or SolidJS — without imposing any CSS, HTML markup structure, or DOM wrappers.

## Component Integration

In AirLib, components built with `setup` receive reactive `props`. Pass that object straight into the `aria()` factory and the controller binds to the same reactive proxy — no glue code, no change detection, no mirrored state. The accordion below is three of those wrappers, and nothing else:

:::code-group[Accordion]

## The Mental Model

Headless Kits operates on a simple principle: **hand the controller your props, and it hands them back ready to spread**.

As your state changes, the controller compiles the matching HTML and ARIA attributes, wires the keyboard and pointer contract, and returns everything through two touchpoints:

1. **`props`** / **`restProps()`**: Your props with the compiled attributes (`role`, `aria-*`, `tabindex`, `disabled`) merged in and the controller-managed keys removed. It stays reactive, so the element follows your state; `restProps()` additionally drops any keys you name.
2. **`ref`**: The pipe that binds the DOM node, registering keyboard and pointer listeners, synchronizing DOM properties, and handling cleanup on unmount.

The controller owns no element of its own — it writes onto the element you render, so your markup, CSS, and component structure stay entirely yours.

The compiled dictionary is also readable on its own, as the low-level `attributes` getter, with `ownKeys` listing every key the controller writes. Reach for it only when you need the raw attributes themselves.

## Any Element, Same Behavior

The controller never picks the host for you. A native `<button>`, a `<div>`, a `<span>`, even an SVG element — the role behaves the same, because the contract is compiled for whichever element you bind:

- **Native hosts** (`native: true`, default): When the element already carries the semantics (`<button>`, `<input>`), the controller skips redundant ARIA (`role="button"` is never written) and lets the browser own keyboard activation and form submission.
- **Custom hosts** (`native: false`): On anything without built-in semantics — non-interactive tags and SVG elements alike — the controller supplies what the browser will not: it injects the `role`, manages `tabindex` focusability, and handles `Enter` and `Space` activation.

Below, the same toggle is bound twice — once to a `<button>`, once to an `<svg>` — and drives a single favourite:

:::interactive[Two hosts]

```tsx
import { aria } from '@airlib/aria';
import { $bind, mutable, setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type ToggleProps = {
  pressed?: boolean;
};

const NativeStar = setup<ComponentProps<'button'> & ToggleProps>((props) => {
  const toggle = aria('toggle', props);

  return () => (
    <button ref={toggle.ref} {...toggle.restProps(['children'])} className="demo-svg-native">
      {props.children}
    </button>
  );
}, 'NativeStar');

const SvgStar = setup<ComponentProps<'svg'> & ToggleProps>((props) => {
  const toggle = aria<SVGSVGElement>('toggle', props, { native: false });

  return () => (
    <svg
      ref={toggle.ref}
      {...toggle.restProps(['children'])}
      className="demo-svg-host"
      viewBox="0 0 24 24"
      width="44"
      height="44"
    >
      <path d="M12 3.5l2.6 5.3 5.9.9-4.2 4.1 1 5.8-5.3-2.8-5.3 2.8 1-5.8L3.5 9.7l5.9-.9z" />
    </svg>
  );
}, 'SvgStar');

const DemoSvgHosts = setup(() => {
  const state = mutable({ pressed: false });

  return () => (
    <div className="demo-svg-card">
      <div className="demo-svg-hosts">
        <div className="demo-svg-slot">
          <NativeStar pressed={$bind(state, 'pressed')}>Favourite</NativeStar>
          <span className="demo-svg-slot-label">{'<button>'}</span>
        </div>
        <div className="demo-svg-slot">
          <SvgStar pressed={$bind(state, 'pressed')} aria-label="Favourite" />
          <span className="demo-svg-slot-label">{'<svg>'}</span>
        </div>
      </div>
      <span className="demo-svg-note">
        Native host and custom host behaves the same - click, enter, space, and it toggles.
      </span>
    </div>
  );
}, 'DemoSvgHosts');
```
