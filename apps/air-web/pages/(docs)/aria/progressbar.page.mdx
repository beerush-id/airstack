# Progressbar

Long-running tasks such as uploads, exports, and multi-step publishing need to report how far along they are. Assistive technologies expect a progressbar to announce its position within a range, its bounds, and — when the remaining work cannot be measured — to say nothing about position at all rather than claiming a false percentage. Native `<progress>` covers the semantics but cannot be styled; custom bars built from `<div>` elements must compile the range attributes by hand and remember to withdraw them while indeterminate.

`@airlib/aria` provides a headless behavioral bridge for progress indicators. It compiles `role="progressbar"`, projects `aria-valuenow`, `aria-valuemin`, `aria-valuemax`, and `aria-valuetext`, withdraws the position claim when the value is unknown, and maps cleanly onto a native `<progress>` element when you want the browser to own the semantics.

You compose a progressbar using this piece:

- **Progressbar**: The read-only range indicator that compiles determinate and indeterminate progress announcements.

## What you get

- **Honest range announcements.** Compiles `aria-valuenow` with `aria-valuemin` and `aria-valuemax` so the position is reported against real bounds.
- **True indeterminate state.** A `null` value withdraws `aria-valuenow` entirely instead of announcing zero.
- **Readable progress text.** `valuetext` announces meaningful units ("Step 2 of 5") where a raw number would not.
- **Native equivalence.** Pass `native: true` to project onto `<progress>` with no redundant role and no value attribute while indeterminate.

## Progressbar

In Aria, Progressbar is the read-only indicator created with `aria('progressbar')` that compiles range semantics and never takes focus.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'progressbar',
  props?: ProgressbarProps,
  options?: ProgressbarOptions
): ProgressbarAria<E>
```

### Parameters

- `props.value` *(number | null, optional)*: Current progress. `null` or omitted renders the bar indeterminate.
- `props.min` *(number, optional, default `0`)*: Lower bound, compiled to `aria-valuemin`.
- `props.max` *(number, optional, default `100`)*: Upper bound, compiled to `aria-valuemax`.
- `props.valuetext` *(string, optional)*: Human-readable position compiled to `aria-valuetext`.
- `options.native` *(boolean, optional, default `false`)*: Set to `true` when bound to a native `<progress>` host.

The controller compiles no accessible name of its own. Bind `aria-label` or `aria-labelledby` on the element so the indicator is announced with the task it belongs to.

### How it behaves

The progressbar is non-interactive by contract: it emits no `tabindex`, attaches no keyboard or pointer handling, and never mutates its own value — the task reports progress by writing `props.value`. A determinate value compiles `role="progressbar"` with `aria-valuenow` and its bounds. Setting `value` to `null` withdraws `aria-valuenow` from both the compiled dictionary and the mounted element while keeping the bounds, which is how an unmeasurable task stays honestly announced. With `native: true`, the role is omitted because `<progress>` implies it, and the value maps to the native `value` and `max` attributes.

:::tip[Indeterminate is not zero]
Announcing `aria-valuenow="0"` for a task whose progress is unknown tells assistive technologies the task has started and made no progress. Omit the value instead: `value={null}` leaves the bounds announced and the position unstated.
:::

### Usage

To use Progressbar, create the indicator with `aria('progressbar', props)`, then pass `bar.ref` and spread `bar.attributes` onto your track element:

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type ProgressbarProps = ComponentProps<'div'> & {
  value?: number | null;
  min?: number;
  max?: number;
  valuetext?: string;
  label?: string;
};

const Progressbar = setup<ProgressbarProps>((props) => {
  const bar = aria('progressbar', props);
  const restProps = props.$omit([
    ...bar.ownKeys,
    'value',
    'min',
    'max',
    'valuetext',
    'label',
    'children',
    'className',
  ]);

  return () => {
    const value = bar.value;
    const width =
      value === null ? undefined : `${Math.round(((value - bar.min) / (bar.max - bar.min)) * 100)}%`;

    return (
      <div
        ref={bar.ref}
        aria-label={props.label}
        {...restProps}
        {...bar.attributes}
        className={props.className}
      >
        <span className="progress-fill" style={{ width }} />
      </div>
    );
  };
}, 'Progressbar');
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type ProgressbarProps = ComponentProps<'div'> & {
  value?: number | null;
  min?: number;
  max?: number;
  valuetext?: string;
  label?: string;
};

const Progressbar = setup<ProgressbarProps>((props) => {
  const bar = aria('progressbar', props);
  const restProps = props.$omit([
    ...bar.ownKeys,
    'value',
    'min',
    'max',
    'valuetext',
    'label',
    'children',
    'className',
  ]);

  const width = () => {
    const value = bar.value;
    return value === null
      ? undefined
      : `${Math.round(((value - bar.min) / (bar.max - bar.min)) * 100)}%`;
  };

  return (
    <div ref={bar.ref} aria-label={props.label} {...restProps} {...bar.attributes} className={props.className}>
      <span className="progress-fill" style={{ width: width() }} />
    </div>
  );
});
```

:::

The visual fill is entirely yours: the controller supplies the announcements, and the wrapper turns `value`, `min`, and `max` into a width. While indeterminate no width is emitted at all, leaving the track to render its own unmeasured state.

## Putting It Together

Once your component is wired with `aria('progressbar')`, drive it from the task that reports progress:

```tsx
<div className="flex flex-col gap-4">
  <Progressbar label="Uploading assets" value={65} />
  <Progressbar label="Publishing" value={2} max={5} valuetext="Step 2 of 5" />
  <Progressbar label="Preparing workspace" value={null} />
</div>
```

## Keyboard Navigation

- **None.** A progressbar is read-only: it takes no tab stop, claims no keys, and reports progress only through the attributes the task writes to it.
