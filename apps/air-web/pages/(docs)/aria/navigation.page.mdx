# AirLib Headless Navigation

A sidebar nav with twenty links is twenty tab stops a keyboard user has to step through to get past, and to assistive technology the pile is an unnamed group of links with no way to jump to it. **AirLib Headless Navigation** (`aria('navigation')`) compiles `role="navigation"` onto the host you render, names it so it can be jumped to, and carries `Up` / `Down` / `Home` / `End` travel across its links under a single tab stop — wrapping at both ends and passing over disabled links. It travels vertically by default, because a horizontal bar of menus is a [`menubar`](/docs/aria/menu), and a horizontal trail of ancestors is a [`breadcrumb`](/docs/aria/breadcrumb).

```tsx
const nav = aria('navigation', props);

<nav ref={nav.ref} {...nav.restProps(['children'])} />
```

## Navigation

Roving link group and navigation landmark. The container holds the accessible name and the arrow-key travel; the links themselves are ordinary [`aria('link')`](/docs/aria/link) controllers.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'navigation',
  props?: NavigationProps,
  options?: AriaOptions
): NavigationAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type NavigationProps = ComponentProps<'nav'> & {
  label?: string;
  labelledby?: string;
  children: ReactNode;
};

const Navigation = setup<NavigationProps>((props) => {
  const nav = aria('navigation', props);

  return () => (
    <nav ref={nav.ref} {...nav.restProps(['children'])}>
      {props.children}
    </nav>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type NavigationProps = ComponentProps<'nav'> & {
  label?: string;
  labelledby?: string;
};

const Navigation = setup<NavigationProps>((props) => {
  const nav = aria('navigation', props);

  return (
    <nav ref={nav.ref} {...nav.restProps(['children'])}>
      {props.children}
    </nav>
  );
});
```

:::

### Parameters

- `props.label` *(string, optional)*: Accessible label compiled to `aria-label`. There is no default — an unnamed navigation carries no name, because two unnamed navigations on a page are indistinguishable and only you know which is which.
- `props.labelledby` *(string, optional)*: Element ID providing the accessible name, compiled to `aria-labelledby`.
- `options.native` *(boolean, optional, default `true`)*: Leave it for a real `<nav>`, which already implies the role. Pass `false` for a generic host so `role="navigation"` is compiled.

### How it behaves

- Compiles `role="navigation"` on a generic host; on a native `<nav>` the role is omitted and only the name is added.
- `Up` / `Down` move DOM focus to the previous / next enabled link, wrapping at both ends.
- `Home` / `End` move focus to the first / last enabled link.
- Disabled links are passed over in every direction.
- One tab stop for the whole group: the current link sits at `tabindex="0"` and every other link parks at `-1`, reached with the arrow keys.
- `Left` / `Right` are left alone — the group travels vertically, so the horizontal arrows keep their browser behavior.
- No selection state of any kind: no `value`, no `aria-activedescendant`, no `aria-current` invented on your behalf. Activation stays with the link.
- `label` and `labelledby` are consumed by the controller and carried in `ownKeys`, so `restProps(['children'])` is the whole omission list.
- This is the baseline the other link groups extend: [`breadcrumb`](/docs/aria/breadcrumb) and [`pagination`](/docs/aria/pagination) are the same roving group locked to the horizontal axis, each adding its own member semantics.

:::tip[Mark the active link current]
The single tab stop lands on whichever link is `current`, so mark the active one — that is where a keyboard user arrives and where `Tab` leaves from. A horizontal top bar of menus is not this role: use [`menubar`](/docs/aria/menu), whose members are menu items rather than links.
:::

## Keyboard Navigation

- **ArrowDown / ArrowUp**: Moves focus to the next / previous enabled link, wrapping at both ends.
- **Home / End**: Moves focus to the first / last enabled link.
- **ArrowLeft / ArrowRight**: Left to the browser — this group travels vertically.
- **Enter / Space**: Left to the focused link, which navigates itself.
- **Tab**: Left to the browser. From inside the group, `Tab` leaves from the current link — the group's only tab stop.

## What you get

- **One tab stop, not twenty.** Arrow travel across the whole group from a single stop.
- **Named landmark.** `label` or `labelledby` makes the group a jump destination.
- **Wrapped travel.** Arrows wrap from the last link back to the first, and past disabled links.
- **Links stay links.** Native navigation, `aria-current`, and disabled lockout all keep working as themselves.
- **Zero markup lock-in.** Native `<nav>` or a custom host; the container only names the group and moves focus.
