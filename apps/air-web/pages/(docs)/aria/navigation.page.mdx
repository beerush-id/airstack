# AirLib Headless Navigation

Most pages carry more than one set of links: a primary menu, breadcrumbs, a sidebar of related pages, a footer sitemap. Unnamed, they are all announced as "navigation", so jumping between them means listening to each one to find out which is which. **AirLib Headless Navigation** (`aria('navigation')`) compiles `role="navigation"` onto the generic host you already render and turns `label` / `labelledby` into the accessible name that tells two collections apart — while leaving every link inside it to its own controller.

```tsx
const navigation = aria('navigation', props);

<div ref={navigation.ref} {...navigation.restProps(['children'])} />
```

## Navigation

The link collection landmark. It projects navigation semantics onto a generic host and carries the name that separates one collection from another.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'navigation',
  props?: NavigationProps,
  options?: NavigationOptions
): NavigationAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type NavigationProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
  children: ReactNode;
};

const Navigation = setup<NavigationProps>((props) => {
  const navigation = aria('navigation', props);

  return () => (
    <div ref={navigation.ref} {...navigation.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type NavigationProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
};

const Navigation = setup<NavigationProps>((props) => {
  const navigation = aria('navigation', props);

  return (
    <div ref={navigation.ref} {...navigation.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

- `props.label` *(string, optional)*: Accessible label compiled to `aria-label`, distinguishing this navigation from others on the page.
- `props.labelledby` *(string, optional)*: Element ID providing the accessible name, compiled to `aria-labelledby`.
- `options.native` *(boolean, optional, default `false`)*: Pass `true` when the host is a real `<nav>`, which already implies the role — the redundant `role="navigation"` is dropped and only the name is compiled.

### How it behaves

- Compiles `role="navigation"` on a generic host. With `native: true` the role is left to the `<nav>` element and only the accessible name is emitted.
- The role comes from `native` alone — never from the host tag and never from where the element sits in the tree.
- The name is compiled whenever `label` or `labelledby` is present and omitted otherwise, so a page with a single navigation carries no redundant `aria-label`.
- Two unnamed navigations stay unnamed: the controller invents no fallback name and counts no instances. Naming repeated collections is yours.
- Structure only: no `tabindex`, no `aria-orientation`, no `aria-activedescendant`, and no roving focus. Arrow keys keep native scroll and clicks are never swallowed.
- The landmark label never leaks onto the links inside it, and those links keep their own navigation contract.
- `label` and `labelledby` are consumed by the controller and carried in `ownKeys`, so `restProps(['children'])` is the whole omission list — neither leaks to the DOM as a stray attribute.

:::tip[Reserve it for major collections]
`navigation` is for major link collections, not every group of links on a page. Marking a footer's three legal links as a navigation landmark adds noise to the landmark list without helping anyone jump anywhere.
:::

## Keyboard Navigation

- **None.** The landmark takes no tab stop of its own. Keyboard users traverse the links inside it, and assistive technologies jump to it by name.

## What you get

- **Navigation on a generic host.** A `<div>` becomes a jump target with no markup lock-in.
- **Distinguishable collections.** `label` and `labelledby` give each navigation its own announced name.
- **No redundant role.** `native: true` on a real `<nav>` leaves the implicit role alone.
- **Links stay links.** The controls inside keep their own controllers, focus, and activation.
- **Placement-stable output.** The compiled attributes are identical in SSR and after hydration, because nothing is read from the DOM.
