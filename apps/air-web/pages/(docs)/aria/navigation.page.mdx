# Headless Navigation

A navigation group is the run of links every page of a site repeats — a sidebar, a section index, a settings menu.

Getting it right means **naming the landmark so it can be jumped to**, **holding one tab stop instead of one per link**, **roving across the links with the vertical arrows**, **stepping over the disabled ones and wrapping at both ends**, and **leaving the activation, the URL, and the current-page marker to the links themselves**.

**Headless Navigation** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const nav = aria('navigation', props);

<div ref={nav.ref} {...nav.restProps(['children'])} />
```

:::interactive[Project Sections]
```tsx
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type DemoNavigationProps = ComponentProps<'div'> & {
  label?: string;
  children: ReactNode;
};

const DemoNavigation = setup<DemoNavigationProps>((props) => {
  const nav = aria('navigation', props, { native: false });

  return () => (
    <div ref={nav.ref} {...nav.restProps(['children'])} className="demo-navigation-group">
      {props.children}
    </div>
  );
}, 'DemoNavigation');

const DemoNativeNavigation = setup<DemoNavigationProps>((props) => {
  const nav = aria('navigation', props);

  return () => (
    <nav ref={nav.ref} {...nav.restProps(['children'])} className="demo-navigation-group">
      {props.children}
    </nav>
  );
}, 'DemoNativeNavigation');

type DemoNavLinkProps = ComponentProps<'a'> & {
  href: string;
  current?: boolean;
  disabled?: boolean;
};

const DemoNavLink = setup<DemoNavLinkProps>((props) => {
  const link = aria('link', props);

  return () => (
    <a ref={link.ref} {...link.restProps(['children'])} className="demo-navigation-link">
      {props.children}
    </a>
  );
}, 'DemoNavLink');
```

## Navigation

**The group.** It names the landmark and moves focus across the links inside it.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'navigation',
  props?: NavigationProps,
  options?: AriaOptions
): NavigationAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type NavigationProps = ComponentProps<'nav'> & {
  label?: string;
  labelledby?: string;
  children: ReactNode;
};

const Navigation = setup<NavigationProps>((props) => {
  const nav = aria('navigation', props);

  return () => (
    <nav ref={nav.ref} {...nav.restProps(['children'])}>
      {props.children}
    </nav>
  );
}, 'Navigation');
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type NavigationProps = ComponentProps<'nav'> & {
  label?: string;
  labelledby?: string;
};

const Navigation = setup<NavigationProps>((props) => {
  const nav = aria('navigation', props);

  return (
    <nav ref={nav.ref} {...nav.restProps(['children'])}>
      {props.children}
    </nav>
  );
});
```

:::

The links inside are ordinary link controllers:

```tsx
const link = aria('link', { href: '#members', current: false });

<a ref={link.ref} {...link.restProps(['children'])} />
```

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **label** _string, optional_: The landmark's accessible name, compiled to `aria-label`. There is no default, because two unnamed navigations on one page are indistinguishable.
- **labelledby** _string, optional_: The ID of an element already on the page that provides that name, compiled to `aria-labelledby`.

### Options

_What you fix when you create it. Read once, never reactive._

- **native** _boolean, optional, default `true`_: Declares the host. A real `<nav>` already means navigation, so no role is compiled; declare a generic element and the host takes `role="navigation"` instead.

### Properties

_What you read or write on the instance afterwards._

- **label** _string | undefined_: The name in force, yours or the role's own default — which this group does not set.

### How it behaves

- **Both hosts become the landmark.** A generic host compiles `role="navigation"`; a real `<nav>` compiles no role, and the name lands on either.
- **The group holds one tab stop.** With native links inside it, the link marked `current` compiles `tabindex="0"` and every other enabled link compiles `-1`. A link on a custom host is a tab stop of its own whatever the group does.
- **The arrows travel and wrap.** Focus moves down and up the group and wraps at both ends; `Home` and `End` jump to the ends.
- **Disabled links are stepped over.** A disabled link keeps its `href` so it stays discoverable, announces `aria-disabled`, parks at `-1`, and is skipped by every direction of travel.
- **The horizontal arrows are left alone.** The group travels vertically, so `ArrowLeft` and `ArrowRight` keep whatever the browser does with them.
- **Roving never activates.** The arrows move focus and nothing else — no click, no navigation, no page change.
- **It invents no selection.** No `value`, no `aria-activedescendant`, and no `aria-current` written on your behalf; the link compiles `aria-current="page"` from its own `current`.
- **It owns no markup.** The group labels itself and moves focus; the links keep their own navigation, activation, and disabled lockout.

### Navigation

_What the keys do._

- **`ArrowDown` / `ArrowUp`** — the next / previous enabled link, wrapping at both ends.
- **`Home` / `End`** — the first / last enabled link.
- **`Enter`** — left to the focused link, which navigates itself.
- **`ArrowLeft` / `ArrowRight`** — left to the browser; this group travels vertically.
- **`Tab`** — left to the browser, which leaves the group from its own single stop.

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### Navigation

```ts
interface NavigationProps {
  label?: string;
  labelledby?: string;
}

interface NavigationOptions {
  native?: boolean;
}

interface NavigationAttributes {
  role?: 'navigation';
  'aria-label'?: string;
  'aria-labelledby'?: string;
}

declare class NavigationAria {
  get label(): string | undefined;
}
```

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`attributes`** is the dictionary you spread; **`ref`** is what you bind the element with; **`props`** is the full props dictionary for spreading onto the host; **`restProps(omit)`** hands back your props with the keys you name left out.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
