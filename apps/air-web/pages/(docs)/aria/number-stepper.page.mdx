# AirLib Headless Number Stepper

Quantities such as guest counts, nights, and tax rates are picked from a range of discrete values, not typed freely — yet a plain text input accepts anything and announces nothing about bounds, a native `<input type="number">` cannot be styled and cannot announce a human-readable value, and hand-rolled steppers walk arrow keys past their own bounds because nobody clamps every write path. **AirLib Headless Number Stepper** (`aria('number-stepper')`) owns that discipline — a single element carrying the clamped value, its bounds, and the keys that move it, without dictating markup or styles. (For the coordinated unit with step buttons and a group container, see [Stepper](/docs/aria/stepper).)

```tsx
const stepper = aria('number-stepper', props);

<div ref={stepper.ref} {...stepper.props}>
  {stepper.value}
</div>
```

import type { ComponentProps } from 'react';

type DemoNumberStepperProps = ComponentProps<'div'> & {
  value?: number;
  min?: number;
  max?: number;

  disabled?: boolean;
  readonly?: boolean;
  label?: string;

  const stepper = aria('number-stepper', props, { native: true });

  return () => (
    <div className="demo-numberstepper">
      <button
        type="button"
        aria-label="Decrease"
        tabIndex={-1}
        disabled={stepper.disabled || stepper.readonly}
        onClick={() => {
          stepper.value -= stepper.step;
        }}
        className="demo-numberstepperbtn"

          stepper.value += stepper.step;
        }}
        className="demo-numberstepperbtn"
      >
        +
      </button>
    </div>
  );

## Number Stepper

A standalone discrete numeric stepper owning a clamped value within an optional range.

```ts
aria<E extends BaseElement = HTMLInputElement>(
  role: 'number-stepper',
  props?: NumberStepperProps,
  options?: NumberStepperOptions
): NumberStepperAria<E>
```

### Usage

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type NumberStepperProps = ComponentProps<'div'> & {
  value?: number;
  min?: number;
  max?: number;
  step?: number;
  valuetext?: string;
  readonly?: boolean;
  disabled?: boolean;
  required?: boolean;
  label?: string;
};

const NumberStepper = setup<NumberStepperProps>((props) => {
  const stepper = aria('number-stepper', props);

  return () => (
    <div ref={stepper.ref} {...stepper.restProps(['children'])} aria-label={props.label}>
      {stepper.value}
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type NumberStepperProps = ComponentProps<'div'> & {
  value?: number;
  min?: number;
  max?: number;
  step?: number;
  valuetext?: string;
  readonly?: boolean;
  disabled?: boolean;
  required?: boolean;
  label?: string;
};

const NumberStepper = setup<NumberStepperProps>((props) => {
  const stepper = aria('number-stepper', props);

  return (
    <div ref={stepper.ref} {...stepper.restProps(['children'])} aria-label={props.label}>
      {stepper.value}
      {props.children}
    </div>
  );
});
```

:::

On a custom host the controller compiles `role="spinbutton"` with the full range vocabulary and owns the key table; render its `value` as the element text. With `native: true` bind to an `<input type="number">` instead — no role is emitted because the element implies it, the browser keeps its own keys and spinner, and the controller synchronizes typed input back into the value.

### Parameters

- `props.value` *(number, optional)*: Current numeric value, clamped to the bounds on every write. Falls back to `min`, then to `0`.
- `props.min` *(number, optional)*: Lower bound compiled to `aria-valuemin`. Omitted leaves the field unbounded below.
- `props.max` *(number, optional)*: Upper bound compiled to `aria-valuemax`. Omitted leaves the field unbounded above.
- `props.step` *(number, optional, default `1`)*: Increment applied per arrow keystroke and per programmatic step.
- `props.valuetext` *(string, optional)*: Human-readable value compiled to `aria-valuetext` — announced units ("3 nights") where a bare number would not.
- `props.readonly` *(boolean, optional)*: Keeps the field focusable and announced while refusing every key; programmatic writes still land.
- `props.disabled` *(boolean, optional)*: Removes the field from the tab order (`tabindex="-1"`) and announces `aria-disabled`.
- `props.required` *(boolean, optional)*: Required validation indicator, compiled to `aria-required` only when true.
- `options.native` *(boolean, optional, default `false`)*: Set to `true` when bound to a native `<input type="number">`.

The controller compiles no accessible name of its own. Bind `aria-label` or `aria-labelledby` on the element so the quantity being stepped is announced.

:::tip[Page step is a class decision]
Page keys move by ten times `step`, fixed at class-definition level rather than exposed as a prop, so a template consumer cannot turn a quantity stepper into something that jumps by arbitrary amounts. Subclass the controller to rescale it for coarse ranges.
:::

### Events

This face dispatches no events of its own. It owns value, bounds, and spinbutton semantics; every commit is a state write you observe reactively through `props.value`, or on a native host through the browser's own `input`/`change` — which carry no `detail`, so read the element:

```ts
const oninput = (event: Event): void => {
  const value = Number((event.currentTarget as HTMLInputElement).value);
};
```

For a face that emits `input`/`change` `CustomEvent`s carrying the committed number, use the `stepper` composite (its `stepper-input` part dispatches them and takes `oninput`/`onchange`), or the `slider`, which carries its own value events.

### How it behaves

- Every write is clamped — arrow keys, page keys, boundary jumps, typed input, direct assignment, and writes from a parent. Narrowing the range re-clamps a live value that ends up past a bound, and widening back never resurrects the discarded value. Holding a key at a boundary keeps announcing the boundary value.
- Unbounded fields omit `aria-valuemin`/`aria-valuemax`, step without clamping, and leave `Home`/`End` to the browser when their bound is undeclared.
- Readonly stays focusable with `aria-readonly="true"` and refuses every key; disabled leaves the tab order with `aria-disabled="true"` and refuses keys and typed input alike.
- Native hosts project the live value as `defaultValue` — the element stays uncontrolled while props remain the source of truth — with `min`/`max`/`step` carried as native attributes. Typing synchronizes back clamped on the way in; clearing the field withdraws the value instead of claiming zero; non-numeric edits are rejected.

## Putting It Together

Once your component is wired with `aria('number-stepper')`, compose it into bounded quantity fields:

```tsx
<div className="flex flex-col gap-4 max-w-sm">
  <NumberStepper label="Guests" value={2} min={1} max={8} />
  <NumberStepper label="Nights" value={10} min={0} max={60} step={5} />
  <NumberStepper label="Tax rate" value={11} readonly={true} />
</div>
```

## Keyboard Navigation

- **Tab**: Focuses the stepper. A disabled field is skipped entirely (`tabindex="-1"`); a readonly field stays focusable.
- **ArrowUp / ArrowDown**: Step by `step`, holding at `max` / `min`. `ArrowLeft`/`ArrowRight` move the text caret, not the value, and stay with the browser.
- **PageUp / PageDown**: Step by ten times `step`.
- **Home / End**: Jump to `min` / `max` when that bound is declared, left to the browser when it is not.
- **Native hosts**: The browser owns every key above; the controller only synchronizes the resulting value.

## What you get

- **Bounded range announcements.** `aria-valuenow` against `aria-valuemin`/`aria-valuemax`, both omitted when you declare no limits.
- **Clamping on every write.** Keys, typing, assignment, and parent range revisions all land inside the declared range.
- **Readable value text.** `valuetext` announces meaningful units where a bare number would not.
- **Native equivalence.** `native: true` projects onto `<input type="number">` with no redundant role, keeping the browser's own stepper and validation.
