# AirLib Headless Text Input

A text field looks native until you need it headless: syncing live `value` both ways, projecting `label`/`invalid` to ARIA, honoring `readonly` without losing focus, parking disabled tab stops, and — on custom hosts — compiling `textbox`/`searchbox` roles with blur commits, all without fighting the browser's caret, autocomplete, or form submission. **AirLib Headless Text Input** (`aria('text-input')`) turns any element into a field that behaves — native IDL on real inputs, full ARIA polyfills on custom hosts, without dictating markup or styles.

```tsx
const input = aria('text-input', props);

<input ref={input.ref} {...input.props} />
```

## Text Input

Live value synchronization with native and custom hosts.

```ts
aria<E extends BaseElement = HTMLInputElement>(
  role: 'text-input',
  props?: TextInputProps,
  options?: TextInputOptions
): TextInputAria<E>
```

### Usage

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type TextInputProps = ComponentProps<'input'> & {
  value?: string;
  label?: string;
  placeholder?: string;
  required?: boolean;
  invalid?: boolean | 'grammar' | 'spelling';
  disabled?: boolean;
};

const TextInput = setup<TextInputProps>((props) => {
  const input = aria('text-input', props);

  return () => (
    <input ref={input.ref} {...input.restProps(['children'])} />
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type TextInputProps = ComponentProps<'input'> & {
  value?: string;
  label?: string;
  placeholder?: string;
  required?: boolean;
  invalid?: boolean | 'grammar' | 'spelling';
  disabled?: boolean;
};

const TextInput = setup<TextInputProps>((props) => {
  const input = aria('text-input', props);

  return (
    <input ref={input.ref} {...input.restProps(['children'])} />
  );
});
```

:::

The compiled dictionary carries `defaultValue`, never `value` — the element stays uncontrolled while props remain the source of truth. Bind `name` yourself; the projection never emits it.

### Parameters

- `props.value` *(string, optional, default `""`)*: Live text value, read and write.
- `props.kind` *(optional, default `'text'`)*: `'search'` selects the `searchbox` role on custom hosts; every other kind carries `textbox`.
- `props.multiline` *(boolean, optional)*: Compiles `aria-multiline="true"` on custom hosts; the native multiline host is a `<textarea>`.
- `props.label` *(string, optional)*: Accessible label compiled to `aria-label`.
- `props.readonly` *(boolean, optional)*: Blocks edits while keeping focusability.
- `props.disabled` *(boolean, optional)*: Blocks edits and commits; custom hosts park at `tabindex="-1"`.
- `props.required` *(boolean, optional)*: Required validation indicator.
- `props.invalid` *(boolean | 'grammar' | 'spelling', optional)*: Invalid indicator, always compiled explicitly (default `"false"`).
- `props.placeholder` *(string, optional)*: Placeholder hint.
- `props.onchange` *(function, optional)*: Called with the committed text when the value commits.
- `options.native` *(boolean, optional, default `true`)*: Pass `false` for custom non-input elements.

### How it behaves

- Native `<input>`/`<textarea>` hosts emit no `role` and sync `readonly`, `disabled`, `required` IDL properties; browser `input`/`change` pass through and are never re-dispatched. `type` compiles only for the search face — an explicit `undefined` is never emitted, since getter-only hosts throw on assignment.
- Custom hosts compile `role="textbox"` (`searchbox` for `kind: 'search'`), `aria-multiline` only when multiline, always-explicit `aria-readonly`/`aria-disabled`/`aria-required`/`aria-invalid`, and `tabindex` (`0` enabled, `-1` disabled).
- Typing commits to reactive `value` unless blocked by `disabled` or `readonly`. Custom hosts dispatch a bubbling `change` CustomEvent on blur following edits; blurs with no diff stay silent, and blurs while disabled track the value but withhold the event.
- The compiled dictionary carries no form attributes — what the field submits is what the author binds, not the snapshot.

:::tip[Search Queries]
For search fields use the [Search Input](/docs/aria/search-input) face, which locks `type="search"` on native hosts and the `searchbox` role on custom ones.
:::

## Keyboard Navigation

- **Tab**: Focuses the field. Disabled custom hosts sit at `tabindex="-1"` and are skipped.
- **Typing / Backspace / arrows**: Native text editing — caret, selection, and deletion belong to the browser (or the custom host's own editor); the controller only gates and observes.
- **Blur**: Commits the value on custom hosts when it moved.

## What you get

- **Two-way live value.** Typing flows into props, writes flow onto the node, uncontrolled by default.
- **Honest hosts.** Native IDL with zero mirrors; custom ARIA with explicit states and a real tab stop.
- **Validation projection.** Direct `label`/`invalid` inputs with an always-explicit baseline.
- **Observable commits.** Bubbling `change` on custom blur-after-edit, browser passthrough on native.
