# Navigation

Most pages carry more than one set of links: a primary menu, breadcrumbs, a sidebar of related pages, a footer sitemap. Unnamed, they are all announced as "navigation", so jumping between them means listening to each one to find out which is which.

`@airlib/aria` compiles the navigation landmark onto the element you already render. Bound to a native `<nav>` it emits no redundant role; bound to a `<div>` it supplies `role="navigation"`. It compiles the accessible name from `label` or `labelledby`, which is what tells two navigations on the same page apart.

You compose a navigation landmark using this piece:

- **Navigation**: The link collection landmark that compiles `role="navigation"` only when the host does not already imply it.

## What you get

- **Native-first projection.** A `<nav>` keeps its implicit role; a custom host gets an explicit `role="navigation"`.
- **Distinguishable navigations.** `label` and `labelledby` compile to `aria-label` and `aria-labelledby` so each collection is announced by name.
- **Structure only.** The links inside keep their own controllers; the landmark adds no focus and no keyboard behavior.

## Navigation

In Aria, Navigation is the link collection landmark created with `aria('navigation')` that projects navigation semantics onto a native or custom host.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'navigation',
  props?: NavigationProps,
  options?: NavigationOptions
): NavigationAria<E>
```

### Parameters

- `props.label` *(string, optional)*: Accessible label compiled to `aria-label`, distinguishing this navigation from others on the page.
- `props.labelledby` *(string, optional)*: Element ID providing the accessible name, compiled to `aria-labelledby`.
- `options.native` *(boolean, optional, default `true`)*: Pass `false` when binding to a custom `<div>` host.

### How it behaves

With `native: true` the controller compiles only the accessible name and leaves the role to the host. With `native: false` it adds `role="navigation"`. The name is compiled whenever `label` or `labelledby` is present, and omitted otherwise — a page with a single navigation does not need one.

:::tip[Reserve links for major collections]
`navigation` is for major link collections, not every group of links on a page. Marking a footer's three legal links as a navigation landmark adds noise to the landmark list without helping anyone jump anywhere.
:::

### Usage

To use Navigation, create the landmark with `aria('navigation', props)`, then pass `navigation.ref` and spread `navigation.attributes` onto your nav element:

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type NavigationProps = ComponentProps<'nav'> & {
  label?: string;
  labelledby?: string;
};

const Navigation = setup<NavigationProps>((props) => {
  const navigation = aria('navigation', props);
  const restProps = props.$omit([...navigation.ownKeys, 'label', 'labelledby', 'children', 'className']);

  return () => (
    <nav ref={navigation.ref} {...restProps} {...navigation.attributes} className={props.className}>
      {props.children}
    </nav>
  );
}, 'Navigation');
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type NavigationProps = ComponentProps<'nav'> & {
  label?: string;
  labelledby?: string;
};

  return (
    <nav ref={navigation.ref} {...restProps} {...navigation.attributes} className={props.className}>
      {props.children}
    </nav>
  );
});
```

:::

## Putting It Together

Once your component is wired with `aria('navigation')`, name every collection on the page:

```tsx
<Navigation label="Primary">
  <a href="/docs">Docs</a>
  <a href="/blog">Blog</a>
</Navigation>
<Navigation label="Breadcrumb">
  <a href="/docs">Docs</a>
  <span>Aria</span>
</Navigation>
```

## Keyboard Navigation

- **None.** The landmark takes no tab stop of its own. Keyboard users traverse the links inside it, and assistive technologies jump to it by name.
