# Search

Searching is one of the few tasks users want to jump to directly, and it is usually buried inside the header next to the navigation. Identifying the search facility as its own landmark is what lets assistive technologies offer it as a destination instead of making users tab through the header to find the field.

`@airlib/aria` compiles the search landmark onto the element you already render. Bound to a native `<search>` element it emits no redundant role; bound to a `<div>` or a legacy `<form>` host it supplies `role="search"`, and it compiles an accessible name when a page holds more than one search facility.

You compose a search landmark using this piece:

- **Search**: The search facility landmark that compiles `role="search"` only when the host does not already imply it.

## What you get

- **Native-first projection.** A `<search>` element keeps its implicit role; a custom host gets an explicit `role="search"`.
- **Legacy host support.** A `<form>` host compiles the role explicitly, because a form implies `form`, not `search`.
- **Optional naming.** `label` and `labelledby` compile to `aria-label` and `aria-labelledby` when a page holds both a site search and a filtered-table search.

## Search

In Aria, Search is the search facility landmark created with `aria('search')` that projects search semantics onto a native or custom host.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'search',
  props?: SearchLandmarkProps,
  options?: SearchLandmarkOptions
): SearchAria<E>
```

### Parameters

- `props.label` *(string, optional)*: Accessible label compiled to `aria-label`.
- `props.labelledby` *(string, optional)*: Element ID providing the accessible name, compiled to `aria-labelledby`.
- `options.native` *(boolean, optional, default `true`)*: Pass `false` when binding to a `<div>` or `<form>` host that does not imply `search`.

### How it behaves

With `native: true` the controller compiles only the accessible name and leaves the role to the host element. With `native: false` it adds `role="search"`, which is what a `<form>` or `<div>` host needs. The name is compiled when provided and omitted otherwise.

:::tip[The host decides the native flag]
`<search>` is the modern host and implies the role, so the default `native: true` is correct. The legacy `<form role="search">` pattern needs `native: false`, because a `<form>` on its own implies a form landmark — leaving the flag at its default would render a search facility announced as a form.
:::

### Usage

To use Search, create the landmark with `aria('search', props)`, then pass `search.ref` and spread `search.attributes` onto your search container:

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type SearchProps = ComponentProps<'search'> & {
  label?: string;
  labelledby?: string;
};

const Search = setup<SearchProps>((props) => {
  const search = aria('search', props);
  const restProps = props.$omit([...search.ownKeys, 'label', 'labelledby', 'children', 'className']);

  return () => (
    <search ref={search.ref} {...restProps} {...search.attributes} className={props.className}>
      {props.children}
    </search>
  );
}, 'Search');
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type SearchProps = ComponentProps<'search'> & {
  label?: string;
  labelledby?: string;
};

const Search = setup<SearchProps>((props) => {
  const search = aria('search', props);
  const restProps = props.$omit([...search.ownKeys, 'label', 'labelledby', 'children', 'className']);

  return (
    <search ref={search.ref} {...restProps} {...search.attributes} className={props.className}>
      {props.children}
    </search>
  );
});
```

:::

The variable and the JSX tag share the name `search` here, which shadows nothing but reads poorly — rename either one in your own codebase.

## Putting It Together

Once your component is wired with `aria('search')`, wrap the field and its submit control:

```tsx
<Search label="Documentation">
  <input type="search" aria-label="Search documentation" />
  <button type="submit">Search</button>
</Search>
```

## Keyboard Navigation

- **None.** The landmark takes no tab stop of its own. Keyboard users interact with the field and submit control inside it.
