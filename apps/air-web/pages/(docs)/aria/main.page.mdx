# AirLib Headless Main

The reason a page has structure at all is so a user can get to its content. Without a `main` landmark, a screen reader user has no direct route past the header and navigation, and a skip link has nothing to target. A page with more than one `main` breaks that route just as thoroughly, because the destination stops being unique. **AirLib Headless Main** (`aria('main')`) compiles `role="main"` onto the generic host you already render, keeps the landmark free of everything that is not structure, and leaves the `id` that your skip link points at in your hands.

```tsx
const main = aria('main', props);

<div id="content" ref={main.ref} {...main.restProps(['children'])} />
```

## Main

The primary content landmark. It projects main semantics onto a generic host so the document's unique content is reachable in one jump.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'main',
  props?: MainProps,
  options?: MainOptions
): MainAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type MainProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
  children: ReactNode;
};

const Main = setup<MainProps>((props) => {
  const main = aria('main', props);

  return () => (
    <div ref={main.ref} {...main.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type MainProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
};

const Main = setup<MainProps>((props) => {
  const main = aria('main', props);

  return (
    <div ref={main.ref} {...main.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

- `props.label` *(string, optional)*: Accessible label compiled to `aria-label`. Omitted when absent, so an unnamed main region carries no redundant attribute.
- `props.labelledby` *(string, optional)*: Element ID providing the accessible name, compiled to `aria-labelledby`.
- `options.native` *(boolean, optional, default `false`)*: Pass `true` when the host is a real `<main>`, which already implies the role — the redundant `role="main"` is dropped and only the name is compiled.

### How it behaves

- Compiles `role="main"` on a generic host. With `native: true` the role is left to the `<main>` element and only the accessible name is emitted.
- The role comes from `native` alone — never from the host tag and never from where the element sits in the tree.
- `label` compiles to `aria-label` and `labelledby` to `aria-labelledby`, both reactively.
- A second main is compiled unchanged: the controller keeps no registry, counts no instances, and never suppresses a duplicate. Uniqueness is yours to enforce.
- Structure only: no `tabindex`, no `aria-live`, no `aria-busy`, no key handling, and no state. Content inside it keeps its own semantics and its own controllers.
- `label` and `labelledby` are consumed by the controller and carried in `ownKeys`, so `restProps(['children'])` is the whole omission list — neither leaks to the DOM as a stray attribute.

:::tip[Exactly one, and give it an id]
A document holds exactly one `main` landmark. Give the element an `id` and point your skip link at it — the landmark tells assistive technologies where the content is, and the `id` gives keyboard users a way to jump there. The controller compiles neither the `id` nor the skip link.
:::

## Keyboard Navigation

- **None.** The landmark itself takes no tab stop and claims no keys; a skip link pointing at its `id` is what moves focus into it.

## What you get

- **Main on a generic host.** A `<div>` becomes the document's primary content landmark.
- **A skip-link target.** Pair it with an `id` so `<a href="#content">` lands keyboard users directly inside it.
- **No redundant role.** `native: true` on a real `<main>` leaves the implicit role alone.
- **Placement-stable output.** The compiled attributes are identical in SSR and after hydration, because nothing is read from the DOM.
- **Structure only.** No focus, no keys, no state — nothing to keep in sync.
