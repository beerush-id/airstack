# Headless Main

Every page carries one region of primary content, and a landmark is how a user reaches it without walking the header and the navigation first.

Getting it right means **compiling `main` onto a generic host**, **leaving a real `<main>` its implicit role**, **keeping the region free of focus and keys**, and **leaving the skip-link `id` to you**.

**Headless Main** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const main = aria('main', props);

<div id="content" ref={main.ref} {...main.restProps(['children'])} />
```

:::interactive[Document Frame]
```tsx
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type DemoMainProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
  children: ReactNode;
};

const DemoMain = setup<DemoMainProps>((props) => {
  const main = aria('main', props);

  return () => (
    <div ref={main.ref} {...main.restProps(['children'])} className="demo-main">
      {props.children}
    </div>
  );
}, 'DemoMain');
```

:::tip
**Give the host the `id` your skip link points at.** The controller compiles no identifier, so the fragment is yours to name — and a skip link that targets a fragment the page never defines lands nowhere.

## Main

**The main landmark.** It compiles `main` onto a generic host and carries the name the landmark list announces.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'main',
  props?: MainProps,
  options?: MainOptions
): MainAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type MainProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
  children: ReactNode;
};

const Main = setup<MainProps>((props) => {
  const main = aria('main', props);

  return () => (
    <div ref={main.ref} {...main.restProps(['children'])}>
      {props.children}
    </div>
  );
}, 'Main');
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps, JSX } from 'solid-js';

type MainProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
  children: JSX.Element;
};

const Main = setup<MainProps>((props) => {
  const main = aria('main', props);

  return (
    <div ref={main.ref} {...main.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **label** _string, optional_: The name screen readers announce for this region, compiled to `aria-label`. Omitted when absent, so an unnamed page region carries no redundant attribute.
- **labelledby** _string, optional_: The ID of an element already on the page that provides that name, compiled to `aria-labelledby`.

### Options

_What you fix when you create it. Read once, never reactive._

- **native** _boolean, optional, default `false`_: Pass `true` when the host is a real `<main>`, which already implies `main`. The redundant role is dropped and only the name is compiled.

### Properties

_What you read or write on the instance afterwards._

- **label** _string | undefined_: The label in force.
- **labelledby** _string | undefined_: The ID reference in force.
- **named** _boolean_: Whether the landmark carries an accessible name.

### How it behaves

- **Compiles `role="main"` on a generic host.** A `<div>` is announced as the document's primary content, and the role is written whether or not you name it.
- **The role follows `native`, never the host tag.** Pass `native: true` and the element supplies the role itself; a custom host keeps its compiled role wherever you place it.
- **Naming is reactive.** Set, change, or clear `label` or `labelledby` and the projection follows on the next write.
- **Structure only.** No `tabindex`, no `aria-live`, no key handling, and no state of its own; a form or a link inside it keeps its own behavior.
- **Exactly one is your rule.** The controller never counts mains and never suppresses a second one, so a document with two compiles both.
- **The `id` and the skip link are yours.** The controller compiles no identifier, so put `id` on the host and point the skip link at it; the browser jumps to that fragment, and the landmark itself takes no tab stop.
- **Both name props stay off the DOM as plain attributes.** `label` and `labelledby` compile to `aria-label` and `aria-labelledby` only, so `restProps(['children'])` is the whole omission list.

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### Main

```ts
interface MainProps {
  label?: string;
  labelledby?: string;
}

interface MainOptions {
  native?: boolean;
}

interface MainAttributes {
  role?: 'main';
  'aria-label'?: string;
  'aria-labelledby'?: string;
}

declare class MainAria {
  get label(): string | undefined;
  get labelledby(): string | undefined;
  get named(): boolean;
}
```

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`props`** / **`restProps(omit)`** is what you spread onto the host — your props minus the keys the controller writes and any you name, with the compiled attributes merged in; **`ref`** is what you bind the element with; **`attributes`** is that compiled dictionary on its own, when you need the low-level view.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
