# AirLib Headless Announcer

Screen-reader announcements fail in three familiar ways: a status message rendered into a plain `<div>` is never announced at all; a region that marks everything assertive interrupts the user mid-task; and moving focus to the message destroys their place on the page. **AirLib Headless Announcer** (`aria('announcer')`) turns any element into the single live region your UI announces through — polite, whole-message reads by default, with assertive urgency compiling the interrupting `alert` role in place, without dictating markup or styles.

```tsx
const announcer = aria('announcer', props);

<div ref={announcer.ref} {...announcer.props}>
  Draft saved
</div>
```

:::interactive[Announcer Overview]
```tsx
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type DemoAnnouncerProps = ComponentProps<'div'> & {
  politeness?: 'polite' | 'assertive' | 'off';
};

const DemoAnnouncer = setup<DemoAnnouncerProps>((props) => {
  const announcer = aria('announcer', props);

  return () => (
    <div ref={announcer.ref} {...announcer.restProps(['children'])} className="p-4 max-w-sm border border-zinc-200 dark:border-zinc-800 rounded-xl bg-zinc-50/50 dark:bg-zinc-900/50 text-sm text-zinc-800 dark:text-zinc-200">
      {props.children}
    </div>
  );
}, 'DemoAnnouncer');
```

<div className="flex flex-col gap-3 max-w-sm">
  <DemoAnnouncer>Draft saved</DemoAnnouncer>
  <DemoAnnouncer politeness="assertive">Deployment failed: 3 type errors in src/index.ts</DemoAnnouncer>
</div>
:::

## Alert

For urgent failures — a deployment failure, an expired session, a validation error — that cannot wait for the current utterance to finish.

Tuned to `politeness: 'assertive'`, so the message interrupts and is read in full as `role="alert"`.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'announcer',
  props?: AnnouncerProps,
  options?: AnnouncerOptions
): AnnouncerAria<E>
```

### Usage

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { inherit, setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type AlertProps = ComponentProps<'div'> & {
  atomic?: boolean;
  busy?: boolean;
  relevant?: string;
  label?: string;
};

const Alert = setup<AlertProps>((props) => {
  const announcer = aria('announcer', inherit(props, { politeness: 'assertive' }));

  return () => (
    <div
      ref={announcer.ref}
      aria-label={props.label}
      {...announcer.restProps(['label', 'children', 'className'])}
      className={props.className}
    >
      {props.children}
    </div>
  );
}, 'Alert');
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { inherit, setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type AlertProps = ComponentProps<'div'> & {
  atomic?: boolean;
  busy?: boolean;
  relevant?: string;
  label?: string;
};

const Alert = setup<AlertProps>((props) => {
  const announcer = aria('announcer', inherit(props, { politeness: 'assertive' }));

  return (
    <div
      ref={announcer.ref}
      aria-label={props.label}
      {...announcer.restProps(['label', 'children', 'className'])}
      className={props.className}
    >
      {props.children}
    </div>
  );
});
```

:::

### Parameters

- `props.politeness` *('polite' | 'assertive' | 'off', optional, default `'polite'`)*: Announcement priority, compiled to `aria-live`. Urgent alerts set `'assertive'`, which also flips the compiled role to `alert`.
- `props.atomic` *(boolean, optional, default `true`)*: Whether the whole region is announced as one unit, compiled to `aria-atomic`.
- `props.busy` *(boolean, optional)*: Suppresses announcements while the region is updating, compiled to `aria-busy` when set.
- `props.relevant` *(string, optional)*: Change kinds to monitor, compiled to `aria-relevant`.

The controller compiles no accessible name of its own. Bind `aria-label` on the element when the message needs one beyond its text.

### How it behaves

The container is compiled with `role="alert"`, `aria-live="assertive"`, and `aria-atomic` written whenever it is true or explicitly set. `aria-busy` and `aria-relevant` are emitted only when provided, so an idle announcer carries no redundant state. The announcer takes no focus and owns no keyboard behavior: the container must already be in the DOM before content is inserted, or assistive technologies never register it.

:::tip[Mount the container before the message]
Assistive technologies register the live observer when the container appears. An alert rendered together with its text — `{error && <Alert>{error}</Alert>}` — is frequently never announced. Keep the container mounted and write the message into it, clearing it back to empty rather than unmounting.
:::

### Putting It Together

Once your component is wired with `aria('announcer', { politeness: 'assertive' })`, keep it mounted and write messages into it:

```tsx
<Alert label="Deployment status">
  {deployment.error ? `Deployment failed: ${deployment.error}` : ''}
</Alert>
```

:::interactive[Alert Interactive Demo]

### Announcement Behavior

- **On content change**: the whole message is announced immediately, interrupting whatever is currently being read.
- **Focus**: never moves. An alert is not a dialog and takes no focus, no tab stop, and no `Escape`.
- **While `busy`**: announcements are suppressed until the region reports it is finished updating.

## Status

For advisory results — "Draft saved", "5 results found", "Copied to clipboard" — that are useful to hear and safe to miss.

Uses the polite, atomic defaults with no tuning, so the message waits for the current utterance to finish and is then read in full.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'announcer',
  props?: AnnouncerProps,
  options?: AnnouncerOptions
): AnnouncerAria<E>
```

### Usage

:::code-group

```tsx [React] executable

import type { ComponentProps } from 'react';

  atomic?: boolean;
  busy?: boolean;
  relevant?: string;
  label?: string;
};

const Status = setup<StatusProps>((props) => {
  const announcer = aria('announcer', props);

  return () => (
    <div
      ref={announcer.ref}
      aria-label={props.label}
      {...announcer.restProps(['label', 'children', 'className'])}
      className={props.className}
    >
      {props.children}
    </div>
  );
}, 'Status');
```

```tsx [SolidJS]
      {props.children}
    </div>
  );

```

:::

### Parameters

- `props.politeness` *('polite' | 'assertive' | 'off', optional, default `'polite'`)*: Announcement priority, compiled to `aria-live`.
- `props.atomic` *(boolean, optional, default `true`)*: Whether the whole region is announced as one unit, compiled to `aria-atomic`.
- `props.busy` *(boolean, optional)*: Suppresses announcements while the result is loading, compiled to `aria-busy` when set.
- `props.relevant` *(string, optional)*: Change kinds to monitor, compiled to `aria-relevant`.

The controller compiles no accessible name of its own. Bind `aria-label` on the element when the result needs a name beyond its text.

### How it behaves

The container is compiled with `role="status"` and `aria-live` resolved from `politeness`, which defaults to `polite`. `aria-atomic` is written when it is true or explicitly set, and `aria-busy` and `aria-relevant` are emitted only when provided.

:::tip[Status is not a validation error]
A field error the user must act on belongs in an assertive announcer (see [Alert](#alert)), or better, in `aria-invalid` plus `aria-describedby` on the field itself. The default polite announcer is for results that are useful to hear and safe to miss — reserve the interrupting channel for things that are not.
:::

### Putting It Together

Once your component is wired with `aria('announcer')`, keep it mounted next to the control that produces the result:

```tsx
<button onClick={save}>Save draft</button>
<Status label="Save result">{saved ? 'Draft saved' : ''}</Status>
```

### Announcement Behavior

- **On content change**: the whole message is announced as soon as the user's current utterance finishes.
- **Focus**: never moves. The user keeps typing or reading where they were.
- **While `busy`**: announcements are suppressed, so a half-fetched result is never read out.

## Log

For append-only streams — chat histories, audit trails, build output, game feeds — where only the new entry should be heard.

Tuned to `atomic: false` with `relevant="additions"` on grow-only streams, so each appended entry is announced on its own without re-reading the history.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'announcer',
  props?: AnnouncerProps,
  options?: AnnouncerOptions
): AnnouncerAria<E>
```

### Usage

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { inherit, setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type LogProps = ComponentProps<'ul'> & {
  politeness?: 'polite' | 'assertive' | 'off';
  busy?: boolean;
  relevant?: string;
  label?: string;
};

const Log = setup<LogProps>((props) => {
  const announcer = aria('announcer', inherit(props, { atomic: false }));

  return () => (
    <ul ref={announcer.ref} aria-label={props.label} {...announcer.restProps(['label', 'children', 'className'])} className={props.className}>
      {props.children}
    </ul>
  );
}, 'Log');
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { inherit, setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type LogProps = ComponentProps<'ul'> & {
  politeness?: 'polite' | 'assertive' | 'off';
  busy?: boolean;
  relevant?: string;
  label?: string;
};

  const announcer = aria('announcer', inherit(props, { atomic: false }));

  return (
    <ul ref={announcer.ref} aria-label={props.label} {...announcer.restProps(['label', 'children', 'className'])} className={props.className}>
      {props.children}
    </ul>
  );
});
```

:::

### Parameters

- `props.politeness` *('polite' | 'assertive' | 'off', optional, default `'polite'`)*: Announcement priority, compiled to `aria-live`.
- `props.atomic` *(boolean, optional, default `true`)*: Whether the whole stream is announced as one unit. Logs set `false`, which is written explicitly so the history is never re-read.
- `props.busy` *(boolean, optional)*: Suppresses announcements while entries are being fetched, compiled to `aria-busy` when set.
- `props.relevant` *(string, optional)*: Change kinds to monitor, compiled to `aria-relevant`.

The controller compiles no accessible name of its own. Bind `aria-label` on the element so the stream is announced by purpose, such as "Chat messages".

### How it behaves

The container is compiled with `role="status"` and `aria-live` resolved from `politeness`. Setting `atomic: false` writes `aria-atomic="false"` explicitly — re-reading the whole stream is exactly what a log must not do. `aria-busy` and `aria-relevant` are emitted only when provided. Announcement tuning is author-set props rather than engine configuration.

:::tip[Newest last]
A log is announced in source order, so append new entries at the end and keep older ones above. Prepending puts each new message after the last announcement in reading order, which reads as a stream running backwards.
:::

### Putting It Together

Once your component is wired with `aria('announcer', { atomic: false })`, append entries and monitor additions only:

```tsx
<Log label="Build output" relevant="additions">
  {entries.map((entry) => (
    <li key={entry.id}>{entry.text}</li>
  ))}
</Log>
```

### Announcement Behavior

- **On append**: the new entry alone is announced once the user's current utterance finishes.
- **On removal or edit**: nothing is announced while `relevant="additions"` is set.
- **While `busy`**: announcements are suppressed, so a partially loaded batch is never read out.

## Timer

For counters — countdowns, stopwatches, session expiry — that change every second and must not narrate each tick.

Tuned to `politeness: 'off'` so the display updates silently; the count stays in consumer state and milestones are announced from a separate polite or assertive announcer.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'announcer',
  props?: AnnouncerProps,
  options?: AnnouncerOptions
): AnnouncerAria<E>
```

### Usage

:::code-group

```tsx [React] executable

  busy?: boolean;
  label?: string;

  const announcer = aria('announcer', inherit(props, { politeness: 'off' }));

  return () => (
    <div
      ref={announcer.ref}
      aria-label={props.label}
      {...announcer.restProps(['label', 'children', 'className'])}
      className={props.className}
    >
      {props.children}
    </div>
  );
}, 'Timer');
```

```tsx [SolidJS]

  label?: string;

  const announcer = aria('announcer', inherit(props, { politeness: 'off' }));

  return (
    <div
      ref={announcer.ref}
      aria-label={props.label}
      {...announcer.restProps(['label', 'children', 'className'])}
      className={props.className}
    >
      {props.children}
    </div>
  );
});
```

:::

### Parameters

- `props.politeness` *('off' | 'polite' | 'assertive', optional, default `'polite'`)*: Announcement priority, compiled to `aria-live`. Counters set `'off'`.
- `props.atomic` *(boolean, optional, default `true`)*: Whether the whole region is announced as one unit, compiled to `aria-atomic` when set or true.
- `props.busy` *(boolean, optional)*: Suppresses announcements while the count is being recalculated, compiled to `aria-busy` when set.
- `props.relevant` *(string, optional)*: Change kinds to monitor, compiled to `aria-relevant`.

No ARIA attribute exists for elapsed time, so the count is held in your own component state and rendered as children — the controller owns only the announcement contract. The controller also compiles no accessible name — bind `aria-label` so the counter is announced as "Time remaining" rather than as a bare number.

### How it behaves

The container is compiled with `role="status"` and `aria-live="off"`. `aria-atomic` is written when it is true or explicitly set, and `aria-busy` and `aria-relevant` are emitted only when provided. Re-rendering the count writes no attributes, which is what keeps a per-second tick from producing per-second attribute churn.

:::tip[Announce milestones from somewhere else]
Keep the timer silent and push "5 minutes remaining" or "Session expired" into a polite or assertive announcer when the moment arrives. Flipping the timer's own `politeness` to `polite` announces every tick, not just the milestone.
:::

### Putting It Together

Once your component is wired with `aria('announcer', { politeness: 'off' })`, let the ticking source write the count and keep the region silent:

```tsx
<Timer label="Time remaining">{formatRemaining(session.remainingSeconds)}</Timer>
<Status label="Session notice">{session.expired ? 'Session expired' : ''}</Status>
```

- **On every tick**: nothing. `aria-live="off"` keeps the counter silent no matter how fast the display changes.

- **Focus**: never moves, and the display takes no tab stop.

## Marquee

For rotating tickers — stock prices, live scores, arrival boards, news strips — that change faster than anyone can read aloud.

Tuned to `politeness: 'off'` so the region is identified without narrating its rotation; pause state and the pause control stay in consumer state.


### Parameters

- `props.politeness` *('off' | 'polite' | 'assertive', optional, default `'polite'`)*: Announcement priority, compiled to `aria-live`. Tickers set `'off'`.
- `props.atomic` *(boolean, optional)*: Whether the whole region is announced as one unit, compiled to `aria-atomic` when set or true.
- `props.busy` *(boolean, optional)*: Suppresses announcements while the ticker reloads, compiled to `aria-busy` when set.
- `props.relevant` *(string, optional)*: Change kinds to monitor, compiled to `aria-relevant`.

No ARIA attribute exists for a paused ticker, so the pause state lives in your own component state; suspending the animation and rendering the control that toggles it stay with the consumer. The controller also compiles no accessible name — bind `aria-label` so the region is announced as "Market ticker" rather than as a strip of numbers.

### How it behaves

The container is compiled with `role="status"` and `aria-live="off"`. `aria-atomic` is written when it is true or explicitly set, and `aria-busy` and `aria-relevant` are emitted only when provided. A pause control toggling rapidly produces no attribute churn, because the controller owns only the announcement contract.

:::tip[Always ship the pause control]
The pattern is not complete without a way to stop the movement: a rotating ticker is unreadable for users who need more time, and a pause control is also what makes the content reachable. Hold the pause flag in your own state and suspend the animation yourself — the controller compiles the semantics, but it owns no motion.
:::

### Putting It Together

Once your component is wired with `aria('announcer', { politeness: 'off' })`, pair it with the pause control that suspends the motion:

```tsx
<Marquee label="Market ticker">
  {ticker.items.map((item) => (
    <span key={item.symbol}>{item.symbol} {item.change}</span>
  ))}
</Marquee>
<button onClick={() => { ticker.paused = !ticker.paused; }}>
  {ticker.paused ? 'Resume' : 'Pause'}
</button>
```

```tsx
    <div ref={announcer.ref} aria-label={props.label} {...announcer.restProps(['label', 'children'])} className="flex items-center gap-4 overflow-hidden p-3 border border-zinc-200 dark:border-zinc-800 rounded-xl bg-zinc-50/50 dark:bg-zinc-900/50 text-sm tabular-nums text-zinc-700 dark:text-zinc-300">
      {props.children}
    </div>
  );
}, 'DemoMarquee');
```

### Announcement Behavior

- **On rotation**: nothing. `aria-live="off"` keeps the ticker silent no matter how fast the content changes.
- **On pause**: the content stops moving so it can be read, and the announcement policy is unchanged.
- **Focus**: never moves, and the ticker takes no tab stop; the pause control beside it is what the user reaches.

## What you get

- **One region for every announcement.** Polite status by default; assertive urgency flips the compiled role to `alert` in place — no second entity, no remount.
- **Whole-message reads.** Atomic by default, so a replacement reads in full; streams opt out per pattern with `atomic={false}`.
- **Silence on request.** `politeness="off"` keeps counters and tickers identified but unnarrated, with milestones announced from a separate region.
- **Loading suppression.** `busy` holds announcements until the update lands, so partial content is never read out.
- **Zero focus theft.** Regions never take focus, tab stops, or keystrokes — mount the container before the message and write into it.
