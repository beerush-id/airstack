# Headless Stepper

A stepper is a number you nudge. Getting it right means **keeping one value shared by the field, the two buttons, and your own writes**, **clamping every path into it to the same bounds**, **stepping on the vertical and page keys while the horizontal keys stay with the caret**, and **taking a button out of reach the moment it has nowhere left to go**.

**Headless Stepper** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const stepper = aria('stepper', props);

<div ref={stepper.ref} {...stepper.restProps(['children'])}>
  {props.children}
</div>
```

## Stepper

**The group and the number.** Bounds, step size, and the current value live here, and every part reads them.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'stepper',
  props?: StepperProps
): StepperAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type QtyProps = ComponentProps<'div'> & {
  value?: number;
  min?: number;
  max?: number;
  step?: number;
};

const Qty = setup<QtyProps>((props) => {
  const stepper = aria('stepper', props);

  return () => (
    <div ref={stepper.ref} {...stepper.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

The field and the two buttons are components of their own, composed inside this one — see **[Stepper Input](#stepper-input)** and **[Step Button](#step-button)**.

### Parameters

_What you pass in. The props object stays live — change a bound and the parts re-derive without rebinding._

- **value** _number, optional_: The current number. It is read back **with the bounds already applied**, and falls back to `min`, then to `0`.
- **min** _number, optional_: The inclusive lower bound. Left out, the stepper is unbounded below and decrement never gives up.
- **max** _number, optional_: The inclusive upper bound. Left out, the stepper is unbounded above and increment never gives up.
- **step** _number, optional, default `1`_: How far a button press or a stepping key moves.
- **page** _number, optional, default `10`_: How far `PageUp` and `PageDown` travel.
- **disabled** _boolean, optional_: Locks the whole stepper: both buttons go inert and the field leaves the tab order.
- **readonly** _boolean, optional_: Refuses steps and typing. The field leaves the tab order yet stays focusable, and the step buttons disarm.
- **required** _boolean, optional_: Says a value must be given. The constraint is carried by the field, not the group.
- **valuetext** _string, optional_: What the number is called out as, so a field showing `150` can be announced as “150 US dollars”.

### Properties

_What you read on the instance afterwards._

- **value** _number_: The number with the bounds applied, on read and on write. This is the read/write surface for your code.
- **min** _number | undefined_: The lower bound, or nothing when it is unbounded below.
- **max** _number | undefined_: The upper bound, or nothing when it is unbounded above.
- **step** _number_: The step increment in use.
- **page** _number_: The page distance in use.
- **disabled** _boolean_: Whether the whole stepper is locked.
- **readonly** _boolean_: Whether the value is closed to the user while staying readable.

### Methods

_What you call on the instance._

- **`commit(raw, notify?)`** → `boolean`: Runs an untrusted reading through the bounds and reports whether it changed anything. Every button press, keystroke, and typed value goes through this door — call it yourself only when you are writing another part.

### How it behaves

- **Every path commits through the same bounds.** Button presses, stepping keys, typed values, and your own writes all go through one commit, so the field can never disagree with the buttons.
- **The container owns the stepping keys.** `ArrowUp`, `ArrowDown`, `PageUp`, `PageDown`, `Home`, and `End` are consumed wherever focus sits inside the group. `ArrowLeft`, `ArrowRight`, and every other key stay with the user — the caret travels, the number does not.
- **A commit is announced by the stepper.** `input` fires per active interaction and `change` fires the moment the value actually moves, both on the container's DOM and its `on*` props; a typed keystroke also reports to the field's `oninput`.
- **The group is only a group.** The container compiles `role="group"` and never takes the value role itself, which is what lets the parts sit inside it in any order you like.
- **Parts bind by containment.** An `aria('stepper-input')`, `aria('stepper-inc')`, or `aria('stepper-dec')` inside this group reads from it — no ids, no prop drilling, and two steppers on one page never reach into each other.
- **Bounds are inclusive.** A write past `max` lands on `max`; an undeclared bound means no clamp in that direction, and `Home`/`End` leave the key to the browser when the bound they would jump to does not exist.
- **Disabled locks the whole group.** The field leaves the tab order and both buttons go inert at once — and a click on a disarmed part is cancelled and stopped from bubbling, so nothing above it reacts either.

## Stepper Input

**The field.** It shows the number, takes a typed one, and lets the stepping keys pass through to the group.

### Usage

```ts
aria<E extends BaseElement = HTMLInputElement>(
  role: 'stepper-input',
  props?: StepperInputProps,
  options?: StepperInputOptions
): StepperInputAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type QtyFieldProps = ComponentProps<'input'> & {
  oninput?: (event: CustomEvent<number>) => void;
  onchange?: (event: CustomEvent<number>) => void;
};

const QtyField = setup<QtyFieldProps>((props) => {
  const input = aria('stepper-input', props, { native: true });

  return () => <input ref={input.ref} {...input.restProps()} />;
});
```

```tsx [SolidJS]

import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

  oninput?: (event: CustomEvent<number>) => void;
  onchange?: (event: CustomEvent<number>) => void;
};

const QtyField = setup<QtyFieldProps>((props) => {
  const input = aria('stepper-input', props, { native: true });

  return <input ref={input.ref} {...input.restProps()} />;
});
```

:::

### Parameters

_What you pass in._

- **oninput** _(event: CustomEvent&lt;string | number | undefined | null&gt;) =&gt; void, optional_: Called with the value at each typed keystroke.
- **onchange** _(event: CustomEvent&lt;number | undefined&gt;) =&gt; void, optional_: Called with the committed value when the value actually moves.

### Options

_What you fix when you create it. Read once, never reactive._

- **native** _boolean, optional, default `false`_: Set `true` on a real `<input>`. The controller compiles it as a plain text input and parses every reading itself, so no browser spinner ever fights the stepping keys. On a custom host the element is compiled as a `spinbutton` with plaintext `contenteditable`, and the controller writes the number as its text — render no children of your own.

### Properties

_What you read on the instance afterwards._

- **value** _number_: The number coming from the group — `0` when the field is on its own with no stepper around it.

### How it behaves

- **Typing commits only valid decimals.** Every keystroke parses as a strict decimal: a valid reading commits through the bounds, an invalid one keeps the current value and is never silently zeroed. Blur commits a valid reading or restores the last committed value to the field.
- **Enter and Space are bypassed.** On the field they are prevented so they cannot submit the form around it; they never step.
- **Readonly removes editability.** A custom host drops `contenteditable` entirely, the field leaves the tab order, and the stepping keys pass through unconsumed so the caret still travels.
- **The spinbutton vocabulary comes from the group.** `aria-valuenow`, `aria-valuemin`, `aria-valuemax`, and your `valuetext` are compiled from the group, so the number a screen reader hears is the number the buttons are working on.
- **A native host stays a plain input.** `type="text"`, `value`, `readonly`, `disabled`, and `required` are set on the element itself and no ARIA mirror is emitted beside them.
- **A custom host keeps the caret.** Keyboard focus selects the whole number, and the controller's own text writes preserve the selection the user had.

### Events

_What it tells you._

- **`input`** — fires per active interaction: a stepping key, a button step, or a typed keystroke. Stepping paths announce on the stepper; a typed keystroke announces on this part's `oninput`, handler-only.
- **`change`** — fires the moment the value actually changes, whoever changed it, with the committed number in `detail`. It is announced on the stepper, not on the field.

On the container both are dispatched as `CustomEvent`s, so a listener of your own hears them. On a native `<input>` the browser's own `input` passes through untouched and the announcement goes to your props only — never replayed onto the element.

```tsx
const stepper = aria('stepper', {
  oninput: (event) => previewPrice(event.detail),
  onchange: (event) => save(event.detail),
});
```

### Navigation

_What the keys do._

- **`ArrowUp` / `ArrowDown`** — step by `step`, consumed by the group.
- **`PageUp` / `PageDown`** — travel by `page`, consumed by the group.
- **`Home` / `End`** — jump to `min` / `max`, and stay the browser's own keys when that bound was never declared.
- **`ArrowLeft` / `ArrowRight`** — stay with the user: caret travel, never stepping.
- **`Enter` / `Space`** — bypassed on the field so the surrounding form is safe.
- **Typing** — reaches the shared value through the bounds as strict decimals. `Tab` is never taken.

Nothing is consumed while the group is disabled or readonly.

## Step Button

**`+` and `−`.** The same part pointed two ways, each giving up at its own bound.

### Usage


### Properties

_What you read on the instance afterwards._

- **disabled** _boolean_: Whether this button has work left to do — `true` when there is no group around it, when the group is disabled or readonly, or when the value is already at the bound it would step toward.

### Methods

_What you call on the instance._

- **`click()`**: Runs one step. _Does nothing when the button is out of reach._

### How it behaves

- **It disables at its own bound.** Decrement goes inert at `min`, increment at `max`, and the other stays live — with no bound declared in its direction, a button never disarms.
- **It re-enables on the same element.** Moving the value back from the bound, or lifting the group's `disabled`, brings the button back without rebinding anything.
- **One press, one step.** Activation commits `value + direction * step` through the bounds, the stepper announces it live, and a press at a bound changes nothing.
- **It sits outside the tab order.** `tabindex="-1"` keeps the field the single tab stop; the buttons are auxiliary and reach by pointer or by their own `click()`.
- **It is written for a `<button>`.** `type="button"` and `disabled` are compiled so the trigger can never submit the form around it, and the browser's own click, `Enter`, and `Space` are what activate it.

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`props`** / **`restProps(omit)`** is what you spread onto the host — your props minus the keys the controller writes and any you name, with the compiled attributes merged in; **`ref`** is what you bind the element with; **`attributes`** is that compiled dictionary on its own, when you need the low-level view.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
