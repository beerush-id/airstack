# Separator

Dividers carry two very different jobs. A static rule only structures content, and announcing it as an interactive element is noise; a resizable pane boundary is a real control that must take focus, announce where the split currently sits, and move under arrow keys. Both are usually built by hand, and the movable one tends to ship without `aria-valuenow` or clamping, so assistive technologies report a widget that says nothing about its position.

`@airlib/aria` provides a headless behavioral bridge for both. It keeps static dividers unfocusable and value-less, emits `role="separator"` only when the host element does not already imply it, announces `aria-orientation` when the divider departs from horizontal, and promotes the divider into a range widget with a tab stop, clamped `aria-valuenow`, and arrow-key adjustment when `movable` is set.

You compose a separator using these pieces:

- **Separator**: The static structural divider that stays out of the tab order.
- **Splitter**: The movable face of the same controller, owning a tab stop and keyboard-driven partition adjustment.

## What you get

- **Quiet static dividers.** No `tabindex`, no value attributes, and no redundant `role` on a native `<hr>`.
- **Correct role projection.** `role="separator"` is compiled only for custom elements that do not imply it.
- **A real splitter control.** `movable` promotes the divider to a focusable range widget announcing `aria-valuenow` against `aria-valuemin` and `aria-valuemax`.
- **Clamped keyboard adjustment.** Arrow keys move the partition and hold it at the declared boundaries instead of overshooting.

## Separator

In Aria, Separator is the divider created with `aria('separator')` that compiles structural semantics and, when `movable` is set, range behavior.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'separator',
  props?: SeparatorProps,
  options?: SeparatorOptions
): SeparatorAria<E>
```

### Parameters

- `props.movable` *(boolean, optional, default `false`)*: Promotes the divider into an interactive splitter.
- `props.value` *(number, optional)*: Current partition position when movable; defaults to `min`.
- `props.orientation` *('horizontal' | 'vertical', optional, default `'horizontal'`)*: Divider axis, announced as `aria-orientation` only when vertical.
- `props.min` *(number, optional, default `0`)*: Lower partition bound, compiled to `aria-valuemin`.
- `props.max` *(number, optional, default `100`)*: Upper partition bound, compiled to `aria-valuemax`.
- `options.native` *(boolean, optional, default `true`)*: Pass `false` when binding to a custom `<div>` or `<span>` host.

The controller compiles no accessible name of its own. Bind `aria-label` on a movable splitter so the partition it controls is announced.

### How it behaves

A static separator is projection only: on a native `<hr>` nothing but `aria-orientation` is emitted, since the element already implies the role, and on a custom host `role="separator"` is added while `tabindex` and every `aria-value*` attribute stay off the element. Setting `movable` recompiles the same controller into a range widget with `role="separator"`, `tabindex="0"`, and a clamped `aria-valuenow`, and attaches arrow-key handling that writes back to `props.value`.

:::tip[movable is an authoring decision]
`movable` is a prop, not an engine option, so a component author decides whether the divider is structural or interactive — a template consumer never flips a static rule into a control. The arrow-key step is fixed at class-definition level; subclass the controller to rescale it for pixel-based partitions.
:::

### Usage

To use Separator, create the divider with `aria('separator', props)`, then pass `separator.ref` and spread `separator.attributes` onto your rule element:

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type SeparatorProps = ComponentProps<'hr'> & {
  orientation?: 'horizontal' | 'vertical';
};

const Separator = setup<SeparatorProps>((props) => {
  const separator = aria('separator', props);
  const restProps = props.$omit([...separator.ownKeys, 'className']);

  return () => (
    <hr ref={separator.ref} {...restProps} {...separator.attributes} className={props.className} />
  );
}, 'Separator');
```


## Movable Splitter

The splitter is the same controller with `movable` set. It binds to the element that receives focus and arrow keys — the track — and renders the fill and thumb as your own presentation.

### How it behaves

The mounted track carries `role="separator"`, `tabindex="0"`, `aria-valuenow`, `aria-valuemin`, and `aria-valuemax`. `ArrowRight` and `ArrowDown` advance the partition; `ArrowLeft` and `ArrowUp` retreat it, on either axis. Every write is clamped to the declared range, so holding an arrow key at a boundary keeps announcing the boundary value instead of drifting past it. Every other key is left to the browser.

### Usage

To use a splitter, pass `movable` through to `aria('separator', props)` and drive your fill and thumb from `separator.value`:

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type SplitterProps = ComponentProps<'div'> & {
  movable?: boolean;
  value?: number;
  min?: number;
  max?: number;
  label?: string;
};

const Splitter = setup<SplitterProps>((props) => {
  const separator = aria('separator', props);
  const restProps = props.$omit([
    ...separator.ownKeys,
    'movable',
    'value',
    'min',
    'max',
    'label',
    'children',
    'className',
  ]);

  return () => {
    const span = separator.max - separator.min;
    const percent = span > 0 ? ((separator.value - separator.min) / span) * 100 : 0;

    return (
      <div
        ref={separator.ref}
        aria-label={props.label}
        {...restProps}
        {...separator.attributes}
        className={props.className}
      >
        <span className="splitter-fill" style={{ width: `${percent}%` }} />
        <span className="splitter-thumb" style={{ left: `${percent}%` }} />
      </div>
    );
  };
}, 'Splitter');
```

## Keyboard Navigation

- **Tab**: Focuses a movable splitter. Static dividers take no tab stop and are skipped entirely.
- **ArrowRight / ArrowDown**: Advances the partition by one step, holding at `max`.
- **ArrowLeft / ArrowUp**: Retreats the partition by one step, holding at `min`.
- **Every other key**: Left unclaimed for the browser and surrounding widgets.
