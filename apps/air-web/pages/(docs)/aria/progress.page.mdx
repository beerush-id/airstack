# Headless Progress

A progress bar reports how far a task has come. Getting it right means **clamping every read without rewriting what the task wrote**, **mapping declared bounds onto the native scale**, **withdrawing the position while nothing is measurable**, and **taking no focus, keys, or pointer**.

**Headless Progress** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const bar = aria('progress', props, { native: false });

<div ref={bar.ref} {...bar.restProps(['children'])} />
```

  max?: number;

## Progress

**The indicator.** It holds the reported position, the declared bounds, and the mapping between them, and it is the only part of the widget.

### Usage

```ts
progress<E extends BaseElement = HTMLProgressElement>(
  props?: ProgressProps,
  options?: ProgressOptions
): ProgressAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type ProgressProps = ComponentProps<'div'> & {
  value?: number | null;
  min?: number;
  max?: number;
  label?: string;
  valuetext?: string;
};

const Bar = setup<ProgressProps>((props) => {
  const bar = aria('progress', props, { native: false });

  return () => (
    <div ref={bar.ref} {...bar.restProps(['children'])}>
      <span className="bar-fill" />
    </div>
  );
});
```

Style the fill against the published variable — no math in the component:

```css
.bar-fill {
  display: block;
  height: 100%;
  width: var(--aria-progress-offset, 0%);
}
```

Bind a real `<progress>` without options and the browser keeps its own semantics:

```tsx
const bar = aria('progress', props);

<progress ref={bar.ref} {...bar.restProps(['children'])} />
```

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **value** _number | null, optional_: Completion number, clamped into the declared range on every read; `null` or omitted reports an unmeasurable task. The prop itself keeps the number the task wrote.
- **min** _number, optional, default `0`_: Lower bound of the declared interval.
- **max** _number, optional, default `100`_: Upper bound of the declared interval.
- **label** _string, optional_: Accessible name, compiled to `aria-label` on a custom host only.
- **valuetext** _string, optional_: Human-readable position, compiled to `aria-valuetext` on both hosts.

### Options

_What you fix when you create it. Read once, never reactive._

- **native** _boolean, optional, default `true`_: Set `false` on a custom element. The custom host then carries the role, the ARIA bounds, and the offset variable; the native host compiles `value` and `max` only.

### Properties

_What you read or write on the instance afterwards._

- **value** _number | null_: The clamped reading, or `null` while unmeasurable. Writing it updates `props.value`.
- **indeterminate** _boolean_: Whether the current reading is `null`.
- **offset** _number | null_: Completion as `0`–`100` along the declared interval — the numeric content of the published variable, unchanged — or `null` while unmeasurable.
- **min** / **max** _number_: The declared bounds in use, defaults filled in.

### How it behaves

- **Every read clamps, the prop never changes.** A report of `140` against `max={100}` reads as `100` while `props.value` stays `140`; narrowing `max` under a live reading lowers what is announced, and widening it back does not resurrect the old number.
- **Custom hosts keep declared units.** The host compiles `role="progressbar"` with `aria-valuenow` carrying the clamped reading, `aria-valuemin` / `aria-valuemax` carrying the declared bounds, and `aria-label` from `label`.
- **Native hosts shift to zero.** The declared interval becomes `value = clamped - min` and `max = max - min`, with no `min` attribute and no role — so `min={20}` with `max={60}` and a reading of `45` compiles `value="25"` and `max="40"`.
- **The fill reads one published fraction.** A custom host carries `--aria-progress-offset` for your stylesheet to size against, and a span of zero or less reports `offset` `0` instead of dividing by the gap.
- **No position while unmeasurable.** A `null` reading omits `aria-valuenow` on a custom host and removes the `value` attribute on a native one, while the declared bounds stay stated.
- **Nothing to interact with.** No tab stop, no keys, no pointer, no events — the indicator reports and nothing more.
- **`valuetext` is the one ARIA mirror that reaches both hosts.** `label` names a custom host only, so a native `<progress>` takes its `aria-label` from you.

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### Progress

```ts
interface ProgressProps {
  value?: number | null;
  min?: number;
  max?: number;
  label?: string;
  valuetext?: string;
}

interface ProgressOptions {
  native?: boolean;
}

interface ProgressAttributes {
  value?: number;
  max?: number;
  role?: 'progressbar';
  'aria-valuenow'?: number;
  'aria-valuemin'?: number;
  'aria-valuemax'?: number;
  'aria-valuetext'?: string;
  'aria-label'?: string;
}

declare class ProgressAria {
  get value(): number | null;
  set value(value: number | null);
  get indeterminate(): boolean;
  get offset(): number | null;
  get min(): number;
  get max(): number;
}
```

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`props`** / **`restProps(omit)`** is what you spread onto the host — your props minus the keys the controller writes and any you name, with the compiled attributes merged in; **`ref`** is what you bind the element with; **`attributes`** is that compiled dictionary on its own, when you need the low-level view.
