# AirLib Headless Progress

A task bar looks like a filled track until the platform gets involved: out-of-range reports must clamp without rewriting what the task wrote, custom hosts must announce declared units while native `<progress>` speaks a zero-based range, an unmeasurable task must withdraw its position instead of claiming zero, and none of it may ever take focus or keys. **AirLib Headless Progress** (`aria('progress')`) owns that normalization — one read-only indicator that compiles honest announcements on either host, without dictating markup or styles.

```tsx
const bar = aria('progress', props);

<progress ref={bar.ref} {...bar.props} />
```

## Progress

Task-completion reporting normalized across native `<progress>` and custom elements.

```ts
aria<E extends BaseElement = HTMLProgressElement>(
  role: 'progress',
  props?: ProgressProps,
  options?: ProgressOptions
): ProgressAria<E>
```

### Usage

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type ProgressProps = ComponentProps<'div'> & {
  value?: number | null;
  min?: number;
  max?: number;
  label?: string;
  valuetext?: string;
};

const Progress = setup<ProgressProps>((props) => {
  const bar = aria('progress', props, { native: false });

  return () => (
    <div ref={bar.ref} {...bar.restProps(['children'])} className={props.className}>
      <span className="progress-fill" />
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type ProgressProps = ComponentProps<'div'> & {
  value?: number | null;
  min?: number;
  max?: number;
  label?: string;
  valuetext?: string;
};

const Progress = setup<ProgressProps>((props) => {
  const bar = aria('progress', props, { native: false });

  return (
    <div ref={bar.ref} {...bar.restProps(['children'])} className={props.className}>
      <span className="progress-fill" />
    </div>
  );
});
```

:::

Style the fill against the published variable — no math in the component:

```css
.progress-fill {
  display: block;
  height: 100%;
  width: var(--aria-progress-offset);
}
```

For the native host, bind without options and let the browser own the semantics — no role is emitted because `<progress>` implies it:

```tsx
const bar = aria('progress', props);

<progress ref={bar.ref} {...bar.props} />
```

### Parameters

- `props.value` *(number | null, optional)*: Completion number, clamped to `[min, max]` on every read without rewriting the input. `null` or omitted renders the bar indeterminate.
- `props.min` *(number, optional, default `0`)*: Lower bound of the declared interval.
- `props.max` *(number, optional, default `100`)*: Upper bound of the declared interval.
- `props.label` *(string, optional)*: Accessible name compiled to `aria-label` on custom hosts.
- `props.valuetext` *(string, optional)*: Human-readable position compiled to `aria-valuetext`.
- `options.native` *(boolean, optional, default `true`)*: Pass `false` for custom non-progress elements.

### How it behaves

- Every read clamps into `[min, max]` while `props.value` keeps exactly what the task wrote — narrowing the range re-clamps a live value that ends up past a bound, and widening back never resurrects the discarded reading.
- Custom hosts keep declared units: `role="progressbar"` with `aria-valuenow` carrying the clamped value, `aria-valuemin`/`aria-valuemax` carrying the declared bounds, and `aria-label` naming the task.
- Native hosts map the declared interval onto the zero-based scale both directions read identically: `max = max - min`, `value = clampedValue - min`, no `min` attribute, no role, no ARIA mirrors.
- A `null` value withdraws the position on both hosts — `aria-valuenow` omitted on custom, the `value` attribute removed on native — while the scale stays declared.
- The indicator is non-interactive by contract: no `tabindex`, no keys claimed, no pointer claimed, no events dispatched, focus never moves.
- Fills size themselves from `--aria-progress-offset`, published on custom hosts in compiled `style`. Script consumers read the same percentage from `bar.offset` (`0`–`100`, `null` while indeterminate) — the numeric content of the variable, with no conversion.

## Putting It Together

Once your components are wired with `aria(...)`, drive them from the task that reports progress:

```tsx
<div className="flex flex-col gap-4 max-w-sm">
  <Progress label="Uploading assets" value={65} />
  <Progress label="Transcoding segments" value={45} min={20} max={60} valuetext="45 of 60 segments" />
  <Progress label="Preparing workspace" value={null} />
</div>
```

## Keyboard Navigation

- **None.** Progress is read-only: it takes no tab stop, claims no keys, and reports progress only through the attributes the task writes to it.

## What you get

- **Clamp-on-read honesty.** Out-of-range reports land inside the declared range while the task's own value stays untouched.
- **Two hosts, one fraction.** Declared units on custom hosts and zero-based mapping on native hosts report the same completion.
- **True indeterminate state.** A `null` value withdraws the position on both hosts instead of announcing zero.
- **Zero interaction.** No tab stop, no keys, no events — the task writes, the indicator announces.
