# Headless Tabs

A tabbed interface shows one panel at a time behind a strip of triggers. Getting it right means **linking every trigger to its panel**, **keeping the strip at a single tab stop**, **letting the arrow keys move focus without swapping panels**, and **telling your code when the selection changes**.

**Headless Tabs** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const tabs = aria('tab', props);

<div ref={tabs.ref} {...tabs.restProps(['children'])} />
```

:::interactive[Account Settings Tabs]
```tsx
import { aria } from '@airlib/aria';

type DemoTabsProps = ComponentProps<'div'> & {

const DemoTabs = setup<DemoTabsProps>((props) => {
  const tabs = aria('tab', props);
```

## Tab

**The group as a whole.** It holds which tab is open, and the list, the buttons, and the panels all follow it.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'tab',
  props?: TabProps
): TabAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type TabsProps = ComponentProps<'div'> & {
  id?: string;
  value?: string;
  orientation?: 'horizontal' | 'vertical';
  disabled?: boolean;
  onchange?: (event: CustomEvent<string>) => void;
};

const Tabs = setup<TabsProps>((props) => {
  const tabs = aria('tab', props);

  return () => (
    <div ref={tabs.ref} {...tabs.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type TabsProps = ComponentProps<'div'> & {
  id?: string;
  value?: string;
  orientation?: 'horizontal' | 'vertical';
  disabled?: boolean;
  onchange?: (event: CustomEvent<string>) => void;
};

const Tabs = setup<TabsProps>((props) => {
  const tabs = aria('tab', props);

  return (
    <div ref={tabs.ref} {...tabs.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **id** _string, optional_: The prefix both sides of the pairing are built from. Generated as `tab-<n>` when you leave it out, so buttons end up as `{id}-tab-{name}` and panels as `{id}-tabpanel-{name}`.
- **value** _string, optional_: The `name` of the open tab. When you leave it out, a button with `selected` takes it, otherwise the first button to mount does.
- **orientation** _'horizontal' | 'vertical', optional, default `'horizontal'`_: Whether the strip runs across or down — which arrow keys move through it, and what screen readers are told.
- **disabled** _boolean, optional_: Locks switching and arrow keys across the **whole group**.
- **onchange** _(event: CustomEvent&lt;string&gt;) =&gt; void, optional_: Called whenever the open tab changes, with the new tab's `name` in `detail`.

### Properties

_What you read or write on the instance afterwards._

- **id** _string_: The prefix in use, generated when you left it out.

### Methods

_What you call on the instance._

- **`list(props?)`** → `TabListAria`: Creates a tab list belonging to this group.
- **`button(props, options?)`** → `TabButtonAria`: Creates a trigger belonging to this group.
- **`panel(props)`** → `TabPanelAria`: Creates a panel belonging to this group.
- **`TabAria.configure(config)`** _static_: Sets the default `orientation` for every group created afterwards.

### How it behaves

- **One tab is always open.** Clicking the tab that is already open changes nothing and fires no event, so the group can never end up empty.
- **You drive it or it drives itself.** Leave `value` out and the group keeps its own selection; set it and the group follows your state.
- **Switching is cancellable.** Calling `preventDefault` on the click stops both the switch and the event.
- **One flag disables everything.** `disabled` on the group leaves every trigger visible but inert — no switching, no arrow keys.
- **Panels don't have to live inside it.** The group is an ordinary container with no meaning of its own, so your layout stays yours.

### Events

_What it tells you._

- **`change`** — fires when a different tab opens, with the new tab's `name` in `detail`.

```tsx
const tabs = aria('tab', {
  value: 'account',
  onchange: (event) => submit(event.detail),
});
```

## Tab List

**The strip of triggers.** It handles the arrow keys and keeps the whole strip at one tab stop.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'tab-list',
  props?: TabListProps
): TabListAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type TabListProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
};

const TabList = setup<TabListProps>((props) => {
  const list = aria('tab-list', props);

  return () => (
    <div ref={list.ref} {...list.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type TabListProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
};

const TabList = setup<TabListProps>((props) => {
  const list = aria('tab-list', props);

  return (
    <div ref={list.ref} {...list.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **label** _string, optional_: The name screen readers give the strip, so **two tab groups on one page** stay distinguishable.
- **labelledby** _string, optional_: The ID of an element already on the page that provides the name.

### Properties

_What you read or write on the instance afterwards._

- **orientation** _'horizontal' | 'vertical'_: The direction this strip runs, taken from the group it belongs to.

### How it behaves

- **Arrow keys move focus, never the selection.** Walking the strip by keyboard doesn't swap panels behind the user.
- **One tab stop for the whole strip.** Tabbing in lands on the open trigger; the arrows reach the rest.
- **Disabled triggers are skipped.** Arrow keys step over them, and a group disabled at the top doesn't move at all.
- **Screen readers get a named list.** The strip is announced as a tab list running in the direction you set.

### Navigation

_What the keys do._

- **`ArrowRight` / `ArrowLeft`** on a horizontal strip — focus the **next / previous** enabled tab, wrapping at the ends.
- **`ArrowDown` / `ArrowUp`** on a vertical strip — focus the **next / previous** enabled tab, wrapping at the ends.
- **`Home` / `End`** — focus the **first / last** enabled tab.
- **`Tab`** — leave the strip for the open panel or the next thing on the page.

## Tab Button

**One trigger.** Give it the same `name` as a panel and the two are linked.

### Usage

```ts
aria<E extends BaseElement = HTMLButtonElement>(
  role: 'tab-button',
  props: TabButtonProps,
  options?: TabButtonOptions
): TabButtonAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type TabButtonProps = ComponentProps<'button'> & {
  name: string;
  id?: string;
  selected?: boolean;
  disabled?: boolean;
};

const TabButton = setup<TabButtonProps>((props) => {
  const button = aria('tab-button', props);

  return () => (
    <button ref={button.ref} {...button.restProps(['children'])}>
      {props.children}
    </button>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type TabButtonProps = ComponentProps<'button'> & {
  name: string;
  id?: string;
  selected?: boolean;
  disabled?: boolean;
};

  const button = aria('tab-button', props);

  return (
    <button ref={button.ref} {...button.restProps(['children'])}>
      {props.children}
    </button>
  );
});
```

:::

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **name** _string, **required**_: The identity this trigger shares with its panel. **The whole pairing is built from it.**
- **id** _string, optional_: An explicit DOM identifier, if you would rather not use the generated one.
- **selected** _boolean, optional_: Takes the selection when the group has no `value` of its own.
- **disabled** _boolean, optional_: This trigger alone refuses to switch. A group disabled at the top applies on top of it.

### Options

_What you fix when you create it. Read once, never reactive._

- **native** _boolean, optional, default `true`_: Pass `false` when the host isn't a `<button>` and you get `Enter` and `Space` handling plus a proper place in the tab order.

### Properties

_What you read or write on the instance afterwards._

- **active** _boolean_: Whether this is the open tab.
- **value** _string_: This tab's `name`.
- **disabled** _boolean_: Whether this trigger is locked, **including by the group**.
- **id** _string_: This trigger's identifier in the DOM.

### Methods

_What you call on the instance._

- **`select()`**: Opens this tab. _Does nothing while disabled._
- **`deselect()`**: _Does nothing._ A tab group always keeps one tab open.
- **`toggle()`**: Opens this tab when it isn't already open.

### How it behaves

- **Activation opens the tab.** A click, `Enter`, or `Space` switches the group to this tab's panel.
- **Disabled means inert.** It stays visible and announced as disabled, but refuses to switch.
- **Paired both ways.** The trigger points at its panel and the panel points back, so renaming one can't orphan the other.
- **Screen readers get a tab.** Announced as open or not, together with the panel it opens.

### Navigation

_What the keys do._

- **`Enter` / `Space`** — opens the focused tab.
- **`Click`** — opens the clicked tab.

## Tab Panel

**The content behind one trigger.** On screen only while its `name` is the open tab.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'tab-panel',
  props: TabPanelProps
): TabPanelAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type TabPanelProps = ComponentProps<'div'> & {
  name: string;
  id?: string;
};

const TabPanel = setup<TabPanelProps>((props) => {
  const panel = aria('tab-panel', props);

  return () => (
    <div ref={panel.ref} {...panel.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type TabPanelProps = ComponentProps<'div'> & {
  name: string;
  id?: string;
};

const TabPanel = setup<TabPanelProps>((props) => {
  const panel = aria('tab-panel', props);

  return (
    <div ref={panel.ref} {...panel.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **name** _string, **required**_: The identity this panel shares with its trigger.
- **id** _string, optional_: An explicit DOM identifier, if you would rather not use the generated one.

### Properties

_What you read or write on the instance afterwards._

- **active** _boolean_: Whether this is the panel **on screen**.
- **selected** _boolean_: The same thing, named after the selection contract it comes from.
- **key** _string_: What this panel pairs on — its `name`, or its `id` when it has no name.
- **id** _string_: This panel's identifier in the DOM.

### How it behaves

- **Hidden until its tab is open.** A closed panel is off screen and out of reach for both users and screen readers.
- **Focusable while open.** Scrollable content stays reachable by keyboard.
- **Mount it only when you need it.** `panel.active` lets you keep heavy content out of the tree until its tab is opened.
- **Screen readers get the trigger's name.** Each panel is announced by the tab that opens it.

### Navigation

_What the keys do._

- **`Tab`** — lands on the open panel from the strip, then continues into its content.

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### Tab

```ts
interface TabProps {
  id?: string;
  value?: string;
  orientation?: 'horizontal' | 'vertical';
  disabled?: boolean;
  onchange?: (event: CustomEvent<string>) => void;
}

interface TabAttributes {
  id: string;
}

declare class TabAria {
  get id(): string | undefined;

  list(props?: TabListProps): TabListAria;
  button(props: TabButtonProps, options?: TabButtonOptions): TabButtonAria;
  panel(props: TabPanelProps): TabPanelAria;

  static config: { orientation: 'horizontal' | 'vertical' };
  static configure(config: { orientation?: 'horizontal' | 'vertical' }): void;
}
```

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`attributes`** is the dictionary you spread; **`ref`** is what you bind the element with; **`props`** is the full props dictionary for spreading onto the host; **`restProps(omit)`** hands back your props with the keys you name left out.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
