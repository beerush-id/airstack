# AirLib Headless Tab

A tabbed interface shows one panel at a time behind a strip of triggers — but hand-rolled markup drifts fast: tab-to-panel IDs generated by hand, `aria-controls` pointing at nothing after a rename, arrow keys scrolling the document instead of roving the strip, and a click that swaps content no assistive technology hears about. **AirLib Headless Tab** (`aria('tab')`) is a role-less root orchestrating a tablist focus manager, `tab` triggers, and `tabpanel` sections: deterministic pair IDs derived from matching `name` values, manual roving that never commits, click/`Enter`/`Space` activation with veto yield, and committed values announced on the root — without dictating markup or styles.

```tsx
const tabs = aria('tab', props);

<div ref={tabs.ref} {...tabs.restProps(['children'])} />
```

## Tab

Role-less root orchestrator holding the active tab name and publishing ambient context for the list, the buttons, and the panels.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'tab',
  props?: TabProps
): TabAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type TabsProps = ComponentProps<'div'> & {
  id?: string;
  value?: string;
  orientation?: 'horizontal' | 'vertical';
  disabled?: boolean;
  onchange?: (event: CustomEvent<string>) => void;
};

const Tabs = setup<TabsProps>((props) => {
  const tabs = aria('tab', props);

  return () => (
    <div ref={tabs.ref} {...tabs.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type TabsProps = ComponentProps<'div'> & {
  id?: string;
  value?: string;
  orientation?: 'horizontal' | 'vertical';
  disabled?: boolean;
  onchange?: (event: CustomEvent<string>) => void;
};

const Tabs = setup<TabsProps>((props) => {
  const tabs = aria('tab', props);

  return (
    <div ref={tabs.ref} {...tabs.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

- `props.id` *(string, optional)*: Namespace the pair IDs derive from. Generated as `tab-<n>` when omitted; buttons derive `{id}-tab-{name}`, panels `{id}-tabpanel-{name}`.
- `props.value` *(string, optional)*: Active tab `name`. The first mounted button claims it when omitted; a button with `selected: true` claims it instead.
- `props.orientation` *('horizontal' | 'vertical', optional, default `'horizontal'`)*: Axis the tablist roves along.
- `props.disabled` *(boolean, optional)*: Locks out activation and roving across the whole group.
- `props.onchange` *(handler, optional)*: Called with the `change` event after each commit; `detail` is the new active tab `name` without a cast.

### How it behaves

- Compiles no `role` — the root is a non-semantic container, so panels are never invalid DOM children of the tablist.
- Exactly one tab stays selected: activating the already-active tab commits nothing and emits nothing.
- A consumer that cancels the activation (`preventDefault` on the click, captured) stops both the commit and the event.

## Tab List

Focus manager compiling `role="tablist"` and roving a single tab stop across the buttons.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'tab-list',
  props?: TabListProps
): TabListAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type TabListProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
};

const TabList = setup<TabListProps>((props) => {
  const list = aria('tab-list', props);

  return () => (
    <div ref={list.ref} {...list.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type TabListProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
};

const TabList = setup<TabListProps>((props) => {
  const list = aria('tab-list', props);

  return (
    <div ref={list.ref} {...list.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

- `props.label` *(string, optional)*: Accessible title announced for the tablist.
- `props.labelledby` *(string, optional)*: ID of the element providing the accessible title.

### How it behaves

- Compiles `role="tablist"` with `aria-orientation` (`horizontal` by default).
- Horizontal roves on `ArrowRight` / `ArrowLeft`; vertical on `ArrowDown` / `ArrowUp`. Both wrap at the ends; `Home` / `End` land on the first / last enabled button.
- Roving moves focus only and never commits — the selection waits for `Enter`, `Space`, or a click.
- Disabled buttons are skipped in traversal; a fully disabled group refuses to rove.

## Tab Button

Interactive trigger compiling `role="tab"` and pairing with its panel through a matching `name`.

```ts
aria<E extends BaseElement = HTMLButtonElement>(
  role: 'tab-button',
  props: TabButtonProps,
  options?: TabButtonOptions
): TabButtonAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type TabButtonProps = ComponentProps<'button'> & {
  name: string;
  id?: string;
  selected?: boolean;
  disabled?: boolean;
};

const TabButton = setup<TabButtonProps>((props) => {
  const button = aria('tab-button', props);

  return () => (
    <button ref={button.ref} {...button.restProps(['children'])}>
      {props.children}
    </button>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type TabButtonProps = ComponentProps<'button'> & {
  name: string;
  id?: string;
  selected?: boolean;
  disabled?: boolean;
};

const TabButton = setup<TabButtonProps>((props) => {
  const button = aria('tab-button', props);

  return (
    <button ref={button.ref} {...button.restProps(['children'])}>
      {props.children}
    </button>
  );
});
```

:::

### Parameters

- `props.name` *(string, required)*: Semantic identity matching the paired panel.
- `props.id` *(string, optional)*: Explicit DOM identifier overriding automatic pair derivation.
- `props.selected` *(boolean, optional)*: Initial selection hint when the root is uncontrolled.
- `props.disabled` *(boolean, optional)*: Prevents interaction with this tab. Group-level disablement applies too.
- `options.native` *(boolean, optional, default `true`)*: Pass `false` on non-button hosts to attach `Space` / `Enter` synthesis and explicit `tabindex`.

### How it behaves

- Compiles `role="tab"`, `aria-selected="true" | "false"`, and `aria-controls` pointing at the paired panel ID.
- The selected button holds the tab stop; unselected buttons carry `tabindex="-1"` (native hosts omit `tabindex` on the active button; custom hosts publish an explicit `0`).
- Activating an enabled button writes its `name` into the root value; a disabled button refuses the commit.

## Tab Panel

Content section compiling `role="tabpanel"`, visible only while its `name` matches the root value.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'tab-panel',
  props: TabPanelProps
): TabPanelAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type TabPanelProps = ComponentProps<'div'> & {
  name: string;
  id?: string;
};

const TabPanel = setup<TabPanelProps>((props) => {
  const panel = aria('tab-panel', props);

  return () => (
    <div ref={panel.ref} {...panel.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type TabPanelProps = ComponentProps<'div'> & {
  name: string;
  id?: string;
};

const TabPanel = setup<TabPanelProps>((props) => {
  const panel = aria('tab-panel', props);

  return (
    <div ref={panel.ref} {...panel.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

- `props.name` *(string, required)*: Semantic identity matching the paired button.
- `props.id` *(string, optional)*: Explicit DOM identifier overriding automatic pair derivation.

### How it behaves

- Compiles `role="tabpanel"` with `aria-labelledby` pointing at the paired button ID.
- Inactive panels receive `hidden`; the active panel is focusable (`tabindex="0"`, so scrollable content stays keyboard-reachable).
- `panel.selected` / `panel.active` mirror the root value for conditional rendering (`{panel.selected && <Content />}`).

## Events

| Event | Authored by | Trigger | `detail` |
| :--- | :--- | :--- | :--- |
| `change` | The tab root | Activation committed a new tab | The new active tab `name` |

```tsx
const tabs = aria('tab', {
  value: 'account',
  onchange: (event) => submit(event.detail),
});
```

A vetoed activation (`preventDefault`) dispatches nothing; re-activating the active tab commits nothing and emits nothing.

## Keyboard Navigation

| Key | Behavior |
| :--- | :--- |
| `ArrowRight` / `ArrowLeft` (horizontal) | Roves focus, wrapping at the ends, without committing. |
| `ArrowDown` / `ArrowUp` (vertical) | Roves focus, wrapping at the ends, without committing. |
| `Home` / `End` | Moves focus to the first / last enabled tab, without committing. |
| `Enter` / `Space` on a button | Activates the focused tab. |
| `Click` on a button | Activates the clicked tab. |
| `Tab` | Exits the tablist, moving to the active panel or the next page element. |

## What you get

- **Pairing without bookkeeping.** Matching `name` values derive both sides of `aria-controls` / `aria-labelledby`, so renames never orphan a panel.
- **Roving that never selects.** Arrows, `Home`, and `End` move the single tab stop; only activation commits, so keyboard exploration never flashes content.
- **Commits you can hear.** Every activation dispatches one bubbled `change` and calls `onchange` with the new name — vetoable, and silent on re-activation.
- **Lockout that composes.** Member and group `disabled` combine; disabled tabs are skipped in traversal and refuse activation on both native and custom hosts.
- **Zero markup lock-in.** Native `<button>` triggers or custom hosts, panels as siblings wherever the layout needs them.
