# AirLib Headless Radio

A radio looks simple until you build a custom one: a native `<input type="radio">` resists cross-browser styling of its circle, while a custom `<div>` needs hand-rolled `role`, roving `tabindex`, `aria-checked`, Space selection, never-toggleable activation, and group membership sync. **AirLib Headless Radio** (`aria('radio')`) turns any element into a radio that behaves — native IDL sync on real inputs, full ARIA polyfills on custom hosts, select-only state and group coordination included, without dictating markup or styles.

```tsx
const radio = aria('radio', props, { native: false });

<div ref={radio.ref} {...radio.props} />
```

## Radio

Mutually exclusive choice member with native IDL sync and group membership.

```ts
aria<E extends BaseElement = HTMLInputElement, T extends Primitive = Primitive>(
  role: 'radio',
  props?: RadioProps<T>,
  options?: RadioOptions
): RadioAria<E, RadioProps<T>>
```

### Usage

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type RadioCardProps = ComponentProps<'div'> & {
  value: string;
  name?: string;
  disabled?: boolean;
  title: string;
  price: string;
};

const RadioCard = setup<RadioCardProps>((props) => {
  const radio = aria('radio', props, { native: false });

  return () => (
    <div ref={radio.ref} {...radio.restProps(['title', 'price', 'children'])}>
      <strong>{props.title}</strong>
      <span>{props.price}</span>
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type RadioCardProps = ComponentProps<'div'> & {

  disabled?: boolean;
  title: string;
  price: string;

const RadioCard = setup<RadioCardProps>((props) => {

  return (
    <div ref={radio.ref} {...radio.restProps(['title', 'price', 'children'])}>
      <strong>{props.title}</strong>
      <span>{props.price}</span>
    </div>
  );
});
```

:::

The dot glyph comes from CSS keyed on `aria-checked` (see the style block above), never from controller state in JSX — the controller owns semantics, the stylesheet owns the mark.

### Parameters

- `props.value` *(Primitive, optional)*: Choice candidate value matching the parent group's active value.
- `props.name` *(string, optional)*: Native HTML form field name pass-through for submission binding.
- `props.checked` *(boolean, optional)*: Explicit checked state when used standalone.
- `props.disabled` *(boolean, optional)*: Blocks activation and state commits.
- `options.native` *(boolean, optional, default `true`)*: Pass `false` when wrapping custom non-input elements (such as `<div>` cards).

### How it behaves

- Native `<input type="radio">` hosts omit `role` and sync the `.checked` and `.disabled` IDL properties; no ARIA state mirror is emitted and browser `click`/`change` are never re-dispatched.
- Custom hosts compile `role="radio"`, `aria-checked` (`true`/`false`), roving `tabindex` (`0` selected, `-1` otherwise), and Space key selection with scroll suppression.
- State is select-only: `radio.checked = true` commits the slot (`group.value = props.value` when grouped); `radio.checked = false`, `deselect()`, and re-activating the holder are no-ops. The slot only moves when the group value changes or another radio selects — a group may still start empty (`value: null`).
- Arrow/Home/End/Enter handling belongs to the group container, not the member: a `radio` member is inert to arrows and `Enter`, owning Space alone.
- Every real commit on a custom host fires a bubbling `change` event carrying the new checked state; canceled triggers, disabled hosts, and no-op re-activations stay silent.
- The compiled dictionary carries no form attributes — bind `name` and `value` on the element yourself for submission.

:::tip[Select-Only State]
A radio never deselects through itself: clicking or pressing Space on the selected option keeps it, whether or not the group is required. To move the slot programmatically, write the registry (`group.value = next`) instead of the member.
:::

## Putting It Together

Once your components are wired with `aria(...)`, compose them to build radio controls with honest state:

```tsx
<DemoRadioGroup value="pro">
  <DemoRadio value="starter" />
  <DemoRadio value="pro" />
  <DemoRadio value="enterprise" disabled={true} />
</DemoRadioGroup>
```

:::interactive[Radio Interactive Demo]
```tsx
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type DemoRadioGroupProps = ComponentProps<'div'> & {
  value?: string;
  disabled?: boolean;
};

const DemoRadioGroup = setup<DemoRadioGroupProps>((props) => {
  const group = aria('radio-group', props);

  return () => (
    <div ref={group.ref} {...group.restProps(['value', 'disabled', 'children'])}>
      {props.children}
    </div>
  );
}, 'DemoRadioGroup');
```

## Keyboard Navigation

- **Tab**: Enters the group at the single tab stop (the selected member, or the first enabled member when empty). Disabled custom members sit at `tabindex="-1"` and are skipped.
- **Space**: Prevents viewport scroll on keydown, selects on keyup. A canceled keyup commits nothing.
- **Arrows**: Belong to the group container — they move focus and commit selection in one transition, wrapping and skipping disabled. No manual mode exists for radios.
- **Enter**: Commits nothing — Enter is not a radio affordance on custom hosts.

## What you get

- **Native IDL sync.** `.checked` and `.disabled` follow props on real inputs with no ARIA mirror and no re-dispatched events.
- **Custom element polyfills.** Role, roving tab stop, `aria-checked`, and Space selection with `native: false`.
- **Honest single-selection.** Select-only projection with no toggle-off path; the group may start empty.
- **Group membership.** Members derive from one external registry write; exclusivity outranks a disabled hold.
- **Observable commits.** Bubbling `change` events per real commit, silence otherwise.
