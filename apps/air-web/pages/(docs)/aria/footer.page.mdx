# Headless Footer

Copyright, policy links, and contact details close the document, and a landmark is what lets a user jump straight to them instead of tabbing through the page.

Getting it right means **compiling `contentinfo` onto a generic host**, **naming it only when a document carries two**, **leaving a real `<footer>` its own implicit role**, and **taking no focus and claiming no keys**.

**Headless Footer** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const footer = aria('footer', props);

<div ref={footer.ref} {...footer.restProps(['children'])} />
```

:::interactive[Site Footer]

:::tip
**Only the page-level footer is a contentinfo landmark.** A `<footer>` inside `<main>`, `<article>`, `<aside>`, or `<section>` closes that section instead and exposes no landmark role at all, so keep one at the body level and name a custom host wherever else you need it.

## Footer

**The footer landmark.** It compiles `contentinfo` onto a generic host and carries the accessible name that tells two footers apart.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'footer',
  props?: FooterProps,
  options?: FooterOptions
): FooterAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type FooterProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
  children: ReactNode;
};

const Footer = setup<FooterProps>((props) => {
  const footer = aria('footer', props);

  return () => (
    <div ref={footer.ref} {...footer.restProps(['children'])}>
      {props.children}
    </div>
  );
}, 'Footer');
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps, JSX } from 'solid-js';

type FooterProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
  children: JSX.Element;
};

const Footer = setup<FooterProps>((props) => {
  const footer = aria('footer', props);

  return (
    <div ref={footer.ref} {...footer.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **label** _string, optional_: The name screen readers announce for this footer, compiled to `aria-label`. Omitted when absent, so an unnamed page footer carries no redundant attribute.
- **labelledby** _string, optional_: The ID of an element already on the page that provides that name, compiled to `aria-labelledby`.

### Options

_What you fix when you create it. Read once, never reactive._

- **native** _boolean, optional, default `false`_: Pass `true` when the host is a real `<footer>`, which already implies `contentinfo`. The redundant role is dropped and only the name is compiled.

### Properties

_What you read or write on the instance afterwards._

- **label** _string | undefined_: The label in force.
- **labelledby** _string | undefined_: The ID reference in force.
- **named** _boolean_: Whether the landmark carries an accessible name.

### How it behaves

- **Compiles `role="contentinfo"` on a generic host.** A `<div>` host is announced as the document footer, whatever the surrounding markup looks like.
- **The role follows `native`, never the host tag or its position.** Pass `native: true` and the element supplies the role itself; a custom host keeps its compiled role wherever you place it, including inside a section.
- **Naming is reactive.** Set, change, or clear `label` or `labelledby` and the projection follows on the next write.
- **Structure only.** No `tabindex`, no `aria-live`, no key handling, and no state of its own; a `submit` or `Enter` inside it is never intercepted, and the links you place in it keep their keyboard behavior.
- **Two footers on one page are yours to manage.** The controller never counts footers and never suppresses a second one, so the name is what keeps them apart in a landmark list.
- **Both name props stay off the DOM as plain attributes.** `label` and `labelledby` compile to `aria-label` and `aria-labelledby` only, so `restProps(['children'])` is the whole omission list.

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### Footer

```ts
interface FooterProps {
  label?: string;
  labelledby?: string;
}

interface FooterOptions {
  native?: boolean;
}

interface FooterAttributes {
  role?: 'contentinfo';
  'aria-label'?: string;
  'aria-labelledby'?: string;
}

declare class FooterAria {
  get label(): string | undefined;
  get labelledby(): string | undefined;
  get named(): boolean;
}
```

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`props`** / **`restProps(omit)`** is what you spread onto the host — your props minus the keys the controller writes and any you name, with the compiled attributes merged in; **`ref`** is what you bind the element with; **`attributes`** is that compiled dictionary on its own, when you need the low-level view.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
