# AirLib Headless Footer

Copyright notices, privacy links, and contact details sit at the end of every page. Users who need them want to jump straight there, and users who do not want them skipped — which requires the page footer to be identified as a landmark rather than as more content to listen through. **AirLib Headless Footer** (`aria('footer')`) compiles `role="contentinfo"` onto the generic host you already render, adds an accessible name when a document needs one, and stays purely structural — no focus, no keys, no state.

```tsx
const footer = aria('footer', props);

<div ref={footer.ref} {...footer.restProps(['children'])} />
```

## Footer

The prime footer landmark. It projects contentinfo semantics onto a generic host and compiles the accessible name that tells two footers apart.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'footer',
  props?: FooterProps,
  options?: FooterOptions
): FooterAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type FooterProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
  children: ReactNode;
};

const Footer = setup<FooterProps>((props) => {
  const footer = aria('footer', props);

  return () => (
    <div ref={footer.ref} {...footer.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type FooterProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
};

const Footer = setup<FooterProps>((props) => {
  const footer = aria('footer', props);

  return (
    <div ref={footer.ref} {...footer.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

- `props.label` *(string, optional)*: Accessible label compiled to `aria-label`. Omitted when absent, so an unnamed page footer carries no redundant attribute.
- `props.labelledby` *(string, optional)*: Element ID providing the accessible name, compiled to `aria-labelledby`.
- `options.native` *(boolean, optional, default `false`)*: Pass `true` when the host is a real `<footer>`, which already implies `contentinfo` — the redundant role is dropped and only the name is compiled.

### How it behaves

- Compiles `role="contentinfo"` on a generic host. With `native: true` the role is left to the `<footer>` element and only the accessible name is emitted.
- The role comes from `native` alone — never from the host tag and never from where the element sits in the tree — so a custom host keeps its compiled role wherever you place it.
- `label` compiles to `aria-label` and `labelledby` to `aria-labelledby`, both reactively: set, change, or clear either one and the projection follows.
- Structure only: no `tabindex`, no `aria-live`, no key handling, and no state. A `submit` or `Enter` inside it is never intercepted.
- Keeping one `contentinfo` per page is yours to manage — the controller never counts footers and never suppresses a second one.
- `label` and `labelledby` are consumed by the controller and carried in `ownKeys`, so `restProps(['children'])` is the whole omission list — neither leaks to the DOM as a stray attribute.

:::tip[Only the page footer is contentinfo]
A `<footer>` inside `<main>`, `<article>`, `<aside>`, or `<section>` closes that section, not the document, and the HTML mapping exposes no role for it at all. Keep the landmark on the body-level footer, and hold to one per page. A custom host compiles `role="contentinfo"` wherever it is placed, so nesting one inside a section publishes a second contentinfo.
:::

## Keyboard Navigation

- **None.** The landmark takes no tab stop and claims no keys; the links inside it keep their own keyboard behavior.

## What you get

- **Contentinfo on a generic host.** A `<div>` becomes a navigable landmark with no markup lock-in.
- **No redundant role.** `native: true` on a real `<footer>` leaves the implicit role alone.
- **Optional naming.** `label` and `labelledby` cover the rare document with more than one footer.
- **Placement-stable output.** The compiled attributes are identical in SSR and after hydration, because nothing is read from the DOM.
- **Structure only.** No focus, no keys, no state — nothing to keep in sync.
