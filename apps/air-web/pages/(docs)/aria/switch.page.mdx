# AirLib Headless Switch

A switch looks simple until you build a custom one: HTML has no `<switch>` element, so a `<div>` or `<button>` needs hand-rolled `role`, `tabindex`, `aria-checked`, instant click/Space/Enter toggling, and group lockout sync. **AirLib Headless Switch** (`aria('switch')`) turns any element into a switch that behaves — ARIA mirrors kept even on native button hosts, select-style coordination for valued members, immediate inversion included, without dictating markup or styles.

```tsx
const sw = aria('switch', props, { native: true });

<button ref={sw.ref} {...sw.props} />
```

## Switch

Instant-activation binary toggle with native button backing and group membership.

```ts
aria<E extends BaseElement = HTMLElement, T extends Primitive = Primitive>(
  role: 'switch',
  props?: SwitchProps<T>,
  options?: SwitchOptions
): SwitchAria<E, SwitchProps<T>>
```

### Usage

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type SwitchProps = ComponentProps<'button'> & {
  checked?: boolean;
  disabled?: boolean;
};

const Switch = setup<SwitchProps>((props) => {
  const sw = aria('switch', props, { native: true });

  return () => (
    <button ref={sw.ref} {...sw.restProps(['children'])}>
      {props.children}
    </button>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type SwitchProps = ComponentProps<'button'> & {
  checked?: boolean;
  disabled?: boolean;
};

const Switch = setup<SwitchProps>((props) => {
  const sw = aria('switch', props, { native: true });

  return (
    <button ref={sw.ref} {...sw.restProps(['children'])}>
      {props.children}
    </button>
  );
});
```

:::

The track and thumb come from CSS keyed on `aria-checked` (see the style block above), never from controller state in JSX — the controller owns semantics, the stylesheet owns the visuals.

### Parameters

- `props.checked` *(boolean, optional, default `false`)*: Binary on/off state, compiled to `aria-checked`.
- `props.value` *(Primitive, optional)*: Choice candidate value when nested inside a selection group.
- `props.name` *(string, optional)*: Semantic identity key or field name on the parent settings group.
- `props.disabled` *(boolean, optional)*: Blocks activation and state commits.
- `props.oninput` *(function, optional)*: Called with the committed state after each activation.
- `props.onchange` *(function, optional)*: Called with the committed state when the selection changes.
- `options.native` *(boolean, optional, default `false`)*: Pass `true` when wrapping a native `<button>` host where the browser handles focus and key events.

### How it behaves

- There is no HTML switch element, so `role="switch"` and `aria-checked` are emitted on both hosts and `checked` is never emitted as an attribute key. Custom hosts add a synthesized tab stop (`0` enabled, `-1` disabled, numbers); button hosts use their native tab stop.
- Every activation flips `checked` exactly once: pointer `click`, `Space` keyup (repeat-safe: many keydowns, one keyup, one inversion), and `Enter` immediately on keydown. `Space` keydown prevents scrolling; canceled triggers verify `!event.defaultPrevented` and commit nothing.
- Native button hosts add no key polyfills and never `preventDefault` — raw key events belong to the browser and activation arrives as the click the browser generates.
- Valued members coordinate through `group.value`; valueless members stay local and can never claim or clear the shared slot. Effective disabled is group `disabled` OR member `disabled`, and lifting a registry lockout hands the widget back on the same node.
- Every real commit on a custom host fires bubbling `change` and `input` events carrying the new state; canceled triggers, disabled hosts, and no-op mutations stay silent.
- The compiled dictionary carries no form attributes — a button-backed switch never becomes a form field by accident.

:::tip[Checkbox vs Switch]
Use a **Checkbox** when the option sits inside a form and takes effect upon submit ("agree to terms", "remember me"). Use a **Switch** when toggling takes effect immediately ("dark mode", "airplane mode"). Unlike checkbox, `Enter` flips a switch.
:::

## Keyboard Navigation

- **Tab**: Focuses the switch. Disabled custom switches sit at `tabindex="-1"` and are skipped.
- **Space**: Prevents viewport scroll on keydown, flips on keyup. A canceled keyup commits nothing.
- **Enter**: Flips immediately on keydown — unlike checkbox, Enter is a switch affordance on custom hosts.

## What you get

- **Immediate inversion.** Click, Space, and Enter each flip exactly once with fresh-state observer ordering.
- **Honest hosts.** Button backing keeps ARIA mirrors with zero polyfills; custom hosts get role, tab stop, and keyboard support.
- **Group-safe membership.** Valued members coordinate through one registry; valueless members stay local; group lockout cascades and releases cleanly.
- **Observable commits.** Bubbling `change` and `input` events per real commit, silence otherwise.
