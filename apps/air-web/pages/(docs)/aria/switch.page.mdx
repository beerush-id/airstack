# Headless Switch

A switch is an on-off that takes effect the moment you flip it. HTML has no switch element, so the semantics are always yours to carry, and getting it right means **flipping on a click, `Space`, or `Enter` exactly once**, **announcing on and off on a host that has no native switch**, **staying inert when the setting is locked out**, and **telling your code the new state**.

**Headless Switch** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const sw = aria('switch', props, { native: false });

<div ref={sw.ref} {...sw.restProps(['children'])} />
```

:::interactive[Settings Switches]
```tsx
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type DemoSwitchProps = ComponentProps<'label'> & {
  checked?: boolean;
  disabled?: boolean;
};

const DemoSwitch = setup<DemoSwitchProps>((props) => {
  const sw = aria('switch', props, { native: false });

  return () => (
    <label className="demo-switch-row">
      <span>{props.children}</span>
      <div ref={sw.ref} {...sw.restProps(['children'])} className="demo-switch" />
    </label>
  );
}, 'DemoSwitch');
```
```html
<div className="demo-switch-stack">
  <DemoSwitch checked={true}>Push notifications</DemoSwitch>
  <DemoSwitch>Dark mode</DemoSwitch>
  <DemoSwitch disabled={true}>Offline sync</DemoSwitch>
</div>
```

## Switch

**The setting itself.** One flip, and the state is committed.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'switch',
  props?: SwitchProps,
  options?: SwitchOptions
): SwitchAria<E>
```

:::code-group

import { aria } from '@airlib/aria';

### Parameters

_What you pass in. The props object stays live — change a value on it and the switch follows._

- **checked** _boolean, optional, default `false`_: Whether the switch is on.
- **value** _Primitive, optional_: The token this switch contributes to a group's shared selection. Give one and the switch is a member; leave it out and it keeps its own state.
- **name** _string, optional_: The identity this setting reports under.
- **disabled** _boolean, optional_: Locks the switch. A group's own `disabled` reaches it the same way.
- **oninput** _(event: CustomEvent&lt;boolean&gt;) =&gt; void, optional_: Called after each activation with the new state in `detail`.
- **onchange** _(event: CustomEvent&lt;boolean&gt;) =&gt; void, optional_: Called when the state changes. _Inside a group, `detail` carries the group's shared value instead._

### Options

_What you fix when you create it. Read once, never reactive._

- **native** _boolean, optional, default `false`_: Set `true` when the host is a real `<button>`, so the browser keeps the focus and the keys and nothing is polyfilled on top of it. There is no native switch either way, so `role="switch"` and `aria-checked` stay compiled.

### Properties

_What you read or write on the instance afterwards._

- **checked** _boolean_: Whether the switch is on. **Writing it turns the setting on or off** — a switch is not select-only like a radio — and a write is refused while disabled.
- **disabled** _boolean_: Whether the switch is locked, **including by the group**.
- **value** _Primitive_: The token this switch contributes to a group.
- **id** _string_: The switch's own identifier — `switch-<n>`, which is also the DOM id unless a group namespaces it.

### Methods

_What you call on the instance._

- **`select()`**: Turns the switch on. _Does nothing while disabled._
- **`deselect()`**: Turns the switch off. _Does nothing while disabled, or while the group requires a non-empty selection._
- **`toggle()`**: Flips it. _This is the path every activation arrives on._

### How it behaves

- **No native switch exists, so the semantics are always carried.** `role="switch"` and `aria-checked` are compiled on every host including a `<button>`, and `checked` is never written as an attribute or a DOM property.
- **One flip per activation.** A click, `Space`, and `Enter` each invert exactly once: `Space` suppresses the page scroll on keydown and commits on keyup, `Enter` commits on keydown, and keydown repeats without a keyup still commit once.
- **A `<button>` host is left to the browser.** With `native: true` no key handling is added and nothing is canceled — activation arrives as the click the browser generates, and the ARIA mirror rides on top of it.
- **Disabled means inert.** Click, `Space`, `Enter`, and writes to `checked` are refused, and the activation events themselves are cancelled and stopped from bubbling — so nothing above the switch reacts to a locked flip either.
- **Group membership on a token.** Inside a selection group with a `value`, the switch reads and writes the shared value rather than its own state; a value-less switch stays local and can never claim or clear the slot. **Lifting a group lock hands the widget back on the same node** — no remount.
- **Nothing submits for you.** `name` and `value` are consumed by the controller, so the compiled dictionary carries no form attributes, and a button-backed switch never becomes a form field by accident.

### Events

_What it tells you._

- **`change`** — fires when the state really flips, with the new state in `detail`. A group member carries the group's shared value there instead.
- **`input`** — fires on the same commit **on a custom host**; a `<button>`-backed switch announces through `change` alone. Canceled triggers, disabled switches, and writes that change nothing stay silent.

```tsx
const sw = aria('switch', {
  checked: false,
  onchange: (event) => setDarkMode(event.detail),
});
```

### Navigation

_What the keys do._

- **`Space`** — flips the switch. The keydown suppresses the page scroll and arms the press; the commit lands on keyup, and a canceled keydown never commits.
- **`Enter`** — flips the switch on keydown. **This is what sets a switch apart from a checkbox.**
- **`Click`** — flips the switch, including through its label.
- **`Tab`** — reaches the switch. On a custom host, a disabled switch leaves the tab order.

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### Switch

```ts
interface SwitchProps {
  checked?: boolean;
  value?: Primitive;
  name?: string;
  disabled?: boolean;
  oninput?: (event: CustomEvent<boolean>) => void;
  onchange?: (event: CustomEvent<boolean>) => void;
}

interface SwitchOptions {
  native?: boolean;
}

interface SwitchAttributes {
  id?: string;
  role?: 'switch';
  disabled?: boolean;
  tabindex?: number;
  'aria-checked'?: 'true' | 'false';
  'aria-disabled'?: 'true' | 'false';
}

declare class SwitchAria {
  id: string;
  get checked(): boolean;
  set checked(value: boolean);
  get disabled(): boolean;
  get value(): Primitive;

  select(): void;
  deselect(): void;
  toggle(): void;
}
```

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`props`** / **`restProps(omit)`** is what you spread onto the host — your props minus the keys the controller writes and any you name, with the compiled attributes merged in; **`ref`** is what you bind the element with; **`attributes`** is that compiled dictionary on its own, when you need the low-level view.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
