# Headless Dialog

A dialog puts a panel over the page and holds attention until it closes. Getting it right means **trapping focus while it is modal**, **closing on `Escape` and outside clicks with a veto**, **returning focus to what opened it**, and **naming the panel from its own content**.

**Headless Dialog** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const dialog = aria('dialog', props);
const trigger = dialog.trigger();
const panel = dialog.panel();

<button ref={trigger.ref} {...trigger.restProps(['children'])} />
```

```tsx
import { aria } from '@airlib/aria';
import { setup, shadowPortal } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type DemoDialogProps = ComponentProps<'div'> & {
  open?: boolean;
  modality?: 'modal' | 'nonmodal';
  dismissable?: boolean;
  children: ReactNode;
};

const DemoDialog = setup<DemoDialogProps>((props) => {
  const dialog = aria('dialog', props);

  return () => (
    <div ref={dialog.ref} {...dialog.restProps(['children'])} className="demo-dialog-group">
      {props.children}
    </div>
  );
}, 'DemoDialog');

type DemoDialogTriggerProps = ComponentProps<'button'> & {
  children: ReactNode;
};

const DemoDialogTrigger = setup<DemoDialogTriggerProps>((props) => {
  const trigger = aria('dialog-trigger', props);

  return () => (
    <button ref={trigger.ref} {...trigger.restProps(['children'])} className="demo-dialog-trigger">
      {props.children}
    </button>
  );
}, 'DemoDialogTrigger');

type DemoDialogPanelProps = ComponentProps<'div'> & {
  floating?: boolean;
  children: ReactNode;
};

const DemoDialogPanel = setup<DemoDialogPanelProps>((props) => {
  const panel = aria('dialog-panel', props);
  const shadow = shadowPortal(() => panel.open);

  return () => shadow(
    <div
      ref={panel.ref}
      {...panel.restProps(['children', 'floating'])}
      className={props.floating ? 'demo-dialog-panel demo-dialog-floating' : 'demo-dialog-panel'}
    >
      {props.children}
    </div>
  );
}, 'DemoDialogPanel');

type DemoDialogTitleProps = ComponentProps<'span'> & {
  children: ReactNode;
};

const DemoDialogTitle = setup<DemoDialogTitleProps>((props) => {
  const title = aria('dialog-title', props);

  return () => (
    <span ref={title.ref} {...title.restProps(['children'])} className="demo-dialog-title">
      {props.children}
    </span>
  );
}, 'DemoDialogTitle');

type DemoDialogDescriptionProps = ComponentProps<'span'> & {
  children: ReactNode;
};

const DemoDialogDescription = setup<DemoDialogDescriptionProps>((props) => {
  const description = aria('dialog-description', props);

  return () => (
    <span ref={description.ref} {...description.restProps(['children'])} className="demo-dialog-note">
      {props.children}
    </span>
  );
}, 'DemoDialogDescription');

  children: ReactNode;
};

const DemoDialogClose = setup<DemoDialogCloseProps>((props) => {
  const close = aria('dialog-close', props);

  return () => (
    <button ref={close.ref} {...close.restProps(['children'])} className="demo-dialog-close">
      {props.children}
    </button>
  );
}, 'DemoDialogClose');
```

:::tip
**Closing is one state write.** Every path — the close button, `Escape`, an outside click, or `dialog.close()` — lands on `open = false`, and the `close` event fires once per transition whichever path got there.

## Dialog

**The overlay as a whole.** It holds the open state, the modality, and the dismissal policy; the trigger, the panel, and the elements inside it all follow it.

### Usage

```ts
aria<E extends HTMLElement = HTMLElement>(
  role: 'dialog',
  props?: DialogProps,
  options?: DialogOptions
): DialogAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type DialogProps = ComponentProps<'div'> & {
  id?: string;
  open?: boolean;
  modality?: 'modal' | 'nonmodal';
  dismissable?: boolean;
  onopen?: (event: CustomEvent<void>) => void;
  onclose?: (event: CustomEvent<void>) => void;
};

const Dialog = setup<DialogProps>((props) => {
  const dialog = aria('dialog', props);

  return () => (
    <div ref={dialog.ref} {...dialog.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps, JSX } from 'solid-js';

type DialogProps = ComponentProps<'div'> & {
  id?: string;
  open?: boolean;
  modality?: 'modal' | 'nonmodal';
  dismissable?: boolean;
  onopen?: (event: CustomEvent<void>) => void;
  onclose?: (event: CustomEvent<void>) => void;
};

const Dialog = setup<DialogProps>((props) => {
  const dialog = aria('dialog', props);

  return (
    <div ref={dialog.ref} {...dialog.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

Keep the panel mounted: a closed panel carries `hidden` on a custom host, so the same instance keeps managing its edges, dismissal, and focus return.

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **open** _boolean, optional, default `false`_: Whether the panel is showing. Read and write it through `dialog.open`.
- **modality** _'modal' | 'nonmodal', optional, default `'modal'`_: Modal traps focus inside the panel and announces `aria-modal="true"`; nonmodal leaves the page reachable and announces `aria-modal="false"`.
- **dismissable** _boolean, optional, default `true`_: Whether `Escape` and outside clicks close it.
- **id** _string, optional_: The prefix every part's identifier is built from, generated as `dialog-<n>` when you leave it out.
- **onopen** / **onclose** _(event: CustomEvent&lt;void&gt;) =&gt; void, optional_: The panel's visibility edges, once per transition, whichever path caused it.

### Properties

_What you read or write on the instance afterwards._

- **open** _boolean, read and write_: Whether the panel is showing.
- **modality** _'modal' | 'nonmodal'_: The modality in use, yours or the default.
- **dismissable** _boolean_: Whether Escape and outside clicks close it.
- **id** _string_: The prefix in use, generated when you left it out.

### Methods

_What you call on the instance._

- **`show()`**: Opens the panel.
- **`close()`**: Closes it and returns focus to what opened it.
- **`toggle()`**: Opens or closes, whichever applies.
- **`trigger(props?, options?)`** → `DialogTriggerAria`: Creates the button that opens it.
- **`panel(props?, options?)`** → `DialogPanelAria`: Creates the overlay container.
- **`title(props?, options?)`** → `DialogTitleAria`: Creates the element that names it.
- **`description(props?, options?)`** → `DialogDescriptionAria`: Creates the element that explains it.
- **`closeButton(props?, options?)`** → `DialogCloseAria`: Creates a button that closes it.

### Events

_What it tells you._

- **`open`** — the panel became visible, after native display, focus capture, and autofocus settled.
- **`close`** — the panel stopped being visible, from every path that closes it.

```tsx
const dialog = aria('dialog', {
  onclose: () => draft.save(),
});
```

### Navigation

_What the keys do._

- **`Tab` / `Shift+Tab`** — cycle through the panel's focusable elements, trapped inside it while modal; free to leave the panel while nonmodal.
- **`Escape`** — closes it when `dismissable`, after a cancelable `cancel` event your code can veto with `preventDefault`.
- **`Enter` / `Space`** — activate the focused control, as anywhere else.

:::

### Properties

_What you read or write on the instance afterwards._

- **open** _boolean_: Whether the dialog it opens is showing.
- **disabled** _boolean_: Whether this trigger refuses to open it.

### How it behaves

- **Announced as opening something.** `aria-haspopup="dialog"` with `aria-expanded` tracking the panel and `aria-controls` pointing at it.
- **Clicking toggles.** A disabled trigger refuses, on either host.
- **It gets the focus back.** When the panel closes, focus returns to whatever held it at open — usually this button.
- **It is exempt from light dismissal.** Clicking the trigger while the panel is open toggles rather than dismissing and reopening.

### Properties

_What you read or write on the instance afterwards._

- **open** _boolean_: Whether the panel is showing.

### How it behaves

- **Named from its own content.** `role="dialog"` with `aria-modal` from the modality, labelled by the title and described by the description through derived identifiers.
- **Focus lands inside on open while modal.** An `[autofocus]` element when you mark one, otherwise the first focusable child, otherwise the panel itself. A nonmodal panel leaves focus where it was.
- **The trap holds while modal.** `Tab` and `Shift+Tab` cycle within the panel; nonmodal leaves them free.
- **Light dismissal ignores the trigger.** A pointer down anywhere outside the panel closes it, except on the trigger that owns it.
- **A native `<dialog>` host stays native.** Visibility runs through `showModal()` and `close()`; a custom host gets `hidden` instead.

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`props`** / **`restProps(omit)`** is what you spread onto the host — your props minus the keys the controller writes and any you name, with the compiled attributes merged in; **`ref`** is what you bind the element with; **`attributes`** is that compiled dictionary on its own, when you need the low-level view.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
