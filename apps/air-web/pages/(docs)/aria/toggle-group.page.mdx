# AirLib Headless Toggle Group

A strip of bold/italic/underline buttons looks trivial until you coordinate it: the pressed state has to live in one place so assistive technology reads `aria-pressed` on a real button, arrows must move focus without silently pressing something, only the pressed button should hold the Tab stop, and clearing a selection has to be announced the same way as making one. Hand-rolled strips get each of these wrong separately — usually the arrow key that quietly toggles a button, or the group that swallows Tab. **AirLib Headless Toggle Group** (`aria('toggle-group')`) coordinates single-press or multi-press state across member toggles — ambient value membership, focus-only circular roving on every axis, and cascaded group disablement — without dictating markup or styles.

```tsx
const group = aria('toggle-group', props);

<div ref={group.ref} {...group.props} />
```

```tsx
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type DemoToggleGroupProps = ComponentProps<'div'> & {
  value?: string | string[];
  multiple?: boolean;
  disabled?: boolean;
};

const DemoToggleGroup = setup<DemoToggleGroupProps>((props) => {
  const group = aria('toggle-group', props);

  return () => (
    <div ref={group.ref} {...group.props} className="demo-toggle-group">
      {props.children}
    </div>
  );
}, 'DemoToggleGroup');

type DemoToggleButtonProps = ComponentProps<'button'> & {
  value?: string;
  disabled?: boolean;
};

const DemoToggleButton = setup<DemoToggleButtonProps>((props) => {
  const toggle = aria('toggle', props);

  return () => (
    <button ref={toggle.ref} {...toggle.restProps(['children'])} className="demo-toggle-button">
      {props.children}
    </button>
  );
}, 'DemoToggleButton');
```

## Toggle Group

Single or multi-press container coordinator that compiles `role="group"` and ambiently manages the pressed value.

```ts
aria<E extends BaseElement = HTMLElement, T extends Primitive = Primitive>(
  role: 'toggle-group',
  props?: ToggleGroupProps<T>
): ToggleGroupAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type ToggleGroupProps = ComponentProps<'div'> & {
  id?: string;
  value?: string | string[];
  multiple?: boolean;
  disabled?: boolean;
  onchange?: (event: CustomEvent) => void;
};

const ToggleGroup = setup<ToggleGroupProps>((props) => {
  const group = aria('toggle-group', props);

  return () => (
    <div ref={group.ref} {...group.props}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type ToggleGroupProps = ComponentProps<'div'> & {
  id?: string;
  value?: string | string[];
  multiple?: boolean;
  disabled?: boolean;
  onchange?: (event: CustomEvent) => void;
};

const ToggleGroup = setup<ToggleGroupProps>((props) => {
  const group = aria('toggle-group', props);

  return (
    <div ref={group.ref} {...group.props}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

- `props.value` *(Primitive | Primitive[], optional)*: Active selection token — a single value in single mode, an array of tokens when `multiple: true`.
- `props.multiple` *(boolean, optional, default `false`)*: Allows several toggle buttons to stay pressed concurrently.
- `props.disabled` *(boolean, optional)*: Disables the entire group and cascades disablement to all members.
- `props.id` *(string, optional)*: Explicit DOM identifier and member id namespace; generated when omitted.
- `props.onchange` *(AriaEventHandler, optional)*: Called with the member `change` event as it bubbles through the container.

### How it behaves

- Compiles `role="group"` always — a toggle group is never promoted to `radiogroup`, and it carries an explicit `aria-disabled="true" | "false"`.
- Ambiently provides the selection context so member toggles derive `aria-pressed` from the group value without prop drilling; a member placed inside without a `value` stays fully standalone, which is how a utility button can sit in the strip without becoming a candidate.
- Activating an inactive member moves the single value to it, and activating the member that already holds it clears the selection back to `undefined` — nothing is ever forced to stay pressed. In `multiple` mode activation flips membership in the array instead.
- Holds one tab stop: the pressed member gets `tabindex="0"` and unpressed members `tabindex="-1"`, while a declared group `disabled` puts every member at `-1` and releases the container's arrow claim entirely.
- Arrow travel never presses anything; committing a member dispatches a bubbling `change` that reaches the container, and writing `value` from outside announces nothing because nobody acted.

## Toggle Buttons

Individual members of a toggle group are standard `toggle` controllers (`aria('toggle')`) that discover the enclosing group through ambient context, so they may sit at any depth below the container. See the [Toggle](/docs/aria/toggle) documentation for the full parameter reference, `aria-pressed` projection, and native `<button>` versus custom host behavior.

## Keyboard Navigation

- **ArrowRight / ArrowDown**: Moves roving focus to the next enabled toggle, wrapping past the last one back to the first.
- **ArrowLeft / ArrowUp**: Moves roving focus to the previous enabled toggle, wrapping past the first one back to the last.
- **Home / End**: Moves focus to the first or last enabled toggle.
- **Space / Enter**: Presses or releases the focused toggle; disabled members refuse both.
- **Tab**: Leaves the toggle group completely, moving focus to the next page element.

## What you get

- **Focus and pressing kept apart.** Arrows move focus on both axes and never commit state, so keyboard users are never surprised by a pressed button.
- **Single or multi-press from one API.** `multiple` switches the same group between exclusive and set membership without changing your markup.
- **One tab stop.** The pressed member owns the stop and siblings are suppressed, so the strip behaves as a single control in the page tab order.
- **Always releasable.** Re-activating the pressed member clears it; there is no `required` lock-in and no forced selection.
- **Native parity on custom hosts.** A `<button>` keeps browser activation with no redundant `role`, while a custom element gains `role="button"` plus synthesized `Enter`/`Space`.
- **Zero markup lock-in.** Render native buttons, icon buttons, or rich custom toggles as long as each member declares its `value`.
