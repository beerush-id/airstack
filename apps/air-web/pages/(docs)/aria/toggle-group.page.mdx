# Headless Toggle Group

Several pressed buttons are one control: bold, italic, and underline belong to a single value, and a set of alignment buttons belongs to another.

Getting it right means **holding the pressed state in one place**, **moving focus with the arrows without pressing anything**, **leaving one tab stop in the page order**, and **letting the group's `disabled` reach every member**.

**Headless Toggle Group** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const group = aria('toggle-group', props);

<div ref={group.ref} {...group.props} />
```

:::interactive[Paragraph Controls]
```tsx
import { aria } from '@airlib/aria';
import { mutable, setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type DemoToggleGroupProps = ComponentProps<'div'> & {
  value?: string | string[];
  multiple?: boolean;
  disabled?: boolean;
  onchange?: (event: CustomEvent) => void;
};

const DemoSegGroup = setup<DemoToggleGroupProps>((props) => {
  const group = aria('toggle-group', props);

  return () => (
    <div ref={group.ref} {...group.props} className="demo-seg">
      {props.children}
    </div>
  );
}, 'DemoSegGroup');

type DemoToggleMemberProps = ComponentProps<'button'> & {
  value: string;
  disabled?: boolean;
};

const DemoSegMember = setup<DemoToggleMemberProps>((props) => {
  const toggle = aria('toggle', props);

  return () => (
    <button ref={toggle.ref} {...toggle.restProps(['children'])} className="demo-seg-item">
      {props.children}
    </button>
  );
}, 'DemoSegMember');

const DemoEditor = setup(() => {
  const state = mutable({ style: ['bold'] as string[], align: 'left' });

  return () => (
    <div className="demo-seg-card">
      <span className="demo-seg-title">Paragraph</span>

      <div className="demo-seg-row">
        <span className="demo-seg-label">Style</span>
        <DemoSegGroup
          multiple
          value={state.style}
          onchange={(event) => {
            state.style = event.detail;
          }}
        >
          <DemoSegMember value="bold">Bold</DemoSegMember>
          <DemoSegMember value="italic">Italic</DemoSegMember>
          <DemoSegMember value="underline">Underline</DemoSegMember>
          <DemoSegMember value="strike" disabled>Strike</DemoSegMember>
        </DemoSegGroup>
      </div>

      <div className="demo-seg-row">
        <span className="demo-seg-label">Align</span>
        <DemoSegGroup
          value={state.align}
          onchange={(event) => {
            state.align = event.detail;
          }}
        >
          <DemoSegMember value="left">Left</DemoSegMember>
          <DemoSegMember value="center">Center</DemoSegMember>
          <DemoSegMember value="right">Right</DemoSegMember>
        </DemoSegGroup>
      </div>
    </div>
  );
}, 'DemoEditor');
```

## Toggle Group

**The coordinator.** One shared value, one tab stop, one arrow handler.

### Usage

```ts
aria<E extends BaseElement = HTMLElement, T extends Primitive = Primitive>(
  role: 'toggle-group',
  props?: ToggleGroupProps<T>
): ToggleGroupAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type ToggleGroupProps = ComponentProps<'div'> & {
  id?: string;
  value?: string | string[];
  multiple?: boolean;
  disabled?: boolean;
  onchange?: (event: CustomEvent) => void;
  children: ReactNode;
};

const ToggleGroup = setup<ToggleGroupProps>((props) => {
  const group = aria('toggle-group', props);

  return () => (
    <div ref={group.ref} {...group.props}>
      {props.children}
    </div>
  );
}, 'ToggleGroup');
```

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **value** _Primitive | Primitive[], optional_: The shared selection — one token in single mode, an array when `multiple`. Without an array a multi-select group resets itself to `[]` on the first press.
- **multiple** _boolean, optional, default `false`_: Keeps several members pressed at once, where a single-select group holds one token.
- **disabled** _boolean, optional_: Locks every member, drops each one out of the tab order, and leaves the arrows unclaimed.
- **id** _string, optional_: The group's identifier and the namespace its members derive theirs from. Generated as `togglegroup-<n>` when omitted.
- **onchange** _(event: CustomEvent) =&gt; void, optional_: Runs for the member's bubbling `change` that reaches the container. `detail` is the group's shared value.

### Properties

_What you read on the instance afterwards._

- **id** _string_: The group's identifier, generated or given.
- **disabled** _boolean_: Whether the whole group is locked.

### Methods

_What you call on the instance._

- **`toggle(props?, options?)`**: Creates a member already bound to this group, which is the programmatic path where markup is not available.

### How it behaves

- **The container is a group, never a radio group.** `role="group"` is compiled always, alongside `aria-disabled` as `"true"` or `"false"`.
- **Membership is a token.** A member with a `value` reads its pressed state from the shared value; a member without one keeps its own state and takes no part in the group.
- **One commit per activation.** In single mode, pressing an inactive member moves the value to it and pressing the pressed member clears the value — nothing is forced to stay pressed. In `multiple` mode, pressing flips membership in the array.
- **One tab stop in single mode.** A member with a token compiles `tabindex="0"` only while it holds the pressed state and `-1` otherwise, so a single-select group is one stop. A multi-select group holds one stop per pressed member. Clear the single value and the group holds **no** stop until something is pressed again — nothing falls back to the first enabled member.
- **Locking cascades.** A disabled group reaches every member: each native host carries `disabled`, each custom host `aria-disabled` and `tabindex="-1"`, and the container stops claiming the arrows — so a disabled group has no tab stop at all.
- **Member ids are namespaced.** With a group `id`, a member's own id becomes `<group-id>-button-<value>`.
- **Arrows never commit.** Travel moves focus only, and writing `value` from outside announces nothing because no member acted.

### Events

_What it tells you._

- **`change`** — the member's own bubbling event reaches the container, which is why `onchange` on the group hears every press. `detail` carries the group's shared value rather than a boolean: the token in single mode, the array in `multiple`.

```tsx
const align = aria('toggle-group', {
  value: 'left',
  onchange: (event) => setAlign(event.detail),
});
```

### Navigation

_What the keys do._

- **`ArrowRight` / `ArrowDown`** — moves focus to the next enabled member, wrapping past the last one to the first.
- **`ArrowLeft` / `ArrowUp`** — moves focus to the previous enabled member, wrapping past the first one to the last.
- **`Home` / `End`** — moves focus to the first or last enabled member.
- **`Space` / `Enter`** — belongs to the focused member, which presses or releases itself; a locked member refuses both.
- **`Tab`** — leaves the group. The stop is the pressed member; with the single value cleared every member sits at `-1`, so an emptied group cannot be reached by keyboard until a value is set again.
- **The handler lives on the container**, not on the members, and matches enabled `[role="button"]` and `<button>` descendants — so it works at any depth and skips a disabled member entirely. Inside a [toolbar](/docs/aria/toolbar) the outer rover owns the arrows and the group leaves them alone.

## Toggle

**The member.** A plain toggle that contributes a token to the group above it.

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **value** _Primitive, required to join_: The token this member contributes. Without it the toggle keeps its own state.
- **disabled** _boolean, optional_: Locks this member. The group's own `disabled` reaches it the same way.
- **pressed** _boolean, optional_: Ignored while the member carries a `value` in a group — the shared value decides.

### How it behaves

- **The member is a toggle**, with the same `aria-pressed`, `type="button"`, and key contract documented on [Toggle](/docs/aria/toggle); the only difference is where its pressed state comes from.
- **Writing `pressed` still works** and moves the shared value, because a write routes through the same `select()` / `deselect()` path a click uses.
- **A locked member refuses activation** and stays out of the roving order, so the arrows step over it.

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### Toggle Group

```ts
interface SingleToggleGroupProps<T extends Primitive = Primitive> {
  multiple?: false;
  id?: string;
  value?: T;
  disabled?: boolean;
  onchange?: (event: CustomEvent<boolean>) => void;
}

interface MultipleToggleGroupProps<T extends Primitive = Primitive> {
  multiple: true;
  id?: string;
  value?: T[];
  disabled?: boolean;
  onchange?: (event: CustomEvent<boolean>) => void;
}

type ToggleGroupProps<T extends Primitive = Primitive> =
  | SingleToggleGroupProps<T>
  | MultipleToggleGroupProps<T>;

interface ToggleGroupAttributes {
  id?: string;
  role?: 'group';
  'aria-disabled'?: 'true' | 'false';
}

declare class ToggleGroupAria {
  id: string;
  get disabled(): boolean;

  toggle<E extends BaseElement = HTMLButtonElement>(
    props?: Partial<ToggleProps>,
    options?: Partial<ToggleOptions>
  ): ToggleAria<E>;
}
```

### Toggle

```ts
interface ToggleProps {
  value?: Primitive;
  pressed?: boolean;
  disabled?: boolean;
  onchange?: (event: CustomEvent<boolean | Primitive | Primitive[]>) => void;
}

interface ToggleAttributes {
  id?: string;
  role?: 'button';
  type?: 'button';
  disabled?: boolean;
  tabindex?: number;
  'aria-pressed'?: 'true' | 'false';
  'aria-disabled'?: 'true' | 'false';
}

declare class ToggleAria {
  id: string;
  get pressed(): boolean;
  set pressed(value: boolean);
  get value(): Primitive;
  get disabled(): boolean;

  select(): void;
  deselect(): void;
  toggle(): void;
}
```

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`props`** / **`restProps(omit)`** is what you spread onto the host — your props minus the keys the controller writes and any you name, with the compiled attributes merged in; **`ref`** is what you bind the element with; **`attributes`** is that compiled dictionary on its own, when you need the low-level view.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
