# Headless Tooltip

A tooltip explains the control it hangs from: a save button's destination, an icon's meaning, a shortcut.

Getting it right means **describing the trigger only while the panel is open**, **revealing on focus without the pointer delay**, **staying open while the pointer crosses into the panel**, and **dismissing on `Escape` without stealing focus**.

**Headless Tooltip** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const tip = aria('tooltip', props);

<div ref={tip.ref} {...tip.restProps(['children'])} />
```

:::interactive[Document Actions]
```tsx
import { aria, type TooltipProps } from '@airlib/aria';
import { setup, teleport } from '@airlib/react';
import type { ComponentProps } from 'react';

const DemoTrigger = setup<ComponentProps<'button'>>((props) => {
  const btn = aria('button', props);

  return () => (
    <button ref={btn.ref} {...btn.restProps(['children'])} className="demo-tip-trigger">
      {props.children}
    </button>
  );
}, 'DemoTrigger');

const DemoPrimaryTrigger = setup<ComponentProps<'button'>>((props) => {
  const btn = aria('button', props);

  return () => (
    <button ref={btn.ref} {...btn.restProps(['children'])} className="demo-tip-trigger demo-tip-trigger--primary">
      {props.children}
    </button>
  );
}, 'DemoPrimaryTrigger');

const DemoTip = setup<TooltipProps>((props) => {
  const tip = aria('tooltip', props);

  return () => {
    if (!tip.open) return null;

    return teleport(
      <div ref={tip.ref} {...tip.restProps(['children'])} className="demo-tip-panel">
        {props.children}
      </div>
    );
  };
}, 'DemoTip');
```

## Tooltip

**The advisory panel.** Non-focusable, described-by, and revealed by the trigger.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'tooltip',
  props?: TooltipProps,
  options?: TooltipOptions
): TooltipAria<E>
```

:::code-group

```tsx [React]
import { aria, type TooltipProps } from '@airlib/aria';
import { setup, teleport } from '@airlib/react';

export const Tooltip = setup<TooltipProps>((props) => {
  const tip = aria('tooltip', props);

  return () => {
    if (!tip.open) return null;

    return teleport(
      <div ref={tip.ref} {...tip.restProps(['children'])}>
        {props.children}
      </div>
    );
  };
}, 'Tooltip');
```

```tsx [SolidJS]
import { aria, type TooltipProps } from '@airlib/aria';
import { setup } from '@airlib/solid';
import { Show } from 'solid-js';

export const Tooltip = setup<TooltipProps>((props) => {
  const tip = aria('tooltip', props);

  return (
    <Show when={tip.open}>
      <div ref={tip.ref} {...tip.restProps(['children'])}>
        {props.children}
      </div>
    </Show>
  );
});
```

:::

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **open** _boolean, optional, default `false`_: Whether the panel is showing. Writing it opens or closes without a trigger in sight.
- **mode** _('hover' | 'focus' | 'click')[], optional, default `['hover', 'focus']`_: Which gestures reach the panel. Drop `focus` and keyboard users get nothing; drop `hover` and only focus and click reveal it.
- **delay** _number, optional, default `300`_: The hover wait in milliseconds. Focus never waits — it opens at once.
- **dismissable** _boolean, optional, default `true`_: Whether an outside press closes the panel. `Escape` closes it either way.
- **xDir** _'before' | 'after' | 'left' | 'between' | 'right', optional_: The horizontal placement token, compiled as `data-tooltip-x`.
- **yDir** _'top' | 'bottom' | 'above' | 'below' | 'between', optional_: The vertical placement token, compiled as `data-tooltip-y`.
- **id** _string, optional_: The panel's identifier, and the value `aria-describedby` points at. Generated as `tooltip-<n>` when omitted.

### Options

_What you fix when you create it. Read once, never reactive._

- **native** _boolean, optional, default `false`_: On a native host the panel also compiles `popover="auto"` or `"manual"` from `dismissable`, so the browser's own light dismiss applies on top of the controller's.

### Properties

_What you read or write on the instance afterwards._

- **open** _boolean_: Whether the panel is showing. Reading and writing it is the same commit the triggers use.
- **delay** _number_: The hover wait in force, defaulted to `300`.
- **mode** _('hover' | 'focus' | 'click')[]_: The gestures in force, defaulted to hover and focus.
- **dismissable** _boolean_: Whether an outside press closes the panel.
- **id** _string_: The panel's identifier, and the one the trigger describes itself with.

### Methods

_What you call on the instance._

- **`show()`**: Opens at once, clearing any pending hover timer. _Refused while the trigger is locked._
- **`close()`**: Closes at once and clears the timer. _Refused while the trigger is locked._
- **`toggle()`**: Inverts the open state. _Refused while the trigger is locked._
- **`scheduleOpen()`**: Starts the hover timer — the delay decides whether it opens now or waits. _This is the path a pointer arrival takes._
- **`cancelOpen()`**: Clears a pending hover timer without changing what is on screen.

### How it behaves

- **The panel is an advisory, not a control.** It compiles `role="tooltip"` and `hidden` while closed, claims no tab stop, and never takes focus — the controller turns autofocus off for this part.
- **The link exists only while the panel does.** `aria-describedby` lands on the trigger while the panel is open and disappears when it closes, so a screen reader never reads stale advisory text.
- **The trigger is found, not passed.** A tooltip created inside an actionable controller — button, link, toggle — describes that controller's element; created inside a plain host, it describes the panel's `parentElement` instead.
- **Hover waits; focus does not.** Arriving with the pointer schedules the open at `delay`; focusing the trigger calls `show()` immediately.
- **The panel is hoverable.** Leaving the trigger into the panel keeps it open — the leave handler ignores a pointer that lands inside the panel.
- **A locked trigger opens nothing.** `show()`, `scheduleOpen()`, and `toggle()` refuse while the trigger is disabled, so a locked control shows no advisory at all.
- **Placement is the stylesheet's job.** The controller writes the anchor pair while the panel is open and turns `xDir` / `yDir` into `data-tooltip-x` / `data-tooltip-y`; where the panel lands is CSS.

### Events

_What it tells you._

- **`change`** — fires on the panel each time visibility commits, bubbling with the new state in `detail`. `Escape`, a blur, an outside press, and a programmatic `open` write all arrive here.

```tsx
const tip = aria('tooltip', {
  onchange: (event) => setHintOpen(event.detail),
});
```

### Navigation

_What the keys do._

- **`Tab`** — reaches the trigger, which reveals the panel as it takes focus. The panel itself is never a stop.
- **`Escape`** — closes an open panel, cancels the default action, and stops the event from reaching listeners above the trigger.
- **Leaving the trigger** — a blur or a pointer that lands outside both trigger and panel closes it.

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### Tooltip

```ts
type OverlayTriggerMode = 'hover' | 'focus' | 'click' | 'rove' | 'combo';

interface TooltipProps {
  id?: string;
  open?: boolean;
  mode?: OverlayTriggerMode[];
  delay?: number;
  dismissable?: boolean;
  xDir?: 'before' | 'after' | 'left' | 'between' | 'right';
  yDir?: 'top' | 'bottom' | 'above' | 'below' | 'between';
  onchange?: (event: CustomEvent<boolean>) => void;
}

interface TooltipOptions {
  native?: boolean;
}

interface TooltipAttributes {
  id?: string;
  role?: 'tooltip';
  hidden?: boolean;
  popover?: 'auto' | 'manual';
  'data-tooltip-x'?: 'before' | 'after' | 'left' | 'between' | 'right';
  'data-tooltip-y'?: 'top' | 'bottom' | 'above' | 'below' | 'between';
}

declare class TooltipAria {
  id: string;
  get open(): boolean;
  set open(value: boolean);
  get delay(): number;
  set delay(value: number);
  get mode(): OverlayTriggerMode[];
  get dismissable(): boolean;

  show(): void;
  close(): void;
  toggle(): void;
  scheduleOpen(): void;
  cancelOpen(): void;
}
```

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`attributes`** is the dictionary you spread; **`ref`** is what you bind the element with; **`props`** is the full props dictionary for spreading onto the host; **`restProps(omit)`** hands back your props with the keys you name left out.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
