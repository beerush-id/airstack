# AirLib Headless Tooltip

Displaying auxiliary advisory text when hovering over or focusing interactive elements is essential for contextual clarity. However, custom tooltips frequently fail core accessibility requirements: omitting `aria-describedby` linkages, clobbering screen reader focus, vanishing unexpectedly when users move the cursor onto the popup, or lacking immediate response on keyboard focus.

**AirLib Headless Tooltip** (`aria('tooltip')`) is a single-unit self-discovering overlay widget compliant with **WCAG 2.1 SC 1.4.13 (Content on Hover or Focus)**:
- **Scope Discovery**: Automatically discovers its interactive host candidate via ambient scope (`scope.actionable`) or falls back to its DOM `parentElement`.
- **Hover & Focus Synchronization**: Pointer hover reveals after a configurable delay (`delay: 300ms`), while keyboard focus reveals immediately (0ms delay).
- **Hoverable Advisory**: The tooltip remains visible when the pointer moves from trigger to panel.
- **Escape Dismissal**: Pressing `Escape` hides the tooltip immediately and stops propagation.
- **Advisory Semantics**: Compiles `role="tooltip"` on the panel and dynamically references it via `aria-describedby` on the trigger strictly while open.

```tsx
const host = aria('button');
const tip = aria('tooltip', { delay: 300 });

<button ref={host.ref} {...host.props}>
  Save Draft
  <div ref={tip.ref} {...tip.props}>
    Saves your changes locally
  </div>
</button>
```

:::interactive[Advisory Hover and Focus Popup]
```tsx
import { aria, type TooltipProps } from '@airlib/aria';
import { setup, teleport } from '@airlib/react';
import type { ComponentProps } from 'react';

const Button = setup<ComponentProps<'button'>>((props) => {
  const btn = aria('button', props);
  return () => (
    <button ref={btn.ref} {...btn.props}>
      {props.children}
    </button>
  );
});

const Tooltip = setup<TooltipProps>((props) => {
  const tip = aria('tooltip', props);

  return () => {
    if (!tip.open) return null;

    return teleport(
      <div ref={tip.ref} {...tip.props}>
        {props.children}
      </div>
    );
  };
});

const TooltipDemo = (props: TooltipProps) => (
  <div className="tooltip-container">
    <Button className="tooltip-trigger">
      <span>{props.mode?.length === 1 && props.mode[0] === 'hover' ? 'Hover Only' : 'Hover or Focus'}</span>
      <Tooltip className="tooltip-panel" delay={props.delay} mode={props.mode} xDir={props.xDir} yDir={props.yDir}>
        <p className="tooltip-text">WCAG 2.1 SC 1.4.13 advisory popup.</p>
      </Tooltip>
    </Button>
  </div>
);
```

## Anatomy & Scope Discovery

The tooltip widget is applied directly to the advisory floating element:

```ts
const tip = aria('tooltip', props?: TooltipProps, options?: TooltipOptions);
```

### Automatic Candidate Discovery

When initialized, `TooltipAria` resolves its trigger anchor in two tiers:

1. **Ambient Scope (`this.scope?.actionable`)**: If nested inside an interactive component that marks itself actionable (such as `ButtonAria`, `LinkAria`, or `ToggleAria`), the tooltip automatically registers an attribute refiner on that controller to inject `aria-describedby` (when open) and bind hover/focus handlers.
2. **DOM Fallback (`this.element.parentElement`)**: When mounted directly inside a plain HTML host without an enclosing controller, `attach()` configures the parent element with `aria-describedby` and hover/focus/keyboard listeners, cleaning them up upon detachment.

### Usage

:::code-group

```tsx [React]
import { aria, type TooltipProps } from '@airlib/aria';
import { setup, teleport } from '@airlib/react';

export const Tooltip = setup<TooltipProps>((props) => {
  const tip = aria('tooltip', props);

  return () => {
    if (!tip.open) return null;

    return teleport(
      <div ref={tip.ref} {...tip.props}>
        {props.children}
      </div>
    );
  };
});
```

```tsx [SolidJS]
import { aria, type TooltipProps } from '@airlib/aria';
import { setup } from '@airlib/solid';
import { Show } from 'solid-js';

export const Tooltip = setup<TooltipProps>((props) => {
  const tip = aria('tooltip', props);

  return (
    <Show when={tip.open}>
      <div ref={tip.ref} {...tip.props}>
        {props.children}
      </div>
    </Show>
  );
});
```

## Architectural & Accessibility Contracts

### Events

`onchange` is called with the open state after the tooltip toggles, and the same `change` `CustomEvent<boolean>` (`bubbles: true`) dispatches on the panel — tooltips announce visibility with `change`, unlike the `toggle` a popover emits:

```ts
const tooltip = aria('tooltip', {
  open: false,
  onchange: (event) => {
    const isOpen = event.detail;
  },
});
```

### Semantic Layering

| Host Element | Attributes Emitted | Semantics & Behavior |
| :--- | :--- | :--- |
| **Trigger (`<button>`)** | `aria-describedby` (when open) | Anchors hover and keyboard focus; injects description only while open. |
| **Custom Trigger (`<div>`)** | `tabindex="0"`, `aria-describedby` (when open) | Receives focus; keyboard focus reveals tooltip immediately. |
| **Panel (`<div>`)** | `id`, `role="tooltip"`, `hidden` | Strictly non-focusable advisory container; hoverable per WCAG 2.1 SC 1.4.13. |

### WCAG 2.1 SC 1.4.13 Compliance

1. **Dismissable**: Pressing the `Escape` key dismisses the tooltip immediately and stops propagation so underlying modals or page listeners are not triggered.
2. **Hoverable**: Pointer can move from the trigger element over the advisory panel without dismissing the tooltip.
3. **Persistent**: Once shown via hover or focus, remains visible until the user moves pointer away, blurs focus, or presses `Escape`.

## Entity Specifications

### `TooltipAria`

- **Role / Type**: Overlay Widget (`aria('tooltip')`)
- **Factory**: `aria('tooltip', props?, options?)` or `tooltip(props?, options?)`
- **Parameters (`TooltipProps`)**:
  - `open` *(boolean, optional, default `false`)*: Controls visibility of the tooltip advisory panel.
  - `mode` *(('hover' | 'focus' | 'click')[], optional, default `['hover', 'focus']`)*: Activation trigger modes. Pass `['hover']` to suppress focus-triggered reveal.
  - `delay` *(number, optional, default `300`)*: Hover delay in milliseconds before showing tooltip on pointerenter.
  - `id` *(string, optional)*: Explicit base identifier used to coordinate `aria-describedby` and panel `id`. Auto-generated by default.
  - `xDir` *('before' | 'after' | 'left' | 'between' | 'right', optional)*: Horizontal placement token.
  - `yDir` *('top' | 'bottom' | 'above' | 'below' | 'between', optional)*: Vertical placement token.
- **Controller Properties & Methods**:
  - `open` *(boolean)*: Reactive open state getter/setter.
  - `delay` *(number)*: Delay in milliseconds getter/setter.
  - `show()`: Opens the tooltip immediately.
  - `close()`: Closes the tooltip immediately.
  - `toggle()`: Inverts the open state.
  - `scheduleOpen()`: Starts the hover timer.
  - `cancelOpen()`: Clears any active hover timer.

## Events

The tooltip element dispatches a `change` event whenever visibility commits:

| Event | Type | Bubbles | Detail |
| :--- | :--- | :--- | :--- |
| `change` | `CustomEvent<boolean>` | `true` | `boolean` (new `open` state) |

## Keyboard Navigation

- **Focus**: Revealing tooltip immediately upon focus.
- **Blur**: Dismisses tooltip upon blur.
- **Escape**: Dismisses the open tooltip immediately and stops propagation.

## What you get

- **Self-discovering linkage.** Tooltips discover their actionable host automatically from ambient scope or parent DOM hierarchy without manual ID wiring.
- **Immediate focus feedback.** Keyboard users don't wait for pointer delay timers; focus reveals content instantly.
- **WCAG 2.1 SC 1.4.13 guarantee.** Pointer hover over the advisory panel does not cause flickering or dismissals.
- **Zero focus hijacking.** The advisory panel never steals tab stops or keyboard focus.
- **Clean SSR describedby linkage.** `aria-describedby` only links the trigger when open, preventing screen readers from reading advisory text prematurely.
