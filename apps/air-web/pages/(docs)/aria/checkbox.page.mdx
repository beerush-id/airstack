# AirLib Headless Checkbox

A checkbox looks trivial until you build a custom one: a native `<input type="checkbox">` resists cross-browser styling of its check mark, while a custom `<div>` needs hand-rolled `role`, `tabindex`, `aria-checked`, Space toggling, tri-state mixed announcements, and group membership sync. **AirLib Headless Checkbox** (`aria('checkbox')`) turns any element into a checkbox that behaves — native IDL sync on real inputs, full ARIA polyfills on custom hosts, mixed-state resolution and group coordination included, without dictating markup or styles.

```tsx
const checkbox = aria('checkbox', props, { native: false });

<div ref={checkbox.ref} {...checkbox.props} />
```

## Checkbox

Binary and tri-state toggle with native IDL sync and group membership.

```ts
aria<E extends BaseElement = HTMLInputElement, T extends AnyType = AnyType>(
  role: 'checkbox',
  props?: CheckboxProps<T>,
  options?: CheckboxOptions
): CheckboxAria<E, CheckboxProps<T>>
```

### Usage

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type CheckboxProps = ComponentProps<'div'> & {
  checked?: boolean;
  indeterminate?: boolean;
  disabled?: boolean;
};

const Checkbox = setup<CheckboxProps>((props) => {
  const checkbox = aria('checkbox', props, { native: false });

  return () => (
    <label>
      <div ref={checkbox.ref} {...checkbox.restProps(['children'])} className="demo-checkbox" />
      <span>{props.children}</span>
    </label>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type CheckboxProps = ComponentProps<'div'> & {
  checked?: boolean;
  indeterminate?: boolean;
  disabled?: boolean;
};

const Checkbox = setup<CheckboxProps>((props) => {
  const checkbox = aria('checkbox', props, { native: false });

  return (
    <label>
      <div ref={checkbox.ref} {...checkbox.restProps(['children'])} className="demo-checkbox" />
      <span>{props.children}</span>
    </label>
  );
});
```

:::

The check glyph comes from CSS keyed on `aria-checked` (see the style block above), never from controller state in JSX — the controller owns semantics, the stylesheet owns the mark.

### Parameters

- `props.checked` *(boolean, optional, default `false`)*: Whether the checkbox is in a checked state.
- `props.indeterminate` *(boolean, optional, default `false`)*: Mixed-state flag that outranks `checked` for announcement. Compiles `aria-checked="mixed"` (custom) or sets the native `.indeterminate` property. Any activation clears it while resolving toward checked.
- `props.disabled` *(boolean, optional)*: Blocks activation and state commits.
- `props.required` *(boolean, optional)*: Whether a checked state is required for form validation, compiling native `required` or `aria-required`.
- `props.invalid` *(boolean | 'grammar' | 'spelling', optional)*: Field validity, compiling to `aria-invalid`.
- `props.name` *(string, optional)*: Semantic identity key or field name on the parent group or form.
- `props.value` *(AnyType, optional)*: Choice candidate value when nested inside a multi-selection group.
- `props.oninput` *(function, optional)*: Called with the committed state after each activation.
- `props.onchange` *(function, optional)*: Called with the committed state when the selection changes.
- `options.native` *(boolean, optional, default `true`)*: Pass `false` when wrapping custom non-input elements (such as `<div>` or `<span>`).

### How it behaves

- Native `<input type="checkbox">` hosts omit `role` and sync the `.checked`, `.indeterminate`, `.disabled`, and `.required` IDL properties; no ARIA state mirror is emitted and browser `click`/`input`/`change` are never re-dispatched.
- Custom hosts compile `role="checkbox"`, `aria-checked` (`true`/`false`/`mixed`), always-explicit `aria-required`, `tabindex` (`0` enabled, `-1` disabled), and Space key toggling with scroll suppression.
- Activation from mixed resolves toward checked and clears the flag; from `true` it commits `false`. Inside a multi-selection group, activation adds or removes the candidate `value` without duplicating or disturbing siblings.
- Every real commit on a custom host fires bubbling `change` and `input` events carrying the new checked state; canceled triggers, disabled hosts, and no-op mutations stay silent.
- The compiled dictionary carries no form attributes — bind `name` and `value` on the element yourself for submission.

:::tip[Tri-State Selection]
Pass `indeterminate={true}` for "select all" rows or tree views. Screen readers announce the mixed state, the glyph renders from `aria-checked="mixed"`, and the next activation resolves into a definitive checked state.
:::

## Putting It Together

Once your components are wired with `aria(...)`, compose them to build checkbox controls with honest state:

```tsx
<div className="flex flex-col gap-3">
  <Checkbox checked={true}>Accept Terms & Conditions</Checkbox>
  <Checkbox indeterminate={true}>Select All (Mixed State)</Checkbox>
  <Checkbox checked={false}>Subscribe to Newsletter</Checkbox>
  <Checkbox disabled={true}>Disabled Option</Checkbox>
</div>
```

## Keyboard Navigation

- **Tab**: Focuses the checkbox. Disabled custom checkboxes sit at `tabindex="-1"` and are skipped.
- **Space**: Prevents viewport scroll on keydown, toggles on keyup. A canceled keyup commits nothing.
- **Enter**: Commits nothing — Enter is not a checkbox affordance on custom hosts.

## What you get

- **Native IDL sync.** `.checked`, `.indeterminate`, `.disabled`, and `.required` follow props on real inputs with no ARIA mirror and no re-dispatched events.
- **Custom element polyfills.** Role, tab stop, `aria-checked`/`aria-required`, and Space toggling with `native: false`.
- **Honest tri-state.** Mixed outranks unchecked for announcement and resolves toward checked on activation.
- **Group membership.** Members add or remove their candidate value without duplicates; standalone members read `checked` directly.
- **Observable commits.** Bubbling `change` and `input` events per real commit, silence otherwise.
