# Checkbox

Form checkboxes present distinct challenges across different platforms: native `<input type="checkbox">` elements do not support styling their internal check marks across all browsers, while custom elements (`<div>`, `<span>`) lack native keyboard activation, focus management, form submission, and tri-state (`indeterminate`) reflection.

`@airlib/aria` provides a headless behavioral bridge for checkboxes. It synchronizes native `.checked` and `.indeterminate` properties on real inputs, polyfills `role="checkbox"`, `tabindex`, and `Space` key toggling on custom elements, and handles tri-state indeterminate conditions without dictating styles or markup.

You compose a checkbox control using this piece:

- **Checkbox**: The checkable toggle controller that manages binary checked state and tri-state indeterminate reflection.

## What you get

- **Native & custom element support.** Binds cleanly to native `<input type="checkbox">` or polyfills `role="checkbox"`, `tabindex="0"`, and Space key toggling on custom elements.
- **Tri-state indeterminate selection.** Supports `indeterminate: true` for parent "select all" controls, compiling `'aria-checked': 'mixed'` for assistive technologies.
- **Group & standalone coordination.** Derives selection automatically when nested in a multi-selection group via `value`, or operates standalone via `checked`.
- **Clean disabled semantics.** Disabled checkboxes ignore clicks, prevent keyboard toggling, and reflect `aria-disabled`.

## Checkbox

In Aria, Checkbox is the toggle widget created with `aria('checkbox')` that coordinates binary and tri-state indeterminate checked states.

```ts
aria<E extends BaseElement = HTMLInputElement, T extends AnyType = AnyType>(
  role: 'checkbox',
  props?: CheckboxProps<T>,
  options?: CheckboxOptions
): CheckboxAria<E, CheckboxProps<T>>
```

### Parameters

- `props.checked` *(boolean, optional, default `false`)*: Whether the checkbox is in a checked state.
- `props.indeterminate` *(boolean, optional, default `false`)*: Whether the checkbox is in a tri-state indeterminate/mixed condition. Compiles `'aria-checked': 'mixed'` and synchronizes native `.indeterminate`.
- `props.disabled` *(boolean, optional)*: Disables the checkbox and removes it from user interaction.
- `props.required` *(boolean, optional)*: Whether a checked state is required for form validation, compiling native `required` or `aria-required`.
- `props.invalid` *(boolean | 'grammar' | 'spelling', optional)*: Indicates an invalid input state, compiling to `aria-invalid`.
- `props.name` *(string, optional)*: Semantic identity key or field name on the parent group or form.
- `props.value` *(AnyType, optional)*: Value payload for collection membership or form submission.
- `options.native` *(boolean, optional, default `true`)*: Pass `false` when wrapping custom non-input elements (such as `<div>` or `<span>`).

### How it behaves

When bound to a native `<input type="checkbox">`, explicit `role` is omitted (implicit in HTML) and native `.checked` and `.indeterminate` properties are kept in sync. When bound to a custom element (`native: false`), it compiles `role="checkbox"`, manages `tabindex` (`0` enabled, `-1` disabled), and polyfills Space key toggling without page scrolling. Activating an indeterminate checkbox resolves it into a definitive checked state.

:::tip[Tri-State Selection]
Pass `indeterminate={true}` to display a partially-selected condition for "select all" rows or tree views. The controller compiles `aria-checked="mixed"` for screen readers and exposes `checkbox.indeterminate` to render your partial-selection icon.
:::

### Usage

To use Checkbox, create the checkbox instance with `aria('checkbox', props, { native: false })` for custom elements, then pass `checkbox.ref` and spread `checkbox.attributes` onto your element:

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type CheckboxProps = ComponentProps<'div'> & {
  checked?: boolean;
  indeterminate?: boolean;
  disabled?: boolean;
};

const Checkbox = setup<CheckboxProps>((props) => {
  const checkbox = aria('checkbox', props, { native: false });
  const restProps = props.$omit([
    ...checkbox.ownKeys,
    'checked',
    'indeterminate',
    'disabled',
    'children',
    'className',
  ]);

  return () => (
    <div ref={checkbox.ref} {...restProps} {...checkbox.attributes} className={props.className}>
      {checkbox.indeterminate ? '−' : checkbox.checked ? '✓' : ''}
    </div>
  );
});
```

## Putting It Together

Once your components are wired with `aria(...)`, compose them to build accessible checkbox controls:

```tsx
<div className="flex flex-col gap-3">
  <label className="flex items-center gap-2">
    <Checkbox checked={true} />
    <span>Accept Terms & Conditions</span>
  </label>
  <label className="flex items-center gap-2">
    <Checkbox indeterminate={true} />
    <span>Select All (Mixed State)</span>
  </label>
  <label className="flex items-center gap-2">
    <Checkbox checked={false} />
    <span>Subscribe to Newsletter</span>
  </label>
  <label className="flex items-center gap-2">
    <Checkbox disabled={true} />
    <span>Disabled Option</span>
  </label>
</div>
```

## Keyboard Navigation

- **Tab**: Focuses into the checkbox or moves to the next focusable page element.
- **Space**: Toggles the checkbox between checked and unchecked (or transitions from indeterminate to checked).
