# Headless Checkbox

A checkbox is a yes-no you can also leave undecided. Getting it right means **marking and unmarking on a click or `Space`**, **showing the undecided state without pretending it is either answer**, **letting the label text toggle the box**, and **telling your code which ones are on**.

**Headless Checkbox** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const checkbox = aria('checkbox', props, { native: false });

<div ref={checkbox.ref} {...checkbox.restProps(['children'])} />
```

:::interactive[Notification Preferences]
```tsx
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type DemoCheckboxProps = ComponentProps<'label'> & {
  checked?: boolean;
  indeterminate?: boolean;
  disabled?: boolean;
};

const DemoCheckbox = setup<DemoCheckboxProps>((props) => {
  const checkbox = aria('checkbox', props, { native: false });

  return () => (
    <label className="demo-checkbox-row">
      <div ref={checkbox.ref} {...checkbox.restProps(['children'])} className="demo-checkbox" />
      <span>{props.children}</span>
    </label>
  );
}, 'DemoCheckbox');
```
```html
<div className="demo-checkbox-stack">
  <DemoCheckbox checked={true}>Email me a weekly digest</DemoCheckbox>
  <DemoCheckbox indeterminate={true}>Select all topics</DemoCheckbox>
  <DemoCheckbox>Push notifications</DemoCheckbox>
  <DemoCheckbox disabled={true}>Legacy SMS alerts</DemoCheckbox>
</div>
```

## Checkbox

**The box itself.** It marks, it unmarks, and it can sit undecided between the two.

### Usage

```ts
aria<E extends BaseElement = HTMLInputElement | HTMLButtonElement>(
  role: 'checkbox',
  props?: CheckboxProps,
  options?: CheckboxOptions
): CheckboxAria<E>
```

### Parameters

_What you pass in. The props object stays live — change a value on it and the box follows._

- **checked** _boolean, optional, default `false`_: Whether the box is marked.
- **indeterminate** _boolean, optional, default `false`_: The undecided state — some of what this box covers is on. **It outranks `checked`** for the announcement, and the next activation resolves it into a marked box.
- **disabled** _boolean, optional_: Locks the box. A click, `Space`, or a write to `checked` commits nothing.
- **required** _boolean, optional_: Asks for this box to be marked before the form is accepted.
- **invalid** _boolean | 'grammar' | 'spelling', optional_: Marks the field invalid, and says what kind of wrong it is.
- **name** _string, optional_: The field name the box reports under when it submits with a form.
- **value** _Primitive, optional_: The token this box contributes to a group's shared selection. Give one and the box is a member; leave it out and the box keeps its own state.
- **oninput** _(event: CustomEvent&lt;boolean&gt;) =&gt; void, optional_: Called after each activation with the new state in `detail`.
- **onchange** _(event: CustomEvent&lt;boolean&gt;) =&gt; void, optional_: Called when the state changes. _Inside a group, `detail` carries the group's shared value instead._

### Options

_What you fix when you create it. Read once, never reactive._

- **native** _boolean, optional, default `true`_: Pass `false` when the host isn't an `<input type="checkbox">` and you want `role`, a tab stop, `aria-checked`, and `Space` handling on it.

### Properties

_What you read or write on the instance afterwards._

- **checked** _boolean_: Whether the box is marked. **Writing it marks or unmarks the box**, and does nothing while disabled.
- **indeterminate** _boolean_: Whether the box is sitting undecided. Read it; set it through `props.indeterminate`.
- **disabled** _boolean_: Whether the box is locked, **including by the group it belongs to**.
- **value** _Primitive_: The token this box contributes to a group.
- **id** _string_: The box's own identifier — `checkbox-<n>`, which is also the DOM id unless a group namespaces it.

### Methods

_What you call on the instance._

- **`select()`**: Marks the box; an undecided box lands on marked. _Does nothing while disabled._
- **`deselect()`**: Unmarks the box, settling an undecided one on the way. _Does nothing while disabled._
- **`toggle()`**: Marks or unmarks. _An undecided box marks rather than emptying, and a disabled one does nothing._

### How it behaves

- **Two hosts, one state.** On a real `<input type="checkbox">` it drives the `.checked`, `.indeterminate`, `.disabled`, and `.required` properties and adds no ARIA mirror or `role`; on any other element it compiles `role="checkbox"`, `aria-checked` as `true`, `false`, or `mixed`, and a place in the tab order.
- **Undecided outranks marked.** `indeterminate` wins the announcement, and the next activation settles it into a definitive marked box instead of emptying it.
- **Disabled means inert.** Click, `Space`, and every state write are refused, and the activation events themselves are cancelled and stopped from bubbling — so nothing above the box reacts to a disabled click either.
- **The label works on any host.** Clicking the `<label>` text marks the box, the way the browser does it for a real input.
- **Group membership on a token.** Inside a checkbox group with a `value`, the box reads and writes the shared selection rather than its own state, and the group's `disabled` reaches it.
- **Nothing submits for you.** `name` and `value` are consumed by the controller, so the compiled dictionary carries no form attributes — put them on the element yourself when the box goes with a form.
- **A canceled trigger commits nothing.** `preventDefault` on the click or on the `Space` keydown leaves the box exactly where it was.

### Events

_What it tells you._

- **`change`** — fires when the state really flips, with the new state in `detail`. A group member carries the group's shared value there instead.
- **`input`** — fires on the same commit **on a custom host**; a real input leaves `input` to the browser. Repeats of a commit, disabled boxes, and canceled triggers stay silent.

```tsx
const checkbox = aria('checkbox', {
  checked: false,
  onchange: (event) => saveTopic(event.detail),
});
```

### Navigation

_What the keys do._

- **`Space`** — marks or unmarks the box. The keydown suppresses the page scroll and the commit lands on keyup; a canceled keydown never commits.
- **`Click`** — marks or unmarks the box, including through its label.
- **`Tab`** — reaches the box. A disabled box is taken out of the tab order.

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### Checkbox

```ts
interface CheckboxProps {
  checked?: boolean;
  indeterminate?: boolean;
  disabled?: boolean;
  required?: boolean;
  invalid?: boolean | 'grammar' | 'spelling';
  name?: string;
  value?: Primitive;
  oninput?: (event: CustomEvent<boolean>) => void;
  onchange?: (event: CustomEvent<boolean>) => void;
}

interface CheckboxOptions {
  native?: boolean;
}

interface CheckboxAttributes {
  id?: string;
  role?: string;
  type?: string;
  checked?: boolean;
  indeterminate?: boolean;
  required?: boolean;
  disabled?: boolean;
  tabindex?: number;
  'aria-checked'?: 'true' | 'false' | 'mixed';
  'aria-required'?: 'true' | 'false';
  'aria-invalid'?: 'true' | 'false' | 'grammar' | 'spelling';
  'aria-disabled'?: 'true' | 'false';
}

declare class CheckboxAria {
  id: string;
  get checked(): boolean;
  set checked(value: boolean);
  get indeterminate(): boolean;
  get disabled(): boolean;
  get value(): Primitive;

  select(): void;
  deselect(): void;
  toggle(): void;
}
```

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`props`** / **`restProps(omit)`** is what you spread onto the host — your props minus the keys the controller writes and any you name, with the compiled attributes merged in; **`ref`** is what you bind the element with; **`attributes`** is that compiled dictionary on its own, when you need the low-level view.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
