# Sidebar

Sidebars hold content that supports the main document without being part of it: related links, filters, notes, a table of contents. Users who need the main content should be able to skip that supporting material, and users who want it should be able to jump straight to it — which only works if it is identified as separate from `main`.

`@airlib/aria` compiles the sidebar landmark onto the element you already render. Bound to a native `<aside>` it emits no redundant role; bound to a `<div>` it supplies `role="complementary"`, and it compiles an accessible name when a page holds more than one sidebar.

You compose a sidebar landmark using this piece:

- **Sidebar**: The supporting content landmark that compiles `role="complementary"` only when the host does not already imply it.

## What you get

- **Native-first projection.** An `<aside>` keeps its implicit role; a custom host gets an explicit `role="complementary"`.
- **Nameable sidebars.** `label` and `labelledby` compile to `aria-label` and `aria-labelledby` when a page holds several.
- **Structure only.** No focus, no keyboard handling, and no state.

## Sidebar

In Aria, Sidebar is the supporting content landmark created with `aria('sidebar')` that projects complementary semantics onto a native or custom host.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'sidebar',
  props?: SidebarProps,
  options?: SidebarOptions
): SidebarAria<E>
```

### Parameters

- `props.label` *(string, optional)*: Accessible label compiled to `aria-label`.
- `props.labelledby` *(string, optional)*: Element ID providing the accessible name, compiled to `aria-labelledby`.
- `options.native` *(boolean, optional, default `true`)*: Pass `false` when binding to a custom `<div>` host.

### How it behaves

With `native: true` the controller compiles only the accessible name and leaves the role to the host. With `native: false` it adds `role="complementary"`. The name is compiled when provided and omitted otherwise.

:::tip[Keep it a sibling of main]
An `<aside>` nested inside `<main>`, `<article>`, `<section>`, `<nav>`, or another `<aside>` is not a complementary landmark — the HTML mapping demotes it to a generic container. Render the sidebar as a sibling of `<main>` so the supporting content stays separate from the content it supports.
:::

### Usage

To use Sidebar, create the landmark with `aria('sidebar', props)`, then pass `sidebar.ref` and spread `sidebar.attributes` onto your aside element:

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type SidebarProps = ComponentProps<'aside'> & {
  label?: string;
  labelledby?: string;
};

const Sidebar = setup<SidebarProps>((props) => {
  const sidebar = aria('sidebar', props);
  const restProps = props.$omit([
    ...sidebar.ownKeys,
    'label',
    'labelledby',
    'children',
    'className',
  ]);

  return () => (
    <aside ref={sidebar.ref} {...restProps} {...sidebar.attributes} className={props.className}>
      {props.children}
    </aside>
  );
}, 'Sidebar');
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type SidebarProps = ComponentProps<'aside'> & {
  label?: string;
  labelledby?: string;
};

const Sidebar = setup<SidebarProps>((props) => {
  const sidebar = aria('sidebar', props);
  const restProps = props.$omit([
    ...sidebar.ownKeys,
    'label',
    'labelledby',
    'children',
    'className',
  ]);

  return (
    <aside ref={sidebar.ref} {...restProps} {...sidebar.attributes} className={props.className}>
      {props.children}
    </aside>
  );
});
```

:::

## Putting It Together

Once your component is wired with `aria('sidebar')`, place it beside the main content rather than inside it:

```tsx
<div className="layout">
  <Main id="content">Article body</Main>
  <Sidebar label="Related links">Related documentation</Sidebar>
</div>
```

## Keyboard Navigation

- **None.** The landmark takes no tab stop and claims no keys; the controls inside it keep their own keyboard behavior.
