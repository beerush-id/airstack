# AirLib Headless Sidebar

Sidebars hold content that supports the main document without being part of it: related links, filters, notes, a table of contents. Users who need the main content should be able to skip that supporting material, and users who want it should be able to jump straight to it — which only works if it is identified as separate from `main`. **AirLib Headless Sidebar** (`aria('sidebar')`) compiles `role="complementary"` onto the generic host you already render and names it when a page holds more than one.

```tsx
const sidebar = aria('sidebar', props);

<div ref={sidebar.ref} {...sidebar.restProps(['children'])} />
```

## Sidebar

The supporting content landmark. It projects complementary semantics onto a generic host so assistive technology can tell the aside from the document it sits beside.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'sidebar',
  props?: SidebarProps,
  options?: SidebarOptions
): SidebarAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type SidebarProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
  children: ReactNode;
};

const Sidebar = setup<SidebarProps>((props) => {
  const sidebar = aria('sidebar', props);

  return () => (
    <div ref={sidebar.ref} {...sidebar.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type SidebarProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
};

const Sidebar = setup<SidebarProps>((props) => {
  const sidebar = aria('sidebar', props);

  return (
    <div ref={sidebar.ref} {...sidebar.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

- `props.label` *(string, optional)*: Accessible label compiled to `aria-label`, distinguishing this sidebar from others on the page.
- `props.labelledby` *(string, optional)*: Element ID providing the accessible name, compiled to `aria-labelledby`.
- `options.native` *(boolean, optional, default `false`)*: Pass `true` when the host is a real `<aside>`, which already implies the role — the redundant `role="complementary"` is dropped and only the name is compiled.

### How it behaves

- Compiles `role="complementary"` on a generic host. With `native: true` the role is left to the `<aside>` element and only the accessible name is emitted.
- The role comes from `native` alone — never from the host tag and never from where the element sits in the tree.
- `label` compiles to `aria-label` and `labelledby` to `aria-labelledby`, both reactively, and both are omitted when absent.
- Two sidebars are distinguished by name, not by position: the controller invents no fallback label and tracks no order.
- It points nowhere — no `aria-controls`, no `aria-labelledby` borrowed from the content it supports, and nothing inside `main` is hidden or claimed.
- Structure only: no `tabindex`, no `aria-live`, no `aria-expanded`, no `aria-orientation`, and no state. Arrow keys and clicks pass through untouched.
- `label` and `labelledby` are consumed by the controller and carried in `ownKeys`, so `restProps(['children'])` is the whole omission list — neither leaks to the DOM as a stray attribute.

:::tip[Keep it a sibling of main]
An `<aside>` nested inside `<main>`, `<article>`, `<section>`, `<nav>`, or another `<aside>` is not a complementary landmark — the HTML mapping demotes it to a generic container and exposes no role for it at all. Render the sidebar as a sibling of `<main>` so the supporting content stays separate from the content it supports. A custom host compiles `role="complementary"` wherever it is placed, so nesting one inside a section still publishes the landmark.
:::

## Keyboard Navigation

- **None.** The landmark takes no tab stop and claims no keys; the controls inside it keep their own keyboard behavior.

## What you get

- **Complementary on a generic host.** A `<div>` becomes supporting content that can be skipped or jumped to.
- **Nameable sidebars.** `label` and `labelledby` separate several asides on one page.
- **No redundant role.** `native: true` on a real `<aside>` leaves the implicit role alone.
- **No ownership of the content.** The sidebar references nothing and hides nothing.
- **Placement-stable output.** The compiled attributes are identical in SSR and after hydration, because nothing is read from the DOM.
