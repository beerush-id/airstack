# Headless Sidebar

A sidebar holds content that supports the document without belonging to it: related links, filters, notes, a table of contents.

Getting it right means **compiling `complementary` onto a generic host**, **leaving a real `<aside>` its own role**, **naming each sidebar when a page holds more than one**, and **taking no tab stop and no ownership of the content inside**.

**Headless Sidebar** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const sidebar = aria('sidebar', props);

<div ref={sidebar.ref} {...sidebar.restProps(['children'])} />
```

:::interactive[Reading Layout]
```tsx
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type DemoSidebarProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
  children: ReactNode;
};

const DemoSidebar = setup<DemoSidebarProps>((props) => {
  const sidebar = aria('sidebar', props);

  return () => (
    <div ref={sidebar.ref} {...sidebar.restProps(['children'])} className="demo-sidebar">
      {props.children}
    </div>
  );
}, 'DemoSidebar');
```

:::tip
**Keep the sidebar a sibling of main.** Name a custom host and it publishes the landmark wherever it sits; a real `<aside>` nested inside other landmark content is demoted to a generic container by the HTML mapping and loses the role.
:::

## Sidebar

**The supporting landmark.** It publishes `complementary` on a generic host and carries the name that separates one sidebar from another.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'sidebar',
  props?: SidebarProps,
  options?: SidebarOptions
): SidebarAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type SidebarProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
  children: ReactNode;
};

const Sidebar = setup<SidebarProps>((props) => {
  const sidebar = aria('sidebar', props);

  return () => (
    <div ref={sidebar.ref} {...sidebar.restProps(['children'])}>
      {props.children}
    </div>
  );
}, 'Sidebar');
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps, JSX } from 'solid-js';

type SidebarProps = ComponentProps<'div'> & {
  label?: string;
  labelledby?: string;
  children: JSX.Element;
};

const Sidebar = setup<SidebarProps>((props) => {
  const sidebar = aria('sidebar', props);

  return (
    <div ref={sidebar.ref} {...sidebar.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **label** _string, optional_: The name the landmark list announces, compiled to `aria-label`. This is what separates two sidebars on one page.
- **labelledby** _string, optional_: The ID of an element already on the page that carries that name, compiled to `aria-labelledby`.

### Options

_What you fix when you create it. Read once, never reactive._

- **native** _boolean, optional, default `false`_: Pass `true` when the host is a real `<aside>`, which already implies `complementary`. The redundant role is dropped and only the name is compiled.

### Properties

_What you read or write on the instance afterwards._

- **label** _string | undefined_: The label in force.
- **labelledby** _string | undefined_: The ID reference in force.
- **named** _boolean_: Whether the landmark carries an accessible name.

### How it behaves

- **A generic host gets the role.** A `<div>` compiles `role="complementary"`, whether or not you name it.
- **`native` decides the role, never the tag.** Pass `native: true` and the element supplies the role itself, so no redundant `complementary` is written.
- **Naming is reactive.** Set, change, or clear `label` or `labelledby` and the projection follows on the next write.
- **Nothing is claimed from the content it supports.** No `aria-controls`, no borrowed name, and nothing inside `main` is hidden or owned.
- **Structure only.** No `tabindex`, no `aria-live`, no state; the controls inside keep their own keyboard behavior.
- **Both name props stay off the host as plain attributes.** `label` and `labelledby` compile to `aria-label` and `aria-labelledby` only, so `restProps(['children'])` is the whole omission list.

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### Sidebar

```ts
interface SidebarProps {
  label?: string;
  labelledby?: string;
}

interface SidebarOptions {
  native?: boolean;
}

interface SidebarAttributes {
  role?: 'complementary';
  'aria-label'?: string;
  'aria-labelledby'?: string;
}

declare class SidebarAria {
  get label(): string | undefined;
  get labelledby(): string | undefined;
  get named(): boolean;
}
```

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`props`** / **`restProps(omit)`** is what you spread onto the host — your props minus the keys the controller writes and any you name, with the compiled attributes merged in; **`ref`** is what you bind the element with; **`attributes`** is that compiled dictionary on its own, when you need the low-level view.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
