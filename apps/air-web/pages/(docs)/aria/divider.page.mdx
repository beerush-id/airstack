# AirLib Headless Divider

A static rule only structures content, but most of you have struggled keeping it quiet: a bare `<div>` line announces nothing to assistive technology, and wiring `role`, orientation, and focus exclusion by hand is easy to get wrong. **AirLib Headless Divider** (`aria('divider')`) turns any element into a structural boundary — always `role="separator"`, never a tab stop, never a value, `aria-orientation` only when vertical. For resizable pane boundaries, see [Splitter](/docs/aria/splitter).

```tsx
const divider = aria('divider', props);

<div ref={divider.ref} {...divider.props} />
```

## Divider

Static structural boundary with no focus, no value, and no keyboard behavior.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'divider',
  props?: DividerProps
): DividerAria<E>
```

### Usage

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type DividerProps = ComponentProps<'div'> & {
  orientation?: 'horizontal' | 'vertical';
};

const Divider = setup<DividerProps>((props) => {
  const divider = aria('divider', props);

  return () => (
    <div ref={divider.ref} {...divider.props} />
  );
}, 'Divider');
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type DividerProps = ComponentProps<'div'> & {
  orientation?: 'horizontal' | 'vertical';
};

const Divider = setup<DividerProps>((props) => {
  const divider = aria('divider', props);

  return <div ref={divider.ref} {...divider.props} />;
});
```

:::

### Parameters

- `props.orientation` *('horizontal' | 'vertical', optional, default `'horizontal'`)*: Divider axis, announced as `aria-orientation` only when vertical.

The controller compiles no accessible name of its own.

### How it behaves

A static divider is projection only: always `role="separator"`, while `tabindex` and every `aria-value*` attribute stay off the element. There is no `native` option and no `<hr>` binding — the host element is always the author's.

:::tip[Divider or splitter is an authoring decision]
The structural-or-interactive choice is made by picking the entity — `aria('divider')` versus `aria('splitter')` — so a template consumer never flips a static rule into a control.
:::

## Putting It Together

Once your component is wired with `aria('divider')`, compose it into structured layouts:

## Keyboard Navigation

- **Tab**: Static dividers take no tab stop and are skipped entirely.
- **Every other key**: Left unclaimed for the browser and surrounding widgets.

## What you get

- **Quiet static dividers.** No `tabindex`, no value attributes, always `role="separator"`.
- **Vertical on departure only.** `aria-orientation` is emitted solely for the vertical axis.
