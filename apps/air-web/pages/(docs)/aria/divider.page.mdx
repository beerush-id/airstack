# Headless Divider

A divider marks where one part of a layout ends and the next begins. Getting it right means **compiling the separator role on your own element**, **announcing the axis only when it departs from the default**, **keeping it out of the tab order**, and **carrying no value**.

**Headless Divider** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const divider = aria('divider', props);

<div ref={divider.ref} {...divider.restProps(['children'])} />
```

:::interactive[Panel Layout]
```tsx
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type DemoDividerProps = ComponentProps<'div'> & {
  orientation?: 'horizontal' | 'vertical';
};

const DemoDivider = setup<DemoDividerProps>((props) => {
  const divider = aria('divider', props);

  return () => <div ref={divider.ref} {...divider.restProps(['children'])} className="demo-divider" />;
}, 'DemoDivider');
```

:::tip
Divider or splitter is an authoring decision, made by picking the entity — `aria('divider')` or `aria('splitter')` — so a consumer of your component can never flip a static rule into a control.
:::

## Divider

**One structural boundary.** No focus, no value, no keys — only an axis.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'divider',
  props?: DividerProps
): DividerAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type DividerProps = ComponentProps<'div'> & {
  orientation?: 'horizontal' | 'vertical';
};

const Divider = setup<DividerProps>((props) => {
  const divider = aria('divider', props);

  return () => <div ref={divider.ref} {...divider.restProps(['children'])} />;
}, 'Divider');
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type DividerProps = ComponentProps<'div'> & {
  orientation?: 'horizontal' | 'vertical';
};

const Divider = setup<DividerProps>((props) => {
  const divider = aria('divider', props);

  return <div ref={divider.ref} {...divider.restProps(['children'])} />;
});
```

:::

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **orientation** _'horizontal' | 'vertical', optional, default `'horizontal'`_: The axis the rule runs along. Only the vertical one is announced, because horizontal is what a separator is assumed to be.

### Properties

_What you read or write on the instance afterwards._

- **orientation** _'horizontal' | 'vertical'_: The axis in force.

### How it behaves

- **Announced as a boundary.** Screen readers hear a separator, so the split in your layout is a split in the document too.
- **Always your element.** There is no native divider to opt into; the host you render carries the separator role.
- **Never a tab stop.** The tab key passes straight over it, in both directions.
- **Never a value.** No `aria-value*` attributes, so it can't be mistaken for a range control.
- **Vertical says so, horizontal doesn't.** The axis is announced only when it departs from the default.

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### Divider

```ts
interface DividerProps {
  orientation?: 'horizontal' | 'vertical';
}

interface DividerAttributes {
  role?: 'separator';
  'aria-orientation'?: 'horizontal' | 'vertical';
}

declare class DividerAria {
  get orientation(): 'horizontal' | 'vertical';
}
```

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`attributes`** is the dictionary you spread; **`ref`** is what you bind the element with; **`props`** is the full props dictionary for spreading onto the host; **`restProps(omit)`** hands back your props with the keys you name left out.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
