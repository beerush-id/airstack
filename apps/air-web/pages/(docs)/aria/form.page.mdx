# AirLib Headless Form

A page can hold several forms: checkout, a filter panel, a comment box, account settings. When they are all just `<form>` elements, assistive technologies cannot list or jump to any of them, because HTML only exposes a form as a landmark when it has an accessible name. An unnamed form is a structural container, not a destination. **AirLib Headless Form** (`aria('form')`) enforces that rule by compilation instead of by memory: with `label` or `labelledby` it emits `role="form"` and the name, and without either it emits no role at all — so a form can never be announced as a landmark it does not qualify as.

```tsx
const form = aria('form', props);

<form ref={form.ref} {...form.restProps(['children'])} />
```

## Form

The form area landmark. It compiles the role only when the container is named, and exposes `form.named` so a wrapper can tell whether the landmark was actually published.

```ts
aria<E extends BaseElement = HTMLFormElement>(
  role: 'form',
  props?: FormLandmarkProps,
  options?: FormLandmarkOptions
): FormAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type FormLandmarkProps = ComponentProps<'form'> & {
  label?: string;
  labelledby?: string;
  children: ReactNode;
};

const FormLandmark = setup<FormLandmarkProps>((props) => {
  const form = aria('form', props);

  return () => (
    <form ref={form.ref} {...form.restProps(['children'])}>
      {props.children}
    </form>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type FormLandmarkProps = ComponentProps<'form'> & {
  label?: string;
  labelledby?: string;
};

const FormLandmark = setup<FormLandmarkProps>((props) => {
  const form = aria('form', props);

  return (
    <form ref={form.ref} {...form.restProps(['children'])}>
      {props.children}
    </form>
  );
});
```

:::

The component is named `FormLandmark` rather than `Form` to stay clear of the package's own `FormAria` type and of form-library components in your app; the controller variable stays `form`.

### Parameters

- `props.label` *(string, optional)*: Accessible label compiled to `aria-label`. Required for the landmark to be exposed.
- `props.labelledby` *(string, optional)*: Element ID providing the accessible name, compiled to `aria-labelledby`. Also satisfies the naming requirement.
- `options.native` *(boolean, optional, default `false`)*: Inert for this role. The `form` role is compiled from the accessible name rather than from the host, so a named form gets `role="form"` either way.

### How it behaves

- With `label` or `labelledby` present, compiles `role="form"` together with the accessible name — explicitly, even on a native `<form>`, because the HTML mapping only exposes a named form as a landmark.
- With neither present, compiles no role at all and the element stays a structural container. Clearing the name withdraws the role again, reactively.
- `form.named` reports whether the landmark is currently exposed, so a wrapper can branch on it.
- The role never depends on `native` or on the host tag: naming is the only gate.
- It is a landmark, not a form engine — no `name`, `value`, `action`, `method`, `enctype`, or `novalidate` is compiled, and a `submit` event is never intercepted.
- A control placed inside keeps its own identity and still participates in `FormData`.
- `label` and `labelledby` are consumed by the controller and carried in `ownKeys`, so `restProps(['children'])` is the whole omission list — neither leaks to the DOM as a stray attribute.

:::tip[Name it after the task]
Use the task the form performs, not the word "form": "Shipping address", "Payment details", "Filter results". That is the string announced in the landmark list, and "form" three times over tells a user nothing about which one to open.
:::

## Keyboard Navigation

- **None.** The landmark takes no tab stop of its own. Keyboard users interact with the fields and submit control inside it, and native form submission stays entirely yours to wire.

## What you get

- **Naming enforced by compilation.** No accessible name means no `role="form"`, so the landmark list never carries a form that does not qualify.
- **A `named` projection.** `form.named` tells your wrapper whether the landmark was actually exposed.
- **Reactive promotion and demotion.** Adding or clearing the name adds or withdraws the role.
- **No form semantics.** No form attributes are compiled and submission is never touched.
- **Placement-stable output.** The compiled attributes are identical in SSR and after hydration, because nothing is read from the DOM.
