# Headless Form

A page can hold a checkout, a filter panel, and a comment box at the same time, and none of them becomes a landmark until it carries an accessible name.

Getting it right means **compiling `role="form"` only while the container is named**, **withdrawing it the moment the name goes**, **never leaning on `native` or the host tag**, and **never touching submission**.

**Headless Form** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const form = aria('form', props);

<form ref={form.ref} {...form.restProps(['children'])} />
```

:::interactive[Checkout Forms]
```tsx
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type DemoFormProps = ComponentProps<'form'> & {
  label?: string;
  labelledby?: string;
  children: ReactNode;
};

const DemoForm = setup<DemoFormProps>((props) => {
  const form = aria('form', props);

  return () => (
    <form ref={form.ref} {...form.restProps(['children'])} className="demo-form">
      {props.children}
    </form>
  );
}, 'DemoForm');

  name: string;
  children: ReactNode;
};

const DemoField = (props: DemoFieldProps) => (
  <div className="demo-field">
    <span className="demo-field-label">{props.name}</span>
    {props.children}
  </div>
);

const Demo = () => (
  <div className="demo-form-stack">
    <div className="demo-form-row">

        <span className="demo-form-title">Where should it go?</span>

      </DemoForm>
    </div>

    <div className="demo-form-row">
      <span className="demo-form-caption">Named by reference to a heading just outside it</span>
      <span id="demo-form-payment-title" className="demo-form-title">How would you like to pay?</span>
      <DemoForm labelledby="demo-form-payment-title">
        <DemoField name="Card number"><input name="card" placeholder="4242 4242 4242 4242" className="demo-field-input" /></DemoField>
        <DemoField name="Billing postcode"><input name="postcode" defaultValue="E1 6AN" readOnly className="demo-field-input" /></DemoField>
```

## Form

**The form area landmark.** It compiles the role only while the container is named, and exposes `form.named` so a wrapper can tell whether the landmark was published.

### Usage

```ts
aria<E extends BaseElement = HTMLFormElement>(
  role: 'form',
  props?: FormLandmarkProps,
  options?: FormLandmarkOptions
): FormAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type FormLandmarkProps = ComponentProps<'form'> & {
  label?: string;
  labelledby?: string;
  children: ReactNode;
};

const FormLandmark = setup<FormLandmarkProps>((props) => {
  const form = aria('form', props);

  return () => (
    <form ref={form.ref} {...form.restProps(['children'])}>
      {props.children}
    </form>
  );
}, 'FormLandmark');
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps, JSX } from 'solid-js';

type FormLandmarkProps = ComponentProps<'form'> & {
  label?: string;
  labelledby?: string;
  children: JSX.Element;
};

const FormLandmark = setup<FormLandmarkProps>((props) => {
  const form = aria('form', props);

  return (
    <form ref={form.ref} {...form.restProps(['children'])}>
      {props.children}
    </form>
  );
});
```

:::

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **label** _string, optional_: The name screen readers announce for this form, compiled to `aria-label`. **The landmark exists only while this or `labelledby` is set.**
- **labelledby** _string, optional_: The ID of an element already on the page that provides that name, compiled to `aria-labelledby`. Satisfies the naming requirement the same way.

### Properties

_What you read or write on the instance afterwards._

- **label** _string | undefined_: The label in force.
- **labelledby** _string | undefined_: The ID reference in force.
- **named** _boolean_: Whether the landmark is currently exposed — the same condition that decides whether the role is written.

### How it behaves

- **A named container compiles `role="form"` and the name together.** Clear the name and both go, leaving a structural container that a screen reader never lists.
- **The role comes from the name alone.** `native` changes nothing here: a named `<form>` gets the explicit role too, because the HTML mapping never exposes an unnamed one as a landmark.
- **`form.named` reports the same condition**, so a wrapper can branch on whether the landmark was published instead of guessing.
- **It is a landmark, not a form engine.** No `action`, `method`, `enctype`, or `novalidate` is compiled, no `submit` event is intercepted, and submission stays yours to wire.
- **A control inside keeps its own identity** and still participates in `FormData`.
- **Both name props stay off the DOM as plain attributes.** `label` and `labelledby` compile to `aria-label` and `aria-labelledby` only, so `restProps(['children'])` is the whole omission list.

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### Form

```ts
interface FormLandmarkProps {
  label?: string;
  labelledby?: string;
}

interface FormLandmarkOptions {
  native?: boolean;
}

interface FormLandmarkAttributes {
  role?: 'form';
  'aria-label'?: string;
  'aria-labelledby'?: string;
}

declare class FormAria {
  get label(): string | undefined;
  get labelledby(): string | undefined;
  get named(): boolean;
}
```

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`attributes`** is the dictionary you spread; **`ref`** is what you bind the element with; **`props`** is the full props dictionary for spreading onto the host; **`restProps(omit)`** hands back your props with the keys you name left out.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
