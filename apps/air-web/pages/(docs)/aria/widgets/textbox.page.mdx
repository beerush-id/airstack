# Textbox

Text fields require synchronizing live value state, managing validation indicators (`aria-invalid`, `aria-required`), and handling readonly and disabled semantics without interfering with native browser caret movement, autocomplete, or form submission. When building custom input containers, manual role projection and keyboard handling are required.

`@airlib/aria` provides headless behavioral controllers for text and search inputs. It manages live value synchronization, projects accessible validation flags, and handles native vs. custom element contracts without dictating markup or styles.

You control text inputs using these pieces:

- **Textbox**: The text input controller that manages live value synchronization, multiline support, and validation state reflection.
- **Searchbox**: The specialized search query controller compiling `type="search"` semantics and query synchronization.

## What you get

- **Live value synchronization.** Synchronizes with DOM input events and keeps the state in sync.
- **Validation and state projection.** Compiles `aria-invalid`, `aria-required`, `aria-readonly`, and `disabled` state seamlessly.
- **Accessible labeling.** Automatically compiles `props.label` into `aria-label`.
- **Searchbox specialization.** Specialized `role="searchbox"` controller for search query fields with native clear and Enter handling.

## Textbox

In Aria, Textbox is the text input controller created with `aria('textbox')` that manages live value synchronization and validation state projection.

```ts
aria<E extends BaseElement = HTMLInputElement>(
  role: 'textbox',
  props?: TextboxProps,
  options?: TextboxOptions
): TextboxAria<E>
```

### Parameters

- `props.value` *(string, optional)*: Live text value.
- `props.label` *(string, optional)*: Accessible label compiled to `aria-label`.
- `props.readonly` *(boolean, optional)*: Readonly indicator.
- `props.disabled` *(boolean, optional)*: Disables the input from user interaction.
- `props.required` *(boolean, optional)*: Required validation indicator.
- `props.invalid` *(boolean | 'grammar' | 'spelling', optional)*: Invalid indicator, compiled to `aria-invalid`.
- `props.placeholder` *(string, optional)*: Placeholder text hint.
- `options.native` *(boolean, optional, default `true`)*: Pass `false` when wrapping custom non-native input containers.

### How it behaves

When bound to a native `<input>` or `<textarea>`, explicit `role="textbox"` is omitted since the browser supplies it natively. Every keystroke fires `oninput` and synchronizes back to state. `required`, `readonly`, and `disabled` compile to their corresponding native HTML attributes, while `invalid` compiles to `aria-invalid`. When bound to a custom element (`native: false`), it compiles `role="textbox"`, manages `tabindex`, and sets `aria-readonly`, `aria-required`, and `aria-disabled`.

:::tip[Custom Elements]
When building custom text editing containers from `<div>` elements, pass `{ native: false }` to the engine options inside your component to attach the appropriate ARIA roles and state attributes.
:::

### Usage

To use Textbox, create the textbox instance with `aria('textbox', props)`, then pass `textbox.ref` and spread `textbox.attributes` onto your input element:

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type TextboxProps = ComponentProps<'input'> & {
  value?: string;
  readonly?: boolean;
  disabled?: boolean;
  required?: boolean;
  invalid?: boolean | 'grammar' | 'spelling';
  placeholder?: string;
  label?: string;
};

const Textbox = setup<TextboxProps>((props) => {
  const textbox = aria('textbox', props);
  const restProps = props.$omit([
    ...textbox.ownKeys,
    'value',
    'readonly',
    'disabled',
    'required',
    'invalid',
    'placeholder',
    'label',
    'className',
  ]);

  return () => (
    <input
      ref={textbox.ref}
      aria-label={props.label}
      {...restProps}
      {...textbox.attributes}
      className={props.className}
    />
  );
}, 'Textbox');
```

## Searchbox

In Aria, Searchbox is the specialized search query controller created with `aria('searchbox')` that compiles search semantics.

```ts
aria<E extends BaseElement = HTMLInputElement>(
  role: 'searchbox',
  props?: SearchboxProps,
  options?: SearchboxOptions
): SearchboxAria<E>
```

### Parameters

- `props.value` *(string, optional)*: Current search query value.
- `props.label` *(string, optional)*: Accessible label for the search field compiled to `aria-label`.
- `props.placeholder` *(string, optional)*: Placeholder hint.
- `props.disabled` *(boolean, optional)*: Disables the search field.
- `props.readonly` *(boolean, optional)*: Readonly indicator.
- `props.required` *(boolean, optional)*: Required validation indicator.
- `props.invalid` *(boolean | 'grammar' | 'spelling', optional)*: Invalid indicator, compiled to `aria-invalid`.

### How it behaves

Searchbox configures the underlying textbox controller with `role="searchbox"` and `type="search"`. Native search inputs provide built-in clear buttons and submission semantics on `Enter`. Query state updates synchronously through `props.value`.

### Usage

To use Searchbox, create the searchbox instance with `aria('searchbox', props)`, then pass `searchbox.ref` and spread `searchbox.attributes` onto your search input:

:::code-group


## Keyboard Navigation

- **Tab**: Focuses into the field or moves to the next focusable element.
- **Typing / Backspace / Arrow Keys**: Native text editing — caret positioning, selection, and deletion are handled natively by the browser.
