# Headless Grid

A grid is a table a user drives from the keyboard, and every cell that carries its own tab stop turns that table into a maze.

Getting it right means **keeping one roving tab stop per grid**, **moving focus without selecting**, **committing through the same path as a click**, **stepping over locked cells**, and **leaving the markup to you**.

**Headless Grid** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const grid = aria('grid', props);

<div ref={grid.ref} {...grid.restProps(['children'])} />
```

## Grid

**The grid itself.** It owns the single roving tab stop, the arrow map, and the value a commit writes.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'grid',
  props?: GridProps
): GridAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type GridProps = ComponentProps<'div'> & {
  id?: string;
  label?: string;
  value?: string;
  selectionMode?: 'cell' | 'row';
  colcount?: number;
  rowcount?: number;
  disabled?: boolean;
  editable?: boolean;
  onchange?: (event: CustomEvent<unknown>) => void;
};

const Grid = setup<GridProps>((props) => {
  const grid = aria('grid', props);

  return () => (
    <div ref={grid.ref} {...grid.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type GridProps = ComponentProps<'div'> & {
  id?: string;
  label?: string;
  value?: string;
  selectionMode?: 'cell' | 'row';

  disabled?: boolean;
  editable?: boolean;
  onchange?: (event: CustomEvent<unknown>) => void;
};

    <div ref={grid.ref} {...grid.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **label** _string, optional_: The name screen readers announce for the grid, compiled to `aria-label`. **A grid without one is unidentifiable**, so pass it.
- **value** _string, optional_: The active cell name in `cell` mode, the active row name in `row` mode. Writing it moves the selection; it never dispatches a change.
- **selectionMode** _'cell' | 'row', optional, default `cell`_: Whether activation commits the cell name or lifts to the enclosing row name.
- **colcount** _number, optional_: The full column extent, compiled to `aria-colcount` even when only part of the grid is rendered.
- **rowcount** _number, optional_: The full row extent, compiled to `aria-rowcount`.
- **editable** _boolean, optional_: Lets the picked cell take text through a `contenteditable` session that `Escape` or a blur commits.
- **disabled** _boolean, optional_: Cascades to every member, which then refuses keys and commits alike.
- **id** _string, optional_: An explicit DOM identifier, generated as `grid-<n>` when omitted.

### Properties

_What you read or write on the instance afterwards._

- **value** _string | undefined_: The committed name. Assigning it moves the selection and dispatches nothing.
- **selectionMode** _'cell' | 'row'_: The mode in force.
- **editable** _boolean_: Whether a picked cell opens a text session.
- **disabled** _boolean_: Whether the grid refuses every keystroke and every commit.
- **isRowMode** _boolean_: The same test as `selectionMode === 'row'`, for branches you read often.
- **locked** _boolean_: `true` while an editable cell holds an open text session, which is what freezes the grid arrows until it commits.

### How it behaves

- **Arrows move focus and never select.** Walking the grid by keyboard leaves the value where it was, so a user can survey the whole table before committing anything.
- **One tab stop for the whole grid.** Tab lands on the selected member, or on the grid itself while no member is picked, and the arrows reach the rest.
- **Activation commits through the click path.** `Enter` commits on release, a click commits, and re-activating the same holder releases the value. `Space` stays inert on every grid member.
- **Disabled cells are stepped over.** A locked cell keeps its slot in the row, so the column math still lines up, but focus never lands on it and it is no tab stop.
- **Editable cells take text in place.** The picked cell becomes `contenteditable` with the caret at the end of its text, the arrows freeze until the session commits, and a repeated click mid-edit is swallowed so the session survives it.
- **A canceled keystroke is passed on.** An enclosing toolbar rover takes precedence, and a key a consumer already handled is never consumed twice.

### Events

_What it tells you._

- **`change`** _CustomEvent&lt;string&gt;_: Fires after a commit from the member that was picked, with the whole grid value as `detail`. The event bubbles through the grid, so you can listen on either.
- **`onchange`** _(event: CustomEvent&lt;unknown&gt;) =&gt; void, optional_: Receives the same event from the reactive props. The published handler type widens `detail` to `unknown`, while the dispatched event carries the grid value as a string, so narrow it where you read it.
- **A programmatic write is silent.** Assigning `grid.value` moves the selection and dispatches nothing, because no one acted.

### Navigation

_What the keys do._

- **`ArrowRight` / `ArrowLeft`** — focus the next / previous enabled cell in the row, stopping at the row's ends. In `row` mode they do nothing, because the row is the unit.
- **`ArrowUp` / `ArrowDown`** — focus the same column in the previous / next row. When that column is locked, focus lands on the nearest enabled cell instead, preferring the one to the left. In `row` mode they move between rows and wrap at the ends.
- **`Home` / `End`** — focus the first / last enabled cell of the row, or the first / last row in `row` mode.
- **`PageUp` / `PageDown`** — focus the same column in the first / last row. In `row` mode they do nothing.
- **`Enter`** — commit the focused cell, or lift the commit to its row in `row` mode; re-activation releases it.
- **`Space`** — inert on every grid member.
- **`Tab`** — enter the grid at its roving stop, then leave for the next thing on the page.

## Treegrid

**The tree variant.** Same coordinator, same members, with the rows-and-expansion role that treegrid requires.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'treegrid',
  props?: TreeGridProps
): TreeGridAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type TreeGridProps = ComponentProps<'div'> & {
  id?: string;
  label?: string;
  value?: string;
  selectionMode?: 'cell' | 'row';
  colcount?: number;
  rowcount?: number;
  disabled?: boolean;
  editable?: boolean;
  onchange?: (event: CustomEvent<unknown>) => void;
};

const Treegrid = setup<TreeGridProps>((props) => {
  const treegrid = aria('treegrid', props);

  return () => (
    <div ref={treegrid.ref} {...treegrid.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type TreeGridProps = ComponentProps<'div'> & {
  id?: string;
  label?: string;
  value?: string;
  selectionMode?: 'cell' | 'row';
  colcount?: number;
  rowcount?: number;
  disabled?: boolean;
  editable?: boolean;
  onchange?: (event: CustomEvent<unknown>) => void;
};

const Treegrid = setup<TreeGridProps>((props) => {
  const treegrid = aria('treegrid', props);

  return (
    <div ref={treegrid.ref} {...treegrid.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### How it behaves

- **`role="treegrid"` replaces `role="grid"`** and nothing else changes: the same parameters, the same members, the same keys.
- **Ids generate as `treegrid-<n>`**, so a treegrid never shares an identifier series with a grid.
- **Expansion stays yours.** The controller announces the treegrid role; which rows are open, and the state attributes that say so, are your markup to write.

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **name** _string, optional_: The row identity that `row` mode commits.
- **rowindex** _number, optional_: The 1-based row position, compiled to `aria-rowindex`.
- **selected** _boolean, optional_: The initial hint, in `row` mode only.
- **disabled** _boolean, optional_: This line alone refuses commits; a grid disabled at the top applies on top of it.

### Properties

_What you read or write on the instance afterwards._

- **selected** _boolean_: Whether this row holds the value. Writable in `row` mode only.
- **value** _unknown_: The row's `name`.
- **disabled** _boolean_: Whether this row is locked, **including by the grid**.

### Methods

_What you call on the instance._

- **`select()`**: Commits this row. _Does nothing outside `row` mode._
- **`deselect()`**: Releases this row. _Does nothing outside `row` mode._
- **`toggle()`**: Commits the row when it is not already committed, releases it when it is.

### How it behaves

- **Focus travels by row, not by cell.** In `row` mode the arrows move between rows and wrap at the ends, while the horizontal arrows do nothing.
- **Row attributes belong to `row` mode.** A row carries `aria-selected` and `aria-disabled` only there; in `cell` mode it holds them back and its cells do the work.
- **The roving stop sits on the selected row in `row` mode**, and on no row at all in `cell` mode, where the cells rove instead.
- **A commit lifts through the row.** Clicking a cell or pressing `Enter` inside it commits the row's `name` rather than the cell's, and re-activation releases it.
- **A disabled row refuses commits** and composes with grid-level disablement.

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **name** _string, **required**_: The cell identity that `cell` mode commits.
- **value** _string, optional_: The cell's initial text, read when an editable session starts.
- **colindex** _number, optional_: The 1-based column position, compiled to `aria-colindex`.
- **readonly** _boolean, optional_: Compiles `aria-readonly="true"`. The cell stays focusable and selectable, unlike a disabled one.
- **selected** _boolean, optional_: The initial hint, in `cell` mode only.
- **disabled** _boolean, optional_: This cell alone refuses commits and keeps out of the tab order.

### Properties

_What you read or write on the instance afterwards._

- **selected** _boolean_: Whether this cell holds the value. Writable in `cell` mode only.
- **editable** _boolean_: Whether the enclosing grid is editable, so a pick opens a text session.
- **value** _unknown_: The cell's `name`.
- **disabled** _boolean_: Whether this cell is locked, **including by the grid**.

### Methods

_What you call on the instance._

- **`select()`**: Commits this cell. _Does nothing in `row` mode._
- **`deselect()`**: Releases this cell. _Does nothing in `row` mode._
- **`toggle()`**: Commits the cell when it is not already committed, releases it when it is.

### How it behaves

- **Cell attributes belong to `cell` mode.** A cell carries `aria-selected`, `aria-disabled`, and its tab stop only there; in `row` mode it carries none of them and the row commits.
- **Tab stops follow the surface.** An editable grid puts every enabled cell at `tabindex="0"`; a plain `cell` grid puts `0` on the selection and `-1` everywhere else; a disabled cell parks at `-1` without shifting the column math.
- **A pick becomes a text session in an editable grid.** The cell compiles `contenteditable`, takes the caret at the end of its text, and keeps the session while the grid arrows are frozen.
- **`aria-readonly` describes the cell, never locks it.** It is announced as read-only and stays selectable, so use `disabled` when you mean the cell refuses.

### Navigation

_What the keys do._

- **`Enter`** — commit this cell in `cell` mode, or commit its row in `row` mode; re-activation releases it.
- **`Space`** — inert.
- **`Escape`** — end an editable session and commit the text.
- **`Tab`** — leave an editable cell, which also commits it.

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### Grid

```ts
interface GridProps {
  id?: string;
  label?: string;
  value?: string;
  selectionMode?: 'cell' | 'row';
  colcount?: number;
  rowcount?: number;
  disabled?: boolean;
  editable?: boolean;
  onchange?: (event: CustomEvent<unknown>) => void;
}

interface GridAttributes {
  id?: string;
  role?: 'grid' | 'treegrid';
  tabindex?: number;
  'aria-label'?: string;
  'aria-colcount'?: number;
  'aria-rowcount'?: number;
  'aria-disabled'?: 'true' | 'false';
}

declare class GridAria {
```

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`props`** / **`restProps(omit)`** is what you spread onto the host — your props minus the keys the controller writes and any you name, with the compiled attributes merged in; **`ref`** is what you bind the element with; **`attributes`** is that compiled dictionary on its own, when you need the low-level view.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
