# AirLib Headless Grid

A grid is the table you can drive from the keyboard: rows and columns traversed with arrows, tab stops that follow the selection mode, selection that follows either the cell or the row. Plain markup gets you halfway — a `<table>` announces structure but gives you no roving focus, every cell you make focusable turns the grid into a tab-stop maze, and selection stays your problem. **AirLib Headless Grid** (`aria('grid')`) is a 2D roving focus coordinator: arrows move focus across rows and columns and never select, `Enter` commits the focused cell (or its enclosing row in `row` mode) through the same click path as pointer activation, and re-activating the holder releases it — without dictating markup or styles.

```tsx
const grid = aria('grid', props);

<div ref={grid.ref} {...grid.props} />
```

The first grid commits cells — focus a cell, then use `ArrowRight`, `ArrowDown`, `Home`, or `PageDown`. Traversal moves focus and commits nothing; clicking or pressing `Enter` picks (`Enter` commits on release), pressing `Enter` again releases, and `Space` stays inert. Dublin is disabled and stepped over. The second grid commits whole rows: clicking any city in a region picks `west` or `east`. The third grid is editable and starts with no pick — click a cell and rewrite it, the cell content is the value, so `Escape` or leaving the cell commits the text into the cell and clears the grid value.

## Grid

When you need a table users drive from the keyboard, use `grid`. You supply the value, the selection mode, and the full extent; the grid owns the tab stops and the arrow-key map.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'grid',
  props?: GridProps
): GridAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type GridProps = ComponentProps<'div'> & {
  id?: string;
  label?: string;
  value?: string;
  selectionMode?: 'cell' | 'row';
  colcount?: number;
  rowcount?: number;
  disabled?: boolean;
  onchange?: (event: CustomEvent<string>) => void;
};

const Grid = setup<GridProps>((props) => {
  const grid = aria('grid', props);

  return () => (
    <div ref={grid.ref} {...grid.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';

const Grid = setup((props) => {
  const grid = aria('grid', props);

  return (
    <div ref={grid.ref} {...grid.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

- `props.value` *(string, optional)*: Active cell name in `cell` mode, active row name in `row` mode. Reads and writes props directly.
- `props.selectionMode` *(cell | row, optional, default `cell`)*: Whether activation commits the cell name or lifts to the enclosing row name.
- `props.label` *(string, optional)*: Accessible name compiled as `aria-label`. A grid without a name is unidentifiable to assistive technology, so pass it.
- `props.colcount` / `props.rowcount` *(number, optional)*: Full grid extent compiled as `aria-colcount` / `aria-rowcount`, even when only part of the grid is rendered.
- `props.disabled` *(boolean, optional)*: Cascades disablement to every member and claims no keystroke.
- `props.editable` *(boolean, optional)*: Lets the picked cell take text — selecting it opens a `contenteditable` session that `Escape` or `blur` commits.
- `props.id` *(string, optional)*: Explicit DOM identifier. Generated as `grid-<n>` when omitted.
- `props.onchange` *(handler, optional)*: Called with the member's `change` event after a commit; `detail` is the whole grid value.

### How it behaves

- Compiles `role="grid"`, `aria-label` when named, `aria-colcount` / `aria-rowcount` when declared, and an explicit `aria-disabled` baseline.
- **Arrows move focus only and never select.** `ArrowRight` / `ArrowLeft` travel within the row, `ArrowUp` / `ArrowDown` keep the column across rows, `Home` / `End` jump to the row ends, `PageUp` / `PageDown` jump to the first / last row. Disabled cells are stepped over.
- **Activation commits and toggles.** `Enter` on a focused cell commits through the same click path as pointer activation (cell name in `cell` mode, row name in `row` mode via bubbling); re-activating the holder clears the value. `Space` is inert on grid members.
- **Tab stops follow the mode — and `editable`.** An editable `cell` grid puts every enabled cell in the tab order (`tabindex="0"`); a disabled cell is no tab stop (`tabindex="-1"`) but keeps its slot so vertical travel stays column-aligned. A plain `cell` grid roves a single stop like `row` mode does: `0` on the selection, `-1` elsewhere. When no value is held and no member owns a stop, the grid itself carries `tabindex="0"` so Tab can still enter — arrows from the focused grid enter the first (or last) enabled cell without selecting.
- **Editable cells take text.** With `editable`, selecting a cell opens it as `contenteditable` and freezes grid arrows until the edit commits; the caret lands at the end of the cell text. `Escape` or leaving the cell stores the text on the cell and clears the grid value; clicking the cell again mid-edit is swallowed so the session survives it.
- Yields any keystroke a consumer canceled, and surrenders traversal to an enclosing toolbar rover.

### Events

A commit is announced by the member that was picked, and it bubbles through the grid. `change` carries the whole grid value as a snapshot:

| Event | Authored by | Trigger | `detail` |
| :--- | :--- | :--- | :--- |
| `change` | The picked cell or row | Pointer click or `Enter` committed a name | `string` — the grid value |

```tsx
const grid = aria('grid', {
  label: 'Departure cities',
  value: 'ber',
  onchange: (event) => submit(event.detail),
});
```

A programmatic write (`grid.value = 'vil'`) moves selection but dispatches nothing: an external write is neither a move nor a commit, because nobody acted.

## Treegrid

When rows expand and collapse, use `treegrid` instead of `grid`. You supply the same props; the grid announces `role="treegrid"` and generates ids as `treegrid-<n>`.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'treegrid',
  props?: TreegridProps
): TreeGridAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type TreegridProps = ComponentProps<'div'> & {
  id?: string;
  label?: string;
  value?: string;
  selectionMode?: 'cell' | 'row';
  disabled?: boolean;
};

const Treegrid = setup<TreegridProps>((props) => {
  const treegrid = aria('treegrid', props);

  return () => (
    <div ref={treegrid.ref} {...treegrid.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';

const Treegrid = setup((props) => {
  const treegrid = aria('treegrid', props);

  return (
    <div ref={treegrid.ref} {...treegrid.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### How it behaves

- Compiles `role="treegrid"` with the same `aria-label`, extent, and `aria-disabled` baseline as `grid`.
- Traversal, selection modes, and the tab stops work exactly like `grid`.
- Ids generate as `treegrid-<n>`; a `grid-<n>` id is never reused for a treegrid.

## Row

When you need to group the cells of one line — and to name the line for `row` mode — use `grid-row`. You supply the row name; the grid commits it when `selectionMode` is `row`.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'grid-row',
  props?: RowProps
): GridRowAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type RowProps = ComponentProps<'div'> & {
  name?: string;
  rowindex?: number;
  selected?: boolean;
  disabled?: boolean;
};

const Row = setup<RowProps>((props) => {
  const row = aria('grid-row', props);

  return () => (
    <div ref={row.ref} {...row.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';

const Row = setup((props) => {
  const row = aria('grid-row', props);

  return (
    <div ref={row.ref} {...row.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

- `props.name` *(string, optional)*: Row identity committed when `selectionMode` is `row`.
- `props.rowindex` *(number, optional)*: 1-based index compiled as `aria-rowindex`.
- `props.selected` / `props.disabled` *(optional)*: Initial hint and lockout; disabled composes with the grid.

### How it behaves

- Compiles `role="row"` with `aria-selected` and `aria-disabled` only in `row` mode (absent in `cell` mode), and `aria-rowindex` when declared.
- Holds the roving tab stop in `row` mode (`tabindex="0"` while selected, `-1` otherwise); carries no tab stop in `cell` mode. When no row is picked the grid itself holds the stop instead.
- Commits only in `row` mode — pointer click or `Enter` through the bubbling click — and re-activation releases the holder; in `cell` mode row activation does nothing to the value.
- A disabled row refuses committing and composes with grid-level disablement.

## GridCell

When you need a pickable position in the table, use `grid-cell`. You supply the cell name; the grid commits it in `cell` mode. In an editable grid every enabled cell is a tab stop, otherwise the single stop roves with the selection.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'grid-cell',
  props: GridCellProps
): GridCellAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type CellProps = ComponentProps<'div'> & {
  name: string;
  colindex?: number;
  readonly?: boolean;
  selected?: boolean;
  disabled?: boolean;
};

const Cell = setup<CellProps>((props) => {
  const cell = aria('grid-cell', props);

  return () => (
    <div ref={cell.ref} {...cell.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';

const Cell = setup((props) => {
  const cell = aria('grid-cell', props);

  return (
    <div ref={cell.ref} {...cell.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

- `props.name` *(string, optional)*: Cell identity committed in `cell` mode.
- `props.colindex` *(number, optional)*: 1-based index compiled as `aria-colindex`.
- `props.readonly` *(boolean, optional)*: Compiles `aria-readonly="true"` — still focusable and selectable, unlike `disabled`.
- `props.selected` / `props.disabled` *(optional)*: Initial hint and lockout.

### How it behaves

- Compiles `role="gridcell"` with `aria-selected` and `aria-disabled` only in `cell` mode (absent in `row` mode), plus `aria-colindex` and `aria-readonly="true"` when declared.
- In an editable grid every enabled cell carries `tabindex="0"`; a disabled cell parks at `tabindex="-1"` so it stays out of the tab order without shifting the column math. In a plain `cell` grid only the selected cell carries `0` and the rest carry `-1`. In `row` mode cells carry no tab stop.
- Re-activation releases the holder — selection is always toggle, and an empty value is allowed.
- Keyboard `Enter` commits on release through the same click path as pointer activation in `cell` mode; `Space` is inert. In `row` mode the cell itself is inert and the commit lifts to the enclosing row.
- With an editable grid, the selected cell compiles `contenteditable` and takes text until `Escape` or `blur` commits.

## ColumnHeader / RowHeader

When you need a sortable column trigger or a row label, use `grid-columnheader` / `grid-rowheader`. You supply the index and the sort direction; headers describe and never take part in selection.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'grid-columnheader',
  props?: ColumnHeaderProps
): GridColumnHeaderAria<E>
```

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'grid-rowheader',
  props?: RowHeaderProps
): GridRowHeaderAria<E>
```

### Usage

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type ColumnHeaderProps = ComponentProps<'div'> & {
  name?: string;
  colindex?: number;
  sort?: 'ascending' | 'descending' | 'none' | 'other';
  disabled?: boolean;
};

const ColumnHeader = setup<ColumnHeaderProps>((props) => {
  const header = aria('grid-columnheader', props);

  return () => (
    <div ref={header.ref} {...header.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';

const ColumnHeader = setup((props) => {
  const header = aria('grid-columnheader', props);

  return (
    <div ref={header.ref} {...header.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

- Column header: `props.name` *(string, optional)* header identity, `props.colindex` → `aria-colindex`, `props.sort` → `aria-sort`.
- Row header: `props.name` *(string, optional)* header identity, `props.rowindex` → `aria-rowindex`.
- `props.disabled` *(boolean, optional)*: Lockout; composes with the grid.

### How it behaves

- Compile `role="columnheader"` / `role="rowheader"` with their index and (column-only) sort state.
- Take no tab stop and never participate in selection — clicks on headers commit nothing.
- A `name` identifies the header for consumers without entering the grid value.

## Keyboard Navigation

| Key | Behavior |
| :--- | :--- |
| `Tab` | Enters the grid — every enabled cell of an editable `cell` grid, the single roving stop otherwise, or the grid itself when nothing holds a stop. |
| `ArrowRight` / `ArrowLeft` | Moves focus to the next / previous enabled cell in the row. Selects nothing. |
| `ArrowUp` / `ArrowDown` | Moves focus to the same column in the previous / next row. |
| `Home` / `End` | Moves focus to the first / last cell in the row. |
| `PageUp` / `PageDown` | Moves focus to the same column in the first / last row. |
| `Enter` | Commits on release the focused cell (or its enclosing row in `row` mode) through the same click path as pointer activation; re-activation clears the value. |
| `Space` | Inert — commits nothing on any grid member. |

## What you get

- **Two-dimensional roving with no selection on travel.** Focus and value are separate gestures, which is what editable grids and spanned layouts require.
- **Two selection modes, one toggle value.** `cell` commits the cell name; `row` lifts to the row through bubbling — pointer and `Enter` commit the same way, re-activation releases, and `Space` stays inert.
- **In-place editing without leaving the grid.** `editable` turns the picked cell into a text session with caret placement, frozen arrows, and `Escape` / `blur` commits.
- **Headers that describe, cells that act.** Sort state, column and row indexes, and full-extent counts project without extra wiring.
- **Zero markup lock-in.** Render `<table>` / `<tr>` / `<td>` / `<th>` or `<div>` structures; the controller only reads roles.
