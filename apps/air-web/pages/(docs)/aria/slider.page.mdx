# Headless Slider

A slider is a number you point at. Getting it right means **clamping every write to the bounds and snapping it to the step**, **answering the arrows, `PageUp`/`PageDown`, `Home`, and `End` without stealing the rest of the keyboard**, **dragging continuously along measured geometry**, and **for a range, keeping two thumbs from crossing while each stays reachable on its own**.

**Headless Slider** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const slider = aria('slider', props);

<div ref={slider.ref} {...slider.restProps(['children'])}>
  {props.children}
</div>
```

:::interactive[Player and Filter Controls]
```tsx
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type DemoSliderProps = ComponentProps<'div'> & {
  label: string;
  suffix?: string;
  value?: number;
  min?: number;
  max?: number;
  step?: number;
  valuetext?: string | ((val: number) => string);
  disabled?: boolean;
};

const DemoSlider = setup<DemoSliderProps>((props) => {
  const slider = aria('slider', props);

  return () => (
    <div className="demo-slider-group">
      <div className="demo-slider-head">
        <span className="demo-slider-caption">{props.label}</span>
        <span className="demo-slider-value">
          {Math.round(Number(slider.value))}
          {props.suffix}
        </span>
      </div>
      <div ref={slider.ref} {...slider.restProps(['children', 'label', 'suffix'])} className="demo-slider">
        {props.children}
      </div>
    </div>
  );
}, 'DemoSlider');

type DemoRangeProps = ComponentProps<'div'> & {
  label: string;
  value?: [number, number];
  min?: number;
  max?: number;
  step?: number;
};

const DemoRange = setup<DemoRangeProps>((props) => {
  const slider = aria('slider', props);

  return () => {
    const [low, high] = slider.value as [number, number];

    return (
      <div className="demo-slider-group">
        <div className="demo-slider-head">
          <span className="demo-slider-caption">{props.label}</span>
          <span className="demo-slider-value">
            {Math.round(low)} – {Math.round(high)}
          </span>
        </div>
        <div ref={slider.ref} {...slider.restProps(['children', 'label'])} className="demo-slider">
          {props.children}
        </div>
      </div>
    );
  };
}, 'DemoRange');

type DemoThumbProps = ComponentProps<'div'>;

const DemoThumb = setup<DemoThumbProps>((props) => {
  const thumb = aria('slider-thumb', props);

  return () => <div ref={thumb.ref} {...thumb.restProps(['children'])} className="demo-slider-thumb" />;
}, 'DemoThumb');
```

## Slider

**The track and the number.** It owns the bounds, the stepping, and the value.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'slider',
  props?: SliderProps,
  options?: SliderOptions
): SliderAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type SliderProps = ComponentProps<'div'> & {
  value?: number | [number, number];
  min?: number;
  max?: number;
  step?: number;
  page?: number;
  valuetext?: string | ((val: number) => string);
  orientation?: 'horizontal' | 'vertical';
  disabled?: boolean;
};

const Slider = setup<SliderProps>((props) => {
  const slider = aria('slider', props);

  return () => (
    <div ref={slider.ref} {...slider.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

    <div ref={slider.ref} {...slider.restProps(['children'])}>

    </div>
  );
});
```

### Parameters

_What you pass in. The props object stays live — change a bound and every later move is measured against it._

- **value** _number | [number, number], optional_: The current number, or the low/high pair of a range. Every write is clamped and snapped, so a pair that arrives crossed is ordered rather than rejected.
- **min** _number, optional, default `0`_: The inclusive lower bound.
- **max** _number, optional, default `100`_: The inclusive upper bound.
- **step** _number, optional, default `1`_: The arrow-key increment, snapped from `min`. A step of `0.1` lands on `0.3`, not `0.30000000000000004`; a step that is zero or negative falls back to unit steps.
- **page** _number, optional, default `10`_: How far `PageUp` and `PageDown` travel.
- **valuetext** _string | ((val: number) => string), optional_: What the value is called out as, either fixed or computed per endpoint. Without it, assistive tech reads the bare number.
- **orientation** _'horizontal' | 'vertical', optional, default `'horizontal'`_: The axis the slider steps along, which is also the axis it announces.
- **disabled** _boolean, optional_: Locks stepping and dragging, and takes the slider out of the tab order.
- **oninput** _(event: CustomEvent&lt;number | [number, number]&gt;) =&gt; void, optional_: Called with the live value after every step and every drag move.
- **onchange** _(event: CustomEvent&lt;number | [number, number]&gt;) =&gt; void, optional_: Called with the committed value when the interaction ends.

### Options

_What you fix when you create it. Read once, never reactive._

- **native** _boolean, optional, default `false`_: Set `true` to bind a real `<input type="range">`, where the browser owns the keys and the drag and the controller keeps `min`, `max`, `step`, and the value in sync with it.

### Properties

_What you read or write on the instance afterwards._

- **value** _number | [number, number]_: The value with the bounds already applied. Writing it clamps, snaps, and orders a pair.
- **isDual** _boolean_: Whether this slider coordinates a low/high pair.
- **min** _number_: The lower bound in use.
- **max** _number_: The upper bound in use.
- **step** _number_: The arrow increment in use.
- **page** _number_: The page-key distance in use.
- **orientation** _'horizontal' | 'vertical'_: The stepping axis.
- **disabled** _boolean_: Whether the slider is locked.

### Methods

_What you call on the instance._

- **`claimThumb()`** → `number`: Gives the next thumb its endpoint index, in creation order. You do not call this — every `aria('slider-thumb')` claims itself from the slider around it.
- **`commitEndpoint(index, raw)`** → `boolean`: Runs a raw endpoint reading through snapping, bounds, and pair order, and reports whether it changed anything. This is the door every drag and key press goes through; call it only if you are writing a part of your own.

### How it behaves

- **Every write lands inside the range.** Values are clamped to `min`/`max` and snapped to `step` counted from `min`, whether they arrive from a key, a drag, or your own assignment.
- **A range never crosses itself.** Each thumb's announced bounds tighten against its sibling — the low end's maximum is the current high, the high end's minimum is the current low — so neither can step or drag past the other.
- **Only the slider's keys are claimed.** The arrows step, `PageUp`/`PageDown` travel by `page`, `Home`/`End` jump to a bound, and everything else — `Tab`, `Enter`, `Escape`, letters — is left to the page. A press at a bound still consumes its key but changes nothing.
- **The track is a target.** Pressing the track moves the nearest endpoint to where you pressed and keeps dragging from there, so a thumb never has to be hit precisely.
- **A single value needs no group.** One number makes the track itself the focusable slider; a low/high pair makes the track a plain group and hands the slider role to each thumb.
- **`aria-valuetext` is the announcement.** What a screen reader says is your `valuetext`, not the raw number, so a volume slider can say “30% volume”.
- **Disabled means inert.** Steps and drags are refused, nothing is consumed, and both the track and its thumbs leave the tab order — and a click on a locked part is cancelled and stopped from bubbling, so nothing above it reacts either.
- **A native range stays native.** With `native: true` the part compiles `type="range"` with `min`/`max`/`step` and no `role`, `tabindex`, or `value` attribute of its own — the browser's live value is the value.

### Events

_What it tells you._

- **`input`** — fires on every step and every drag move, with the live value in `detail`. This is the channel for a read-out that follows the pointer.
- **`change`** — fires when the interaction ends — key release, blur, or pointer up — with the committed value in `detail`. A gesture that changed nothing is silent.

```tsx
const slider = aria('slider', {
  value: 30,
  oninput: (event) => preview(event.detail),
  onchange: (event) => save(event.detail),
});
```

Both are dispatched on the part that moved: the track for a single value or a press on the track, the thumb for a range. Listening on the element yourself works too; there the DOM types the event as `Event`, so `detail` needs a cast to `SliderEvent`.

### Navigation

_What the keys do._

- **`ArrowRight` / `ArrowUp`** — step **up** by `step`.
- **`ArrowLeft` / `ArrowDown`** — step **down** by `step`.
- **`PageUp` / `PageDown`** — travel by `page`.
- **`Home` / `End`** — jump to `min` / `max`.
- **`Click` or drag** — move the nearest endpoint to the pointer and keep going from there.

On a single value these answer on the track; on a range, on whichever thumb has focus.

## Slider Thumb

**One endpoint.** It reads its number from the slider around it and says where it sits.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'slider-thumb',
  props?: AriaProps
): SliderThumbAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type ThumbProps = ComponentProps<'div'>;

const Thumb = setup<ThumbProps>((props) => {
  const thumb = aria('slider-thumb', props);

  return () => <div ref={thumb.ref} {...thumb.restProps(['children'])} />;
});
```

```tsx [SolidJS]

import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

  const thumb = aria('slider-thumb', props);

  return <div ref={thumb.ref} {...thumb.restProps(['children'])} />;
});
```

:::

### Properties

_What you read on the instance afterwards._

- **endpoint** _number | undefined_: The number this thumb stands for, straight from the slider. `undefined` when there is no slider around it to read from.
- **offset** _number_: That endpoint as a percentage along the range, `0`–`100` — the same number the CSS variable carries, for when you need it in JavaScript.
- **disabled** _boolean_: Whether the slider has locked this thumb out.

### How it behaves

- **It finds its slider on its own.** A thumb takes its coordinator from the component around it and claims an endpoint in creation order, so the first `aria('slider-thumb')` is the low end and the second is the high end. With no slider around it, a thumb is inert.
- **On a range, it is the slider.** Each thumb carries `role="slider"`, its own tab stop, and the announced value, minimum, maximum, and value text — and it answers the eight keys itself.
- **On a single value, it is the mark.** The track holds the slider role and the keys; the thumb only reports the position through `--aria-slider-thumb-offset` and can be dragged.
- **Its announced bounds are its sibling.** The low thumb is announced as `min` up to the current high, the high thumb as the current low up to `max`, so the two can't be stepped or dragged through each other.
- **A drag tracks the pointer.** Pressing a thumb focuses it and follows the pointer in stepped values along the track geometry — from the left edge horizontally, from the bottom edge vertically — and releases its commit when the pointer is up.
- **It inherits the lock.** When the slider is disabled the thumb announces `aria-disabled="true"`, stops dragging, and a click on it is cancelled and contained.

### Events

_What it tells you._

- **`input`** — fires here while this thumb steps or drags, with the live value in `detail`.
- **`change`** — fires here when this thumb's interaction ends, with the committed value in `detail`.

### Navigation

_What the keys do._

On a range, each thumb answers the slider keys itself: **arrows** step, **`PageUp`/`PageDown`** travel by `page`, **`Home`/`End`** jump to its own bound, and **`Tab`** moves between the two thumbs. On a single value the thumb owns no keys — the track answers them.

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### Slider

```ts
interface SliderProps {
  value?: number | [number, number];
  orientation?: 'horizontal' | 'vertical';
  min?: number;
  max?: number;
  step?: number;
  page?: number;
  valuetext?: string | ((val: number) => string);
  disabled?: boolean;
  oninput?: (event: CustomEvent<number | [number, number]>) => void;
  onchange?: (event: CustomEvent<number | [number, number]>) => void;
}

interface SliderOptions {
  native?: boolean;
}

interface SliderAttributes {
  role?: 'slider' | 'group';
  type?: 'range';
  min?: number;
  max?: number;
  step?: number;
  value?: number;
  disabled?: boolean;
  tabindex?: number;
  'aria-disabled'?: 'true' | 'false';
  'aria-valuenow'?: number;
  'aria-valuemin'?: number;
  'aria-valuemax'?: number;
  'aria-valuetext'?: string;
  'aria-orientation'?: 'horizontal' | 'vertical';
}

declare class SliderAria {
  get isDual(): boolean;
  get min(): number;
  get max(): number;
  get step(): number;
  get page(): number;
  get orientation(): 'horizontal' | 'vertical';
  get disabled(): boolean;
  get value(): number | [number, number];
  set value(next: number | [number, number]);

  claimThumb(): number;
  commitEndpoint(index: number, raw: number): boolean;
}
```

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`props`** / **`restProps(omit)`** is what you spread onto the host — your props minus the keys the controller writes and any you name, with the compiled attributes merged in; **`ref`** is what you bind the element with; **`attributes`** is that compiled dictionary on its own, when you need the low-level view.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
