# AirLib Headless Slider

A slider looks like a thumb on a track until the platform gets involved: values must clamp to bounds, snap to steps, answer eight keyboard keys without stealing the rest, drag continuously along measured geometry, and — for ranges — keep two thumbs from crossing while each stays independently focusable. **AirLib Headless Slider** (`aria('slider')` + `aria('slider-thumb')`) owns that coordination — a track container plus one or two thumbs that read from it, without dictating markup or styles.

```tsx
const slider = aria('slider', props);
const thumb = aria('slider-thumb');

<div ref={slider.ref} {...slider.props}>
  <div ref={thumb.ref} {...thumb.props} />
</div>
```

## Slider

Bounded numeric entry over a track coordinator and thumb endpoints.

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'slider',
  props?: SliderProps,
  options?: SliderOptions
): SliderAria<E>

aria<E extends BaseElement = HTMLElement>(
  role: 'slider-thumb',
  props?: AriaProps
): SliderThumbAria<E>
```

### Usage

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type SliderProps = ComponentProps<'div'> & {
  value?: number | [number, number];
  min?: number;
  max?: number;
  step?: number;
  page?: number;
  valuetext?: string | ((val: number) => string);
  orientation?: 'horizontal' | 'vertical';
  disabled?: boolean;
};

const Slider = setup<SliderProps>((props) => {
  const slider = aria('slider', props);
  const thumb = aria('slider-thumb');

  return () => (
    <div ref={slider.ref} {...slider.restProps(['children'])}>
      <div ref={thumb.ref} {...thumb.props} />
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type SliderProps = ComponentProps<'div'> & {
  value?: number | [number, number];
  min?: number;
  max?: number;
  step?: number;
  page?: number;
  valuetext?: string | ((val: number) => string);
  orientation?: 'horizontal' | 'vertical';
  disabled?: boolean;
};

const Slider = setup<SliderProps>((props) => {
  const slider = aria('slider', props);
  const thumb = aria('slider-thumb');

  return (
    <div ref={slider.ref} {...slider.restProps(['children'])}>
      <div ref={thumb.ref} {...thumb.props} />
      {props.children}
    </div>
  );
});
```

:::

The track compiles `role="group"` only for dual-thumb tuples — a single value needs no grouping. Thumbs discover their coordinator from ambient scope and claim endpoints in creation order: first thumb reads the value (or the low end), second reads the high end.

### Parameters

- `props.value` *(number | [number, number], optional)*: Current value or low/high tuple, read and write through clamping.
- `props.min` *(number, optional, default `0`)*: Inclusive lower bound.
- `props.max` *(number, optional, default `100`)*: Inclusive upper bound.
- `props.step` *(number, optional, default `1`)*: Arrow-key increment, snapped from the lower bound. Non-positive steps fall back to unit steps.
- `props.page` *(number, optional, default `10`)*: Page-key increment in value units.
- `props.valuetext` *(string | ((val: number) => string), optional)*: Readable value text, static or derived per endpoint.
- `props.orientation` *(horizontal | vertical, optional, default `horizontal`)*: Stepping axis and announced orientation.
- `props.disabled` *(boolean, optional)*: Blocks stepping and drag.
- `props.oninput` *(function, optional)*: Called with the live value after each committed step or drag move.
- `props.onchange` *(function, optional)*: Called with the committed value when the interaction ends.
- `options.native` *(boolean, optional, default `false`)*: Bind a native `<input type="range">`; the browser owns keys and drag, the controller syncs state.

### Events

Both events dispatch on the thumb element carrying the slider value (`number`, or the tuple for ranges):

Declare the handlers as props and the controller calls them with the committed event — `detail` is typed, no cast:

```ts
const slider = aria('slider', {
  value: 30,
  oninput: (event) => {
    const value = event.detail;
  },
  onchange: (event) => {
    const committed = event.detail;
  },
});
```

Attaching to the element still works, but there the DOM library types the listener as `Event`, so reading `detail` needs `event as SliderEvent`. Import the type from `@airlib/aria` when you take that path.

- `input`: `CustomEvent` with `bubbles: true`, after each committed step or drag move.
- `change`: `CustomEvent` with `bubbles: true`, when the interaction ends (key release, blur, or pointer up) with a committed value. Presses that commit nothing stay silent.

### How it behaves

- Commits clamp to `[min, max]` and snap to `step` from the lower bound, without floating-point drift (`0.1` steps land on `0.3`, not `0.30000000000000004`).
- Dual-thumb tuples enforce `low <= high`: each thumb's announced bounds tighten against the other (low's `aria-valuemax` is the current high, high's `aria-valuemin` is the current low), and neither thumb can drag or step past its sibling. Crossed writes are ordered, never inverted.
- Only the slider's keys are claimed: arrows step, `PageUp`/`PageDown` move by `page`, `Home`/`End` jump to bounds. `Tab`, `Escape`, `Enter`, and letters are left to the page. Presses past a bound change nothing but are still consumed; while `disabled`, nothing is consumed and the slider leaves the tab order (`tabindex="-1"`, `aria-disabled="true"`).
- Dragging a thumb tracks stepped values continuously along the track geometry, horizontally from the left edge or vertically from the bottom edge.
- Pressing the track jumps the nearest endpoint to the pressed position and keeps dragging from there — no thumb required, with `input`/`change` dispatching on the track.
- Each thumb publishes its committed endpoint as `--aria-slider-thumb-offset` (a percentage along `[min, max]`), so stylesheets position thumbs with `left: var(--aria-slider-thumb-offset)` — or `bottom:` for vertical — and never compute ratios. Script consumers read the same percentage from `thumb.offset` (`0`–`100`, `0` when the range has no span) — the numeric content of the variable, with no conversion.
- Native hosts compile `type="range"` with `min`/`max`/`step` and sync both directions through the element's live value, projecting no `role`, `tabindex`, `name`, or `value` attributes of their own.

## Keyboard Navigation

- **Tab**: Focuses the track for single values and each thumb for dual ranges (`tabindex="0"`, resolving to `tabindex="-1"` while disabled).
- **Arrow keys**: Step by `step` in every orientation.
- **PageUp / PageDown**: Move by `page` value units.
- **Home / End**: Jump to `min` / `max`.

## What you get

- **Honest bounds.** Clamping, snapping, and tuple ordering on every write path — programmatic or interacted.
- **Dual-thumb reachability.** Both thumbs focusable, independently announced, tightened against each other, unable to cross.
- **Claim-only keyboard.** The eight slider keys are consumed; everything else passes through, even at bounds, never while disabled.
- **Native parity.** Range inputs keep browser keys and drag while the controller syncs state both directions.
