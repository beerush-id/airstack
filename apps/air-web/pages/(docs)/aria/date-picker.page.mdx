# Headless Date Picker

A date picker takes one date two ways: typed in, or picked from a calendar. Getting it right means **accepting typed text without choosing anything yet**, **landing focus on the current day when the calendar opens**, **letting the arrow keys travel days without choosing**, and **handing focus back to whatever opened the calendar**.

**Headless Date Picker** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const picker = aria('date-picker', props);

<div ref={picker.ref} {...picker.restProps(['children'])} />
```

:::interactive[Pick a Day]
```tsx
import { aria } from '@airlib/aria';
import { setup, derived, For, shadowPortal, Snippet } from '@airlib/react';
import type { ComponentProps } from 'react';

const dayLabel = (iso: string) => String(Number(iso.slice(8, 10)));

type DemoPickerProps = ComponentProps<'div'> & {
  value?: string;
  min?: string;
  max?: string;
  label?: string;
  disabled?: boolean;
};

const DemoPicker = setup<DemoPickerProps>((props) => {
  const picker = aria('date-picker', props);

  return () => (
    <div ref={picker.ref} {...picker.restProps(['children'])} className="demo-date-picker">
      <div className="demo-date-picker-row">
        <DemoPickerInput />
        <DemoPickerTrigger />
      </div>
      <DemoPickerCalendar>
        <div className="demo-date-picker-nav">
          <DemoPrevMonth />
          <Snippet>
            {() => (
              <span className="demo-date-picker-label">
                <span className="demo-date-picker-month">{picker.range.monthStr}</span>
                <DemoYearInput />
              </span>
            )}
          </Snippet>
          <DemoNextMonth />
        </div>
      </DemoPickerCalendar>
    </div>
  );
}, 'DemoPicker');

type DemoPickerInputProps = ComponentProps<'input'> & {
  id?: string;
  disabled?: boolean;
};

const DemoPickerInput = setup<DemoPickerInputProps>((props) => {
  const input = aria<HTMLInputElement>('date-picker-input', props);

  return () => (
    <input ref={input.ref} {...input.props} placeholder="YYYY-MM-DD" className="demo-date-picker-input" />
  );
}, 'DemoPickerInput');

type DemoPickerTriggerProps = ComponentProps<'button'>;

const DemoPickerTrigger = setup<DemoPickerTriggerProps>((props) => {
  const trigger = aria<HTMLButtonElement>('date-picker-trigger', props);

  return () => (
    <button
      ref={trigger.ref}
      {...trigger.restProps(['children'])}
      className="demo-date-picker-trigger"
      aria-label="Open calendar"
    >
      <span className="demo-date-picker-icon" aria-hidden="true" />
    </button>
  );
}, 'DemoPickerTrigger');

type DemoMonthNavProps = ComponentProps<'button'>;

const DemoPrevMonth = setup<DemoMonthNavProps>((props) => {
  const nav = aria<HTMLButtonElement>('date-picker-nav', { type: 'month', direction: -1 });

  return () => (
    <button ref={nav.ref} {...nav.restProps(['children'])} className="demo-date-picker-navbtn" aria-label="Previous month">
      ‹
    </button>
  );
}, 'DemoPrevMonth');

const DemoNextMonth = setup<DemoMonthNavProps>((props) => {
  const nav = aria<HTMLButtonElement>('date-picker-nav', { type: 'month', direction: 1 });

  return () => (
    <button ref={nav.ref} {...nav.restProps(['children'])} className="demo-date-picker-navbtn" aria-label="Next month">
      ›
    </button>
  );
}, 'DemoNextMonth');

const DemoYearInput = setup((props) => {
  const input = aria<HTMLInputElement>('date-picker-year-input', props);

  return () => (
    <input ref={input.ref} {...input.props} className="demo-date-picker-year" />
  );
}, 'DemoYearInput');

type DemoPickerCalendarProps = ComponentProps<'div'>;

const DemoPickerCalendar = setup<DemoPickerCalendarProps>((props) => {
  const calendar = aria<HTMLElement>('date-picker-calendar', props);
  const shadow = shadowPortal(() => calendar.open);

  return () => shadow(
    <div ref={calendar.ref} {...calendar.restProps(['children'])} className="demo-date-picker-calendar">
      {props.children}
      <div className="demo-date-picker-grid">
        <For each={() => calendar.grid.weeks}>
          {(day) => <div className="demo-date-picker-day demo-date-picker-head">{day}</div>}
        </For>
        <For each={() => calendar.grid.dates}>
          {(date) => <DemoDay date={date} />}

      </div>
    </div>
  );
}, 'DemoPickerCalendar');

type DemoDayProps = ComponentProps<'div'> & {
  date: string;
};

const DemoDay = setup<DemoDayProps>((props) => {
  const day = aria<HTMLElement>('date-picker-day', props);

  return () => (
    <div ref={day.ref} {...day.restProps(['children'])} className="demo-date-picker-day">
      {day.date.date}
    </div>
  );
}, 'DemoDay');
```

## Date Picker

**The group as a whole.** It holds the chosen date and whether the calendar is open, and the field, the button, and the calendar all follow it.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'date-picker',
  props?: DatePickerProps
): DatePickerAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps, ReactNode } from 'react';

type PickerProps = ComponentProps<'div'> & {
  id?: string;
  value?: string;
  month?: number;
  year?: number;
  min?: string;
  max?: string;
  label?: string;
  locales?: string[];
  open?: boolean;
  disabled?: boolean;
  required?: boolean;
  oninput?: (event: CustomEvent<string>) => void;
  onchange?: (event: CustomEvent<string | undefined>) => void;
  onopen?: (event: CustomEvent<true>) => void;
  onclose?: (event: CustomEvent<false>) => void;
  children: ReactNode;
};

const Picker = setup<PickerProps>((props) => {
  const picker = aria('date-picker', props);

  return () => (
    <div ref={picker.ref} {...picker.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';

const Picker = setup((props) => {
  const picker = aria('date-picker', props);

  return (
    <div ref={picker.ref} {...picker.restProps(['children'])}>
      {props.children}
    </div>
  );
});
```

:::

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **id** _string, optional_: The prefix the field, the button, and the calendar are linked through. Generated as `date-picker-<n>` when you leave it out.
- **value** _string, optional_: The chosen date as `YYYY-MM-DD`. Leave it out and nothing is chosen.
- **month** _number, optional_: The shown month as `1`–`12`. Defaults to the chosen date's month, otherwise the current month.
- **year** _number, optional_: The shown year as `YYYY`. Defaults to the chosen date's year, otherwise the current year.
- **min** _string, optional_: The earliest date that can be chosen. Earlier days read disabled and refuse every choosing path.
- **max** _string, optional_: The latest date that can be chosen. Later days read disabled and refuse every choosing path.
- **label** _string, optional_: The calendar's name for screen readers. Leave it out and the dialog is unnamed.
- **locales** _string[], optional_: The locale stack every label is formatted with. Defaults to the runtime locale.
- **disabled** _boolean, optional_: Locks typing, opening, and choosing across the **whole composite**.
- **required** _boolean, optional_: Marks the field as required.
- **open** _boolean, optional_: Whether the calendar shows.
- **oninput** _(event: CustomEvent&lt;string&gt;) =&gt; void, optional_: The raw field text as it is typed.
- **onchange** _(event: CustomEvent&lt;string | undefined&gt;) =&gt; void, optional_: The chosen date, `undefined` once it is cleared.
- **onopen** / **onclose** _(event: CustomEvent&lt;true&gt; | CustomEvent&lt;false&gt;) =&gt; void, optional_: The popup's edges, through every path.

### Options

_What you fix when you create it. Read once, never reactive._

- **type** _'single' | 'range', optional, default `'single'`_: The value archetype this instance reads.
- **grid** _'fixed' | 'dynamic', optional, default `'fixed'`_: Whether the month keeps six rows or drops the rows that hold no day of it.
- **native** _boolean, optional, default `true`_: Pass `false` when the host isn't a native element for the role.

### Properties

_What you read or write on the instance afterwards._

- **value** _string | undefined_: The chosen date. Writing sets it directly.
- **month** _number_: The month the grid shows, `1`–`12`. Writing it moves the grid.
- **year** _number_: The year the grid shows. Writing it moves the grid.
- **open** _boolean_: Whether the calendar shows.
- **disabled** _boolean_: Whether the composite refuses interaction.
- **range** _ParsedDate_: The shown month as a date — `monthStr` is the label the header shows.
- **today** _ParsedDate_: Today, parsed.
- **start** _ParsedDate_: The chosen date, parsed. Empty while nothing is chosen.
- **end** _ParsedDate_: Always empty on a single picker.
- **limit** _object_: The earliest and latest dates you allow, ready to compare, as `min` and `max`.
- **draft** _(string | undefined)[]_: The half-chosen date while a pick is pending; empty otherwise.
- **id** / **panelId** / **triggerId** _string_: The identifiers the parts link through.

### Methods

_What you call on the instance._

- **`select(start, end?)`**: Chooses a day: it becomes the value, `change` fires, and the calendar closes.
- **`deselect(index?)`**: Clears the chosen date and announces `change`. Does nothing while disabled.
- **`navigateMonth(direction)`**: Moves the grid a month back (`-1`) or forward (`1`), across the year boundary. Chooses nothing.
- **`navigateYear(direction)`**: Moves the grid a year back (`-1`) or forward (`1`). Chooses nothing.

### How it behaves

- **Typing announces, never chooses.** `input` carries the text as you type; the value changes only when a day is chosen.
- **Choosing closes.** A day saves itself as `value`, announces `change`, and closes the popup.
- **Travel never saves.** Arrows, `Home` / `End`, and `PageUp` / `PageDown` move focus or flip the month; the chosen date stays put.
- **One tab stop for the whole grid.** The active day carries it; the rest stay out of the tab order.
- **Out-of-range days refuse everything.** They read disabled and ignore clicks, `Enter`, and `Space`.
- **Focus comes home.** Choosing or dismissing returns focus to the field or button that opened the popup.
- **The dialog is named by `label`.** Leave it out and the calendar carries no accessible name.

### Events

_What it tells you._

- **`input`** — the raw field text while typing, in `detail`.
- **`change`** — the chosen date in `detail`, `undefined` once it is cleared.

```tsx
const picker = aria('date-picker', {
  value: '2026-10-14',
  onchange: (event) => save(event.detail),
});
```

### Navigation

_The group handles no keys itself._ Text goes to the **field**, grid travel to the **calendar**, choosing to the **days**.

## Date Picker Input

**The text field.** Type a date when you know it instead of opening the calendar.

### Usage

```ts

  role: 'date-picker-input',
  props?: AriaProps,
  options?: AriaOptions
): DatePickerInputAria<E>
```

:::code-group

```tsx [React]

type PickerInputProps = ComponentProps<'input'> & {
  id?: string;
  disabled?: boolean;
};

const PickerInput = setup<PickerInputProps>((props) => {
  const input = aria<HTMLInputElement>('date-picker-input', props);

  return () => (
    <input ref={input.ref} {...input.props} placeholder="YYYY-MM-DD" />
  );

```

```tsx [SolidJS]
  disabled?: boolean;

  return (
    <input ref={input.ref} {...input.props} placeholder="YYYY-MM-DD" />
  );

```

:::

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **id** _string, optional_: This field's identifier in the DOM.
- **slot** _string, optional_: Marks the field as one end of a range — `'start'` or `'end'`. Leave it out on a single picker.
- **disabled** _boolean, optional_: This field alone refuses typing and opening. Group-level disablement applies on top.

### Options

_What you fix when you create it. Read once, never reactive._

- **native** _boolean, optional, default `true`_: Pass `false` when the host isn't an `<input>`.

### Properties

_What you read or write on the instance afterwards._

- **slot** _string | undefined_: Which side of a range this field stands for — `start` or `end`. Left out, the field edits a single date.
- **isRangeInput** _boolean_: Whether the field belongs to a range rather than a single date.

### Methods

_The field exposes no methods of its own._

### How it behaves

- **Every keystroke announces.** Typing sends `input` with the raw text and stops there.
- **Shows the chosen date.** The field carries the committed `value` — picking a day rewrites it, typing never does. Your half-typed text stays put until the next pick.
- **Locked means locked.** While the group is disabled, typing goes nowhere.
- **Always linked.** The field carries the popup's open state and points at the calendar, so the linkage is visible on the field itself.

### Events

_The field dispatches no events of its own._ Editing arrives as `input` on the **group**.

### Navigation

_What the keys do._

- **Printable keys** — edit the text like any field.

:::

### Parameters

_What you pass in. This part takes no date props — it reads everything from the group it belongs to._

### Options

_The calendar doesn't take any options._

### Properties

_What you read or write on the instance afterwards._

- **id** _string_: The dialog identifier the field and the button point at.
- **open** _boolean_: Whether the popup shows.
- **weeks** _string[]_: The seven weekday column labels.
- **dates** _ParsedDate[]_: Every cell of the shown month, left to right.
- **grid** _DateGrid_: The month, the weekday labels, and the cells together.
- **popup** _PopoverAria_: The popover this dialog runs on.

### Methods

_The calendar exposes no methods of its own._

### How it behaves

- **Hidden until open.** A closed calendar is off screen and out of reach.
- **Days need no key wiring.** The popup handles every grid key from the focused day, so cells stay plain.
- **Unreadable days hold still.** A day with a broken date keeps focus instead of throwing.
- **Screen readers get a named dialog.** Announced as `"Calendar"`.

### Events

_The calendar dispatches no events of its own._ Choosing arrives as `change` on the **group**.

### Navigation

_What the keys do._

- **`ArrowLeft` / `ArrowRight`** — focus the **previous / next** day.
- **`ArrowUp` / `ArrowDown`** — focus the day a **week back / forward**.
- **`Home` / `End`** — focus the **first / last** day of the week.
- **`PageUp` / `PageDown`** — flip the shown month back / forward.
- **`Enter` / `Space`** — save the focused day and close.
- **`Escape`** — close without saving.
- **`Tab`** — leave the grid from the current day.

## Date Picker Nav

**Month and year travel buttons.** One click steps the grid without choosing anything.

```ts
aria<E extends BaseElement = HTMLButtonElement>(
  role: 'date-picker-nav',
  props?: DatePickerNavProps
): DatePickerNav<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type NavProps = ComponentProps<'button'> & {
  type: 'month' | 'year';
  direction: -1 | 1;
};

const Nav = setup<NavProps>((props) => {
  const nav = aria<HTMLButtonElement>('date-picker-nav', props.$pick(['type', 'direction']));

  return () => (
    <button ref={nav.ref} {...nav.restProps(['children'])}>
      {props.children}
    </button>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type NavProps = ComponentProps<'button'> & {
  type: 'month' | 'year';
  direction: -1 | 1;
};

const Nav = setup<NavProps>((props) => {
  const nav = aria<HTMLButtonElement>('date-picker-nav', { type: props.type, direction: props.direction });

  return (
    <button ref={nav.ref} {...nav.restProps(['children'])}>
      {props.children}
    </button>
  );
});
```

:::

### Parameters

_What you pass in. These parts take no date props — they borrow the group they sit in._

- **type** _'month' | 'year', optional, default `'month'`_: Which dimension the control steps.
- **direction** _-1 | 1, optional, default `-1`_: Back or forward.

### Properties

_What you read or write on the instance afterwards._

- **type** _'month' | 'year'_: The dimension in use.
- **direction** _-1 | 1_: The direction in use.

### How it behaves

- **One click steps the grid.** A month control moves one month, rolling the year across December and January; a year control moves one year.
- **Travel saves nothing.** `value` stays exactly as it was.
- **A canceled click travels nothing.** `preventDefault` on the click holds the grid still.

### Navigation

_What the keys do._

- **`Enter` / `Space`** — steps the grid on a native button through the browser itself.
- **`Click`** — steps once.

```tsx [SolidJS]
    <input ref={input.ref} {...input.props} type="number" />
  );
});
```

:::

### Parameters

_What you pass in. It takes no date props of its own — it borrows the group it sits in._

### Options

_This part takes no options._

### Properties

_This part exposes no properties of its own._

### Methods

_This part exposes no methods of its own._

### How it behaves

- **A year typed is a year shown.** The grid moves to that year; the month stays where it is.
- **It never chooses.** Typing a year leaves `value` exactly as it was.
- **It borrows the group.** It reads and moves the picker around it, and does nothing without one.

### Events

_This part dispatches no events of its own._ A year lands on the **group** as the shown year, not as a chosen date.

### Navigation

_What the keys do._

- **Digits** — build the year as you type, through the field itself.
- **`Enter`** — keeps the year on screen; the calendar stays open.

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`attributes`** is the dictionary you spread; **`ref`** is what you bind the element with; **`props`** is the full props dictionary for spreading onto the host; **`restProps(omit)`** hands back your props with the keys you name left out.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
