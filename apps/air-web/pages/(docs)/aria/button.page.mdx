# AirLib Headless Button

Button is a simple action element, but most of you have struggled dealing with it: a button inside `<form>` submits by accident unless you remember `type="button"`, and a custom `<div>` button needs hand-rolled `role`, `tabindex`, and `Space`/`Enter` listeners to stay accessible. **AirLib Headless Button** (`aria('button')`) turns any element into a button that behaves — safe `type="button"` defaults on native hosts, `role`/`tabindex`/keyboard polyfills on custom hosts (`native: false`), without dictating markup or styles.

```tsx
const btn = aria('button', props, { native: false });

<div ref={btn.ref} {...btn.props}>
  Click Me
</div>
```

:::interactive[Custom Button]
```tsx
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

const CustomButton = setup((props) => {

  return () => (

  );

```

## Button

Command trigger with safe form defaults and event forwarding.

```ts
aria(role: 'button', props?: ButtonProps, options?: ButtonOptions): ButtonAria<E>
```

### Usage

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type ButtonProps = ComponentProps<'button'> & {
  disabled?: boolean;
};

const Button = setup<ButtonProps>((props) => {
  const button = aria('button', props);

  return () => (
    <button ref={button.ref} {...button.restProps(['children'])}>
      {props.children}
    </button>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type ButtonProps = ComponentProps<'button'> & {
  disabled?: boolean;
};

const Button = setup<ButtonProps>((props) => {
  const button = aria('button', props);

  return (
    <button ref={button.ref} {...button.restProps(['children'])}>
      {props.children}
    </button>
  );
});
```

:::

### Parameters

- `props.type` *('button' | 'submit' | 'reset', optional, default `'button'`)*: Compiles `type="button"` by default on native buttons to prevent implicit form submission.
- `props.disabled` *(boolean, optional)*: Disables the button, preventing interaction and removing it from the tab order.
- `options.native` *(boolean, optional, default `true`)*: Pass `false` when wrapping custom non-button elements (such as `<div>` or `<span>`).

### How it behaves

Native `<button>` hosts omit explicit `role="button"`. Custom hosts (`native: false`) compile `role="button"`, `tabindex` (`0` enabled, `-1` disabled), and keyboard polyfills: click on `Enter` keydown and `Space` keyup. `Enter` never calls `preventDefault`; only `Space` keydown is prevented to suppress scroll. A canceled (synthesized) click aborts form submission and reset. Disabled hosts ignore pointer clicks, keyboard activation, and form mechanics alike.

:::tip[Custom Elements]
When wrapping non-button elements (like `<div>` or `<span>`), pass `{ native: false }` to the engine options inside your component to attach keyboard polyfills and focus attributes.
:::

## Putting It Together

Once your components are wired with `aria(...)`, compose them to build accessible buttons:

```tsx
<div className="flex items-center gap-2">
  <Button onClick={() => console.log('Saved!')}>Save Changes</Button>
  <Button disabled={true}>Disabled</Button>
</div>
```

## Keyboard Navigation

- **Tab**: Focuses into the button or moves to the next focusable page element. Disabled custom buttons sit at `tabindex="-1"` and are skipped.
- **Space**: Prevents viewport scroll on keydown, activates on keyup.
- **Enter**: Activates on keydown without preventing the event default.

## What you get

- **Safe form defaults.** Compiles `type="button"` by default, preventing unintended form submission when nested inside `<form>`.
- **Custom element polyfills.** Polyfills `role="button"`, `tabindex="0"`, and Space/Enter key events when wrapping custom elements with `native: false`.
- **Accessible state reporting.** Reflects `aria-disabled` to screen readers and assistive devices.
- **Clean disabled semantics.** Disabled buttons ignore clicks, suppress keyboard activation, and exit the tab order.
