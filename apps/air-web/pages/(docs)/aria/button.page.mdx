# Headless Button

A button is the simplest thing on a page until it sits inside a form: forget `type="button"` and every click submits it, and a `<div>` standing in for a button needs its role, its place in the tab order, and its keys handed to it by hand.

**Headless Button** gives you a button that behaves on any element — the safe form default on a real `<button>`, and the role, the tab order, and the keys on anything else.

```tsx
const button = aria('button', props, { native: false });

<div ref={button.ref} {...button.restProps(['children'])} />
```

:::interactive[Buttons]
```tsx
import { aria } from '@airlib/aria';
import { mutable, setup } from '@airlib/react';
import type { ComponentProps, FormEvent } from 'react';

const DemoFormCard = setup(() => {
  const state = mutable({ submissions: 0 });
  const save = aria('button', { type: 'button' });
  const submit = aria('button', { type: 'submit' });

  const handleSubmit = (event: FormEvent<HTMLFormElement>) => {
    event.preventDefault();
    state.submissions += 1;
  };

  return () => (
    <form className="demo-button-card" onSubmit={handleSubmit}>
      <span className="demo-button-card-title">Inside a form</span>
      <div className="demo-button-row">
        <button ref={save.ref} {...save.restProps(['children'])} className="demo-button">
          Save
        </button>
        <button
          ref={submit.ref}
          {...submit.restProps(['children'])}
          className="demo-button demo-button--custom"
        >
          Submit
        </button>
      </div>
      <span className="demo-button-count">submissions: {state.submissions}</span>
    </form>
  );
}, 'DemoFormCard');

type DemoCustomButtonProps = ComponentProps<'div'> & {
  disabled?: boolean;
};

const DemoCustomButton = setup<DemoCustomButtonProps>((props) => {
  const button = aria('button', props, { native: false });

  return () => (
    <div
      ref={button.ref}
      {...button.restProps(['children'])}
      className="demo-button demo-button--custom"
    >
      {props.children}
    </div>
  );
}, 'DemoCustomButton');

const DemoCustomCard = setup(() => {
  const state = mutable({ activations: 0 });

  return () => (
    <div className="demo-button-card">
      <span className="demo-button-card-title">On a non-button host</span>
      <div className="demo-button-row">
        <DemoCustomButton onClick={() => (state.activations += 1)}>Custom host</DemoCustomButton>
        <DemoCustomButton disabled>Disabled custom host</DemoCustomButton>
      </div>
      <span className="demo-button-count">activations: {state.activations}</span>
    </div>
  );
}, 'DemoCustomCard');
```

## Button

**One action trigger.** It behaves like a native button whether the host is one or not.

### Usage

```ts
aria<E extends BaseElement = HTMLButtonElement>(
  role: 'button',
  props?: ButtonProps,
  options?: ButtonOptions
): ButtonAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type ButtonProps = ComponentProps<'button'> & {
  type?: 'button' | 'submit' | 'reset';
  disabled?: boolean;
};

const Button = setup<ButtonProps>((props) => {
  const button = aria('button', props);

  return () => (
    <button ref={button.ref} {...button.restProps(['children'])}>
      {props.children}
    </button>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type ButtonProps = ComponentProps<'button'> & {
  type?: 'button' | 'submit' | 'reset';
  disabled?: boolean;
};

const Button = setup<ButtonProps>((props) => {
  const button = aria('button', props);

  return (
    <button ref={button.ref} {...button.restProps(['children'])}>
      {props.children}
    </button>
  );
});
```

:::

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **type** _'button' | 'submit' | 'reset', optional, default `'button'`_: The form behavior. Leave it and a click never submits; set `submit` or `reset` when that is the point of the button.
- **disabled** _boolean, optional_: Locks the button out of pointer, keyboard, and form mechanics.

### Options

_What you fix when you create it. Read once, never reactive._

- **native** _boolean, optional, default `true`_: Pass `false` when the host isn't a `<button>`, and the role, the tab order, and the keys come with it.

### Properties

_What you read or write on the instance afterwards._

- **type** _'button' | 'submit' | 'reset'_: The form behavior in force.
- **disabled** _boolean_: Whether the button is locked.

### How it behaves

- **No surprise submits.** A native button defaults to `type="button"`, so nesting it in a form doesn't submit on click.
- **Any element can be the button.** With `native: false`, a `<div>` or `<span>` gets the button role, a place in the tab order, and `Enter` / `Space` activation.
- **Disabled means inert.** Click, `Enter`, and `Space` are bypassed on either host — nothing activates and no activation handler runs. A native host leaves the tab order; a custom host is parked outside it.
- **Only the activation events are owned.** A handler you attach for something else — hover, focus, your own keys — is your code on your element, and the browser has no disabled concept for a `<div>`, so those stay live unless you gate them.
- **Cancellation is honored.** A click you cancel also cancels the submit or reset it would have caused.
- **Screen readers are told.** A locked button is announced as disabled rather than going silently dead.

### Navigation

_What the keys do._

- **`Tab`** — focuses the button. A disabled custom host is parked outside the tab order and skipped.
- **`Space`** — stops the page scrolling on keydown and activates on keyup.
- **`Enter`** — activates on keydown and leaves the event default alone.

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### Button

```ts
interface ButtonProps {
  type?: 'button' | 'submit' | 'reset';
  disabled?: boolean;
}

interface ButtonOptions {
  native?: boolean;
}

interface ButtonAttributes {
  role?: string;
  type?: 'button' | 'submit' | 'reset';
  disabled?: boolean;
  tabindex?: number;
  'aria-disabled'?: 'true' | 'false';
}

declare class ButtonAria {
  get type(): 'button' | 'submit' | 'reset';
  get disabled(): boolean;
}
```

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`attributes`** is the dictionary you spread; **`ref`** is what you bind the element with; **`props`** is the full props dictionary for spreading onto the host; **`restProps(omit)`** hands back your props with the keys you name left out.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
