# Headless Meter

A meter reports one measurement inside a known range — how full, how warm, how loaded.

Getting it right means **committing out-of-range writes to the nearer bound**, **re-clamping a live reading when the interval moves**, **reporting in the units you declared on either host**, **naming the gauge on hosts that cannot name themselves**, and **staying out of the tab order, the key map, and the pointer entirely**.

**Headless Meter** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const gauge = aria('meter', props);

<div ref={gauge.ref} {...gauge.restProps(['children'])} />
```

:::interactive[Workspace Usage]
```tsx
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type DemoMeterProps = {
  label: string;
  reading: string;
  value?: number;
  min?: number;
  max?: number;
  valuetext?: string;
};

const DemoMeter = setup<DemoMeterProps>((props) => {
  const gauge = aria('meter', props, { native: false });

  return () => (
    <div className="demo-meter-row">
      <div className="demo-meter-head">
        <span className="demo-meter-caption">{props.label}</span>
        <span className="demo-meter-reading">{props.reading}</span>
      </div>
      <div ref={gauge.ref} {...gauge.restProps(['children', 'reading', 'valuetext'])} className="demo-meter-track">
        <span className="demo-meter-fill" />
      </div>
    </div>
  );
}, 'DemoMeter');

const DemoNativeMeter = setup<DemoMeterProps>((props) => {
  const gauge = aria('meter', props, { native: true });

  return () => (
    <div className="demo-meter-row">
      <div className="demo-meter-head">
        <span className="demo-meter-caption">{props.label}</span>
        <span className="demo-meter-reading">{props.reading}</span>
      </div>
      <meter ref={gauge.ref} {...gauge.restProps(['children', 'reading', 'valuetext'])} className="demo-meter-native" />
    </div>
  );
}, 'DemoNativeMeter');
```

## Meter

**The gauge.** It reports a reading inside its bounds, in the units you declared.

### Usage

```ts
aria<E extends BaseElement = HTMLElement>(
  role: 'meter',
  props: MeterProps,
  options?: MeterOptions
): MeterAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type MeterProps = ComponentProps<'div'> & {
  value?: number;
  min?: number;
  max?: number;
  label: string;
  valuetext?: string;
};

const Meter = setup<MeterProps>((props) => {
  const gauge = aria('meter', props, { native: false });

  return () => (
    <div ref={gauge.ref} {...gauge.restProps(['children'])} className="meter-track">
      <span className="meter-fill" />
    </div>
  );
}, 'Meter');
```

On a native `<meter>`, declare the host and let the element carry the reading:

```tsx
const gauge = aria('meter', props, { native: true });

<meter ref={gauge.ref} {...gauge.restProps(['children'])} />
```

### Parameters

_What you pass in. The props object stays live — change a value on it and the part follows._

- **value** _number, optional_: The reading, committed clamped to the declared interval. Left out, the gauge reports `min`.
- **min** _number, optional, default `0`_: The lower bound, in the units your reading is already in.
- **max** _number, optional, default `100`_: The upper bound, in those same units.
- **label** _string, **required**_: The gauge's accessible name. **`<meter>` has no naming attribute**, so this compiles to `aria-label` on either host.
- **valuetext** _string, optional_: The reading spelled out — `"72 GB of 100 GB"` — compiled to `aria-valuetext` beside the number on either host.

### Options

_What you fix when you create it. Read once, never reactive._

- **native** _boolean, optional, default `false`_: Declares the host. A native `<meter>` carries `value`, `min`, and `max` itself and compiles no role; a custom host takes `role="meter"` and the ARIA value mirrors instead.

### Properties

_What you read or write on the instance afterwards._

- **value** _number_: The reading in force, clamped to the interval. **Writing it commits the nearer bound**, never the raw number.
- **min** _number_: The lower bound in force, `0` when you declared none.
- **max** _number_: The upper bound in force, `100` when you declared none.
- **offset** _number_: The reading as a percentage of the interval — the same number the published variable carries, and `0` when the interval has no span.

### How it behaves

- **Writes commit clamped.** A reading past a bound stores that bound, so the number you read back, the value that is announced, and the fill all agree.
- **A narrowed interval re-clamps the live reading.** Move `min` or `max` past a value already written and the gauge reports the nearer bound. The number you wrote stays where it was — the reported reading does not.
- **Original units on both hosts.** Nothing is rescaled to a fixed range, so a reading of `45` between `10` and `90` stays `45` everywhere.
- **A custom host compiles the reading for assistive technology.** `role="meter"` with `aria-valuenow`, `aria-valuemin`, and `aria-valuemax` beside it.
- **A native host compiles no role and no value mirrors.** `<meter>` already means a gauge; it takes `value`, `min`, and `max` directly, with the name and the spelled-out reading on top.
- **One variable drives the fill.** A custom host publishes `--aria-meter-offset` as a percentage in its compiled `style`, and `gauge.offset` carries the same number for script.
- **The spelled-out reading is not stripped for you.** `valuetext` is forwarded like any other prop, so `restProps(['children', 'valuetext'])` keeps it off the host while `aria-valuetext` still compiles.
- **It takes no focus and claims no input.** No tab stop, no key handling, no pointer handling — you write the reading, the gauge reports it.

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### Meter

```ts
interface MeterProps {
  value?: number;
  min?: number;
  max?: number;
  label: string;
  valuetext?: string;
}

interface MeterOptions {
  native?: boolean;
}

interface MeterAttributes {
  value?: number;
  min?: number;
  max?: number;
  role?: 'meter';
  'aria-valuenow'?: number;
  'aria-valuemin'?: number;
  'aria-valuemax'?: number;
  'aria-valuetext'?: string;
  'aria-label'?: string;
  style?: {
    '--aria-meter-offset'?: string;
  };
}

declare class MeterAria {
  get value(): number;
  set value(next: number);
  get min(): number;
  get max(): number;
  get offset(): number;
}
```

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`props`** / **`restProps(omit)`** is what you spread onto the host — your props minus the keys the controller writes and any you name, with the compiled attributes merged in; **`ref`** is what you bind the element with; **`attributes`** is that compiled dictionary on its own, when you need the low-level view.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
