# Headless Search Input

A search field is a text field the platform has opinions about. Getting it right means **asking for `type="search"` so the browser brings its own clear button**, **still carrying `role="searchbox"` when the host is not an input**, **keeping the query live while it is typed**, and **telling your code when the query has settled**.

**Headless Search Input** does all of that for you, and leaves the markup and the styling entirely yours.

```tsx
const search = aria('search-input', props);

<input ref={search.ref} {...search.restProps()} />
```

:::interactive[Widget Search]
```tsx
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

const ENTRIES = [
  { name: 'Tabs', tier: 'Composite' },
  { name: 'Accordion', tier: 'Composite' },
  { name: 'Combobox', tier: 'Composite' },
  { name: 'Listbox', tier: 'Composite' },
  { name: 'Switch', tier: 'Widget' },
];

type DemoSearchProps = ComponentProps<'input'> & {
  label?: string;
  value?: string;
  disabled?: boolean;
};

const DemoWidgetSearch = setup<DemoSearchProps>((props) => {
  const search = aria('search-input', props);

  return () => {
    const term = (props.value ?? '').trim().toLowerCase();
    const hits = ENTRIES.filter((entry) => entry.name.toLowerCase().includes(term));

    return (
      <div className="demo-query">
        <label className="demo-field">
          <span className="demo-field-label">{props.label}</span>
          <input ref={search.ref} {...search.restProps(['children', 'label'])} className="demo-field-input" />
        </label>
        <div className="demo-query-results">
          {hits.map((entry) => (
            <div key={entry.name} className="demo-query-hit">
              <span>{entry.name}</span>
              <span className="demo-query-tier">{entry.tier}</span>
            </div>
          ))}
          {hits.length === 0 ? <div className="demo-query-empty">{'No widget matches that query.'}</div> : null}
        </div>
      </div>
    );
  };
}, 'DemoWidgetSearch');

const DemoArchiveSearch = setup<DemoSearchProps>((props) => {
  const search = aria('search-input', props);

  return () => (
    <label className="demo-field">
      <span className="demo-field-label">{props.label}</span>
      <input ref={search.ref} {...search.restProps(['children', 'label'])} className="demo-field-input" />
    </label>
  );
}, 'DemoArchiveSearch');
```

:::tip
This is the **search face of one controller**, not a second text field: `aria('search-input')` is `aria('text-input')` with the search semantics locked. Reach for it when the field is a query, and for [Headless Text Input](/docs/aria/text-input) for everything else.
:::

## Search Input

**The query field.** One live string, announced as a search box on any host.

### Usage

```ts
aria<E extends BaseElement = HTMLInputElement>(
  role: 'search-input',
  props?: SearchInputProps,
  options?: SearchInputOptions
): SearchInputAria<E>
```

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type SearchBoxProps = ComponentProps<'input'> & {
  label?: string;
  value?: string;
};

const SearchBox = setup<SearchBoxProps>((props) => {
  const search = aria('search-input', props);

  return () => (
    <label>
      <span>{props.label}</span>
      <input ref={search.ref} {...search.restProps(['label'])} />
    </label>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type SearchBoxProps = ComponentProps<'input'> & {
  label?: string;
  value?: string;
};

const SearchBox = setup<SearchBoxProps>((props) => {
  const search = aria('search-input', props);

  return (
    <label>
      <span>{props.label}</span>
      <input ref={search.ref} {...search.restProps(['label'])} />
    </label>
  );
});
```

### Parameters

_What you pass in. The props object stays live — typing moves it, and writing it moves the field._

- **value** _string, optional, default `''`_: The live query. **Typing writes into it** and writing it pushes text into the field.
- **placeholder** _string, optional_: The hint shown while the query is empty.
- **label** _string, optional_: The name the field is announced by, for the times a visible `<label>` is not on screen.
- **required** _boolean, optional_: Asks for a non-empty query before the form is accepted. **This face always states it**, as `required` on a native host and `aria-required` on both.
- **readonly** _boolean, optional_: Refuses edits **while staying focusable and selectable**.
- **disabled** _boolean, optional_: Refuses edits and commits, and takes the field out of the tab order on a custom host.
- **invalid** _boolean | 'grammar' | 'spelling', optional, default `false`_: Says the query is wrong, and which kind of wrong it is.
- **multiline** _boolean, optional_: Declared as `aria-multiline` on a custom host. A query is single-line, so this is inherited rather than useful.
- **kind** _'text' | 'password' | 'search' | 'email' | 'tel' | 'url', optional_: Inert on this face — the face is already search.
- **onchange** _(event: CustomEvent&lt;string&gt;) =&gt; void, optional_: Called with the settled query once the text really moves.

### Options

_What you fix when you create it. Read once, never reactive._

- **native** _boolean, optional, default `true`_: Pass `false` when the host is not an `<input>`, and the field gets `role="searchbox"`, a tab stop, and an ARIA mirror for every state.

### Properties

_What you read or write on the instance afterwards._

- **value** _string_: The query. Writing it replaces what the user sees.
- **disabled** _boolean_: Whether the field is locked.

### How it behaves

- **The face is locked.** `type="search"` on a native host and `role="searchbox"` on a custom one, with no way to ask this face for plain text — that is `aria('text-input')`.
- **`aria-required` is always stated.** This face names the required state on both hosts, so assistive tech is never left guessing whether a query is mandatory.
- **The platform keeps its keys and its chrome.** `Enter` submits, `Escape` and the browser's own clear button belong to the platform, and nothing here prevents or claims any of them.
- **Clearing is not a special event.** Emptying the field reads back as an empty query through the ordinary `input` sequence — no `search`, `cancel`, or `clear` event is invented.
- **Live while typing, settled on commit.** Every keystroke moves `value` unless the field is disabled or readonly, and `onchange` only runs when the text really changed.
- **Everything else is the text controller.** Validation projection, the `defaultValue` spread, readonly staying focusable, and disabled meaning inert are the same rules — see [Headless Text Input](/docs/aria/text-input).

### Events

_What it tells you._

- **`input`** — the browser's own text event on a native host, which the controller reads to keep the query live. Never replayed.
- **`change`** — the commit signal, carrying the settled query in `detail`. On a native host the browser's own `change` (leaving the field after an edit, or `Enter`) is handed to `onchange` as a fresh event and **is never put back on the element**, so a listener of your own still sees exactly one. On a custom host the controller dispatches a bubbling `change` of its own. A blur with no diff and any commit under `disabled` stay silent.

```tsx
const search = aria('search-input', {
  value: '',
  onchange: (event) => runQuery(event.detail),
});
```

## API Reference

What you can actually use, with every alias and every base resolved to what it really is. Each attribute dictionary also takes the standard HTML attributes and event handlers for its host, and each props dictionary takes any extra keys you want forwarded.

### Search Input

```ts
interface SearchInputProps {
  value?: string;
  kind?: 'text' | 'password' | 'search' | 'email' | 'tel' | 'url';
  multiline?: boolean;
  readonly?: boolean;
  disabled?: boolean;
  required?: boolean;
  invalid?: boolean | 'grammar' | 'spelling';
  placeholder?: string;
  label?: string;
  onchange?: (event: CustomEvent<string>) => void;
}

interface SearchInputOptions {
  native?: boolean;
}

interface SearchInputAttributes {
  defaultValue?: string;
  type?: 'search';
  readonly?: boolean;
  disabled?: boolean;
  required?: boolean;
  placeholder?: string;
  role?: 'searchbox';
  tabindex?: number;
  'aria-label'?: string;
  'aria-multiline'?: 'true';
  'aria-readonly'?: 'true' | 'false';
  'aria-disabled'?: 'true' | 'false';
  'aria-required'?: 'true' | 'false';
  'aria-invalid'?: 'true' | 'false' | 'grammar' | 'spelling';
}

declare class SearchInputAria {
  get value(): string;
  set value(next: string);
  get disabled(): boolean;
}
```

### On every one of them

```ts
ref: (element: E | null) => (() => void) | undefined;

get props(): T;
get attributes(): Record<string, unknown>;
get ownKeys(): string[];
get isNative(): boolean;
get current(): E | null;
set current(element: E | null);

assign(props: Partial<T>): void;
refine(refiner: (props: T, attrs: A) => Partial<A> | void): (destroyed?: boolean) => void;
on<K extends keyof HTMLElementEventMap>(type: K, handler: (event: HTMLElementEventMap[K]) => void): () => void;
on(type: string, handler: (event: Event) => void): () => void;
restProps(omit?: (keyof T)[]): T;
destroy(): void;
```

- **`attributes`** is the dictionary you spread; **`ref`** is what you bind the element with; **`props`** is the full props dictionary for spreading onto the host; **`restProps(omit)`** hands back your props with the keys you name left out.
- **`assign()`** changes several parameters at once, **`refine()`** adds attributes of your own, **`on()`** listens for anything the part fires, **`destroy()`** tears it down.
