# Search Input

`@airlib/aria` provides a headless behavioral controller for search inputs, compiling search semantics for query fields without dictating markup or styles.

Search Input shares the text input controller with the search face selected, compiling `type="search"` onto the native input. Native search inputs provide built-in clear buttons and submission semantics on `Enter`. Query state updates synchronously through `props.value`.

You control search inputs using this piece:

- **Search Input**: The specialized search query controller compiling `type="search"` semantics and query synchronization.

## What you get

- **Live value synchronization.** Synchronizes with DOM input events and keeps the state in sync.
- **Validation and state projection.** Compiles `aria-invalid`, `aria-required`, `readonly`, and `disabled` state seamlessly.
- **Accessible labeling.** Automatically compiles `props.label` into `aria-label`.
- **Search specialization.** A dedicated `aria('search-input')` face for search query fields with native clear and Enter handling.

## Search Input

In Aria, Search Input is the specialized search query controller created with `aria('search-input')` that compiles search semantics.

```ts
aria<E extends BaseElement = HTMLInputElement>(
  role: 'search-input',
  props?: SearchInputProps,
  options?: SearchInputOptions
): SearchInputAria<E>
```

### Parameters

- `props.value` *(string, optional)*: Current search query value.
- `props.label` *(string, optional)*: Accessible label for the search field compiled to `aria-label`.
- `props.placeholder` *(string, optional)*: Placeholder hint.
- `props.disabled` *(boolean, optional)*: Disables the search field.
- `props.readonly` *(boolean, optional)*: Readonly indicator.
- `props.required` *(boolean, optional)*: Required validation indicator.
- `props.invalid` *(boolean | 'grammar' | 'spelling', optional)*: Invalid indicator, compiled to `aria-invalid`.

### How it behaves

Search Input shares the text input controller with the search face selected, compiling `type="search"` onto the native input. Native search inputs provide built-in clear buttons and submission semantics on `Enter`. Query state updates synchronously through `props.value`.

### Usage

To use Search Input, create the controller with `aria('search-input', props)`, then pass `search.ref` and spread `search.attributes` onto your search input:

:::code-group

```tsx [React]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type SearchInputProps = ComponentProps<'input'> & {
  value?: string;
  label?: string;
  placeholder?: string;
  disabled?: boolean;
};

const SearchInput = setup<SearchInputProps>((props) => {
  const search = aria('search-input', props);
  const restProps = props.$omit([
    ...search.ownKeys,
    'value',
    'label',
    'placeholder',
    'disabled',
    'className',
  ]);

  return () => (
    <input
      ref={search.ref}
      type="search"
      {...restProps}
      {...search.attributes}
      className={props.className}
    />
  );
});
```
