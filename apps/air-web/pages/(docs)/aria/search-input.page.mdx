# AirLib Headless Search Input

A search field looks like a text field until the platform gets involved: native `type="search"` brings its own clear button and submission semantics, while a custom searchbox needs the right role, live query sync, and validation projection without fighting the browser. **AirLib Headless Search Input** (`aria('search-input')`) is the search face of the text controller — it locks `type="search"` on native hosts and `role="searchbox"` on custom ones, without dictating markup or styles.

```tsx
const search = aria('search-input', props);

<input ref={search.ref} {...search.props} />
```

## Search Input

Search query synchronization on the locked search face.

```ts
aria<E extends BaseElement = HTMLInputElement>(
  role: 'search-input',
  props?: SearchInputProps,
  options?: SearchInputOptions
): SearchInputAria<E>
```

### Usage

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type SearchInputProps = ComponentProps<'input'> & {
  value?: string;
  label?: string;
  placeholder?: string;
  disabled?: boolean;
};

const SearchInput = setup<SearchInputProps>((props) => {
  const search = aria('search-input', props);

  return () => (
    <input ref={search.ref} {...search.restProps(['children', 'className'])} className={props.className} />
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type SearchInputProps = ComponentProps<'input'> & {
  value?: string;
  label?: string;
  placeholder?: string;
  disabled?: boolean;
};

const SearchInput = setup<SearchInputProps>((props) => {
  const search = aria('search-input', props);

  return (
    <input ref={search.ref} {...search.restProps(['children', 'className'])} className={props.className} />
  );
});
```

:::

The compiled dictionary carries `type="search"` and `defaultValue`, never `value` — the element stays uncontrolled while props remain the source of truth. Bind `name` yourself; the projection never emits it.

### Parameters

- `props.value` *(string, optional, default `""`)*: Live search query, read and write.
- `props.label` *(string, optional)*: Accessible label compiled to `aria-label`.
- `props.placeholder` *(string, optional)*: Placeholder hint.
- `props.readonly` *(boolean, optional)*: Blocks edits while keeping focusability.
- `props.disabled` *(boolean, optional)*: Blocks edits and commits.
- `props.required` *(boolean, optional)*: Required indicator, always compiled explicitly on this face.
- `props.invalid` *(boolean | 'grammar' | 'spelling', optional)*: Invalid indicator, always compiled explicitly (default `"false"`).

### How it behaves

- The face locks search semantics: `type="search"` on native hosts (so the platform owns the clear button and `Enter` submission), `role="searchbox"` on custom hosts.
- Every keystroke syncs into reactive `value` unless blocked by `disabled` or `readonly`. Clearing the field reads back as an empty query through the standard input sequence — no `search`, `cancel`, or `clear` events are invented.
- Unlike the text face, `aria-required` is always stated explicitly on native hosts, and every keystroke stays platform-owned: `Enter`, `Escape`, and arrows are never prevented or claimed.
- The search face is an alias over the text controller: validation projection, blur commits on custom hosts, form-attribute isolation, and teardown behave identically. See [Text Input](/docs/aria/text-input) for the shared contract.

## Keyboard Navigation

- **Tab**: Focuses the field. Disabled hosts are skipped.
- **Typing / Backspace / arrows**: Native search editing — the platform owns the caret, the clear button, and `Enter` submission.
- **Escape**: Left to the platform; the controller claims no search-specific keystroke.

## What you get

- **Locked search semantics.** `type="search"` natively, `searchbox` on custom hosts, no role or tab stop invented on native.
- **Live query sync.** Keystrokes flow into props both directions, programmatic writes reach the node immediately.
- **Explicit validation.** `aria-required` and `aria-invalid` stated, never dropped.
- **Zero invented events.** Clearing reads back as empty input; the platform keeps its keys.
