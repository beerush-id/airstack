# AirLib Headless File Picker

A file picker looks like a button until the platform gets involved: the real work happens in a hidden `<input type="file">` that must stay in sync with your filters, report dismissal as well as selection, and behave identically whether the visible trigger is a native button or a styled `<div>`. **AirLib Headless File Picker** (`aria('file-picker')`) owns that bridge — it creates the hidden input on attach, removes it on teardown, and forwards every activation to it, without dictating markup or styles.

```tsx
const picker = aria('file-picker', props);

<button ref={picker.ref} {...picker.props} />
```

import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';

type DemoFilePickerProps = ComponentProps<'button'> & {

    </button>
  );

  return () => (

      Browse
    </div>
  );

## File Picker

System file-picker activation over a hidden native input.

```ts
aria<E extends BaseElement = HTMLButtonElement>(
  role: 'file-picker',
  props?: FilePickerProps,
  options?: FilePickerOptions
): FilePickerAria<E>
```

### Usage

:::code-group

```tsx [React] executable
import { aria } from '@airlib/aria';
import { setup } from '@airlib/react';
import type { ComponentProps } from 'react';

type FilePickerProps = ComponentProps<'button'> & {
  accept?: string;
  multiple?: boolean;
  capture?: 'user' | 'environment';
  disabled?: boolean;
};

const FilePicker = setup<FilePickerProps>((props) => {
  const trigger = aria('file-picker', props);

  return () => (
    <button ref={trigger.ref} {...trigger.restProps(['children'])}>
      {props.children}
    </button>
  );
});
```

```tsx [SolidJS]
import { aria } from '@airlib/aria';
import { setup } from '@airlib/solid';
import type { ComponentProps } from 'solid-js';

type FilePickerProps = ComponentProps<'button'> & {
  accept?: string;
  multiple?: boolean;
  capture?: 'user' | 'environment';
  disabled?: boolean;
};

const FilePicker = setup<FilePickerProps>((props) => {
  const trigger = aria('file-picker', props);

  return (
    <button ref={trigger.ref} {...trigger.restProps(['children'])}>
      {props.children}
    </button>
  );
});
```

:::

The compiled dictionary carries `type="button"` and `disabled` on native hosts, or `role="button"` with `tabindex` and `aria-disabled` on custom ones — never `accept`, `multiple`, or `capture`. Those live on the hidden input, not the trigger.

### Parameters

- `props.accept` *(string, optional)*: Accepted file types filter, synced onto the hidden input.
- `props.multiple` *(boolean, optional)*: Multi-file selection flag, synced onto the hidden input.
- `props.capture` *('user' | 'environment', optional)*: Media capture source for mobile devices.
- `props.disabled` *(boolean, optional)*: Blocks the picker from opening.
- `props.onchange` *(function, optional)*: Called with the selected files after a successful pick.
- `props.oncancel` *(function, optional)*: Called when the picker closes without a selection.
- `options.native` *(boolean, optional, default `true`)*: Bind a native `<button>`; set `false` for custom hosts.

### Events

Both events dispatch on the trigger element:

```ts
const picker = aria('file-picker', {
  onchange: (event) => {
    const files = event.detail;
  },
  oncancel: () => {
    // picker dismissed without a selection
  },
});
```

Attaching to the trigger still works, but there the DOM library types the listener as `Event`, so reading `detail` needs `event as FilePickerEvent`.

- `change`: `CustomEvent<File[]>` with `bubbles: true`, carrying the selected files.
- `cancel`: `CustomEvent<void>` with `bubbles: false`, fired on picker dismissal without selection.

### How it behaves

- The hidden `<input type="file">` is created when the trigger binds and removed with it — teardown takes the internal host away, so no stray inputs linger in the document.
- `accept`, `multiple`, and `capture` sync reactively: assigning new props updates the hidden input without rebinding.
- Every activation bridges once: click, `Enter`, and `Space` each open the picker exactly once per gesture. A canceled initiating event (`defaultPrevented`) or `disabled` opens nothing.
- Custom hosts get full button mechanics: `role="button"`, roving-safe `tabindex` (`-1` while disabled), `aria-disabled` announcements, suppressed `Space` scrolling with keyup activation, and immediate `Enter` activation.
- The native `change` on the hidden input never replays to the page — exactly one announcement (the controller's) is observable per selection.

## Keyboard Navigation

- **Tab**: Focuses the trigger. Disabled hosts resolve to `tabindex="-1"` on custom elements and are skipped natively.
- **Enter**: Opens the picker immediately on both hosts.
- **Space**: Opens the picker on keyup for custom hosts (keydown scrolling is suppressed); left to the platform natively.

## What you get

- **Hidden input ownership.** Created on bind, constraint-synced while live, removed on teardown — never leaked, never hand-wired.
- **Honest selection events.** One bubbling `change` carrying `File[]` per confirmation, one non-bubbling `cancel` per dismissal, nothing replayed.
- **Inertness by default.** `disabled` and consumer cancellation both keep the picker closed on every host.
- **Custom-host parity.** Non-semantic elements get the role, focus, keys, and announcements a native button has for free.
